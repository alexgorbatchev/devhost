# Rust port feature verification

The Rust port has implementations and executable checks for the feature groups below. This is an inventory of the Go contract and the available evidence, not a declaration that every platform or user journey has passed.

The reference is Go `fa2ffb9402319a81721d53717614cf8bea61fad6`, the commit behind `v0.0.20`. The [machine-readable inventory](../../../apps/devhost/rust/parity/inventory.json) assigns all 231 production Go source files and public contract documents to 24 feature groups. It records Git blob hashes, individual behavior obligations, Rust implementation paths and test sources. Go test fixtures and test-only support packages are excluded from the production inventory; their behaviors inform the checks. Shared frontend source remains in the same repository and bundle.

## Detect omitted or changed contracts

From the repository root:

```sh
git fetch origin main --tags
bun apps/devhost/scripts/verifyRustParity.ts
```

The check rejects an advanced Go reference, new/unassigned production sources or public documents, changed reference hashes, unexplained working-tree differences, duplicate assignments and missing implementation/test paths. An explicit reference may be passed as the final argument. Intentional port-branch changes to shared Go code or documentation have separate hashes and explanations; they do not modify the oracle.

The [acceptance map](../../../apps/devhost/rust/parity/obligations.json) expands all 120 grouped obligations into concrete triggers, effects, failure behavior, cleanup and evidence selectors. Each case names the remaining gap. Its evidence definitions distinguish shared external-CLI comparisons, Rust regressions, shared frontend components and build-only contracts. All cases remain open until their complete contract has execution receipts or an explicit shared-component justification; the map is an acceptance plan, not a pass report. The inventory check rejects missing, duplicate or stale obligations and broken evidence references.

When Go changes, inspect the range, identify every affected behavior in the inventory, repair the Rust implementation and rerun the affected comparisons before recording new hashes. Do not regenerate hashes merely to silence the check. The catch-up range contains release-only commits, command-backed serving and named-session controls, the project/global restart scope split, and global retirement of instances whose launch directory was removed. The behavior changes have shared executable scenarios. The v0.0.19-to-v0.0.20 range adds preflight validation of file-serving roots during global restart; the shared renamed-root scenario passes both executables. The port branch also repairs Go defects reproduced in comparisons: closing-tag injection uses original document-byte offsets, and duplicate names in a service restart batch restart each service once. On macOS, command-backed serving also uses the system lsof listener reader instead of an unsupported gopsutil API. These repairs are recorded separately from the unchanged Go oracle.

## Evidence levels

- **Shared comparison:** the same fixture and assertions execute against separate Go and Rust processes, configurations, ports and state. Rust Anything also records Go exit codes and output and replays the same inputs against Rust.
- **Rust regression:** native Rust tests exercise the behavior. A passing test does not establish a Go comparison that was never run.
- **Source correspondence:** a Go source is assigned to a Rust implementation and behavior obligation. File hashes detect drift; they do not prove equivalent semantics.
- **Native acceptance:** run the applicable comparison on the named operating system and architecture. Cross-compilation alone cannot satisfy it.

## Repeatable verification

Build the Go oracle at the pinned commit in an isolated checkout with `just devhost compile`; its executable is `apps/devhost/bin/devhost`. Build the optimized Rust candidate with `just rust build-release`. Follow the [Rust Anything record/replay procedure](rust-port-parity.md#record-and-replay-with-rust-anything) for every `apps/devhost/rust/tests/*.jsonl` corpus. Record and replay anew when either reference or corpus changes. Help wording and generated completion script bytes vary by CLI framework; compare command/flag availability, exit status, streams and completion behavior separately. The maintained comparison runner snapshots each binary before execution so other builds cannot replace a candidate during validation.

Run the shared native scenarios against both binaries:

```sh
just rust test --test stack_commands
DEVHOST_STACK_TEST_BINARY=/absolute/path/to/go/devhost just rust test --test stack_commands
just rust test --test remote_transport
DEVHOST_REMOTE_TEST_BINARY=/absolute/path/to/go/devhost just rust test --test remote_transport
```

The maintained `just rust comparisons <clean-Go-oracle-checkout> <repaired-Go-binary> <optimized-Rust-binary> <new-evidence-directory>` recipe runs the corpora and shared native fixtures with retained hashes, logs and explicit assertions for the unchanged oracle's duplicate-restart, legacy-document, nested-include path, literal-environment and exhausted automatic-port retry defects. Fixed-port collisions, successful automatic retries and exhausted retries share real occupied-port fixtures that check references, startup order and cleanup. On macOS, four command-serving scenarios are excluded only for the unchanged oracle, whose listener API is unsupported; a separate exact failure assertion reproduces that unsupported API. Repaired Go and Rust run all four scenarios. Repaired Go and optimized Rust must pass those fixtures. CI runs the recipe on hosted Linux x64, Linux ARM64 and macOS ARM64, checks current-Go inventory drift, and uses the pinned Rust toolchain; Linux x64 additionally checks the declared minimum compiler and 90% first-party line/function coverage. Candidate packaging is a separate manual input and uploads unpublished artifacts only.

The runner also walks all 26 public help entry points and compares command names and short/long flag availability. It runs the shared CLI validation, precedence, skill, stamped-version and native Bash Readline cases against each executable. Three additional Rust regressions retain framework-specific help layout, installation instructions and diagnostic wording; those are excluded from the shared subset. Flag types/defaults and invalid inputs require semantic cases rather than equal help prose. Each binary's version is checked against its own stamp.

One intentional semantic CLI difference is explicitly accepted: an unsupported completion shell prints help and exits successfully in Go 0.0.20 (Cobra default), while Rust rejects unknown shell names with an error and exit status 1. The shared invalid-input assertions exclude that Go 0.0.20 quirk while the Rust diagnostic regression enforces rejection. The four supported shell generators remain in the shared checks.

Then run `just rust check` for first-party formatting, Clippy and 90% line/function coverage, and `just check` for the shared Go, UI, docs and workflow checks. Coverage measures exercised implementation, not feature completeness. Preserve the actual command output, exit code, duration, platform, both full revisions and binary/input hashes with each comparison. A dirty build needs its patch or source hash alongside the base commit; never label it as the unchanged base revision.

Additional shared executable fixtures live in `tests/stack_commands/{files,control,worktrees,documents,health,lifecycle,processes}.rs`, `tests/stack_lifecycle/compatibility.rs`, `tests/cli/readline.rs` and `tests/root_certificate.rs`. Linux x86_64 runs against Go v0.0.20 and optimized Rust cover file responses and traversal, configuration editing and control WebSockets, saved Git worktree switching, opaque environment values, HTTP/2 health recovery, detached startup, native Bash completion, certificate lookup and Caddy generation receipts. Health fixtures compare process-only timing semantics and TCP, HTTP and HTTPS probe intervals, deadlines and failure-to-success transitions. Lifecycle fixtures compare daemon status/start/stop failures, failed-start cleanup retry and escalation for a TERM-ignoring foreground process. For a TERM-ignoring daemon start helper, both Go binaries kill the helper but report exit 1; Rust preserves cancellation exit 130. This accepted failure is checked separately and does not cover detached descendants. Reload fixtures cover rejected manifests, newly discovered include globs and route recovery. Selection and document fixtures also pass against repaired Go; the unchanged oracle retains the duplicate-restart and legacy-HTML defects described above. These runs expand the evidence without closing the remaining per-obligation mapping or native, browser, authenticated and external acceptance.

The command-tree comparison walks all 26 visible Go command help entries and compares subcommands and long/short flag names with Rust. Rust Anything inputs cover flags and errors; native scenarios cover runtime effects. Parser type labels, usage layout and prose remain framework-specific.
