# Jump between the page and the source: proposed experience

Diagrams: [current](../component-source-current.html), [proposed](../component-source-proposed.html). [Wireframe](../wireframes/component-source.html).

Status: design proposal, not implemented behavior. The [shared UX pattern reference](../patterns.md) wins where this proposal disagrees with it.

Source revision: alexgorbatchev/devhost `edb5c0fc01cabae490e92ac23d4c785ec896c4ed`. Features: SRC-01, SRC-02, SRC-03. Redesign ticket: tracked privately.

Product rule: the public docs set the contracts this flow keeps. `guides/devtools.md` promises that "**Alt + right-click** on an element opens its React component's source file in your editor and copies the path. It needs a development build that exposes source locations, and opens the file in the selected worktree."; `guides/react-highlight.md` says that "A successful response means devhost received the update, not that anything matched on the page." and that "devhost does not launch editors and ships no editor plugin."; the owner's rules add that every manifest setting applies through hot reload. So a cursor update answering success whether or not anything matched is intended, opening the file in the checkout the page runs is intended, and reaching the editor through its URL handler is today's documented design; none of them is a defect. The gaps are around them: React 19, the current React, records its source locations in a form devhost never reads, so both documented features fail silently on it and markers reach the agent without a file; nothing tells the person that a path was copied or that the editor did not open; the editor is a team-wide manifest setting with four choices; and highlight from the editor misses the element the cursor sits in and leaves its outline behind when the layout moves.

## Target experience

The person holds Alt and right-clicks a button on their React 19 page, or, with Select Elements latched on, walks the highlight to it with the arrow keys and presses Shift+F10. The element is outlined with its role and name before the click, by the same resolver Select Elements uses, and the source menu opens at once beside it, inside the window and clear of the toolbar's notices, with focus on its first item. Its title names the editor and where that choice comes from, "Open in Cursor · from your devhost config file"; the line under it names the checkout the files are in, "Files in fix-nav ~/acme/.worktrees/fix-nav"; then the element and each component that renders it, "\<h1>" at "frontend/src/components/PlaygroundLayout.tsx:15:7", each with its non-default props, followed by a **Copy Path** item per entry. Enter opens the file at that line and column in the person's editor, and the notice stack says what happened, "Opened PlaygroundLayout.tsx:15:7 in Cursor", or, in words, why it did not; typing c and Enter copies the path and says "Copied path · frontend/src/components/PlaygroundLayout.tsx:15:7". When the page records no source for the element, the same menu opens and says why, with **Copy Element Path**, so the gesture never ends in a dead click and the browser's own menu is never taken for nothing. The same lookup gives page context's marks their file, so an agent asked about "#1" gets "PlaygroundLayout.tsx" instead of searching for it. Going the other way, an editor plugin publishes its cursor and every open page of the stack outlines the element the cursor sits in, in the checkout that page runs, and the outline stays on that element through scrolling, resizing and the hot update the edit causes. The editor is the person's: `DEVHOST_EDITOR`, then the devhost config file, then the team's manifest. Nothing here writes to the stack, so there is no Undo: opening a file and copying a path change nothing devhost could take back, and each says what it did. Benchmarks: click-to-component opens a component's source on Option+Click and lists the component and its parents on Option+Right-click; React DevTools reads React 19's owner stacks and maps them through source maps without any build plugin; Vite's `/__open-in-editor` and Next.js's dev overlay open a file through the editor's own command (launch-editor) and report when that command is missing, and launch-editor takes the person's editor from an environment variable before guessing; LocatorJS keeps the editor choice per person rather than per project; Chrome DevTools walks the DOM with the arrow keys and keeps "Copy" actions in its context menu; VS Code's "Copy Path" and "Copy Relative Path" copy without opening. Competitor behavior is evidence here, never a requirement.

## Target steps

Today: 3 steps on a React 18 page whose editor registered its URL handler (Alt + right-click, click the entry, which copies and opens without a word, then look for the editor), and 1 dead step on React 19, where Alt + right-click shows nothing and takes the browser's menu with it. Proposed: 3 steps on both: Alt + right-click with the element outlined before the click, **Open** an entry or **Copy Path**, read the outcome in the notice stack. Highlight from the editor stays 2 steps, the editor publishing its cursor and the page outlining the element, but now finds the element the cursor sits in and keeps the outline on it.

1. **Point at an element (the shared element resolver, read only).** Holding Alt (Option on macOS) and right-clicking an element of the app page, outside devhost's own surfaces, opens its source menu; while Select Elements is latched on, Shift+F10 or the context-menu key opens it for the highlighted element (`KEY-12`, `MENU-1`; `keyboard-14`). Both resolve the element with the one resolver that Select Elements and holding Alt use, which page-context owns and which outlines the element with its role and name before the click, so the element shown is the element looked up (`SEL-9`; `selection-09`). devhost takes the browser's context menu only for Alt + right-click and always answers it: the source menu opens at once, also when there is no source to show (`MENU-3`, `KEY-2`; `selection-11`, `keyboard-02`). Alt pressed as part of a chord, or to type a character, never starts selection (`KEY-2`). A right-click without Alt stays the page's and closes an open source menu, and Alt + right-click inside devhost's own surfaces stays the browser's, as today.
   - Defaults: on while `[devtools.editor].enabled` is true, the default; with it false, both Alt + right-click and highlight from the editor are off, the browser's menu opens, and the docs' settings row says that it turns off both (`SEL-11`; `selection-14`).
   - Keys: Alt + right-click; in Select Elements, the arrow keys walk the highlight and Shift+F10 or the context-menu key opens the menu (`KEY-12`; the two 2.11 rows component-source owns).
2. **Find the element's source in the page's checkout (the shared source lookup, in the page, read only).** The page reads the element's React source: React 18's `_debugSource` and `__source` first, as today; then, on React 19, the fiber's `_debugStack`, the stack React records where the JSX was created, whose first frame outside React is the JSX call site; then the React DevTools extension's renderer interface, kept as the last fallback (`page-context-06`). Each bundle position is mapped back through the page's source maps, read from script elements, from modules loaded through `import` and chunks loaded later, from a `SourceMap` response header, or from the last `sourceMappingURL` comment whatever follows it (`source-and-minimap-10`). The owner chain is walked the same way, each owner's `_debugStack` included, and duplicates are dropped, so the menu lists the element and the components that render it. Paths are resolved in the page's checkout: the selected checkout of the repository the page's service runs from, with a path from another checkout of that repository rewritten to it, as today (`SEL-3`; `selection-03`). The same lookup gives page context's marks their source file, so on React 19 a mark reaches the agent with its file and page-context's row shows it, "#1 h1 Devtools playground · PlaygroundLayout.tsx:15", or "no source found" (`SEL-9`; `page-context-06`). It stays one shared module under `packages/devhost-ui/src/devtools/shared/` (today `reactSourceInspection.ts` and `symbolicateSourceLocation.ts`), which page-context's marks and this flow's menu both call; it adds no control route.
   - While a source map is read for the first time, the open menu shows "Finding the source of \<h1>…" where its entries go, never an empty menu, with focus on the menu itself; when the entries arrive, focus moves to the first of them (`STATE-1`, `KEY-6`).
3. **Read the source menu (a menu anchored at the element, read only).** The menu opens at the pointer, or at the highlighted element after Shift+F10, inside the viewport and never clipped (`SURF-9`). It is a transient layer above the page, placed in the page area on the side of the pointer away from the dock, so it covers neither the notice stack nor docked chat's header, composer or decision card; where that area is narrower than the menu, the menu narrows to it, down to 240 CSS pixels, and wraps its paths (`SURF-1`, `SURF-6`; `surfaces-01`). Alt + right-click lands outside an open toolbar panel, which closes as any click away closes it (`SURF-2`), so the menu never covers another devhost surface's controls. It takes pointer input only where it draws, and the outline of the element it opened on stays anchored to that element while it is open (`SURF-11`, `SURF-12`; `surfaces-10`, `surfaces-11`). Its title names the editor and where that choice comes from: "Open in Cursor · from your devhost config file", "Open in WebStorm · from DEVHOST_EDITOR", "Open in VS Code · from devhost.toml", or "Open in VS Code · devhost's default" (`SEL-11`, `CC-39`; `selection-14`). The line under the title names the checkout the files are in by its `SEL-4` label, "Files in fix-nav ~/acme/.worktrees/fix-nav" (`SEL-4`; `selection-04`, `language-04`). Then one entry per source: the element or component name, "\<h1>", a badge per non-default prop, as today, and the path relative to that checkout with line and column, "frontend/src/components/PlaygroundLayout.tsx:15:7"; a path longer than the menu is shortened in the middle, keeping the file name and line, with the full path in its tooltip and accessible name (`WORD-8`). After a separator, one **Copy Path** item per entry, "Copy Path · \<h1>" (`WORD-3`); the reference writes "Copy path" in `KEY-10` and in this flow's section 4 lines, while `WORD-3` gives action labels, menu items included, title-style capitalization; this proposal reads `WORD-3` as deciding the item's label, "Copy Path", and leaves aligning `KEY-10` and section 4 with it to the pattern reference's author. The menu's foot shows its keys from the binding definitions, "↑↓ Move · Enter Open · Esc Close" (`KEY-13`; `keyboard-15`).
   - A menu with one source has one entry and one **Copy Path** item and no group heading; with two or more, a heading labels each group, "Element and components" over the entries and "Copy" over the **Copy Path** items (`MENU-2`).
   - Keys: focus moves into the menu on open, on its first item (`KEY-6`; `keyboard-10`); ArrowUp and ArrowDown move, Home and End jump, a letter jumps to the next item that starts with it, so typing c reaches **Copy Path**, and Enter or Space activates; Escape, Tab or Shift+Tab closes it (`KEY-10`, `KEY-8`; `keyboard-07`, `keyboard-13`). When Escape, Tab, Shift+Tab or one of its items closes it, focus goes where `KEY-5` and `KEY-6` send it for a surface opened with the pointer: to the page element that had focus before the right-click, which is the element itself when the click focused it; opened with Shift+F10, focus returns to the Select Elements toggle with the highlight still on the element (`KEY-12`). A click outside the menu closes it and acts on what it lands on, as any click on the page does, and devhost moves no focus after it. devhost never adds a `tabindex` to a page element to give it focus, because the devtools stay isolated from the page. This proposal reads `KEY-10`'s "the element it opened on" this way: the page element that had focus before the right-click, or the element itself when the click focused it, and never a page element devhost gives focus to; settling the wording of `KEY-10`, `KEY-6` and 2.3's Accessibility paragraph is left to the pattern reference's author.
   - Inside the open menu devhost keeps every key; once it closes, the page's keys work again without a click on the page (`KEY-5`).
4. **Open the file in the editor (Open in Editor, a hand-off to the editor; no devhost write).** Enter or a click on an entry closes the menu and hands that file, line and column in the page's checkout to the person's editor (`SURF-15`). The notice stack reports the outcome, announced once (`FB-2`, `FB-9`; `feedback-02`):
   - Through devhost's editor launch (Backend 2, `[discuss]`): "Opening PlaygroundLayout.tsx:15:7 in Cursor…" until devhost answers (`FB-1`), then "Opened PlaygroundLayout.tsx:15:7 in Cursor" once the editor's command took the file, a success notice that closes 4 s after the pointer and focus leave it (`FB-3`, `FB-6`, `O14`, `WORD-4`). When the editor cannot start, a failure notice in words that stays until dismissed: "Cursor did not open PlaygroundLayout.tsx:15:7: its command, cursor, was not found. Install Cursor's shell command, or choose another editor in your devhost config file." with **Copy Path** and **Copy Error**, which copies the original error (`FAIL-2`, `WORD-7`, `FB-6`; `feedback-03`, `feedback-07`, `language-09`; `source-and-minimap-02`).
   - Through the editor's URL handler, today's way and the way while Backend 2 is undecided: "Sent PlaygroundLayout.tsx:15:7 to Cursor · devhost cannot tell whether Cursor opened", never "Opened", because a page cannot see whether a URL handler ran; it reports no failure, so it closes as a success notice does, 4 s after the pointer and focus leave it (`FB-5`, `FB-6`, `O14`; `source-and-minimap-02`).
   - Opening a file reads it and starts no service, so it never asks (`REV-1`) and stays available while another operation runs (`HOLD-3`); opening no longer copies anything by itself.
   - The shared editor hand-off is one function under `packages/devhost-ui/src/devtools/shared/`, which takes a file, a line and a column and reports through these notices; every **Open in Editor** that other flows offer with the config editor off (config-editor, manifest-hot-reload, proxy-settings, worktree-switch, startup-and-recovery) calls it (`MENU-4`).
5. **Copy a path (a clipboard write in the page; no devhost write).** **Copy Path** puts the entry's path, relative to the checkout with its line and column, on the clipboard, closes the menu and shows "Copied path · frontend/src/components/PlaygroundLayout.tsx:15:7", which closes 4 s after the pointer and focus leave it (`FB-2`, `FB-3`, `FB-6`, `WORD-4`, `O14`; `feedback-02`, `language-11`; `source-and-minimap-02`). When the browser refuses the clipboard, a failure notice reads "Could not copy the path: the browser did not allow clipboard access", with the path as selectable text in it, and stays until dismissed (`FAIL-2`, `FB-6`).
   - Copying and opening are actions of this page, not operations of the stack: they write no line in the stack's log and no operation record, which `FB-7` and `ACT-1` keep for operations; their notices and the announcer are notices-and-feedback's.
6. **Choose your editor (`DEVHOST_EDITOR`, the devhost config file or the manifest; a setting the person saves, applied through hot reload).** devhost takes the editor from `DEVHOST_EDITOR`, else `[devtools.editor].ide` in the devhost config file, else `[devtools.editor].ide` in the manifest, which stays the team's default, else VS Code; the control server sends the page the merged value with its source, which the menu's title names (`SEL-11`, `CC-39`; `selection-14`; `source-and-minimap-03`). A change in the devhost config file or the manifest applies through hot reload and reaches open pages with the next health message, as a manifest `ide` change does today (owner rule); `DEVHOST_EDITOR` is read when the stack starts, like every environment variable of the devhost process. A value devhost cannot use is reported where it was set: the manifest and the devhost config file reject it on save with the accepted values while the stack keeps running what it accepted, as today, and an unusable `DEVHOST_EDITOR` prints one line at start naming it and the editor used instead (`FAIL-2`, `HOLD-6`). Beyond the four built-in editors, any editor with a URL handler works through a URL template, `[devtools.editor].url = "myeditor://open?file={file}&line={line}&column={column}"`, and any editor with a command through `[devtools.editor].command = ["subl", "{file}:{line}:{column}"]` in the devhost config file, which needs devhost's editor launch (Backend 2 and 3, `[discuss]`; `source-and-minimap-03`).
7. **Highlight the element under the editor's cursor (`POST /__devhost__/react-highlight/cursor`, read only for the stack).** An editor plugin or script publishes the cursor as `file:line:column`, as today, and every open page of the stack outlines what that location renders. A relative locator is relative to the checkout the page runs, which the page already follows through a switch, never the checkout the stack started from (`SEL-3`, `SEL-4`; `source-and-minimap-09`); an absolute path or a `file://` URL inside the stack's checkouts matches the same element, and a relative path that names no file there is tried against each service's folder and used when exactly one file matches (`source-and-minimap-08`). The match is the innermost JSX element that contains the cursor, whose opening tag starts at or before the cursor and whose closing tag ends after it, so a cursor anywhere in `<h1>Devtools playground</h1>` outlines the heading, and earlier occurrences of the tag are counted only before that element's own `<` (`source-and-minimap-08`). The source maps searched are step 2's: script elements, modules loaded through `import`, chunks loaded later and `SourceMap` headers (`source-and-minimap-10`). The outline stays on its element: it is re-measured on scroll, resize, layout change and DOM mutation; after a hot update re-renders the JSX, the page matches the same locator again and moves the outline to the new element; when nothing matches any more, the outline gives way to "\<h1> left the page" at its last place until the next cursor update (`SURF-12`; `surfaces-11`; `source-and-minimap-08`). The `devhost:react-highlight` event and the console warning carry the root the locator was compared with and, when nothing matched, one reason: `no-source-file` (no loaded source map holds the file), `component-tag` (the JSX there renders no element of its own), `no-dom-match` or `outside-checkouts` (`source-and-minimap-08`, `source-and-minimap-09`, `source-and-minimap-10`). The POST still answers success once received, as documented. Outlines stay below the toolbar, never block clicks, and clear on `{"locator": null}`, on the next update and when the stream drops, as today.

Branches and edge states:

- **Shift+F10 in Select Elements.** The menu anchors at the highlighted element and, when it closes, focus returns to the Select Elements toggle with the highlight kept (`KEY-12`, `KEY-6`).
- **No source found.** The menu opens all the same, titled "No source for \<h1>", with one sentence naming the cause and **Copy Element Path**, which copies the element path page context sends, "main > section.hero > h1", and reports "Copied element path · main > section.hero > h1" (`MENU-3`, `FAIL-2`; `selection-11`; `page-context-06`). The causes: "No React component renders this element." when the element has no React fiber; "This page's React build records no source locations: React 18 needs the JSX development transform, and React 19 a development build." when its fiber records none; "Found \<h1> in index.js line 5294, but its source map could not be read (404)." when the map does not load (`STATE-4`). The browser's menu is never taken without this answer.
- **A source outside the stack's checkouts**, such as a linked package elsewhere on disk. The entry shows its absolute path shortened with `~`, **Copy Path** works, and Open works through the URL handler; through devhost's launch it is unavailable with "This file is outside this stack's checkouts" in the menu's status line and as the entry's accessible description, because the launch opens only files inside them (Backend 2; `MENU-3`, `HOLD-1`).
- **The repository switches.** The menu opens and works, and its checkout line names the checkout the page still shows with the operation in progress, "Files in main ~/acme · Switch and Restart Stack is running · 2 of 6 started", because reads and hand-offs stay available during service operations (`HOLD-3`, `SEL-4`); today the gesture silently falls through to the browser's menu. The page reloads into the new checkout when the switch ends, which closes the menu.
- **A blocked checkout.** With the page's selected checkout deleted, the menu lists the sources with their paths and **Copy Path**, and each entry's Open is unavailable, focusable with `aria-disabled`, with "The checkout ~/acme/.worktrees/fix-nav was deleted; its services still run from it" as visible text in the menu's status line and as each entry's accessible description (`HOLD-4`, `HOLD-1`, `MENU-3`). The menu then offers `MENU-5`'s lead action, **Return to Configured Checkout**, a link that opens the Worktrees panel with that action focused, where it asks in place as worktree-switch specifies (`REV-2`, `REV-4`), and **Check Again**, which reads the checkout list once and stops nothing (`HOLD-4`).
- **The lost connection.** The lookup, **Copy Path** and Open through a URL handler keep working, because they run in the page; an editor that devhost launches is unavailable with "Lost connection to devhost; retrying" in the menu's status line and as each entry's accessible description until the stream returns, and the lost-connection notice's **Retry Now**, notices-and-feedback's, is the way forward (`HOLD-2`, `HOLD-1`); highlight from the editor clears its outlines, as documented.
- **The toolbar collapsed.** Alt + right-click and highlight from the editor work the same; a failure notice from opening or copying stays visible in the collapsed toolbar's one-line form beside the badge until dismissed, and successes close by themselves (`SURF-8`, `FB-8`).
- **A page opened from another machine.** A file opens on the machine that runs the stack, so Open is unavailable with "Opening in an editor works only on the machine that runs this stack" and **Copy Path** works (`HOLD-7`, `MENU-3`; Backend 2). Who can reach the control API from the network is `network-exposure-01`'s, outside this redesign.
- **The page's own modal dialog.** Alt + right-click on an element inside the page's dialog opens the menu inside the dialog's top layer, where the notice stack and the announcer already move, so its items take the keyboard and the pointer and its notices are heard (`SURF-11`, `FB-9`; `surfaces-10`). The paused bar is unchanged. `SURF-11` names only the notice stack and the announcer as moving into the page's dialog; this proposal moves the source menu there too, and naming it in `SURF-11` is left to the pattern reference's author, with toolbar-shell, which owns the layering it uses.
- **A rejected configuration, or chat that cannot take a message.** Neither blocks anything in this flow (`HOLD-6`, `HOLD-5`).
- **A lost answer from devhost's editor launch.** The notice reads "devhost did not answer; Cursor may have opened PlaygroundLayout.tsx:15:7" with **Copy Path** and stays until dismissed; the page never sends the request again by itself, because a second launch can open a second window (`REV-12`, `FB-6`).
- **A cursor on a component tag.** `<PlaygroundLayout />` renders no element of its own: without React's source metadata the event says `component-tag` and nothing is outlined, as the docs explain; with it, every element the component renders is outlined, as today.
- **Several pages open.** Every open page of the stack matches the same locator, each against its own checkout, so a page whose service runs another repository compares with that repository's checkout (`SEL-3`).

## What changes versus today

- **Removed:** the dead click on React 19, where devhost took the browser's menu and showed nothing; the single entry button that copies and opens without a word; swallowed clipboard errors; the start-time checkout sent as the root of every cursor update; the outline measured once into a fixed box; paths cut from the left; the source menu switched off without a word while the page's repository switches or is blocked.
- **Merged:** Select Elements, holding Alt and Alt + right-click resolve elements with one resolver (page-context's); marks and the source menu read one source lookup, now including React 19; every **Open in Editor** across devhost calls one editor hand-off with one set of outcome and failure notices.
- **New:** React 19 source locations from `_debugStack` without a browser extension; source maps from modules loaded through `import`, later chunks and `SourceMap` headers; the "No source" menu with its cause and **Copy Element Path**; **Copy Path** items; outcome and failure notices for copying and opening; the checkout line; the editor's source in the menu's title; the menu keyboard model with type-ahead and its hint line; Shift+F10 in Select Elements; the editor from `DEVHOST_EDITOR` and the devhost config file; URL and command templates and devhost's editor launch (`[discuss]`); highlight of the element that contains the cursor, absolute and `file://` locators, service-folder fallback, anchored outlines that follow hot updates, "\<h1> left the page", and the root and reason in the event; the menu inside the page's modal dialog.
- **Changed:** the editor comes from `DEVHOST_EDITOR`, then the devhost config file, then the manifest (`CC-39`); Alt + right-click during a switch or on a blocked checkout opens the menu with its reason instead of falling through to the browser's menu; Open no longer copies, and **Copy Path** no longer opens; the menu takes focus and returns it (`KEY-6`), where today it never takes focus and handles only Escape; a relative locator compares with the page's own checkout, where today the cursor update's start-time root wins (`useReactHighlightOverlay.ts:63`); a path is shortened in the middle, where today it is cut from the left; with Backend 2 approved, devhost starts the editor's command, which `guides/react-highlight.md` says it never does today.
- **Kept:** walking every safeguard of the current flow:
  - When the build exposes source locations, the menu lists the element and its component chain with their non-default primitive props and paths mapped back through the page's source maps, without duplicates.
  - The element looked up is the one under the pointer that Select Elements would pick (`SEL-9`).
  - A path from another checkout of the repository is rewritten to the selected checkout, so the editor opens the file the page runs (`resolveWorktreeSourcePath`).
  - The menu stays inside the window and closes with Escape, a click outside or a worktree switch.
  - Alt + right-click inside devhost's own surfaces stays the browser's, a right-click without Alt stays the page's and closes an open menu, and `[devtools.editor].enabled = false` turns off both Alt + right-click and highlight from the editor.
  - The React DevTools extension's renderer interface still answers when the fiber records no source.
  - The built-in editors keep their URL handlers, which stay the way to reach an editor when devhost does not start it.
  - A manifest `ide` outside the accepted values is rejected on save with the accepted list while the accepted manifest keeps running, and a saved editor change reaches open pages with the next health message, without a reload.
  - Highlight reaches every open page of the stack and never another stack's; a cursor update posts to the page's own hostname.
  - The cursor route answers success once it received a well-formed update and `400` for a malformed one, as documented.
  - Highlight first compares with React's source metadata and falls back to source maps, and matches simple tags when the metadata is missing, as documented.
  - Outlines sit above page content and below devhost's toolbar, never block clicks, and clear on `{"locator": null}`, on the next update and when the stream drops: `reference/control-api.md` keeps "editor highlights clear" after `CC-26`'s rewording.

## Recommended priority

The flow is used less often than chat or the Services panel, but page context sends every mark through its lookup. Ship first the slice with no backend dependency: the React 19 lookup in the shared module, which fixes marks and the menu at once, the "No source" answer, the menu's keyboard model, **Copy Path** with its notices, the checkout line and the URL-handler outcome that never claims success.
