# Edit configuration in the browser: proposed experience

Diagrams: [current](../config-editor-current.html), [proposed](../config-editor-proposed.html). [Wireframe](../wireframes/config-editor.html). Research: [Edit configuration in the browser: research](config-editor-research.md) (frozen at `edb5c0fc`).

Status: design proposal, not implemented behavior. The [shared UX pattern reference](../patterns.md) wins where this proposal disagrees with it.

Source revision: alexgorbatchev/devhost `190a8bb53e8cd903d2db0a92cb0886f29671607f` (Rust `main`). Features: CFG-01, CFG-02, CFG-03, CFG-04, CFG-05, CFG-06. Redesign ticket: tracked privately.

Product rule: the owner's rules state that the config editor is off by default, because a manifest decides which commands devhost runs, and that every manifest setting applies through hot reload, never through a restart to apply. `stacks/hot-reload.md` adds that a rejected edit leaves the stack on the configuration it accepted before, until a later save is accepted. Under `HOLD-8`, using devhost from another environment is a primary use case: with the editor on, this machine and an authenticated remote browser (signed in with the shared devhost passkey, or paired with a one-time `devhost pair` link, `O36`) read and save the configuration alike, and every other client can do neither (`O38`, `O54`, decided 2026-11-18; they replace the owner's earlier rule that saves come only from the same machine). So the editor being off until a manifest turns it on, saves from an authenticated browser in another environment, every save applying through hot reload without a question, and a rejected reload keeping the accepted manifest running are intended, not defects. The gap is around that intended write: the person cannot see what a save will restart or change beyond the file, cannot tell which reload's result belongs to which save, cannot see what the stack runs after a rejection or get back to it, can lose unsaved text to a page reload, a change on disk or a save that turns the editor off, and meets problems marked on the wrong line, in waves, as raw parser errors; and any client that reaches the stack reads every manifest file today (`network-exposure-04`).

## Target experience

The person opens **Config**, or **Edit** where devhost reports a problem: a rejected change, a crashed service, a failed row. The Configuration window opens at once over the page, as a modal dialog whose height stops above the toolbar's notices, at the file and line that hold the problem, marked, with the context it was opened for in a banner at its top: the rejection with its structured error, or the exited service with its exit, its cause and its frozen last output lines. Its header names the file by its role and short path and the worktree whose manifest it edits. As the person types, one check lists every problem a reload would find, each on the line where the fix goes and worded key first and fix last, and the line beside **Save** states what saving will do: "Saving restarts api (changed) and worker (depends on api)", the page's own service first when the save restarts it, or "Restarts nothing". **Save**, or ⌘S, runs at once and keeps focus while the same place shows each restarted service's progress; the outcome then replaces the progress beside **Save**, certified only once the reload that read this version ended: "Applied devhost.toml: restarted api (changed) and worker (depends on api) · 6 of 6 running · 3.1 s", or why it was not applied, with the failing service's own last lines. Each file keeps its own draft and its last outcome across file switches, closing the window and page reloads; a change on disk or in another tab never replaces a draft without a choice. A rejected file stays marked as not applied, with the lines that differ from what the stack runs and **Show Differences** and **Restore Running Version** as the way back. Saves start processes that cannot be taken back, so there is no Undo save: the editor's undo history survives a save, a failed reload restores the accepted manifest by itself, and **Restore Running Version** writes back what runs. Benchmarks: VS Code refuses to save over a file changed on disk and offers Compare and Overwrite, restores unsaved editors after a window reload (hot exit) and keeps its undo history across saves; JetBrains IDEs offer load the disk version, keep mine or show the difference, and keep Local History of saved files; Vite, Next.js and Tilt apply a configuration save at once and report what restarted; Docker Compose names each service it recreates; `kubectl diff` shows what an apply would change before it writes; nginx's `-t` and Caddy's admin API keep the running configuration when a new one fails to load; VS Code's Problems panel lists every problem at once and jumps to its line. Competitor behavior is evidence here, never a requirement.

## Target steps

Today: 6 steps, two of them outside the window: **Config**, guess the file from a clipped path, edit while problems appear in waves and on the wrong lines, **Save**, read "Saved and applied.", which can belong to another save or be false, then the terminal or the Services panel to learn what restarted and whether it held. Proposed: 4 steps, all in the window: **Config**, or **Edit** at the problem; edit with every problem and the save's reach in view; **Save**; read the outcome beside **Save**, which names each restart.

1. **Turn the editor on (a manifest edit, one write applied through hot reload).** The editor stays off by default (owner rule): a person writes `[devtools.configEditor] enabled = true` in a manifest with any editor, hot reload applies it, and **Config** appears on every open page of the stack with the next health message, without a page reload; while it is off, every config route answers `404`, as today. With it off, every surface that reports a manifest or devhost config file problem shows the file and line with **Copy** instead of **Edit**, because devhost has no editor integration (`MENU-3`, `MENU-4`, `SURF-15`, `O51`; `surfaces-15`). **Config** is a bar item whose tooltip reads "Edit this stack's configuration: its manifest files and the devhost config file" (toolbar-shell's words, `WORD-1`); it counts drafts, "Config · 2 unsaved", with the files in its accessible name ("Config: 2 files with unsaved changes: devhost.toml, admin/devhost.toml"), and once the rejection notice of a manifest file or the devhost config file that is not applied is dismissed, it takes the not-applied look, told by shape and the text "1 not applied" (notices-and-feedback's marker words, counting the files not applied), in every tab, until a reload of that source is accepted, also while the window is closed; while the notice shows, **Config** stays plain, because the notice is the one report (`ACT-7`, `SURF-8`, `FAIL-4`, `ACT-13`; `feedback-09`, `surfaces-06`). With the toolbar collapsed, toolbar-shell's badge takes the rejected-configuration look in `ACT-7`'s order and keeps the rejection's notice in one line beside it, whose **Edit** opens step 3.
   - Keys: Alt+Ctrl+B focuses the bar; **Config** is an arrow stop (ArrowLeft, ArrowRight, Home, End); Enter or Space opens the window (`KEY-3`, `KEY-4`; `keyboard-03`).
2. **Open the Configuration window (`GET /__devhost__/config/files`, `/__devhost__/config/schema` and `/__devhost__/config/drafts`, read only).** The window is a modal dialog (`aria-modal="true"`, opened with `showModal()`): the page, the bar, the notice stack and docked chat are inert while it is open, Tab cycles inside it, and its height is capped by the inset toolbar-shell's dock publishes, so it never overlaps the notice stack, whose text stays visible beside it in either corner placement (`SURF-4`, `SURF-1`, `KEY-7`, `SURF-9`; `surfaces-01`, `surfaces-04`, `surfaces-09`). It shows its frame at once, with "Loading devhost.toml…" where the text goes, and the files route answers without waiting for a running reload, restart or switch (Backend 8), so it is never an empty, disabled box (`STATE-1`; `language-15`, `config-editor-14`). Focus moves to the file's text (`KEY-6`). Its header reads "Configuration", then the selected file's role, short path and the worktree whose manifest it edits: "Root manifest · devhost.toml · main ~/acme", or after a switch "fix-nav ~/acme/.worktrees/fix-nav" (`SEL-4`, `WORD-11`; `selection-04`). Drafts restored from the control server show one line under the header, "2 files have unsaved changes: devhost.toml, admin/devhost.toml" (`UNDO-2`, `CC-19`). While an operation runs on the stack, the header carries one line naming it with its progress, "Apply devhost.toml is running · 3 of 6 started · checks and saves wait for it", and the text stays readable and editable (`HOLD-3`, `HOLD-1`). The window's header actions (**File**, **Revert**, **Save**, **Close**) keep their size and stay in view whatever the body holds; only the text and the problem list scroll (`SURF-9`).
   - Words: every text in the window follows the glossary: "manifest file" for one TOML file of a manifest, never "config file"; "devhost config file" for `config.toml`; "configuration" for both together, never "settings"; "hot reload" only for applying a saved file and "reloads" only for what the page's dev server does; "applied" and "not applied" as the two outcomes of one event (`WORD-1`; `language-02`, `language-03`, `language-08`). Action labels use title-style capitalization (**Show Differences**, **Restore Running Version**, **Use Disk Version**, **Review Drafts**), everything else sentence case, and devhost stays lowercase (`WORD-3`; `language-17`).
   - Cannot load: the body shows one sentence naming what failed and the next step, built from the cause the backend sent, never a response body: "Acme Shop is not running, so its configuration cannot be loaded. Start it with devhost start in ~/acme", with **Retry** and **Copy Error** holding the original text; drafts and files the window already held stay, marked with their age; focus is inside the window, so Escape closes it (`STATE-4`, `FAIL-2`, `HOLD-2`; `language-09`, `notices-and-feedback-01`).
   - Keys: Escape in the text moves focus to the **File** list; Escape elsewhere in the window closes it with every draft kept; Tab and Shift+Tab indent and outdent in the text, and Ctrl+M (⌥⇧M on macOS) switches Tab between indenting and moving focus, named in the window's hint line ("Tab indents · ⌥⇧M Tab moves focus · Esc File list · ⌘S Save" on macOS, "Tab indents · Ctrl+M Tab moves focus · Esc File list · Ctrl+S Save" elsewhere); outside the text, Tab cycles **File**, **Revert**, **Save**, **Close** and the banner's actions and back to the text, never leaving the window (`KEY-7`, `KEY-8`, `KEY-13`; `keyboard-07`, `keyboard-08`, `keyboard-11`, `keyboard-15`). Closed by any means, focus returns to the control that opened the window; opened with the pointer, to the page element that had focus before; when that control is gone (a crash view minimized), to its trigger (`KEY-6`, `KEY-5`; `keyboard-10`). A click on the backdrop closes the window the same way, drafts kept.
3. **Open the window at a problem (Edit from a notice, the crash view or a failed row; read only).** Every entry point to a problem opens the window on the file that holds it, scrolled to its line and column, marked, with the context in a banner at the top of the window, from one structured error (file relative to the root manifest, line, column, key, message) (`MENU-4`, `SURF-4`; `selection-10`, `config-editor-09`). The banner for a rejection keeps showing in the window until a reload of that source is accepted, also after the window closes and reopens: "admin/devhost.toml line 4, services.admin.autostart: unknown key. The stack still runs the accepted manifest." (`FAIL-2`, `WORD-7`, `HOLD-6`, `ACT-7`); a rejection that no single file holds lists the files involved. **Edit** in the crash view first minimizes the crash view to its notice (`SURF-3`; `surfaces-02`) and, like **Edit** on a failed Services row and **Config** while a service is exited, opens the service's definition with its `FAIL-3` evidence in the banner: "api exited with code 1 at 14:02 before its health check", its frozen last output lines ('error: Module not found "src/server.ts"') and what devhost ran ("Ran bun run src/server.ts in backend/ · devhost.toml line 14"), with **Restart api**, `MENU-5`'s lead action for an exited service, which hands off to the restart services-panel owns and shows its progress and outcome in the banner, and **Show All Output**, which expands that service's output in place in the window (`SURF-4`, `FAIL-3`, `MENU-5`, `WORD-2`; `status-08`, `journey-crash-to-fix-02`). A save that changes api's definition restarts it anyway, so the banner then reports that save's outcome for api. The `[services.api]` header and its command line are marked in the gutter, and the **File** list marks the file that defines a failing service, includes included ("defines api, which exited"). The window holds no log viewer of its own: reading other services' output is the pinned log panel's, after the window closes with drafts kept (`SURF-13`; `surfaces-12`). **Show All Output** expands only the exited service's own output, the shared recovery view's log (`SURF-4`, `SURF-14`); every other service's output stays in the pinned log panel (`SURF-13`). The banner leads with **Restart api** because `MENU-5` leads an exited service's recovery with **Restart**, so the state always has a way forward. The crash view's recovery actions follow `MENU-5`, which startup-and-recovery owns, with **Edit** leading after a retry that failed the same way (`MENU-5`; `selection-12`).
4. **Pick a file (the File list, read only).** **File** is a combobox, its field and list in one shadow tree, whose options are grouped by role: "This stack" (Root manifest · devhost.toml; Include · admin/devhost.toml) and "devbox", the machine that runs the stacks, named by `machineName` in the devhost config file or else its host name (devhost config file · ~/.config/devhost/config.toml, "shared by every stack on devbox") (`KEY-10`, `SEL-10`, `WORD-1`, `O61`; `keyboard-13`, `language-06`, `config-editor-01`). Each option's role, short path and state are text in its accessible description, never only on hover: "unsaved", "applying", "applied", "not applied", "defines api, which exited"; a long path is shortened in the middle with the full path in its tooltip and accessible name, and the trigger never grows past its slot, so **Revert**, **Save** and **Close** stay in the window (`WORD-8`, `SURF-9`). When the files outgrow the list, it gains a find field, focused on open, that filters by path and role as the person types, keeps the group headers with their counts and reads "No file matches "zz"" with **Clear Filter** when nothing matches (`SEL-10`, `SURF-10`, `STATE-2`; `selection-13`). With the devhost config file selected, a neutral line under the header reads "Changes here apply to every stack on devbox" (`SEL-11`, `O61`; `selection-14`). Its completions offer the shared Caddy settings, `machineName`, `stopTimeout`, the shared passkey's public key and `rpId`, and `[devtools.shortcuts]`, whose bindings override the manifest's binding by binding (`O17`, `O30`, `O36`, `O61`, `CC-39`); neither file offers an editor setting (`O51`). Switching files keeps each file's draft and each file's last save outcome (`UNDO-2`, `UNDO-8`).
   - Defaults: the window opens on the file of the problem it was opened for, else the file shown last, else the root manifest.
   - Keys: ArrowUp and ArrowDown move the highlighted file, Enter picks it, Escape closes the list and keeps focus on **File** (`KEY-10`, `KEY-8`).
5. **Edit with every problem and the save's reach in view (`POST /__devhost__/config/validate`, read only).** After each pause in typing, one check returns every problem the reload would find, in one list ordered by line: settings and values, dependency cycles, ports and working directories; only a TOML syntax error stops the later checks, and the list then says "Fix the syntax error to check the rest of the file" (Backend 4; `config-editor-02`). Each problem is marked where the fix goes and worded key first and fix last, with the file relative to the root manifest, never its absolute path, a parser prefix or an error chain (`FAIL-2`, `WORD-7`, `WORD-8`; `language-09`, `language-10`, `language-18`, `config-editor-03`): an unclosed header on line 21 is marked at the end of line 21, "Line 21: the table header [services.web is not closed; add ]"; a cycle marks the `dependsOn` line of each service in it, "Line 9, services.api.dependsOn: web already depends on api, which makes a cycle: api → web → api"; a missing folder marks its key's line, "Line 23, services.web.cwd: no folder frontend-missing in this worktree"; a problem in another file is listed with that file first, "admin/devhost.toml line 4, services.admin.autostart: unknown key", and **Open**, which shows it at its line; a problem with no position is listed without a marker, never on line 1. A key devhost retired, such as a leftover `[devtools.editor]` table, is a warning, never a problem or a rejection: its line carries a warning mark and the list reads "Line 40, devtools.editor: retired and ignored; [devtools.componentSource].enabled now turns off the source menu", and the save applies (`FAIL-6`, `SEL-11`). The problem list never covers the line holding the cursor. Completions and problem tooltips open inside the viewport, above the cursor when the room below is short, and are never clipped by the window (`SURF-9`; `config-editor-04`).
   - Beside **Save**, one line states what saving the draft will do, from the backend's check of it (Backend 3): each service it restarts and why (changed, depends on a changed service, same repository), the page's own service first; each service it starts or stops; for the devhost config file, the stacks whose URLs move; a return to the configured worktree; the editor turning itself off (`REV-10`, `SEL-11`, `SEL-1`, `O9`; `selection-02`, `selection-14`, `review-03`, `review-06`, `review-07`). Examples: "Saving restarts api (changed) and worker (depends on api)"; "Restarts nothing"; on web's page with worktrees on, "Saving restarts web, this page's service (same repository as api), api (changed) and docs (same repository as api)"; "Saving moves HTTPS to port 4443 and the URLs of 3 stacks: Acme Shop, Acme Admin and Acme Platform"; "Saving returns acme to main ~/acme and restarts all 6 services" (worktree-switch's words); "Saving turns the config editor off and closes this window". A port change names the new port, because the stacks' URLs move with it, and the outcome waits for the new listener to answer (`WORD-12`, `FB-13`). These are statements, never a question: **Save** stays available beside them (`REV-10`; `review-06`). While the stack runs another operation, the check waits for it and the problem list reads "Checking after Apply devhost.toml finishes…" instead of keeping old markers silently (`HOLD-3`, `STATE-1`; `config-editor-14`).
   - Keys: Ctrl+Space (⌥I on macOS) lists completions; Enter breaks the line; Mod+S saves; CodeMirror's Alt chords stay inside the text, page-wide chords are suspended while the window is open, and keys typed into the text never reach the page's listeners in any phase (`KEY-1`, `KEY-2`, `KEY-5`, `KEY-9`, `CC-28`; `keyboard-02`, `keyboard-05`).
6. **Save (`POST /__devhost__/config/save` with an `operationId`, one write applied through hot reload).** **Save** or Mod+S runs on one press, because a save is reported, never reviewed (`REV-1`, `REV-10`), except for `REV-3`'s other work: a save that turns the config editor off while other files hold drafts asks in place (step 6's question below). The route keeps every guard it has, with the client check `O54` widens: this machine or an authenticated remote browser (`O36`, `HOLD-7`), the version the draft was based on (`409` with the file on disk), the reload's own checks (`422` with the problems), an atomic write that keeps the file's mode and follows a symbolic link to its target, and nothing written when any of them refuses; it answers `202 Accepted` with the save's operation record before it writes (`ACT-1`, `REV-12`, `CC-37`). The pressed **Save** keeps focus, `aria-busy` and `aria-disabled`, never `disabled`, and reads "Saving devhost.toml…" (`KEY-11`, `FB-9`; `keyboard-12`). Beside it the save's progress shows in place, updated at least once a second: while another reload runs, "Waits for Apply admin/devhost.toml · 3 of 6 started · this save applies next" (`REV-12`, `HOLD-3`; `review-15`, `config-editor-12`); then "Apply devhost.toml · 1 of 2 restarted · 4 s", with one row per touched service and its state and step in `WORD-6`'s words: "restarting · Apply devhost.toml", "starting · health check 2 s of 30 s", "running" (`FB-1`, `ACT-3`, `WORD-4`, `WORD-6`; `feedback-01`, `status-05`). The text stays editable, and **Save** stays available: a second **Save** or Mod+S while that file's save applies waits behind it and says so beside **Save**, "Waits for Apply devhost.toml · 1 of 2 restarted · this save applies next", then is reported with its own reload (`REV-12`, `HOLD-3`; `selection-11`). A save of the same file from another tab or another program is the same later save `REV-12` reports, which waits for this one and, when a reload reads it first, makes this one read "Replaced by your next save". The stack's terminal and log print the same one outcome line for this save as for any save of the file, with its origin (`FB-10`, `FB-7`; `feedback-15`); notices-and-feedback words the origin. A script or an agent that saves through the config route gets the same `202` record and reads the save's outcome from the health stream, or as the last outcome in `devhost stack info` (short alias `devhost status`) in agent output's own contract, never by watching the file (`FB-11`, `O62`; `feedback-16`).
   - The question: on a save of `[devtools.configEditor] enabled = false` while admin/devhost.toml holds a draft, **Save** expands in place, inside the window, into "Saving turns the config editor off and closes this window. admin/devhost.toml has unsaved changes, kept until the editor is on again.", a group labelled by that sentence; **Review Drafts** takes **Save**'s place, focused and taking Enter, and shows admin/devhost.toml; the confirming **Save Anyway** sits beside it (`REV-3`, `REV-4`, `SURF-2`; `review-11`, `surfaces-13`). **Save Anyway** is `WORD-2`'s label for this question's confirming choice, beside **Switch Anyway** and **Send Anyway**. Escape, or a click elsewhere in the window that lands on no control, cancels the question and returns focus to **Save**; a click on another control cancels it, and that control takes focus and acts; closing the window cancels it with the window (`REV-4`, `KEY-8`, `KEY-6`). Without other drafts, the same save runs on one press.
7. **Read the outcome beside Save (the operation record on `/__devhost__/ws/health`, read only).** The outcome replaces the progress beside **Save** and is certified only once the reload that read this saved version ended with its services in the states it reports, a service with a `process` health check counting as started only after it stayed up for `O28`'s 1 s (`FB-2`, `FB-3`, `FB-5`, `O28`, `O9`; `feedback-02`, `feedback-04`, `config-editor-05`). Success: "Applied devhost.toml: restarted api (changed) and worker (depends on api) · 6 of 6 running · 3.1 s", "Applied devhost.toml: nothing restarted · 0.4 s", or with the page's own service first, "Applied devhost.toml: restarted web (this page's service; same repository as api), api (changed) and docs (same repository as api) · 6 of 6 running · 13 s" (`FB-3`, `WORD-4`; `language-07`, `language-11`). Not applied: "devhost.toml not applied: worker exited with code 127 at 14:02, 0.3 s after it started · Restored the accepted manifest: 6 of 6 running · 16 s", with worker's own last output lines ("sh: scripts/worker-missing.sh: No such file or directory") and what devhost ran, every touched service listed with its own result (`FAIL-1`, `FAIL-2`, `FAIL-3`, `UNDO-1`; `feedback-05`, `feedback-07`, `status-06`); while the reload rolls back, the progress reads "Restoring the accepted manifest" (`UNDO-1`). The outcome is announced once, a failure in the assertive region (`FB-9`; `feedback-14`); focus stays on **Save**, whose accessible description takes a failure's cause sentence (`KEY-11`). A save whose version no finished reload read before a later version of the file was read reads "Replaced by your next save" (`REV-12`).
   - The outcome stays with its file (`UNDO-8`, `REV-12`; `feedback-03`, `config-editor-13`): switching files, closing the window and a page reload never drop it, and the **File** list shows it on the file's option. Once the file has a new draft, the outcome stays as that file's last save, with its time, "Last save 14:02: Applied devhost.toml: …", under the draft's reach line, so it never reads as the state of the new text. A success stays while the window is open; a not-applied outcome stays until the same file applies or the person dismisses it (`FB-6`). With the window closed during a save, the notice stack shows the activity line "Apply devhost.toml · 1 of 2 restarted · 3 s", then the outcome notice in its place, a success closing after `O14`'s reading time (6.9 s for the 18-word "Applied devhost.toml: …" sentence) once the pointer and focus leave it, with its countdown starting only when the browser window is next focused if it arrived while the window was unfocused (`O53`), and a failure staying; the window shows the same outcome when it opens again, and the stack's log keeps it (`FB-1`, `FB-2`, `FB-6`, `FB-7`, `FB-8`, `O14`, `O53`; `feedback-10`).
8. **Recover a file that is not applied (Show Differences, read only; Restore Running Version, one write applied through hot reload).** A file whose last reload was not applied is in a state of its own: the banner says that the file on disk differs from what the stack runs, "devhost.toml is not applied: worker exited with code 127 at 14:02, 0.3 s after it started. The stack still runs the accepted manifest.", the lines that differ from the running version are marked in the gutter, and the text never reads as saved and applied (`UNDO-6`, `HOLD-6`, `WORD-7`; `feedback-12`, `language-08`, `config-editor-06`). **Show Differences** shows the running version beside the version on disk, read only, in the shared diff view. **Restore Running Version** writes the text the stack runs back over the current disk version, as an ordinary save (version-checked, checked, applied through hot reload, progress and outcome beside **Save**), and reports what it restored: "Restored devhost.toml to the version Acme Shop runs · nothing restarted · 0.4 s"; the rejection then clears on every surface, announced once (`UNDO-6`, `FAIL-4`, `ACT-7`, `REV-10`). devhost never writes the running version back by itself, because the rejected text is the person's work. **Revert** discards the selected file's draft and shows the version on disk, read again when it is pressed, never the version the window opened (`O29`); it never asks, and Mod+Z in the text brings the discarded draft back, because the editor's history keeps the replacement. The editor's undo history also survives a save, so an applied save is undone by undoing the text and saving again, which reports its own reload; there is no Undo save (`UNDO-6`). A rejection repeated with the same error updates its report, "· 2 times, last at 14:05", instead of adding another, and the terminal prints one line saying so, naming what it restarted and rolled back (`FAIL-4`).

Branches and edge states:

- **The editor is off.** **Edit** gives way to the file and line with **Copy**; devhost opens no editor and has no editor setting (`MENU-3`, `MENU-4`, `SURF-15`, `O51`); the notice names the setting that turns the editor on, `[devtools.configEditor] enabled = true`.
- **A page opened from another environment (`O38`, `O54`; Backend 10).** With the editor on, an authenticated remote browser (signed in with the shared devhost passkey or paired with a `devhost pair` link, `O36`) opens, checks and saves the configuration exactly as a browser on this machine does, and the files route tells the page it may save (`canSave`). Until that browser signs in or pairs, **Config** shows the unauthenticated state from the moment the bar draws: unavailable with the one reason "Sign in with passkey or pair this browser to use devhost here", visible beside it and as its accessible description, offering **Sign In with Passkey** when the shared passkey is configured for the domain and how to get a `devhost pair` link; the window never opens, and every config route answers that client `403` with the same sentence, so no file content, path or draft reaches it (`HOLD-7`, `HOLD-8`, `MENU-3`, `HOLD-1`, `WORD-7`; `review-16`, `network-exposure-04`). When the browser's session ends while the window is open, **Save** and **Restore Running Version** become unavailable with that reason in the window's header line, and the drafts stay in the page until it signs in again (`HOLD-7`, `HOLD-1`).
- **Another operation in progress.** The window opens at once with the operation named in its header (step 2); checks wait and say so (step 5); a save waits for a running reload, restart, Restart Stack or switch and names it (step 6); when it runs, a save of a file the stack no longer lists, because a switch moved the stack to another worktree, is refused with that reason and the draft kept (`HOLD-3`, `REV-12`, `REV-13`).
- **A save made while another reload runs.** It waits and says so, then is reported with its own reload, never with the one that was running; a save from another tab of the same file is reported in that tab, and a save whose version was never read first reads "Replaced by your next save" (`REV-12`; `review-15`, `config-editor-12`).

## Backend and contract changes

**Backend** (the Rust control server's config routes in `apps/devhost/src/devtools/config_files.rs` and the services runtime under `apps/devhost/src/services/`, preserving the owner's rules (off by default, every setting applied through hot reload), `O38`'s and `O54`'s sign-in rule for reads and saves, the version check, the reload's checks before any write, the atomic write that keeps modes and follows links, one save and one reload at a time per stack, and a rejected reload keeping the accepted manifest running):

1. **The save's operation record.** `POST /__devhost__/config/save` takes `operationId`, a lowercase UUID the caller generates, and answers `202 Accepted` with the record before it writes: kind `save`, the file as its target, the origin (the page ID), its steps (`waiting` naming the operation it waits for, `checking`, `written`, then the reload that reads it, `Apply <file>`, with each touched service's step at least once a second) and its outcome: `applied` with each restarted service and its reason, `not-applied` with the structured error and the failing service's evidence, `replaced`, `unseen` (Backend 12), or `saved-not-running` for a save into a worktree the stack does not run (Backend 14). Refusals keep their codes and bodies (`403`, `409` with the file on disk, `422` with the problems), each a JSON body. A request repeated with an ID the server holds returns that record and writes nothing. Serves `config-editor-05`, `config-editor-12`, `config-editor-13`. Required. Contract: `CC-37`; notices-and-feedback owns the record's model and readers, and services-panel ships it first.
2. **Reload records name the versions they read.** Every finished reload's record, from a save or any other write, names each file it read with its SHA-256 version; a save resolves as applied or not applied when a finished reload read its version, and as replaced when a later version of the file was read first; the window learns of a change on disk from the same versions, without polling. Serves `config-editor-07`, `config-editor-12`, `config-editor-13`. Required. Contract: `CC-37`.
3. **The plan from the check.** `POST /__devhost__/config/validate` returns `plan` with the problems: each service the save would restart with its reason (`changed`, `depends-on` a service, `same-repository` as a service), the services it would start or stop, for the devhost config file the stacks whose URLs move, `returnsToConfiguredWorktree` with the repository, and `turnsEditorOff`, computed by running the reload's own affected-service and repository-group selection on the candidate the check already builds; built with manifest-hot-reload, whose `devhost reload --dry-run` prints the same plan. Serves `config-editor-05`. Required. Contract: `CC-37`, `CC-23`.
4. **Every check in one pass.** The check collects the problems of every stage that does not depend on an earlier one (settings and values, dependency cycles over the declared `dependsOn` graph, ports, working directories of every service whose `cwd` parses) and returns them together; only a TOML syntax error stops the later stages, and the response says so (`stoppedAt: "syntax"`). Today the check stops at a syntax error and otherwise returns the first error the runtime's check meets (`apps/devhost/src/devtools/config_files.rs:180-213`, `apps/devhost/src/services/stack/runtime.rs:217-261`). Serves `config-editor-02`. Required.
5. **Structured problems and rejections.** Each problem and each rejection carries `file` relative to the root manifest's folder, `line`, `column`, `keyPath`, a `message` worded key first and fix last without the file's absolute path or parser prefixes, the offending line, and a close key when one exists; a parse error reported at a newline moves to the end of the line before it; a cycle carries the `dependsOn` key path of each service in it, and a missing folder `services.<name>.cwd`. Today only a TOML syntax error carries a line and column, and every other problem carries at most a `keyPath` with the raw message (`apps/devhost/src/devtools/config_files.rs:185-197`, `apps/devhost/src/devtools/config_files.rs:215-243`). The configuration status of a rejected reload carries the same structure, and, when a service crashed, its name, exit and last output lines, which manifest-hot-reload captures (`journey-crash-to-fix-03`). Serves `config-editor-03`, `config-editor-09`. Required.
6. **The running version.** The services runtime keeps the raw text of every file the last accepted reload of each source read, in memory for the stack's lifetime; the files route returns each file's `runningVersion`, and on request its `runningContent` for **Show Differences**; **Restore Running Version** is an ordinary save of that text over the current disk version. devhost never writes it back by itself. Serves `config-editor-06`. Required.
7. **Drafts on the control server.** `/__devhost__/config/drafts` (`GET`, `PUT`, `DELETE`) keeps one draft per stack and file with the version it was opened at and a revision; a `PUT` from an older revision answers `409` with the current draft; drafts stay while the editor is off and end when the stack stops; the route follows the same client rule as the files (Backend 10). worktree-switch reads it to name drafts before a switch. Serves `config-editor-08`. Required. Contract: `CC-19`.
8. **Listing without waiting.** On Rust `main` the files route already lists the files from the stack's live view (`apps/devhost/src/services/stack/live.rs:131-155`, `apps/devhost/src/devtools/config_files.rs:131-147`) without the operation lock; this redesign keeps that and guards it with a test, while a save's lookup and checks stay behind the runtime's own queue, so a save never writes a file a switch just retired; the health stream names the running operation (`ACT-1`), which the window's header line reads. Serves `config-editor-14`. Required.
9. **A `process` health check counted after `O28`'s time.** A changed service with a `process` health check counts as started only once it stayed up for 1 s after it was spawned (`O28`'s recommended default, calibrated in Phase 7); an exit within that time, with any exit code, 0 included, fails the reload with its exit code and last output lines, and the reload rolls back. Each changed service with a `process` check adds that second to the reload, and a command that stays up, such as a watch supervisor whose child fails, still passes it. Serves `config-editor-05`. Required; the rollback and the reload's outcome line are manifest-hot-reload's.
10. **The sign-in check on every config route.** With the config editor on, every config route (files, schema, validate, save, drafts and the running version) answers this machine and an authenticated remote browser (signed in with the shared devhost passkey or paired with `devhost pair`, `O36`), and answers every other client `403` with the JSON error "Sign in with passkey or pair this browser to use devhost here"; the save's `is_local_client` check (`apps/devhost/src/devtools/config_files.rs:269-274`) and the read routes' `Host`-only guard (`apps/devhost/src/devtools/config_files.rs:85-98`) become that one check, the relay connector's refusal of every config request other than `GET`, `HEAD` and `OPTIONS` (`apps/devhost/src/remote/proxy.rs:58-71`) becomes the same session check, and the files route returns `canSave` for the page. Serves `network-exposure-04`, `review-16`. Required; ships with `O36`'s sign-in, which the agent-chat redesign builds (`O38`, `O54`, `HOLD-7`, `HOLD-8`).
11. **Watch the file a save changes.** The manifest reader and the devhost config file's inputs record each file by its path as given and by its resolved path (`std::fs::canonicalize`); the watcher watches both directories, matches an event for either name, resolves the links again after every reload and on every event for a link itself, keeps watching a path whose link a tool replaced with a regular file, and drops a former target's directory when no input needs it; messages keep the path as given. Today the input watcher watches only the parent folder of each path as given and matches events against those paths alone (`apps/devhost/src/services/watch.rs:232-272`, `apps/devhost/src/services/watch.rs:312-357`). Tests run on Linux and macOS CI. Serves `manifest-hot-reload-08`, `manifest-hot-reload-10`. Required.
12. **A save devhost did not see.** When no reload reads a written version of a file the running stack lists within 5 s of the write, counted only while no operation (startup, a reload, a restart or a worktree switch) holds the stack, the save's record ends `unseen` and the window says "devhost did not see this save; the stack still runs the accepted manifest. Apply it with devhost reload in ~/acme" (`devhost reload`, `CC-23`); a version a later save replaced before any reload read it ends `replaced`, never `unseen` (`O42`). Serves `manifest-hot-reload-08`. Recommended.
13. **Service context for the window.** The published service state, which services-panel ships (its Backend 1 and 9), carries each service's defining file and line, what devhost ran and its exit record with its frozen last lines; the window and its banner read it, and the **File** list marks the file that defines a failing service. Serves `journey-crash-to-fix-02`. Required (services-panel builds the state).
14. **Files of a worktree the stack does not run.** The files, validate and save routes take an optional `worktree` path, which must be one of the repository's registered worktrees from the worktree list; with it they list, check and write that worktree's manifest and includes, version-checked, without touching the running stack or starting a reload, and the save's record ends `saved-not-running`; a path outside the registered worktrees answers `422` with a JSON reason, because `403` stays the sign-in refusal (Backend 10, `CC-37`); these saves never end `unseen`, since no reload reads them. worktree-switch's details line and its `Check Again` read the same check. Serves `MENU-4`'s **Edit** in the worktree list. Required (with worktree-switch).

## Recommended priority

**P2.** The triggers are ordinary for anyone who turns the editor on: every manifest edit with a mistake meets problems marked on the wrong line, in waves, as raw parser errors with absolute paths (`config-editor-02`, `config-editor-03`); a quick follow-up save reads "Saved and applied." about 14 s before its own reload runs, and still would if that reload were rejected (`config-editor-12`); a changed `process`-health service that exits at once reads as applied (`config-editor-05`); a rejected save shows the rejected text as saved with no way back to what runs (`config-editor-06`); a page reload, often one devhost's own save invites, or a save that turns the editor off drops every draft without a word (`config-editor-08`); a manifest, include or devhost config file saved through a symbolic link never applies, on Linux and, since the Rust watcher, on macOS too, and on macOS a link that a tool replaced with a regular file stops every later save from applying (`manifest-hot-reload-08`, `manifest-hot-reload-10`); and with the editor on, any client that reaches the stack, on the network or through the relay, can read every manifest and the devhost config file, `env` values included (`network-exposure-04`). The files on disk stay intact and nothing invalid reaches disk, so the cost is lost unsaved text, a stack running a configuration the person believes changed, and time spent in the terminal; that ranks it below the P1 flows whose writes act on the wrong target or report a stopped stack as healthy. The editor is off by default, so it is used less often than the Services panel and the terminal's lifecycle commands. Ship first the slice with no backend dependency: the modal window and its keyboard model, the **File** list's roles and paths, completions inside the viewport, per-file outcomes kept across file switches, the loading frame, the unloadable window's sentence with its controls in view, and the words. Ship the link-following watcher as an independent backend fix in the same release, because it fails totally and silently for the people it hits. Then the checks: every stage in one pass, structured positions and the `process` health grace, which makes a failing command fail its reload as `devhost.example.toml` already documents. Then the save's operation record with version-based outcomes, the reach line and the outcome that names each restart, built with manifest-hot-reload's plan and outcome line, so no release states a reach the reload does not report. Last, drafts on the control server, the disk-change view, the running version with **Show Differences** and **Restore Running Version**, **Edit** at the problem with its banner, and the sign-in check on every config route, which ships with `O36`'s sign-in (`O38`, `O54`). This redesign depends on two foundation redesigns, and each slice above waits for the parts of them it uses: notices-and-feedback provides the notice stack, the announcer, the lost-connection reason and the operation record's model, and this flow draws the window's progress and outcomes from that record and draws the header line for a report waiting in the inert notice stack (the save's outcomes and the unloadable window wait for it: `config-editor-05`, `config-editor-06`, `notices-and-feedback-01`); toolbar-shell provides the bar, **Config**'s segment and tooltip, the dock's inset that caps the window's height, the collapsed badge, `Button`'s unavailable state, the binding registry and the early key script (the window's keyboard map and focus containment wait for it: `config-editor-10`).
