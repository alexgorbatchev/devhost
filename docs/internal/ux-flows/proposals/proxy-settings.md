# Change the shared proxy settings: proposed experience

Diagrams: [current](../proxy-settings-current.html), [proposed](../proxy-settings-proposed.html). [Wireframe](../wireframes/proxy-settings.html).

Status: design proposal, not implemented behavior. The [shared UX pattern reference](../patterns.md) wins where this proposal disagrees with it.

Source revision: alexgorbatchev/devhost `edb5c0fc01cabae490e92ac23d4c785ec896c4ed`. Features: SET-06, SET-08. Redesign ticket: tracked privately.

Product rule: the owner settled that Caddy listening on every interface by default is documented and intended, and that settings apply through hot reload, never "restart to apply". `guides/shared-managed-caddy-settings.md` promises that when the devhost config file is saved, "Caddy moves to the new settings in one reload, including a new `adminAddress`." and "Services, routes, terminals, and chat sessions keep running." So the default listener on every interface, a save that applies without a question, and a rejected change that leaves the running shared Caddy settings in place are intended, not defects. The gap is around them: a loopback setting that silently does nothing on macOS, a held port reported as applied, open pages stranded on a port that closed, saves that never say what they changed, rejections that never say what keeps running, stacks that miss a change another process applied, and services that cannot learn the address people actually use. Who can reach a stack's control routes from the network is the product owner's, outside the reference (`network-exposure-01`); this redesign decides only what the listener settings do and how every surface reports them.

## Target experience

The person who must move the proxy, because another program holds port 443, a Linux machine has no low-port grant, or they want the stacks off the network, types `devhost caddy --help` and reads where the shared Caddy settings live, with this machine's path: "~/.config/devhost/config.toml". `devhost caddy start`, `devhost start` and `devhost status` say what the proxy listens on in one line, "HTTPS on port 443, every interface, reachable from your network", so the listener's reach is never a guess. They edit the `[caddy]` table in any editor, or in the Configuration window, which states before the save what it will do: "Saving moves the URLs of 3 stacks to port 4443: Acme Shop, Docs and Blog". Nothing asks. devhost checks the change before Caddy moves: a port another program holds, a loopback listener macOS cannot give without root, or a stack directory hostname a stack already uses is refused with nothing moved, naming the file, the line, the key and what holds it, and saying what keeps running. A change that passes moves Caddy once for the whole machine; devhost tells every open page first, then certifies that the new listener answers. Each stack's terminal prints one line naming what changed and the URLs that moved, "Applied config.toml: HTTPS port 443 → 4443 · 1.4 s", and each open page shows "devhost moved to port 4443" with **Open**, which keeps the page's path and query, while its toolbar follows its stack to the new address instead of drawing every service down. Services that need their public URL take it from a service reference and restart with the new one; every other service keeps running. A setting is undone by saving the old value, which reports its own move; a rejected change is undone by **Restore Running Version** in the Configuration window or by any save that matches what runs, which clears the rejection on every page and every terminal: there is no Undo of its own. Benchmarks: Vite prints its local and network addresses at start and says how to expose it, so a dev server's reach is stated, never assumed; `nginx -t` and `caddy validate` check a configuration before a reload and keep the running one when it fails; Docker publishes `127.0.0.1:8080:80` on loopback only and `docker ps` shows the address each port is bound to; Tailscale's `serve status` says whether a service is reachable within the tailnet or from the internet; VS Code's Ports view shows each forwarded port's local address and whether it is private or public. Competitor behavior is evidence here, never a requirement.

## Target steps

Today: 6 steps, two of them guesses: search the CLI and the docs for where the setting lives, find the file through two environment variables, edit and save, read "Applied the shared Caddy settings from \<path\>." and every URL again in each terminal, find every open tab drawn as crashed, then work out the new address and type it. Proposed: 3 steps: read where the file is from `devhost caddy --help` or any start, save it with its reach stated, read one outcome per stack and press **Open** on each open page.

1. **Find where the shared Caddy settings live (`devhost caddy --help`, `devhost caddy start`, `devhost start`, `devhost status`; read only).** `devhost caddy --help` ends with "Ports, listeners and the stack directory hostname are shared Caddy settings in the devhost config file: ~/.config/devhost/config.toml", the path resolved for this environment (`DEVHOST_CONFIG_DIR`, else `XDG_CONFIG_HOME`, else `~/.config/devhost`, as today) and shortened with `~` (`WORD-1`, `WORD-8`, `SURF-15`; `language-02`, `proxy-settings-05`). `devhost caddy start` names what runs, its listener, the file and how to stop it, "Caddy runs HTTPS on port 443 on every interface, reachable from your network · settings: ~/.config/devhost/config.toml · stop it with devhost caddy stop" (`FB-10`; `feedback-02`), and `devhost start` and `devhost status` print the same facts as one proxy line, "Proxy: HTTPS on port 443, every interface, reachable from your network · ~/.config/devhost/config.toml" (`FB-10`, `FB-11`; `proxy-settings-01`, `proxy-settings-05`). A loopback listener reads "Proxy: HTTPS on 127.0.0.1:4443 and [::1]:4443, this machine only", and with `http = true` the line adds "HTTP on port 8080". This flow words the line; stack-run-stop prints it among its start and status lines, and first-run-setup in `devhost caddy start`'s outcome. Agent output carries the same facts in its own layout with the absolute path (`WORD-9`, `FB-11`; `language-16`).
   - Words: "devhost config file" for `config.toml` and "shared Caddy settings" for its `[caddy]` table, never "settings file", "global config" or "proxy config" (`WORD-1`; `language-02`); stacks by name, with the checkout label when two share a name (`WORD-1`, `SEL-4`; `language-01`).
   - `devhost caddy privileged-ports` says what it does before it does it: its help line reads "Let Caddy listen on ports below 1024 without root (Linux; downloads Caddy if needed and asks for your password)", and on Linux a download it needs prints first-run-setup's download lines: what downloads and from where before it starts, "Downloading Caddy for Linux amd64 from caddyserver.com…", its progress as it arrives, and the size once known, "Installed Caddy 2.11.9 at ~/.local/state/devhost/caddy/caddy · 48 MiB · 9.4 s"; caddyserver.com's download sends no length, so neither the size nor the version is known before it, and this flow follows first-run-setup's proposed exception to `WORD-9`'s "with the size". Before `sudo` it prints "Granting Caddy ports below 1024 runs sudo setcap and may ask for your password" (`WORD-9`; `review-05`, `proxy-settings-05`). On macOS it no longer claims that no setup is needed: "macOS lets Caddy listen on ports below 1024 on every interface without setup. A loopback-only bindHost below port 1024 needs root, so devhost refuses it; use httpsPort 4443 or any port from 1024." On Linux, `devhost caddy download` that replaces a binary holding the grant ends with "Run devhost caddy privileged-ports again: the new Caddy cannot use ports below 1024" on its own line (`WORD-8`, `WORD-9`; `proxy-settings-05`).
   - Under `AGENT=1`, `devhost caddy privileged-ports` refuses before any `sudo` with one line, "Ask the person to run devhost caddy privileged-ports in a terminal", as `REV-8` has the trust commands do, because a cached `sudo` ticket would otherwise let an agent change Caddy's capabilities silently; `REV-8` names only the trust commands, so this extension is proposed for the reference (Backend 12). The trust commands keep `REV-8` as written (`REV-8`; `review-05`).
   - Keys: none; terminal output only.
2. **Change a setting, with its reach stated before the save (an editor, or the Configuration window and `/__devhost__/config/validate`; one write, applied through hot reload).** The person edits the `[caddy]` table in any editor and saves; nothing asks, because a save is reported, never reviewed (`REV-1`, `REV-10`; `review-03`, `review-06`). In the Configuration window (config-editor's surface: off by default, saves only from this machine, owner rules), with "Devhost config file · ~/.config/devhost/config.toml" picked under "This machine", the line "Changes here apply to every stack on this machine" sits under the header, and beside **Save** one line states what saving the draft will do, from the backend's check of it (Backend 9; `REV-10`, `SEL-1`, `SEL-6`, `SEL-11`; `selection-06`, `review-03`, `review-06`, `language-01`). This flow gives each setting its words; config-editor draws the line:
   - `httpsPort`: "Saving moves the URLs of 3 stacks to port 4443: Acme Shop, Docs and Blog"; the stacks are listed by name in the line's tooltip and accessible description when there are more than two (`SEL-1`, `SEL-6`).
   - `http` and `httpPort`: "Saving adds plain HTTP on port 8080 to 3 stacks: Acme Shop, Docs and Blog", or "Saving removes plain HTTP from 3 stacks".
   - `bindHost`: "Saving makes 3 stacks reachable only from this machine: Acme Shop, Docs and Blog"; the other way, in the warning style, "Saving makes 3 stacks reachable from your network: Acme Shop, Docs and Blog".
   - `stackDirectoryHost`: "Saving moves the stack directory to https://stacks.localhost:4443/".
   - `stackDirectoryAllowRemote = true`, in the warning style: "Saving lets other devices on your network read the stack directory, with every stack's URLs and raw configuration files; it has no sign-in"; while `bindHost` is a loopback address, "Saving changes nothing while bindHost is 127.0.0.1: only this machine reaches the stack directory".
   - `adminAddress`: "Saving moves Caddy's admin API to 127.0.0.1:22000; no URL changes".
   - A service whose `env` or `command` uses the `publicUrl` property of a service reference (step 7): "Saving restarts web in Acme Shop (uses services.web.publicUrl)", the page's own service first (`REV-10`, `SEL-3`).
   - Nothing that runs changes: "Changes nothing that runs".
   - When the save moves the address of the page the window is open on, the line adds "This page moves to port 4443; its unsent chat text and page context come along", because the page hands them to the control server before the move (step 5); nothing is discarded, so no question asks (`REV-3`, `UNDO-2`).
   - These are statements, never a question: **Save** stays available beside them (`REV-10`). The plan comes from `/__devhost__/config/validate`, which returns what saving would do (`CC-37`). Problems the check finds (Backend 2) show in the window's problem list on their line before the save, in the words of step 6 ("line 3: port 4443 is in use by nc (PID 77959) on 127.0.0.1"), and a draft the check refuses is not saved, as config-editor's save does today (`MENU-4`, `REV-11`). The statement and the problems are checked again whenever the running shared Caddy settings change, for example when another stack's start applied the file, so the line never describes settings that no longer run (`REV-13`; `review-14`).
   - Keys: the Configuration window's own (Mod+S saves, config-editor's; `KEY-9`).
3. **devhost checks the change, tells open pages, then moves Caddy once (the apply; part of the one write).** Every running stack watches `config.toml`, as today, and the first to take the route lock every devhost process shares applies the change once for the machine; settings another process already applied are not applied twice (Kept). Before anything moves, devhost runs every check it can (`REV-11`; `review-07`, `feedback-04`): the file's validation, each problem with its file, line, column and key (Backend 1; `MENU-4`); a probe of each new listener port (`httpsPort`, and `httpPort` while `http = true`) on 127.0.0.1, ::1 and the bind host, which names the program and PID that hold it, Caddy's own current listeners excluded (Backend 2; `proxy-settings-02`); on macOS, a loopback `bindHost` (127.0.0.1 or ::1) with a listener below port 1024, which macOS gives only to root (Backend 2; `proxy-settings-01`); and a `stackDirectoryHost` that a running stack's service uses (Backend 2; `proxy-settings-04`). A failed check refuses the change with nothing moved (step 6).
   - When the change moves a listener (a port, `http`, or the bind host), the process that applies it first tells every running stack through its control server on the loopback control port the state directory records, and each stack sends each open page whose address changes the message `{"type": "listeners-moving", "origin", "operationId"}` with that page's own scheme and hostname on the new port (Backend 4; `HOLD-2`; `review-14`, `feedback-11`, `status-04`, `proxy-settings-03`). A stack that does not answer within 1 s never holds the move up.
   - Caddy then moves in one reload under the route lock, as today, and devhost certifies the move: a TLS handshake through 127.0.0.1 and [::1] on each new listener reaches Caddy, within 5 s (Backend 6; `FB-5`; `feedback-04`, `proxy-settings-02`). Only then does devhost write the record of what Caddy runs; when the handshake fails, it reloads Caddy back to the running settings and the change is not applied, with its cause (step 6).
   - Services, routes, terminals and chat sessions keep running, and moving URLs never changes a service's state (`ACT-2`; `status-01`); the one exception is a service whose definition uses its public URL (step 7). `adminAddress` moves with the reload, and `devhost caddy stop` and `devhost caddy trust` keep finding Caddy at the address it runs (Kept).
4. **Read the outcome in every stack's terminal and log (one line per stack).** Every running stack follows the record of what Caddy runs, whoever moved it: a save of `config.toml`, another stack's `devhost start`, or `devhost caddy start` (Backend 7; `proxy-settings-07`). When the record changes, the stack takes its URLs from it, publishes its state, and prints one outcome line in its terminal and log, then only what changed: the URLs that moved, labelled by service, and stack-run-stop's directory line (`FB-3`, `FB-7`, `FB-10`, `WORD-4`, `CC-22`; `feedback-02`, `feedback-03`, `feedback-05`, `feedback-15`, `language-08`, `language-11`, `proxy-settings-04`):

     ```text
     Applied config.toml: HTTPS port 443 → 4443 · 1.4 s · after config.toml changed on disk
     web    https://shop.localhost:4443/
     api    https://shop.localhost:4443/api/
     All stacks on this machine: https://devhost.localhost:4443/
     ```

   - Each changed key is named with its old and new value in the person's words: "bindHost 0.0.0.0 → 127.0.0.1: reachable only from this machine"; "stack directory moved to https://stacks.localhost:4443/"; "plain HTTP on port 8080", followed by each service's HTTP URL beside its HTTPS one ("web    http://shop.localhost:8080/"), because a tunnel needs that address; "adminAddress 127.0.0.1:20197 → 127.0.0.1:22000"; "restarted web (uses services.web.publicUrl)" (`FB-3`, `WORD-4`; `proxy-settings-04`). A change of `bindHost` or a port adds the proxy line of step 1 (`proxy-settings-01`).
   - Turning `stackDirectoryAllowRemote` on adds one warning line: "Other devices on your network can now read https://devhost.localhost/ with every stack's URLs and raw configuration files; it has no sign-in." (`WORD-7`; `proxy-settings-04`).
   - The origin ends the line as the record names it: "· after config.toml changed on disk" for a save, "· from the terminal (devhost start in ~/blog)" or "· from the terminal (devhost caddy start)" for a start that applied the file (`WORD-4`, `ACT-1`). A save that changes nothing that runs prints "Applied config.toml: nothing changed" (`FB-10`).
   - Agent output prints the same facts on one line in its own layout, with the absolute path and every changed key's old and new value (`WORD-9`, `FB-11`; `language-16`). The full URL list is never printed again; it prints at the first start and on request, `devhost status` (`FB-10`, `CC-22`).
5. **Open pages follow the move (the page's status stream; read only, and one navigation the person chooses).** A page that receives `listeners-moving` shows its progress as an activity line, "Apply config.toml · moving to port 4443 · 1 s" (`FB-1`, `WORD-4`). When its status stream closes with the move, the page connects its status stream to the same hostname on the new port (Backend 5), and once that answers with the move's record, the activity line gives way to notices-and-feedback's condition notice, "devhost moved to port 4443", with one line under it, "This page still uses port 443, which closed when config.toml changed.", and **Open**, which opens this page at port 4443 in the same tab with its path, query and fragment kept; its accessible name is "Open this page at port 4443" (`HOLD-2`, `SURF-15`, `FB-5`; `feedback-03`, `feedback-11`, `status-04`, `proxy-settings-03`). The page stops retrying the old address once the new one answers.
   - On `listeners-moving`, before its stream closes, the page hands its unsent chat text, pasted images and page context to the control server's draft record under the new address (`UNDO-2`), so **Open** brings them back; configuration drafts are kept per stack and file and are unaffected. A screenshot share ends with the page, and the outcome names what could not come along (`FB-4`, `REV-3`).
   - Between the stream's close and the new address answering, every service keeps its last known state drawn as unknown with "last seen 14:02", never down or failed (`CC-26`); once the new address answers, the toolbar is live again from it, and its service links name port 4443 (`ACT-5`, `ACT-2`, `ACT-12`; `status-01`, `status-04`). notices-and-feedback draws the lost-connection state; this flow supplies the move's cause.
   - Every write on the old page (Restart, Restart Changed and its key, Start, Restart Stack, switches, Save, Send) is unavailable with one reason, said once in the notice and given to each blocked control as its accessible description: "This page still uses port 443. Open it at port 4443 to make changes." (`HOLD-1`, `HOLD-2`, `MENU-3`), because a write from the old address comes from another origin, which the control server refuses. Reads, the page context and chat drafts stay (`UNDO-2`).
   - The notice is a condition, ranked with the lost connection (`FB-8`, `ACT-7`), and fits every acceptance viewport with its line and **Open** in view, a long address wrapping with the full URL in its tooltip and accessible name (`SURF-9`, `WORD-8`): it never takes focus (`KEY-6`), the announcer reads it once in the polite region (`FB-9`), Escape never dismisses it (`KEY-8`), and it ends when the person opens the new address or the move is undone; **Dismiss** leaves the marker "moved" on the stack name until then (`SURF-8`, `UNDO-3`; `feedback-09`). A reload the page's dev server asks for meanwhile is a detail of this notice, never a **Reload blocked** whose **Reload** loads the closed port (notices-and-feedback's).
   - The Configuration window that saved the change shows the move beside **Save** while it runs, "Moving 3 stacks to port 4443…", then its outcome from the record once the new address answers: "Applied config.toml: moved the URLs of 3 stacks to port 4443 · 1.4 s", with "This page continues at https://shop.localhost:4443/admin?tab=2" and **Open**; focus moves to the outcome's sentence (`FB-2`, `FB-9`, `KEY-11`). Its **Save** is then unavailable with the reason above (`HOLD-2`).
   - A move devhost could not certify is undone before the page goes anywhere: Caddy returns to the running settings, the old address answers again, the page reconnects there, and the activity line gives way to the failure of step 6, never to "moved" (`FB-5`, `REV-13`).
   - Pages opened on another device lose their connection when `bindHost` becomes a loopback address, as the statement beside **Save** said; nothing can reach them to say more.
   - Keys: **Open** and **Dismiss** are ordinary buttons in the notice's Tab order; Enter or Space activates them (`KEY-4`, `KEY-9`).
6. **A change that is not applied (the apply's outcome when a check or Caddy refuses it; a condition until a configuration is accepted).** Nothing moves. Each running stack prints one line led by the file, line, column and key, then the cause, the fix and what keeps running, with the offending line under it, and the original text behind **Copy Error** and in agent output's one `devhost: ERR:` line (`FAIL-2`, `MENU-4`, `WORD-7`, `WORD-8`, `HOLD-6`, `WORD-9`; `selection-10`, `language-09`, `language-10`, `proxy-settings-04`):
   - a held port, with the program that holds it as its evidence: "~/.config/devhost/config.toml:3:13 not applied: caddy.httpsPort: port 4443 is in use by nc (PID 77959) on 127.0.0.1. Choose another port or stop that program. Every stack still runs the running shared Caddy settings: HTTPS on port 443, every interface." (`REV-11`, `FAIL-3`; `proxy-settings-02`);
   - a value out of range: "~/.config/devhost/config.toml:3:13 not applied: caddy.httpsPort: must be an integer between 1 and 65535. Every stack still runs the running shared Caddy settings: HTTPS on port 443, every interface.";
   - a loopback listener below 1024 on macOS: "~/.config/devhost/config.toml:5:12 not applied: caddy.bindHost: 127.0.0.1 on HTTPS port 443 needs root on macOS. Set httpsPort to 4443 or any port from 1024, or start Caddy from a privileged launcher. Every stack still runs the running shared Caddy settings: HTTPS on port 443, every interface." (`proxy-settings-01`); the same file refuses `devhost caddy start` before Caddy starts, with the same cause and fixes, and exits non-zero (`REV-11`);
   - a stack directory hostname a stack uses: "~/.config/devhost/config.toml:4:22 not applied: caddy.stackDirectoryHost: stacks.localhost is a hostname of web in Acme Shop (~/acme/devhost.toml line 14). Choose another hostname or change web's host. …", naming the stack, the service and the manifest line, never only a PID (`WORD-4`; `language-06`, `proxy-settings-04`);
   - a move devhost could not certify: "~/.config/devhost/config.toml:3:13 not applied: caddy.httpsPort: port 4443 answered on 127.0.0.1 but not through Caddy; another program holds it for IPv4.    - a save while Caddy is stopped: "config.toml not applied yet: devhost's proxy is not running. devhost caddy start applies it." (`proxy-settings-07`).
   - A `devhost start` that a service's hostname collides with `stackDirectoryHost` is refused with both places named: "devhost.toml:14:8 not started: services.web.host: stacks.localhost is the stack directory's hostname, set by caddy.stackDirectoryHost in ~/.config/devhost/config.toml line 4. Change web's host or the stack directory's hostname." (`MENU-4`, `FAIL-2`; `proxy-settings-04`); stack-run-stop prints it among its start refusals.
   - Every open page of every stack shows one condition notice, ranked with failures (`ACT-7`, `FB-8`): "devhost config file not applied: config.toml line 3, column 13, caddy.httpsPort: port 4443 is in use by nc (PID 77959) on 127.0.0.1. Every stack still runs the running shared Caddy settings: HTTPS on port 443, every interface." with the offending line under it, then **Edit** while the config editor is on, which opens the Configuration window on `config.toml` at line 3 with the rejection in its banner (`SURF-4`; `surfaces-04`), else **Open in Editor**, then **Copy Error**, whose copied text starts with "~/.config/devhost/config.toml:3:13" (`MENU-3`, `MENU-4`, `FAIL-2`); **Edit** leads, because a problem in the file is fixed in the file (`MENU-5`).    - In the Configuration window a rejected `config.toml` is a state of the file: the window marks the lines that differ from what runs and offers **Show Differences** and **Restore Running Version**, which writes the running text back and applies like any save; there is no "Undo save" (`UNDO-6`; `review-06`). The record of what Caddy runs keeps the text it was read from for this (Backend 7).
   - A rejection that repeats updates its report: "config.toml not applied again: same error as 14:02 · 2 times, last at 14:05", and the notice keeps one report with "2 times, last at 14:05" (`FAIL-4`).

7. **Give a service its public URL (a service reference in the manifest; applied through hot reload).** Service references gain `publicUrl`: the service's first public URL as devhost prints it, "https://shop.localhost:4443", without the port on 443 and with the service's path when it has one ("https://shop.localhost:4443/api"). A manifest uses it in `env` or `command` as it uses `url`, for example `APP_URL` set to the reference `services.web.publicUrl` inside a reference's double braces (Backend 10; `proxy-settings-06`). devhost never adds it to every service's environment by itself, because a port change would then restart every routed service of every stack; a service that uses it restarts when it changes, as the environment-variables guide already promises for ports ("devhost restarts the services whose variables change, so they never hold a stale port"). The statement beside **Save** and the outcome name each one with its reason, "restarted web (uses services.web.publicUrl)" (`REV-10`, `FB-3`, `SEL-11`); its row shows restarting with that reason, then running, and every other service keeps its state (`ACT-2`, `ACT-3`; `status-01`). When such a restart fails, the move still stands, because Caddy already runs the new settings, and that stack's outcome is a partial result with the failed service's evidence and its lead action: "Applied config.toml: HTTPS port 443 → 4443 · 5 of 6 running · web exited with code 1 at 14:02 after its restart (uses services.web.publicUrl)", with web's last output lines and **Restart** first, then **Logs** and **Edit** (`FAIL-1`, `FAIL-3`, `MENU-5`; `feedback-05`). A reference to a service without a hostname fails at start, as `url` fails for a service without a port.

Branches and edge states:

- **The config editor is off.** Every entry is an editor's save; the rejection notice shows the file and line with **Open in Editor** and **Copy Error** instead of **Edit**, and no statement precedes the save; `devhost reload --dry-run` prints the same plan as the window's statement for the devhost config file, with `--stdin` checking a candidate text (`MENU-3`, `MENU-4`, `FB-11`, `CC-23`).
- **A save while Caddy is stopped, then `devhost caddy start`.** Every running stack prints step 6's "not applied yet" line; its pages already show notices-and-feedback's "devhost's proxy is not reachable. Start it with devhost caddy start". `devhost caddy start` applies the file, and every running stack follows the record within 2 s: it prints its outcome line, stack-run-stop's "Acme Shop's routes answer again at 14:12", and clears its rejection. A page that lost its stream when Caddy stopped cannot learn a new port, because nothing answers at its old address; its notice keeps the proxy's state, and the stack's terminal names the new URLs (`ACT-10`, `FB-3`; `proxy-settings-07`).
- **A start applies a change that a save could not.** After a refused save (a held port) and the holder's exit, `devhost start` in another project applies the file; every running stack follows the record within 2 s, so its toolbar links, its printed URLs and the stack directory name the same port, and its rejection clears (`ACT-12`, `FAIL-4`; `proxy-settings-07`). A later manifest reload, **Restart Stack** or switch prints URLs from the same record.
- **Another operation runs on a stack.** The move does not wait for a stack's restart or reload: that stack sends `listeners-moving` at once, follows the record when its operation ends, and prints its outcome line after that operation's own (`HOLD-3`, `REV-12`). A Configuration window save made during a move waits for it and is reported with its own apply (`REV-12`).
- **A lost response or a stale view.** A Configuration window save whose response was lost takes its outcome from the record by its `operationId`, never saves again (`REV-12`, `ACT-1`); a save whose base version differs from the file on disk is refused with "Not saved: the file changed on disk", the draft kept (`REV-13`, `UNDO-3`).
- **The page's own modal dialog.** The moved notice and the rejection notice move into the dialog with the notice stack, and **Open**, **Edit** and **Copy Error** work from there (`SURF-11`).
- **Hold Reloads.** The move reloads no page by itself; **Open** is a navigation the person chooses, never held (`UNDO-2`).
- **The stack directory moves.** A `stackDirectoryHost` or port change moves the directory's address; the outcome line and stack-run-stop's "All stacks on this machine" line name the new one, and the stack directory's own page is stack-directory's.
- **Agents and scripts.** An agent's save is reported like any save, "· after config.toml changed on disk", because the watcher cannot tell who wrote the file (`ACT-1`); agent output reads every outcome and rejection on one line (`WORD-9`); `devhost caddy privileged-ports` refuses under `AGENT=1` (step 1).
- **Who can reach stacks from the network.** A loopback `bindHost` now keeps every stack off the network on macOS as on Linux, which is this redesign's; who may reach the control API stays the product owner's (`network-exposure-01`), whose stopgap admits only loopback clients to chat.

## What changes versus today

- **Removed:** the silent widening of `bindHost = "127.0.0.1"` to every interface on macOS, replaced by a loopback listener from port 1024 and a refusal below it; "Applied the shared Caddy settings from \<path\>." followed by every service URL again, replaced by one outcome line and only the URLs that moved; "shared Caddy settings rejected: \<Go error chain\>", replaced by step 6's line; the toolbar title "devhost config change not applied", replaced by "devhost config file not applied"; "managed caddy does not need privileged-port setup on macOS.", replaced by what applies; every service drawn down on a page whose port moved, and its endless retry of the closed address; the stack directory collision that names only a PID.
- **Merged:** "Applied the shared Caddy settings", "shared Caddy settings rejected" and "devhost config change not applied" become one event, applied or not applied (`WORD-1`); each stack's private copy of the shared Caddy settings and the record of what Caddy runs become one record that every URL, link, list and the stack directory read.
- **New:** the devhost config file's path in `devhost caddy --help`, the proxy line at `devhost caddy start`, `devhost start` and `devhost status`; the statement of each setting's reach beside **Save**; the checks before the move (held ports with their holder, a loopback listener macOS cannot give, a directory hostname in use); the certification of the new listener and the restore when it fails; `listeners-moving` and pages that follow their stack to the new address with **Open**; the change summary with each key's old and new value; plain-HTTP URLs printed while `http = true`; the remote-access warning; the restore line and the repeat count; the `publicUrl` service reference; privileged-ports' help line, its download and password notices, its refusal under `AGENT=1` and the re-run line after a download on Linux.
- **Changed:** on macOS, `bindHost = "127.0.0.1"` listens on loopback from port 1024 and is refused below it, a documented behavior that changes (Project contracts); a service whose definition uses `publicUrl` restarts when a change moves its public URL, the one exception to "Services, routes, terminals, and chat sessions keep running."; running stacks follow a change that a start applies, where today only their own watcher moved them; a held port is refused before the move, as the docs already promise; a rejection clears whenever `config.toml` matches what runs, from any path.
- **Kept:** walking every safeguard of the current flow:
  - The devhost config file's location: `DEVHOST_CONFIG_DIR`, else `XDG_CONFIG_HOME/devhost`, else `~/.config/devhost` on every platform; a missing file leaves every setting at its default.
  - Every running stack watches `config.toml` with the manifest's debounce and applies one save at a time, without restarting services, routes, terminals or chat sessions, except services that use `publicUrl` (`REV-10`, owner rule).
  - Caddy moves in one reload under the route lock every devhost process shares, including a new `adminAddress`; settings another process already applied are not applied twice; `devhost caddy stop` and `devhost caddy trust` find Caddy at the admin address it runs.
  - An invalid file, a claimed directory hostname or a reload Caddy refuses keeps Caddy on the settings it runs, and its files are rendered back for them; now a held port, a loopback listener below 1024 on macOS and an uncertified move do the same (`HOLD-6`, `REV-11`).
  - Validation names each bad key: unknown keys, ports outside 1 to 65535, an empty `adminAddress`, an unsupported `bindHost`, a `stackDirectoryHost` with a scheme, port or path; a `[caddy]` table in a manifest is rejected naming the devhost config file; now each with its line and column (`MENU-4`).
  - A repeated rejection is printed once, now with its count (`FAIL-4`).
  - The config editor is off by default and saves only from this machine; it validates the same file before writing it and creates a missing file (owner rules, `HOLD-7`).
  - The stack directory answers only this machine unless `stackDirectoryAllowRemote` is set, serves read-only methods with same-origin checks, and keeps the per-stack snapshot local-only; setting the option back to `false` withdraws remote access on reload.
  - `bindHost` defaults to every interface, as documented (owner rule); a loopback `bindHost` on Linux listens on loopback only.
  - `devhost caddy privileged-ports` grants low ports on Linux with `setcap`, downloading Caddy first when needed; devhost sets up no `authbind` or firewall redirect.
  - `devhost caddy start` and every stack that starts apply the file's settings; Caddy keeps its settings until `devhost caddy stop`, and the next `devhost caddy start` reads the file again.
  - Only a person changes the machine's certificate trust, at a terminal (`REV-8`).

## Recommended priority

**P1.** The realistic trigger is one deliberate setting: a person on shared Wi-Fi sets `bindHost = "127.0.0.1"` on macOS to keep unreleased apps, admin panels and manifests private, and every stack stays reachable from the network while devhost says nothing (`proxy-settings-01`), the setting people would reach for while chat's own exposure is open (`network-exposure-01`). The other triggers are rarer and cost time rather than data: moving `httpsPort` turns every open tab of every stack red with no new address (`proxy-settings-03`), a port that a local dev server holds on loopback is reported applied while IPv4 clients reach that server (`proxy-settings-02`), saves and rejections leave every terminal on a misleading last line (`proxy-settings-04`, `proxy-settings-07`), and apps on any port but 443 build public URLs that do not answer (`proxy-settings-06`). Nothing is lost in any of them, and a refused change keeps the running settings, but the exposure is silent until someone checks. Machine-wide settings change far less often than stacks start and stop, which keeps the rest of the flow below stack-run-stop. Ship first the backend-only slice that ends the silent exposure: the loopback listener on macOS with its refusal below port 1024 and the proxy line at start (Backend 2's macOS check, 3 and 11); whether it ships with the `network-exposure-01` stopgap is the product owner's open decision. Then the checks before the move with their not-applied lines, the certification and its restore, and the record every stack follows, with the structured issues and the restore and repeat lines (Backend 1, 2, 6, 7 and 8); then the pages that follow the move, which wait for notices-and-feedback's lost-connection state so that no release draws the move as an outage (Backend 4 and 5); then the statement beside **Save** with config-editor's window, the CLI help and privileged-ports' lines; and last `publicUrl`, once the reference names its contract. Seams, with no blocker in either direction beyond notices-and-feedback: notices-and-feedback draws the lost connection and the "devhost moved to port 4443" notice, and this flow sends `listeners-moving` and makes the new address readable; config-editor's window draws the line beside **Save**, the banner and **Restore Running Version** from this flow's plan and record; stack-run-stop prints the proxy line and "All stacks on this machine" at start, in `devhost stack list` and `devhost status`, and the reserved-hostname refusal; manifest-hot-reload builds the port probe and the restored line this flow reuses; first-run-setup prints the proxy line in `devhost caddy start`'s outcome; stack-directory reads the same record for its page.
