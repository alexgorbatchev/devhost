# Serve a folder or a running port: proposed experience

Diagrams: [current](../serve-folder-current.html), [proposed](../serve-folder-proposed.html). [Wireframe](../wireframes/serve-folder.html).

Status: design proposal, not implemented behavior. The [shared UX pattern reference](../patterns.md) wins where this proposal disagrees with it.

Source revision: alexgorbatchev/devhost `edb5c0fc01cabae490e92ac23d4c785ec896c4ed`. Features: SRV-01, SRV-02, SRV-03, SRV-04, MAN-08. Redesign ticket: tracked privately.

Product rule: the owner's rules make several behaviors of this flow intended. Caddy listens on every interface by default, as documented, so a served folder is readable by anyone who can reach that listener; a server routed with `--port` runs outside devhost, which never starts, restarts or stops it ("External services (`managed = false`) show status only"); devhost never opens a browser; human output and agent output (`AGENT=1`) differ on purpose. None of them is a defect, and this redesign gates none of them. The gap is around them: the terminal never says what is served, where it listens, whether it is ready, how to stop it or that chat is on; a `--port` session prints its URL as ready while nothing answers; the folder's page hides the folder behind its README and lists it in byte order; a mistyped name leaves the file browser for a service recovery page; and every serve session turns chat on with no way to turn it off. Who can reach a serve session's chat from the network is `network-exposure-01`'s, which the product owner handles outside the reference; this redesign decides nothing about it.

## Target experience

The person types `devhost serve --dir docs --domain notes.localhost` and reads, without a 37-column prefix, what is served and where it listens: "Serving ~/acme/docs · Caddy listens on all interfaces, port 443 · chat off", then "Ready in 0.3 s: https://notes.localhost/ · Ctrl-C stops this session". A `--port` session says what it waits for instead of claiming it is ready: "Waiting for 127.0.0.1:3000 to accept connections · 12 s", then its ready line once the server answers. Opening the URL shows the folder itself: its name as the page's heading path, folders first, then files in natural, case-insensitive order, each row with its size and modified time, a filter, and the README rendered below the listing under its own file name, as on GitHub. A Markdown file renders with its front matter table, a visible error when the front matter does not parse, and GitHub's alerts as titled callouts; **Rendered** and **Source** switch this file's view only, and the URL keeps it. A mistyped name stays in the file browser: "No file named on-cal.md in docs/guides", "Did you mean on-call.md?", and that folder's listing below. Ctrl-C ends the session with one line naming what it removed and what keeps running, then the command that starts it again. A taken hostname names the session holding it, its folder or port, its PID and how to stop it. The stack directory lists the session under the same folder or port, as a serve session, with its hostname, its state and how to stop it. Chat stays off unless the person names the folder an agent may edit with `--chat <folder>`. A serve session writes nothing in the folder, so there is no Undo: Ctrl-C is its way back, and its outcome prints the command that starts it again. Benchmarks: GitHub, GitLab and Gitea list a folder with its README rendered below the file list, switch Preview and Code per file, show "Error in user YAML" above invalid front matter and render `[!WARNING]` alerts as callouts; Caddy's `file_server browse` and Finder list folders first with sizes, dates and natural order; Vercel's `serve` and Vite print the local and network addresses and a ready line; Go's `net/http` directory listing prefixes `./` to a name whose first segment holds a colon. Competitor behavior is evidence here, never a requirement.

## Target steps

Today: 8 steps on the main path: run `devhost serve`, read one prefixed line that names neither the folder nor readiness, open a README that hides the folder, follow a README link, **Show source**, climb the breadcrumb, scan a listing in byte order, Ctrl-C into "shutting down the stack". Proposed: 5 steps: start, read the ready line, the folder's listing with its README below, a file, Ctrl-C with its outcome.

1. **Start a serve session (`devhost serve`, one write: it claims the hostname, routes it, starts devhost's file server for a folder, and starts the shared Caddy when it is not running).** `devhost serve --domain notes.localhost` serves the current folder, `--dir` another one relative to it, and `--port 3000` a server already listening on 127.0.0.1:3000; `--domain` stays required and bare (Kept). devhost's own lines carry the label `devhost`, as `reference/output.md` already gives lines written before a manifest is read, never an invented stack name such as `serve-notes.localhost`, so at 120 columns no line wraps because of its label (`WORD-1`, `WORD-9`). The first line names what is served, the listener and chat: "Serving ~/acme/docs · Caddy listens on all interfaces, port 443 · chat off", or for a port "Routing to 127.0.0.1:3000 · Caddy listens on all interfaces, port 443 · chat off" (`FB-10`, `WORD-8`). The listener is what the shared Caddy settings resolve to, so a person serving notes reads that other machines can reach them; with `bindHost = "127.0.0.1"` where it applies, it reads "Caddy listens on 127.0.0.1, port 443", and proxy-settings owns what that resolution reports (`FB-10`).
   - Words: a serve session is a serve session, named by its folder or its port (`WORD-1`): no line, page, stack directory card or help text calls it a stack, a project or a primary service or names it `serve-notes.localhost`, and `serve (primary)` and "shutting down the stack" go (`WORD-1`, `WORD-3`, `serve-folder-11`). Every devhost-wide words module and state word comes from services-panel's shared module (`SURF-14`, `WORD-6`).
   - Chat: chat is off in a serve session unless `--chat <folder>` names the folder an agent may edit, relative to the current folder like `--dir`; the first line then reads "chat on: agents edit ~/acme/docs" (`SEL-11`, `serve-folder-04`). A `--port` session never gives an agent the shell's current folder: without `--chat` its chat is off, and with it the agent edits the named folder (`serve-folder-04`). This default is not settled by the reference, which leaves `serve-folder-04` to the product owner (section 1, `review-16`); it is **[discuss]** in Backend 5 and recorded as a cross-flow conflict, recommended off.
   - Caddy and trust: when the shared Caddy is not running, the session starts it, as today. Before the trust step's password prompt, the session says that it will ask for the password to trust devhost's local certificate authority (`WORD-9`); the prompt runs only when a person can answer it, standard input a terminal and `AGENT=1` unset, as today, and never under `AGENT=1`, where one warning tells the agent to have the person run `devhost caddy trust` in a terminal (`REV-8`, `CC-13`). An install prints the root's name, its SHA-256 fingerprint and the command that removes it, which first-run-setup words (`REV-8`, `UNDO-5`).
   - A taken hostname is refused before anything is routed, with exit status 1 and nothing left running (Kept), and the refusal names the holder in the person's terms and the next step: "notes.localhost is already used by the serve session for ~/acme/docs (PID 49514, started 15:50)", then "Stop it with Ctrl-C in its terminal, or run:", then `kill 49514` on its own line, then "Or choose another --domain." (`FAIL-2`, `WORD-7`, `WORD-8`, `serve-folder-03`). A stack holder is named by its name, its checkout label and its root manifest, "notes.localhost is already used by Acme Shop (main ~/acme · ~/acme/devhost.toml, PID 50112)", with `devhost stop --manifest ~/acme/devhost.toml` as the command, in stack-run-stop's words for a stack (`SEL-4`, `FAIL-2`). The refusal never prints "from ." or an empty path.
   - Keys: Ctrl-C at any point of the start cancels it, removes what it claimed and says so as a cancellation, not an error (`KEY-14`, `FAIL-5`).
2. **Read that it is ready (`devhost serve`'s ready line, read only).** A folder session prints its ready line once its route answers: "Ready in 0.3 s: https://notes.localhost/ · Ctrl-C stops this session" (`FB-5`, `FB-10`, `KEY-14`, `WORD-4`, `CC-22`). A `--port` session is starting until its port first accepts a connection: on a terminal it keeps one status line updated at least once a second, "Waiting for 127.0.0.1:3000 to accept connections · 12 s · start your server, or check the port number", and without a terminal it prints that line once; the ready line follows only once the port answers, "Ready in 14.1 s: https://app.localhost/ · Ctrl-C stops this session" (`FB-5`, `ACT-4`, `STATE-1`, `manifest-hot-reload-2-04`, `serve-folder-01`). It waits as long as the person lets it, with no timeout, because starting the server after the route is the ordinary order of work. The hostname is routed from the start, so a page opened meanwhile shows startup-and-recovery's "127.0.0.1:3000 is not reachable" page with **Check Again**, never a disabled **Restart** or an empty log, and reloads into the app once the port answers (`ACT-9`, `MENU-5`, `MENU-3`).
   - Reading followed for the session and its target: the session reads starting in the terminal until its port first answers (`ACT-4`, `status-02`), while its target, which devhost does not run, reads reachable or not reachable on every browser surface, never starting, failed or exited (`ACT-9`); recorded as a cross-flow conflict for the reference's author.
   - After the ready line, a target that stops answering prints one line, "127.0.0.1:3000 stopped accepting connections at 14:05; its page shows it as not reachable until it answers", and one when it answers again, "127.0.0.1:3000 accepts connections again · 14:06", never one line per check (`ACT-9`, `FAIL-4`, `FB-10`).
   - The toolbar on a served page names the session by its folder or port ("~/acme/docs", shortened in the middle when long, with the full label in its tooltip and accessible name) and its one service by the same label, a folder session's file server reading running and a `--port` target reachable or not reachable with its check and time, from services-panel's shared state indicator (`WORD-1`, `WORD-8`, `ACT-2`, `ACT-9`, `SURF-14`); toolbar-shell draws the name and keeps the toolbar's placement per served folder (`SURF-7`, `CC-5`).
3. **Open the folder (a page load, read only).** The page's one heading is the path itself: the served folder's name, then each folder down to the one shown, each ancestor a same-tab link and the shown folder plain text with `aria-current="page"`, "docs / guides"; the served folder's absolute path never appears on the page (`WORD-1`, `serve-folder-05`). Under it, one line counts what the folder holds, "3 folders · 12 files" (`WORD-5`). The tab title starts with the same path, "docs/guides · devhost". The listing is a table with Name, Size and Modified columns: folders first, then files, each group in natural, case-insensitive order (file2 before file10, alpha before UPPER.TXT), a folder's name ending in "/" beside a folder icon and a file's beside an icon of its kind, so neither is told by the icon alone (`ACT-13`, `serve-folder-07`). Sizes use binary units with one decimal under 10 ("2.1 MiB", "512 B"), folders show no size, and modified times are local and 24-hour: today's as "14:02", this year's as "Nov 15 14:02", older ones as "Nov 15, 2025" (`WORD-8`). Every name is a same-tab link built as a path relative to the folder with `./` in front, so "Re: meeting.md", "TODO:list.md" and a folder "notes:2026" open like any other name (`SURF-15`, `serve-folder-10`); rows carry no external-link arrow, because nothing on these pages opens a new tab (`SURF-15`, `serve-folder-07`). Rows are compact, at least 24 CSS pixels tall (`SURF-9`).
   - The filter: a search field labelled "Filter guides" above every non-empty listing filters the rows as the person types, by name, highlights the matched text, keeps folders before files and says the count, "3 of 15 entries match "on"", announced politely; with no match it reads "No entry in docs/guides matches "xyz"" with **Clear Filter** (`SEL-10`, `STATE-2`, `WORD-2`).
   - A Markdown index: a folder holding `index.md`, `README.md` or `readme.md`, in that order, shows its listing first and that file rendered below it, in a section headed by the file's name, "README.md", which links to the file on its own page, with the same view control as step 4; the folder's other entries, the files the README never links to included, are each one click from the folder's URL (`serve-folder-05`). A folder holding `index.html` still serves it unchanged, as a site (Kept).
   - An empty folder reads "docs/drafts is empty. Files added here appear when you reload the page." in the shared empty-state block, with no filter (`STATE-2`, `SURF-14`).
   - Keys: the full page keeps the document's standard keys and adds no shortcuts (`KEY-1`); Tab moves through the heading path's links, the filter, then each row's link in order; Escape in the search field clears it, as the browser does.
4. **Read a Markdown file (a page load, read only).** A `.md` file renders as GitHub Flavored Markdown without raw HTML or unsafe links, its YAML front matter as a table above it (Kept); its heading path ends with the file's name, and its tab title reads "release-checklist.md · docs/guides · devhost". Front matter that does not parse shows an error above its raw block, in the shared cannot-load style and never as an ordinary code sample: "Front matter is not valid YAML: line 1, column 8: flow sequence in block collection must be sufficiently indented and end with a ]", and valid YAML that is not a mapping reads "Front matter is a list, not a mapping of keys and values" (`FAIL-2`, `WORD-7`, `STATE-4`, `serve-folder-09`). GitHub's five alerts, `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` and `[!CAUTION]`, render as callouts titled Note, Tip, Important, Warning and Caution with an icon each, in the design system's state colors at 4.5:1 text contrast in both themes and distinct in forced colors, and the bracketed marker never shows (`ACT-13`, `serve-folder-09`).
   - The view control: two buttons, **Rendered** and **Source**, beside the heading path, the active one pressed (`aria-pressed="true"`), so the control shows the view and its labels are not actions (`SEL-11`, `WORD-3`, `serve-folder-08`). It applies to this file only: **Source** adds `?view=source` to this page's URL with `history.replaceState`, so a reload, the back button and a shared link keep it, and every other file opens rendered; nothing is kept in browser storage, and the hostname-wide preference of today is removed (`SEL-11`, `serve-folder-08`). In the source view, each link target of the raw text (`[text](target)`, `<https://…>` and bare URLs) is a link with the rendered view's sanitizing, so a relative link to another file opens it and a `javascript:` target stays text (`serve-folder-08`).
   - Keys: Tab reaches **Rendered** and **Source**, and Enter or Space presses one; the page adds no shortcuts (`KEY-1`).
5. **Recover from a missing file (a page load, read only).** A name that does not exist under the served folder, `/guides/on-cal.md`, is answered by devhost's file server with status 404 and a page inside the file browser: the heading path down to the nearest folder that exists, then the failure in words, "No file named on-cal.md in docs/guides", then up to three names of that folder closest to the missing one, ignoring case and at most two edits away, as same-tab links, "Did you mean on-call.md?", then that folder's listing (`SURF-16`, `MENU-5`, `FAIL-2`, `WORD-7`, `serve-folder-06`). A missing folder on the way reads "No folder named old in docs/guides". The page offers no **Restart**, no checkout list, no internal address and no logs, because a typo is no service's failure (`MENU-3`, `MENU-5`), and its tab title starts with the failure, "Not found: on-cal.md · docs/guides · devhost" (`O16`). The same page answers for a CLI serve session and a manifest `serve` service; startup-and-recovery's document injection never replaces it (`SURF-16`, `CC-4`, `O5`). A hidden name, or a link that leaves the served folder, gets the same page as any missing name and is never offered as a close name (Kept). A request that is not a page load gets a one-line text 404, "Not found: no file named on-cal.md in docs/guides".
6. **Stop the session (Ctrl-C, one write).** Ctrl-C removes the session's route and hostname claim, stops the file server and prints one outcome line naming what it removed and what keeps running: "Stopped the serve session for ~/acme/docs · removed https://notes.localhost/ · Caddy keeps running · 0.2 s", for a port "Stopped the serve session for 127.0.0.1:3000 · removed https://app.localhost/ · your server on 127.0.0.1:3000 and Caddy keep running · 0.2 s", then "Start it again with:" and the command on its own line, `devhost serve --dir ~/acme/docs --domain notes.localhost` (`KEY-14`, `FB-10`, `WORD-4`, `UNDO-5`, `serve-folder-02`). A second Ctrl-C while it stops forces the rest within a second, as for a foreground stack (`KEY-14`). The exit status stays 130 after Ctrl-C and 143 after `SIGTERM`, whose line reads "Stopped by SIGTERM (143) at 15:52:10 · removed https://notes.localhost/ · Caddy keeps running", a stop, never a failure (`FAIL-5`, `WORD-7`, `WORD-8`). There is no Undo: the session wrote nothing in the folder, and the printed command is its way back (`UNDO-5`).

Branches and edge states:

- **A manifest `serve` service.** Steps 3 to 5 are the same pages, with the stack's toolbar, chat setting and worktrees; its missing-file page is step 5's, never a recovery page with **Restart** or a checkout list (`SURF-16`). A `serve` service that a manifest declares wrongly is rejected with the file, line, column and key, in manifest-hot-reload's and stack-run-stop's structured error: "devhost.toml line 14, column 9, services.design.serve: the folder packages/desing does not exist. Did you mean packages/design?", and each key `serve` rejects (`cwd`, `env`, `injectPort`, `lifecycle`, `proxyLocalOrigin`, `watch`, `managed = false`, a process-only health check) is named the same way (`MENU-4`, `FAIL-2`).
- **A `--port` session started before its server, or with the wrong port.** Step 2's waiting line and startup-and-recovery's not-reachable page say the same thing, and neither blames a service named serve or offers a restart (`ACT-9`, `MENU-3`).
- **The hostname is held by a stack.** Step 1's refusal names the stack, its checkout and its manifest, and `devhost stop --manifest` (`FAIL-2`, `SEL-4`).
- **`devhost stack replace --all` (today `devhost stack restart --all`) from another terminal.** Its printed set lists this session by its name, "serve session ~/acme/docs (PID 48800) · keeps running", and leaves it running; stack-run-stop prints "The serve session for notes.localhost keeps running devhost 0.0.12; restart it in its terminal to use devhost 0.0.13", and this session's terminal prints nothing, because nothing happened to it (`SEL-6`, `REV-7`, `O31`, `CC-36`).
- **`devhost stack list`.** It stays a list of manifest stacks, whose PID-and-manifest-path lines feed `devhost stop --manifest` and pickers (`reference/output.md`: output meant for other programs); a serve session is found through step 1's refusal, the stack directory (next branch) and `--all`'s printed set.
- **A serve session in the stack directory.** The directory keeps listing serve sessions beside manifest stacks, read-only with links (Kept), and draws each one from the session's record (Backend 1, Backend 11). The card's title is the session's name: its folder for a folder session, "~/acme/docs", or its target for a `--port` session, "127.0.0.1:3000", shortened in the middle when long, with the absolute folder or the address in its tooltip and accessible name, and never `serve-notes.localhost` (`WORD-1`, `WORD-8`, `serve-folder-11`). Beside the title a kind label reads "Serve session · folder" or "Serve session · port", and the directory's counts name serve sessions apart from stacks, "2 stacks · 1 serve session", so no card or count calls a serve session a stack (`WORD-1`, `WORD-5`). The hostname URL stays the card's main link. A serve card has no Directory line, because its title already names the folder or the target, so a `--port` card never shows the folder its command ran in (`WORD-8`, `serve-folder-11`). Its one row shows the state from services-panel's shared state indicator: a folder session's file server reads running, because devhost runs it; a `--port` target reads reachable or not reachable with its check and time and "runs outside devhost", "not reachable · checked 14:05 · start your server on 127.0.0.1:3000", its hostname link opening startup-and-recovery's not-reachable page with **Check Again**; neither reads External (`ACT-2`, `ACT-9`, `ACT-13`, `MENU-5`, `SURF-14`). Configuration's root manifest line reads "None: the serve session for ~/acme/docs reads no devhost.toml" (or "for 127.0.0.1:3000"), never "Manifest-free file or port session". A details line says how to stop it, in step 1's refusal's words: "Stop it with Ctrl-C in its terminal · PID 48800 · started 15:50" (`MENU-6`, `SEL-6`, `WORD-8`). The filter finds the session by its name, so "3000" or "acme/docs" finds it, and by its hostname (`SEL-10`). Since no surface names a session `serve-<domain>` any more, the card needs no second name to match its terminal, whose header line names the same folder or port (step 1). Two sessions serving one folder on two hostnames are two cards with the same title, told apart by their hostname links. stack-directory draws the card with its shared card and state components; this branch states what a serve session's card says (recorded as a cross-flow conflict with stack-directory).
- **The shared Caddy stops while the session runs.** The session prints one line, "Caddy stopped at 14:10; https://notes.localhost/ does not answer until Caddy starts again", and one when its route answers again, as `ACT-10` gives a stack (`ACT-10`, `FB-10`).
- **The session stops while a page is open.** The page's toolbar shows the lost connection with the reason the session sent before its stream closed, "The serve session for ~/acme/docs stopped at 14:05. Start it again with devhost serve in ~/acme", every write on the page unavailable with that reason; notices-and-feedback words the notice (`HOLD-2`, `ACT-5`).
- **Chat in a serve session.** With chat off, the toolbar's chat entry points are unavailable with one reason, "Chat is off in this serve session. Start the session with --chat \<folder\> to let an agent edit that folder.", which agent-chat draws (`HOLD-5`, `MENU-3`); with `--chat ~/acme/docs`, chat behaves as in a stack, its agent editing that folder (`serve-folder-04`).
- **Write-blocking states.** This flow's writes are the terminal's start and stop; its pages write nothing, so another operation in progress, a blocked checkout and saves taken only from this machine block nothing here (`HOLD-3`, `HOLD-4`, `HOLD-7`); a serve session reads the devhost config file's shared Caddy settings, and a rejected change to that file leaves the session on the running settings, blocking nothing (`HOLD-6`).
- **A file or folder that cannot be read.** It answers status 500 inside the file browser with one sentence, "Could not read docs/guides/on-call.md: permission denied", **Retry**, which reloads the page, and the heading path to its folder; never "Could not read document" as plain text and never a recovery page (`STATE-4`, `FAIL-2`).
- **No JavaScript.** The listing's links, the escaped source text and step 5's listing still work, as documented today (Kept).
- **Agent output (`AGENT=1`).** It carries the same facts in its own layout: each line `devhost: <message>` with absolute paths and PIDs, the served folder or target address, the listener, chat on or off with the agent's folder, the waiting and ready lines, the stop outcome, and every error, step 1's refusal included, as one `devhost: ERR:` line holding the holder's kind, folder or port, PID and start time and the next steps (`WORD-9`, `FB-11`, `CC-30`).
- **Who can reach a serve session from the network.** Chat and the control API of a serve session run on the same control server as a stack's, so `network-exposure-01`'s stopgap covers serve sessions unchanged; that exposure belongs to `network-exposure-01`, `proxy-settings-01` and `serve-folder-04`'s reach, which the product owner handles outside the reference, and this redesign decides nothing about it.

## What changes versus today

- **Removed:** the invented stack name `serve-<domain>` as every line's label and as the session's name on every surface; `serve (primary)`; "shutting down the stack" and "Stack stopped." for a serve session; the URL printed as ready before a `--port` target answers; a README or Markdown index replacing the folder's listing; "Directory listing" as every listing's heading and the word devhost as the breadcrumb's root; byte-order sorting; the external-link arrow on same-tab rows; the hostname-wide **Show source** preference in browser storage; the recovery page, with its disabled **Restart serve**, empty logs, internal port and worktree picker, as the answer to a missing file; the refusal's "from ." with only a PID; on the stack directory's card of a serve session, the `serve-<domain>` title, the External badge on a folder session's file server, a `--port` card's Directory showing the folder its command ran in, and "Manifest-free file or port session"; chat on in every serve session with no way off, and the shell's current folder as a `--port` session's agent folder (recommended, **[discuss]**).
- **Merged:** a folder's listing and its Markdown index become one page, the listing first; the breadcrumb and the page's heading become one heading path; a missing file in a CLI serve session and in a manifest `serve` service, today two different recovery pages, gets one page, the file browser's 404 (step 5).
- **New:** the header line naming what is served, the listener and chat; the ready line with Ctrl-C; the `--port` waiting status line and its reachability lines; the stop outcome with what keeps running and the command that starts it again; the holder named in a refusal; sizes, modified times, kind icons, counts and a filter in listings; the view control per file in the URL; links in source view; the front matter error; GitHub alerts; the file-browser 404 with close names; the cannot-read state; a serve session's stack directory card, titled by its folder or port, with its kind, its state and how to stop it; `--chat <folder>`.
- **Changed:** a folder with a Markdown index shows its listing first (contract change below); **Show source** applies to one file instead of every Markdown page on the host, and `apps/devhost/internal/files/browser_test.go`'s `TestMarkdownSourcePreferenceInBrowser`, which asserts the remembered preference across a restart, changes to assert the per-file view and `?view=source`; `apps/devhost/internal/files/handler_test.go`'s `TestServeFiles` cases "markdown", "readme index", "lowercase readme index" and "markdown before readme" change to expect the listing with the index below it, its "listing" and "missing" cases to expect the new order, rows and 404 page, and `TestReadFailuresReturnServerError` to expect the cannot-read page; `apps/devhost/internal/files/breadcrumb_test.go`'s `TestBreadcrumbNavigationInBrowser` expects the served folder's name as the root instead of devhost; a `--port` session reports ready only once its port answers, matching what `start/serve.md` already promises; `devhost stack replace --all` leaves serve sessions running instead of replacing them (`O31`, `CC-36`, stack-run-stop's); the stack directory titles a serve session by its folder or port instead of `serve-<domain>`, so `packages/devhost-ui/src/statusPages/components/stories/StackDirectoryCard.stories.tsx`'s `ManifestFree` story, which asserts an External cell and "Manifest-free file or port session" on a fixture stack's name, becomes two stories of a folder session and a port session; and because the session's name no longer holds its hostname, its access log is keyed by the hostname instead of the name, so `apps/devhost/internal/services/routes_test.go`'s `TestStackRoutesNameTheAccessLogAfterTheStackIdentity` gives its serve case two sessions of one folder on two hostnames.
- **Kept:** walking every safeguard of the current flow:
  - One command gives a folder or a running port an HTTPS hostname with no manifest; Caddy starts on demand and keeps running after Ctrl-C.
  - `devhost serve` reads no `devhost.toml`, `DEVHOST_MANIFEST` included, writes nothing into the served folder, and requires a bare `--domain`.
  - A `--port` server is never started, restarted or stopped by devhost, and keeps running after the session ends (owner rule; `ACT-9`).
  - Files are read on every request, so a reload shows edits and new files.
  - Reads stay confined to the served folder: hidden files, `../` escapes and symbolic links that leave it answer 404, now the file browser's 404, which never reveals or suggests a hidden name.
  - Markdown renders as GitHub Flavored Markdown without raw HTML or unsafe links, with its front matter table; the source view, now with links, applies the same sanitizing.
  - Files support `GET`, `HEAD` and byte ranges; the server is static, with no fallback to a single-page app's `index.html`; a folder with `index.html` serves it unchanged.
