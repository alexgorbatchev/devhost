# The toolbar itself: proposed experience

Diagrams: [current](../toolbar-shell-current.html), [proposed](../toolbar-shell-proposed.html). [Wireframe](../wireframes/toolbar-shell.html).

Status: design proposal, not implemented behavior. The [shared UX pattern reference](../patterns.md) (revision 6) wins where this proposal disagrees with it.

Source revision: alexgorbatchev/devhost `190a8bb53e8cd903d2db0a92cb0886f29671607f` (Rust `main`). Features: TB-01, TB-02, TB-04, TB-05, TB-06. Redesign ticket: tracked privately.

Product rule: `packages/devhost-ui/src/devtools/AGENTS.md` makes the toolbar a guest on the page: "The injected devtools UI must remain visually isolated from the host page", its host takes no pointer events and "every interactive surface must opt back in with `pointer-events-auto`", and "A host modal makes ordinary controls outside it inert; promotion changes paint order only." The product owner's rules add one explicit exception to page isolation (`O16`, `ACT-7`): devhost prefixes app pages' browser tab titles while a waiting agent or a failure persists and restores the app's own title when cleared. The owner's rules also establish that every manifest setting applies through hot reload, that using devhost from another environment is a primary use case gated safely rather than confined to one machine (`HOLD-8`, `O36`, `O59`), and that the CPU, RAM and Disk readouts measure the whole machine running the stacks (`guides/devtools.md`, "Host resource usage", named by `O61`). So a page's modal dialog silencing the toolbar is intended, and devhost never fights it by removing the page's `aria-hidden`, `inert` or focus trap; machine-wide readouts are intended; the manifest's `[devtools.status].position` being the team's placement is intended; none of them is a defect. The gap is around them: the toolbar's empty box takes the page's clicks, its notices vanish under its own panels, under docked chat and while it is collapsed, open popovers overlap the right-edge log minimap, default devtools button borders fall below 3:1 contrast in both themes and the stack name control lacks a visible chevron affordance, narrow wrapped docks break into ragged rows with an orphan Disk row, the toolbar looks live while a page dialog makes it inert, only a team-wide manifest edit moves it, the keyboard reaches it last, keys typed into it still reach the page's capture listeners, and its readouts raise alarms nobody can act on.

## Target experience

The person opens any page of the stack and the dock (the bar and its notices) appears where they last left it, on every hostname of the stack: bottom right, as the team's devhost.toml says, until they move it. Only what devhost draws takes their clicks, so the app's controls beside a notice keep working and Select Elements can mark them. When the toolbar sits on the app's account menu, they open the stack name menu (whose button carries a visible chevron affordance and a >=3:1 border) and choose **Move to** › **Bottom Left**, or drag the bar there, or choose **Collapse**; the choice is theirs alone, survives every reload and never changes the manifest. From another environment (a laptop, a phone, or through a relay preview), an unauthenticated browser sees the app and one toolbar state, "Sign in with passkey or pair this browser to use devhost here", while an authenticated browser (signed in with the shared passkey or paired, 30-day idle session) uses every control and finds **Sign Out This Browser** (or **Unpair This Browser**) in the stack name menu. Collapsed, the toolbar is one badge with a visible expand chevron that still says what needs them, "1 failed · 1 changed", with each pending notice kept as one line beside it, and it never turns red for a routine restart; while a waiting agent or a failure persists, app pages also prefix the browser tab's title and restore the app's own title when cleared. Notices stay readable in every state: panels, docked chat and the Configuration window open beyond them, an open panel paints above docked chat, every toolbar popover reserves the right-edge minimap width so it never overlaps the minimap at 320 px, 390 px or desktop widths, chat, approval prompts and notices adapt cleanly down to 320 CSS pixels for phones, and narrow wrapped docks collapse host meters and separate rows cleanly. From the keyboard, Alt+Ctrl+B reaches the bar from anywhere and comes back; the bar is one Tab stop walked with the arrow keys; `[devtools.shortcuts]` in `~/.config/devhost/config.toml` lets each person override the team's bindings; keys typed into devhost's fields never reach the page, and a click on a toolbar button leaves the page's own shortcuts working. The CPU, RAM and Disk readouts settle on calibrated thresholds instead of flickering, never borrow a crashed service's look, and each opens its details for `devbox`: the machine's figures, this stack's share and a verdict. While the page's own dialog is open, devhost's notices and chat move into it and the rest of the bar says it is paused. The only write here is the person's own layout, which is its own way back: **Move to**, the collapsed badge and **Reset to Manifest Default** reverse it, so there is no Undo control. Benchmarks: the Next.js dev indicator offers four corners and dragging, and keeps an issue count on its collapsed badge; TanStack Devtools and the Vercel toolbar let each person drag their toolbar along the edges, and the Astro dev toolbar remembers that it was hidden; VS Code's notifications never sit under its panels, its Focus Next Part cycles focus between parts and back, and one keybinding registry draws every hint in each platform's notation; browser DevTools run in their own frame, so a page never sees their keys, and their docked panes never overlap; Docker Desktop and Activity Monitor attribute CPU and memory to the processes that use them; the WAI-ARIA toolbar pattern gives a toolbar one Tab stop and arrow keys. Competitor behavior is evidence here, never a requirement.

## Target steps

Today: keeping the toolbar off the app's own controls takes 5 steps and changes it for the whole team: open the shared devhost.toml, pick the other right-hand corner, save, check the page, then click the borderless stack name to collapse it, again after every reload; reaching it from the keyboard takes a Tab walk through the whole page (the 13th stop on the small fixture page). Proposed: 2 steps, once, for this person only: open the stack name menu (a click, or Alt+Ctrl+B then Enter) and choose **Move to** › **Bottom Left** or **Collapse**; one chord reaches the bar from anywhere.

1. **Open a page: the dock mounts where this person left it (`GET /__devhost__/config.json`, read only).** devhost injects its toolbar into every HTML page of the stack whenever any devtools feature is on, the CPU, RAM and Disk readouts included, and one master switch, `[devtools].enabled = false`, turns every feature off with nothing injected (`SEL-11`). The document injection adds a small classic script, `/__devhost__/keys.js`, first in `<head>` (step 5), beside today's module script before `</body>`. The module script fetches `/__devhost__/config.json` with `no-store`, as today; it now carries this person's layout record for the stack, the resolved machine name (`O61`), the merged key bindings (`O17`) and the client's auth state (`O36`), so the dock mounts at its saved placement and collapsed state and is never drawn first somewhere else (`SURF-7`, `CC-5`). The dock is the bar and its notice stack together: one landmark (`complementary`) named "devhost", in the page's top layer, inside the Shadow DOM, as today (`KEY-3`). It sits in one of five placements, top left, top right, bottom left, bottom center or bottom right: the manifest's `[devtools.status].position`, bottom right by default, until the person chooses another (step 7).
   - The bar renders whenever any of its segments has something to show: Services (service status on), Worktrees (the stack has a repository), the readouts (resources on), Config (the config editor on), the third-party launchers, Running agents and Chat (chat on), and Hold Reloads (the browser has the Navigation API). Turning a feature off removes its segment and nothing else, and never turns off **Hold Reloads**: the reload hold runs whenever the toolbar's script is injected and the person has it on, whether or not any other segment shows (`SEL-11`). A segment with nothing to show right now keeps its place in the bar's order instead of shifting its neighbours: Running agents stays, with "No agents in this worktree" (`STATE-2`, `WORD-11`, `CC-33`, running-agents').
   - On a page opened from another environment by an unauthenticated browser (neither this machine, nor signed in with the shared passkey, nor paired via `devhost pair`), the dock mounts in its unauthenticated state: the bar shows the stack name and one status sentence, "Sign in with passkey or pair this browser to use devhost here", offering **Sign In with Passkey** when the shared passkey is configured for this domain and instructions to pair via `devhost pair` as fallback; every gated control is unavailable, nothing starts, and the app page stays usable (`HOLD-7`, `HOLD-8`, `O36`).
   - Only what devhost draws takes pointer input: the visible bar, each notice card, open panels and docked surfaces. The dock's own box takes none, and each of those opts back in, so the empty space beside a notice, between the bar and the stack and around a short bar passes clicks and Select Elements' picks to the page (`SURF-11`, `SEL-9`).
   - Each bar item names its scope in its tooltip and accessible description, so the person knows what it reaches: Services, Worktrees and Config "the whole stack"; Running agents and Chat "this worktree" (`WORD-11`); CPU, RAM and Disk "devbox" (the stack's machine name from `machineName` in `config.toml`, else the machine's OS host name up to its first dot, `O61`); Hold Reloads and the third-party launchers "this page" (`SEL-3`).
   - Defaults: bottom right and expanded unless the manifest or the person's layout record says otherwise; **Hold Reloads** on, as today.
2. **Reach the dock from the keyboard (`focusToolbar`, read only).** Alt+Ctrl+B (`focusToolbar`, configurable, step 6) moves focus from anywhere on the page to the bar item focused last, else the stack name; pressed again it moves to the pinned log panel while it is open, then to docked chat's composer while chat is docked, and from the last of these back to the element that had focus before the first press (`KEY-3`). While the toolbar is collapsed it focuses the collapsed badge (step 8); while the page's own modal dialog is open it focuses the notice stack's first action, because the bar is paused (step 9). The dock's DOM and Tab order follow its drawn order (WCAG 1.3.2, 2.4.3): with the dock at the bottom, the notice stack's actions come first, then the bar, then the pinned log panel and docked chat; with the dock at the top, the bar comes before the notices drawn below it, followed by the pinned log panel and docked chat (`KEY-3`).
   - The bar follows the toolbar pattern: it is one Tab stop; ArrowLeft and ArrowRight move between its items, Home and End jump to the ends, and Tab leaves it. Every item is an arrow stop, each readout included (step 3). Enter, Space, or the arrow that points where the panel opens (ArrowUp with the dock at the bottom, ArrowDown at the top) opens the item's panel or menu with focus inside (`KEY-4`, `KEY-6`). Each notice's actions and **N More** (expanding in place with **Show Fewer**) are ordinary Tab stops in the notice stack (`FB-8`, `WORD-3`). The bar is built on `@base-ui/react`'s Toolbar, with `Toolbar.Button` and `focusableWhenDisabled` for its items.
   - An unavailable bar item stays in place, `aria-disabled` with its reason as its accessible description, never removed and never live-looking. The reason shows once as visible text in the notice stack, which is the dock's status line: the lost connection's condition notice, the activity line of the operation that blocks it, the unauthenticated prompt (`O36`), or the paused line (`MENU-3`, `HOLD-1`, `HOLD-7`). This flow ships the shared button boundary and unavailable-state primitives: `Button` (`packages/devhost-ui/src/components/ui/Button.tsx` and `constants.ts:32`) switches its default variant border from `border-border` (`--dh-line`, 1.63:1 dark / 1.57:1 light) to `border-input` (`--dh-input-line`, >=3:1 in both themes, matching `packages/design/references/devtools.html:758`) (`ACT-13`, `serve-command-09`), and gains an unavailable state that renders `aria-disabled="true"`, ignores activation, keeps focus and points `aria-describedby` at the visible reason, which every flow's controls then use; a focused control that becomes unavailable keeps focus (`MENU-3`, `HOLD-1`, `KEY-11`).
   - Hints: a control with a binding shows its key in its tooltip and as `aria-keyshortcuts`, through `Button`'s `shortcut` prop and outside its accessible name, read from one binding registry under `packages/devhost-ui/src/devtools/` that also drives the key handlers and the docs' Keyboard section (step 6). macOS shows Apple's glyphs in Apple's order (⌃⌥B), other platforms words joined by + (Ctrl+Alt+B), and a hint names the character the person's keyboard layout puts on the bound physical key where the browser reports the layout (`KEY-13`, `BAR-4`).
   - Keys: Alt+Ctrl+B; ArrowLeft, ArrowRight, Home and End on the bar; Enter, Space, or ArrowUp or ArrowDown toward the panel; Tab and Shift+Tab leave the bar (`KEY-3`, `KEY-4`).
3. **Read the bar and its readouts (`/__devhost__/ws/health` and `/__devhost__/ws/resources`, read only).** From its start the bar reads, as today: the stack name (with a visible menu/collapse chevron affordance, step 7), Services, Worktrees, CPU, RAM and Disk, Config, the third-party launchers, Running agents, Hold Reloads and Chat. In a serve session, the stack name shows the session's folder or target (`~/acme/docs` or `127.0.0.1:3000`, shortened in the middle with full text in tooltip and accessible name) instead of an invented `serve-<domain>` (`WORD-1`, `WORD-8`). The segments are their flows': the Services trigger and its changed badge are services-panel's (the badge's restart icon and Alt+Ctrl+R act on the set Restart Changed names, `SEL-1`, `SEL-2`), Worktrees is worktree-switch's, Config config-editor's (its tooltip reads "Edit this stack's configuration: its manifest files and the devhost config file", `WORD-1`), the launchers third-party-devtools', Running agents running-agents', Hold Reloads reload-control's and Chat agent-chat's. This flow owns the bar they sit in: its order, its fit, its keyboard model and its shared looks.
   - The bar keeps one row at every acceptance viewport (`1600x1000`, `1280x800`, `900x900`, and `640x400` at 200% zoom, `SURF-9`). When its items would wrap, it changes form by a fit test at the current width, never by a count, in this order until they fit: the Services trigger shows its fixed-width summary (`BAR-1`, `SURF-10`, services-panel's form); the third-party launchers fold into one **Devtools** control (third-party-devtools' form); CPU, RAM and Disk fold into one **Host** item that shows the highest level among them; the stack name and the branch shorten in the middle, with the full text in their tooltip and accessible name; last, items from the bar's end inward, never Chat or the Services trigger, move into a **More** menu at the bar's end, each keeping its label, state and binding. At 1280x800 under 200% zoom (640x400 CSS pixels) a full bar shows the summary, **Devtools** and **Host**, and every item stays reachable (`SURF-9`, `SURF-10`, `O8`).
   - Below 640 CSS pixels (`320px` and `390px` phone and narrow viewports, `O8`, `serve-command-09`): chat, approval prompts and the notice stack take their 320 CSS pixel phone layout (owned by agent-chat and notices-and-feedback), while the bar and other surfaces never overflow the window horizontally. On narrow wrapped docks (`320px`/`390px`), CPU, RAM and Disk compact into the single **Host** item (or fold into **More** when space is tight), and whenever the dock wraps onto a second row, horizontal row dividers (`border-t`) separate wrapped rows cleanly so the dock never expands into 3–4 ragged rows with left-only vertical dividers and an orphan `Disk` row.
   - Each readout is a bar item button labelled by its figure: "CPU 42%", "RAM 86% high ▴", "Disk 27 GiB free" (or "Disk 8 GiB free very low ▾▾"). Its level follows `O48` (decided, calibrated) rather than single unsmoothed samples or percentage-of-disk alarms:
     - **CPU** averages its readings of the last **20 s** (the page stamps each arrival, counts each distinct reading once and leaves out the first CPU reading after devhost starts) and reads **high** at **70%** (back to normal below **65%**) and **very high** at **90%** (back to high below **85%**), with no separate hold.
     - **RAM** takes **each reading as it comes** and reads **high** at **75%** (back to normal below **70%**) and **very high** at **90%** held for **10 s** (back to high below **85%**).
     - **Disk** shows free space and, on a disk of any size, reads **low** below **20 GiB** free and **very low** below **10 GiB** free, each level clearing only once free space is **1 GiB** above its floor (21 GiB and 11 GiB).
     - A level that is not normal shows its word after the figure ("high", "very high", "low", "very low") and a mark of its own, ▴ for high, ▴▴ for very high, ▾ for low and ▾▾ for very low, never a service state's glyph or the failed look, so a busy machine never looks like a crashed service (`ACT-13`, `O48`).
   - Enter, Space or a click opens the readout's details, a popover anchored to it (`SURF-2`, `KEY-4`, `KEY-12`): the machine's figures on `devbox` (`O61`) ("RAM on devbox: 41.5 of 48 GiB used", "CPU on devbox: 94% of 12 cores busy, average of the last 20 s", "Disk on devbox: 27 GiB free of 994 GiB (excludes purgeable space)"); this stack's share with its top three services ("This stack: 3.2 GiB · web 2.1 GiB, api 0.8 GiB, worker 0.3 GiB", sampled by Rust `sysinfo` in `apps/devhost/src/devtools/resources.rs` reusing the verified process trees in `apps/devhost/src/services/containment.rs`); everything else ("Other programs: 38.3 GiB"); the last 60 s as a small chart whose lowest, highest and average readings are text beside it; and one verdict sentence ("Busy because of other programs: this stack uses 12% of CPU"). Sizes use binary units with their names (`GiB`) for RAM and Disk alike (`WORD-8`, `O48`), building on the binary arithmetic of `toolbar-shell-05`. The figures no longer live only in a native title that Tab, touch and recordings never reach.
   - While the resources stream is down, the readouts hide instead of showing stale numbers, as today (`CC-26` keeps this).
   - Defaults: the readouts' `pollInterval` settings are unchanged (2 s for CPU and RAM, 1 min for Disk).
   - Keys: each readout is an arrow stop; Enter or Space opens its details with focus on their first line; Escape closes them and returns focus to the readout (`KEY-6`, `KEY-8`).
4. **Open a panel, a menu or chat without covering a notice or the log minimap (`ToolbarPopover` and the docked surfaces, read only).** The notice stack sits beside the bar, between it and every other devhost surface, in every placement (`SURF-1`). The dock publishes one inset, the distance from its viewport edge to the far edge of the notice stack (today it publishes only the bar's edge), and every surface reads it: a toolbar panel opens beyond the notice stack, on its trigger's side; docked chat docks beyond it on its own edge and never covers the bar's row, in any placement; the Configuration window's height is capped by it, so every notice's text stays readable beside the window while the window makes the notices inert (`SURF-4`, config-editor's window). An open toolbar panel, the Running agents list included, paints above docked chat (`CC-1`). The notices' order, their count and **N More** / **Show Fewer** are notices-and-feedback's (`FB-8`, `WORD-3`); their place is this flow's.
   - Along the right edge, from the window edge inward: the minimap strip, the pinned log panel while it is open, then the dock and docked chat, which shift inward by the width of whatever lies outside them (`SURF-5`). `ToolbarPopover` (`packages/devhost-ui/src/devtools/shared/components/ToolbarPopover.tsx:84-87`) also reserves `--devhost-minimap-collapsed-width` whenever the minimap is visible (both right inset and `max-w`), so no open toolbar panel or readout popover overlaps the right-edge log minimap strip at `320px`, `390px`, `640px` or desktop widths (`SURF-5`, `SURF-9`, `O8`, `serve-command-09`).
   - When the surfaces beside the dock cannot keep their header, a first row and their actions in view (`SURF-9`), the notice stack shows its first notice and folds the rest into **N More**, which expands in place with **Show Fewer** to fold again; its order never changes (`FB-8`, `WORD-3`). At 320 CSS pixels wide (`O8`), notices, docked chat and approval cards use their phone layout without horizontal overflow; other panels constrain their width to the viewport minus margins and any visible minimap inset so nothing clips horizontally.
   - While a library's devtools panel is docked at the page's bottom edge, the dock moves onto that panel's top edge, or to the top of the window when the panel is taller than half of it, and follows the panel's own resize handle, so no devhost element covers the panel; the person's placement returns when the panel closes, and the move is never saved (`SURF-1`, `SURF-7`).
   - While a page element under the dock or docked chat has focus, both step aside to the other end of their edge so the element is never entirely hidden, and come back when focus leaves; this move is never saved either (`SURF-9`).
   - Panels follow `SURF-2`: one open at a time, anchored to their trigger, dismissed by Escape, a click outside or Tab past their last control. Their shared frame, `ToolbarPopover`, gives every panel a filter slot that takes focus on open when its rows overflow, a body that alone scrolls and a footer outside the scroll (`SURF-10`, `SEL-10`), which services-panel, worktree-switch, running-agents and third-party-devtools fill.
   - Keys: on open, focus moves into the panel, to its filter when it has one, else its first control (`KEY-6`). Inside a panel, Tab and Shift+Tab move in visual order; Tab past the last control or Shift+Tab before the first closes the panel and returns focus to its trigger (`KEY-7`). Escape or a click outside closes the panel and returns focus to its trigger, or, when the panel was opened with the pointer, to the page element that had focus before (`KEY-5`, `KEY-6`, `KEY-8`). Escape closes only the innermost layer: a completion list, then a menu or submenu, then an in-place question, cancelled, which returns focus to the control that asked while the panel stays open, then a nested popover, then the panel (`KEY-8`); Escape never collapses the toolbar, dismisses a notice or answers anything.
5. **Type into a devhost field without the page seeing the keys (`/__devhost__/keys.js`, read only).** The early script registers window capture listeners for `keydown`, `keypress`, `keyup` and `beforeinput` before any page script. For an event whose `composedPath()[0]` is a devhost text field (Find worktree, the chat composer, the configuration text, filter fields, the Disable Reloads request, the Deny note, the crop fields) it stops the original with `stopImmediatePropagation`, dispatches at that field a clone that never leaves the shadow root (`composed: false`), so devhost's own handlers, React's and CodeMirror's included, run on it, and copies the clone's `preventDefault()` onto the original, whose default action, typing the character, otherwise proceeds (`KEY-5`). On a page whose '/' shortcut listens in the capture phase, typing feature/login into Find worktree keeps all 13 characters in the field. All text entry stays in the Shadow DOM, so a field and what names, describes or lists for it stay in one tree.
   - A focused bar item or notice action keeps only Enter, Space, the arrow keys, Home, End and Escape; every other key reaches the page, so a click on **Hold Reloads** no longer silences the page's own shortcuts. Inside an open panel, menu or modal dialog devhost keeps every key. A panel or menu opened with the pointer (a `pointerdown` with `pointerType` mouse, pen or touch on its trigger) returns focus, when Escape or a click outside closes it, to the page element that had it before the click; one opened from the keyboard, or by an assistive technology's click without that `pointerdown`, returns focus to its trigger; Tab past a panel's last control always returns focus to its trigger (`KEY-5`, `KEY-6`, `KEY-7`, `CC-28`). This replaces today's documented "Click the page to give it the keyboard back."
6. **Use the page-wide chords (`[devtools.shortcuts]`, read only until a chord's action runs).** devhost binds page-wide only Alt+Ctrl chords on the physical key, each configurable under `[devtools.shortcuts]` in the manifest (the team default) and overridable binding by binding under `[devtools.shortcuts]` in the person's devhost config file (`~/.config/devhost/config.toml`, `O17`, `SEL-11`, `CC-39`): `restartServices` (Alt+Ctrl+R, Restart Changed, services-panel's action), `focusToolbar` (Alt+Ctrl+B, step 2), `logs` (Alt+Ctrl+O, the pinned log panel, log-minimap's) and `chat` (Alt+Ctrl+C, docked chat's composer, agent-chat's); Stop Turn's `stopTurn` (Alt+Ctrl+.) is agent-chat's and lives in the same registry (`KEY-2`, `KEY-9`). Chords act in the page scope, also while the page's own modal dialog is open, and are suspended in text entry and while a devhost menu or modal dialog is open (`KEY-1`). Every chord's action is also a control, so a chord that the desktop or VoiceOver takes costs only the shortcut. The registry's entry for `restartServices` says what it restarts, the changed services or, when none changed, the page's own service, as services-panel's button names it (`SEL-2`).
   - One grammar on both sides: modifiers `ctrl`, `alt`, `shift` and `meta` (or `cmd`), in any case, plus exactly one key: a letter, a digit, a period (`.` or `period`, canonical token `.`, resolved to `code: "Period"` so `stopTurn`'s default `alt+ctrl+.` is valid), or a named key from one documented list (`enter`, `escape`, `space`, `tab`, `backspace`, `delete`, `up`, `down`, `left`, `right`, `f1` to `f12`). Validation in `apps/devhost/src/manifest/validation.rs:1320-1328` (extended beyond ASCII letters and digits to accept `.`, `period`, and the named-key list) and `apps/devhost/src/config.rs` accepts exactly the values the page matches and normalizes them, and the control server sends the page each merged binding resolved to its key code and modifiers, with the file it came from (`config.toml`, the manifest, or default), so the page never parses a string again; one JSON table of cases (including `stopTurn = "alt+ctrl+."`) drives both the Rust and the UI tests. Every value validation accepts fires. A value devhost cannot use prints one warning, on start and on each hot reload that keeps it, naming the key, the file and line, the value and the binding in effect ("devtools.shortcuts.restartServices "ctrl+enterr" in devhost.toml line 31 is not a usable shortcut: unknown key enterr; using Alt+Ctrl+R"), in human output, in agent output and in the stack's log, and never falls back silently (`KEY-2`, `CC-29`).
   - A chord event whose `key` is a printable character other than the bound key's own is typed text, never a chord: on Windows, where AltGr reports Ctrl+Alt, AltGr+R typing ® reaches its target untouched, with no `preventDefault`, no `stopPropagation` and no restart (`KEY-2`). Text entry, where chords are suspended, covers the page's `input`, `textarea`, `select`, editable content and custom ARIA editing widgets whose role is `textbox`, `searchbox`, `combobox` or `spinbutton` (`KEY-1`, `toolbar-shell-12`). A `grid` is not text entry, so the chord keeps working in a data grid, while the printable-character test protects what a cell's editor types.
   - `guides/devtools.md` gains one Keyboard section that lists every binding of the 2.11 table in both platforms' notation, read from the registry, documents per-person overrides in `~/.config/devhost/config.toml` (`O17`, `CC-39`), and names the clashes a person may meet with how to rebind: Windows Magnifier resizes its lens with Ctrl+Alt+R while it runs, and VoiceOver takes every Control+Option chord (`KEY-13`, `CC-29`).
   - Keys: the four chords above; the full map is 2.11's.
7. **Move, collapse or sign out of the toolbar for yourself (`PUT /__devhost__/layout`, one write to this person's layout record, not disruptive).** The stack name button (`DevtoolsToolbar--collapse`, `packages/devhost-ui/src/devtools/shared/components/DevtoolsToolbar.tsx:64-83`) shows the dh mark, the stack name ("Acme Shop") and a visible menu/collapse chevron affordance (`▾`) inside a >=3:1 control boundary (`--dh-input-line`, `serve-command-09`); its accessible name begins with that name, "Acme Shop, devhost menu", and it opens the stack name menu (`aria-haspopup="menu"`) instead of collapsing directly (`KEY-4`, `MENU-1`, `toolbar-shell-09`). The menu, headed by the stack and its worktree ("Acme Shop · main ~/acme", `SEL-4`, `WORD-11`), puts its toolbar items in one group (`MENU-2`): **Move to**, whose submenu lists **Top Left**, **Top Right**, **Bottom Left**, **Bottom Center** and **Bottom Right**, the current placement checked; **Collapse**; **Reset to Manifest Default**; and **All Stacks on devbox** (naming the stacks' machine via `machineName` in `config.toml`, else the host name up to its first dot, `O61`), which opens the stack directory in the same tab (`MENU-1`, `MENU-2`, `SURF-15`, `WORD-2`, `WORD-3`). When the layout already matches the manifest, **Reset to Manifest Default** is unavailable with "Already where devhost.toml puts it: bottom right, expanded" as a line under it (`MENU-3`).
