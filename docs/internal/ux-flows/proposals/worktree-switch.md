# Switch the stack to another worktree: proposed experience

Diagrams: [current](../worktree-switch-current.html), [proposed](../worktree-switch-proposed.html). [Wireframe](../wireframes/worktree-switch.html). Research: [notes](worktree-switch-research.md).

Status: design proposal, not implemented behavior. The [shared UX pattern reference](../patterns.md) wins where this proposal disagrees with it.

Source revision: alexgorbatchev/devhost `190a8bb53e8cd903d2db0a92cb0886f29671607f` (Rust `main`). Features: WT-01, WT-02, WT-03, WT-04, WT-05, WT-06. Redesign ticket: tracked privately.

Product rule: a worktree switch never falls back silently to another worktree. `stacks/worktrees.md` says "devhost does not fall back to another checkout by itself" (updated to `worktree` per `WORD-11`), and `apps/devhost/AGENTS.md` ("Service supervision boundary") says "Missing saved selections remain stopped for explicit recovery; never silently fall back or leave a partially switched group running." Under `O43` (decided 2026-11-18), reading the worktree list stops nothing: devhost starts none of a deleted worktree's services and never falls back, while processes still running keep running until the person chooses recovery (`HOLD-4`). Under `O7` (decided 2026-11-25), external services (`managed = false`) never block worktree switches and need no warning when managed services switch: managed services restart from the target worktree's folder while external services stay untouched and marked `external` in the Services panel. Under `O36` and `O37` (decided 2026-11-25 and 2026-11-18), this machine and authenticated remote browsers (signed in with the shared-domain passkey with phone support, or paired via `devhost pair`) switch worktrees and stop other stacks identically on both entry points (`HOLD-8`). The same docs establish that a switch restarts every managed service and that **Stop Stack** stops another running stack so its worktree can be picked (kept by `O10`). So a switch that restarts the stack's managed services, a failed switch that restores the worktree it left and never a third one, a deleted worktree that devhost never replaces by itself, and an authenticated browser that can stop another stack are intended; none of them is a defect. Rust `main` (`190a8bb5`) already fixed `worktree-switch-14` (`apps/devhost/src/services/worktrees.rs:360-370`) so rejected running manifests stay with hot reload instead of stopping services on refresh. The remaining gaps are everything around those intended behaviors: nothing names the switch's reach before the one-click press or in its result, external services still block the whole repository (`apps/devhost/src/services/worktrees.rs:137-141`), switching fails on target manifests missing a selected name instead of reporting it and startup never names a restored linked worktree, conversations and agents in the old worktree drop out of sight, **Stop Stack** ends someone else's stack with no question, no attribution and a fixed 10 s stop request to the shared supervisor that gives up with "is still stopping" (`apps/devhost/src/services/stack/runtime.rs:455-462` at `bc33e2f1`), refreshing a deleted running worktree still stops its services (`runtime.rs:489-536`), a crash mid-switch leaves the unverified target saved in `active.json` (`worktrees.rs:195-203`), worktree routes lack `O36` remote authentication (`apps/devhost/src/devtools/server.rs:374-463`), and the recovery state for a deleted worktree leads with **Restart** instead of **Return to Configured Worktree**.

## Target experience

The person opens **Worktrees** from the bar, which shows the running worktree's label ("main ~/acme", shortening the path in the middle when the bar is tight), and keeps the page, its scroll position and their place: an anchored panel opens with focus in **Find worktree** at its top and one shared worktree list below it, the main worktree first, then each linked worktree by branch, every row showing its branch (or "Detached" with a 7-character commit ID), its short commit ID, its path shortened with `~` and its badges as shapes and words. Typing filters by branch, path or the start of a commit ID; the arrows move the highlight and Enter picks the row without switching anything. Under the list, a details line says why the highlighted row is unavailable, in use or deleted and offers the way forward (**Edit** at the failing line when the config editor is on, or the file and line with **Copy** when it is off, plus **Copy Error**, **Open Stack**, **Stop Stack**, **Check Again**; editor integration is removed under `O51`). External services (`managed = false`) never block switching and trigger no warning (`O7`): managed services restart from the target worktree's folder while external services stay untouched. The footer's **Switch and Restart Stack** carries a reach line that names everything the press will do: "Restarts all 6 services of Acme Shop from fix-nav ~/acme/.worktrees/fix-nav (repository acme) with new automatic ports · took 14 s last time", keeping the services the run was started with. One press switches when nothing else is at stake; when an agent works or waits for the person in this worktree, or the page holds unsaved drafts, held reloads or page context, the press expands in place into one question that names each item, with **Answer First** focused and **Switch Anyway** beside it. While the switch runs, the pressed button keeps focus and counts its steps ("Switching to fix-nav · 3 of 6 stopped · 5 s"), the panel lists each step with the service it waits on, and the bar still names main with "switching to fix-nav", never claiming the target before it runs. The page then reloads at the same URL and starts with focus on one outcome: "Switched acme from main ~/acme to fix-nav ~/acme/.worktrees/fix-nav: restarted 6 services · 6 of 6 running · 14 s", naming anything the switch left behind ("Claude Code · Fix the nav · This worktree (live) · waiting for you", discarded held reloads, lost marks) and linking the previous worktree so the way back is one switch away; the notice stays for its calibrated reading time (`O14`) and pauses on arrival if the browser window was unfocused (`O53`). A failed start returns to the previous worktree service by service and says so in the panel ("Returned to main ~/acme: 6 of 6 running"), with the failing service's cause, any missing-setup install command (`O32`), and **Retry Switch**. A deleted running worktree reads as deleted, never preselected, and leads with **Return to Configured Worktree** in the toolbar and on every recovery page, while reading the list stops nothing (`O43`). From another environment, browsers authenticated with the shared-domain passkey or a `devhost pair` link switch and stop identically to this machine, while unauthenticated browsers see writes unavailable with `"Sign in with passkey or pair this browser to use devhost here"` (`O36`, `O37`). A switch restarts processes and cannot be taken back, so there is no Undo: its rollback (`UNDO-1`) restores the previous worktree when the target fails, and its outcome names the previous worktree as the way back (`UNDO-5`). Benchmarks: VS Code, JetBrains IDEs and GitHub Desktop show a branch name first with a short commit ID, search branches by name, path or commit, never preselect a repository that is gone, and switch a clean worktree without asking while asking when local work would be lost; JetBrains asks "Stop and Rerun" before replacing a run; Git itself lists worktrees whose folder is gone as `prunable` and leaves removing them to `git worktree prune`; `docker compose up <service>` keeps a project's chosen services when it is brought up again; Kubernetes reports a rollback as an outcome of its own and keeps old replicas serving until new ones are ready; Vercel and Netlify give each branch its own URL instead of switching one environment, which devhost's "Several worktrees at once" already offers. Competitor behavior is evidence here, never a requirement.

## Target steps

Today: 5 steps, two of them blind: open **Worktrees** (focus lands in the search field at the bottom), scan rows and click badges for reasons, press **Switch and restart stack** with nothing said about what it stops or drops, watch one spinner for 14 to 27 s, land on the reloaded page with no outcome (the terminal holds it, naming folder basenames). Proposed: 4 steps: open **Worktrees** with focus in **Find worktree**, pick a row with the arrows and Enter, press **Switch and Restart Stack** after reading its reach line, read the outcome on the reloaded page, where focus starts.

1. **Open Worktrees (`GET /__devhost__/worktrees`, read only).** The bar's **Worktrees** trigger shows the selected worktree's `SEL-4` label ("main ~/acme", or "Detached c521449 ~/acme/.worktrees/bisect", shortening the path in the middle on narrow widths per toolbar-shell's fit sequence), and its accessible name carries the full label, "Worktrees: main ~/acme" (`SEL-4`, `WORD-1`, `WORD-8`, `WORD-11`). When a repository of the stack is blocked because its selected worktree was deleted or unregistered, the trigger adds the state as a shape and a word ("∅ fix-nav · deleted"), never by color alone, and the collapsed badge carries the same condition ("∅ dh · fix-nav deleted ▴") with its one-line notice beside it (`ACT-13`, `SURF-8`, `ACT-7`). The trigger is one arrow stop on the bar: Alt+Ctrl+B focuses the bar, ArrowLeft and ArrowRight reach it, and Enter, Space or the arrow toward the panel opens it (`KEY-3`, `KEY-4`). The panel is an anchored popover (`SURF-2`), placed and sized so it never overlaps the notice stack in either corner placement, painted above docked chat, reserving `--devhost-minimap-collapsed-width` clear of the right-edge log minimap, using `>= 3:1` `--dh-input-line` default button borders in both themes, and fitted to every acceptance viewport with its find field, details line, reach line and footer outside the scrolling list (`SURF-1`, `SURF-9`, `SURF-10`, `ACT-13`). Opening it reads the worktree list again, as today (`git worktree list`, each worktree's manifest and service folders), and that read stops nothing (`HOLD-4`, `O43`): it only publishes what it found. The panel's header names the repository, with a **Repository** choice when the stack runs services from several repositories, and says when the list was read, "Read 14:02", beside **Refresh Worktrees**; the list updates in place from the published state while the panel is open (`ACT-12`). While the list loads, its place reads "Loading worktrees of acme…" (`STATE-1`, `WORD-11`).
   - Keys: focus starts in **Find worktree**, at the top of the panel (`KEY-6`, `KEY-10`); Tab moves to the highlighted row's remedies in the details line, then the footer; Shift+Tab from the find field reaches **Refresh Worktrees** and the **Repository** choice; Tab past the last control or Shift+Tab before the first closes the panel and returns focus to the trigger (`KEY-7`); Escape or a click outside closes it, focus returning to the trigger, or, when the panel was opened with the pointer, to the page element that had focus before (`KEY-5`, `KEY-6`, `KEY-8`). Keys typed into the find field never reach the page (`KEY-5`). Under the find field, the panel's hint line reads "↑↓ Move · Enter Pick · Esc Close", drawn from the same key definitions as its handlers, in the platform's notation (`KEY-13`, `BAR-4`).
2. **Find and pick a worktree (read only).** The list is the shared worktree list, one component under `packages/devhost-ui/src/` that this flow ships in both style entries, the devtools Shadow DOM stylesheet and the status pages' document stylesheet, so the toolbar, recovery pages, the crash view and the collapsed list on an app's own 404 render the same rows with the same words (`SURF-14`, `SEL-4`, `WORD-11`). It is a combobox: the find field and the list share one shadow tree, ArrowUp and ArrowDown move the highlighted row (`aria-activedescendant`), Enter picks it, and rows are never several Tab stops and hold no controls (`KEY-10`). Rows put the main worktree first, then linked worktrees by branch; each row reads its label from the one worktree-label builder this flow ships with the list, "fix-nav · 08c92af · ~/acme/.worktrees/fix-nav", a long path shortened in the middle with the full path in its tooltip and accessible name (`SEL-4`, `WORD-8`, `WORD-11`), and its badges, each a shape and a word: **running**, **configured**, **unavailable**, **in use**, **blocked**, **deleted** and **edit not applied** (`ACT-13`, `WORD-6`), their words and shapes living in services-panel's shared state-words module and state indicator. Each badge's reason is text in the row's accessible description, never only on hover (`KEY-10`). Stack-directory cards, the running agents list, chat's conversation list and both sides of a switch in the terminal take their worktree labels from the same builder (`SEL-4`).
   - Find: branch and path match fuzzily with the matched text highlighted, and every worktree's full HEAD commit matches by exact prefix, so "08c92a" finds fix-nav and "c521449" lists both main and the detached worktree when they share that commit (`SEL-4`, `SEL-10`). A hexadecimal query that matches nothing reads "No worktree has HEAD at 08c92aff", any other query "No worktree matches "fixx"", each with **Clear Filter** (`SEL-10`, `STATE-2`, `WORD-11`). A repository with only its main worktree reads "acme has no other worktrees. Add one with git worktree add" followed by the command on its own line (`STATE-2`, `WORD-11`).
   - Defaults: the highlight and the pick start on the selected worktree when it is available; a selected worktree that was deleted or unregistered is never preselected, and the highlight then starts on the configured worktree (`SEL-4`). Enter in the find field picks the highlighted row and never starts a switch (`REV-2`, `KEY-9`).
   - The details line: below the list, outside it, headed by the highlighted row's label and its reason sentence, holding that row's remedies as the Tab stops after the find field, and updated as the highlight moves (`KEY-10`, `MENU-4`). It never covers another row's badges. For an unavailable worktree whose manifest fails, the reason is one structured line with the file relative to that worktree, its line, column and key, the path written once: "devhost.toml does not parse · line 13, services.api.port: strings cannot contain newlines". When the config editor is on, the details line offers **Edit** at that line in that worktree (`SURF-4`); when the config editor is off (the default), it shows the file and line (`devhost.toml:13`) with **Copy** instead (devhost has no editor integration, `O51`). Both states include **Copy Error**, which copies the original text, and **Check Again**, which reads the list again once the file is fixed, because devhost does not watch the manifests of worktrees it does not run; validation issues list one per line (`MENU-4`, `FAIL-2`, `WORD-7`, `HOLD-1`, `O51`). A worktree whose folder is gone reads "deleted · ~/acme/.worktrees/old is gone; Git still lists it", never a raw Git exit status, with the command `git worktree prune` to copy, because devhost runs only read-only Git commands (`WORD-7`, `SURF-15`).
3. **Read the reach and press Switch and Restart Stack (`POST /__devhost__/worktrees` with an `operationId`, one write).** The footer's button reads **Switch and Restart Stack** on every surface, its label carrying no count, in title-style capitalization while its reach line, reasons, outcomes and state words use sentence case (`WORD-2`, `WORD-3`, `BAR-2`, `MENU-6`). One line beside it names the stack, the repository and the target worktree and what the press does: "Restarts all 6 services of Acme Shop from fix-nav ~/acme/.worktrees/fix-nav (repository acme) with new automatic ports · took 14 s last time", and its tooltip and accessible description list the six, "web, api, docs, worker, admin and mail" (`SEL-5`, `SEL-1`, `BAR-2`, `REV-2`, `WORD-11`). In a run started with names, the line names what stays off: "Restarts web, api and docs of Acme Shop from fix-nav ~/acme/.worktrees/fix-nav with new automatic ports; worker, admin and mail stay not started" (`SEL-5`, `SEL-7`). External services (`managed = false`) declared in the repository never block switching and add no warning before or after the switch (`O7`, `SEL-5`): managed services restart from the target worktree's folder while external services stay untouched and marked `external` in the Services panel. While a manifest edit is rejected, the line adds that the switch runs the target worktree's own manifest, which it checks first (`HOLD-6`).
   - Picking is the first step and the button the second (`REV-2`): the button runs on one press when nothing else is at stake (`REV-1`), and it is unavailable, focusable with its reason as visible text in the panel's status line and as its accessible description, while nothing other than the running worktree is picked ("Pick a worktree other than main, which runs now"), while another operation runs ("Restart Stack is running · 3 of 6 started", `HOLD-3`), while the page has lost its stack's status stream (`HOLD-2`), while an unauthenticated remote browser has not signed in or paired (`HOLD-7`, `O36`, `O37`), and while the repository is blocked by a deleted or unregistered running worktree (step 7) (`MENU-3`, `HOLD-1`).
   - **Other work asks first, in place (`REV-3`, `REV-4`).** Before it runs, the control names each item of other work the switch moves the page away from: every chat conversation of this worktree that works or waits for the person, by agent, title and edit mode in the owner's words ("Claude Code · Fix the nav · This worktree (live) · waiting for you", `WORD-10`, `WORD-11`, `O1`), every agent the running agents list sees working in this worktree ("Codex in a terminal · working"), unsaved Configuration window drafts of this worktree's files, held reloads with their count, and page context (including any active tab share) (`SEL-5`). While any exists, the press expands in place into one question, a group labelled by its sentence, "Switch Acme Shop to fix-nav ~/acme/.worktrees/fix-nav and leave this work in main?", described by its items and by the six services it restarts:
     - "Claude Code · Fix the nav · This worktree (live) · waiting for you: it keeps waiting in main, and its request stays answerable from every page of Acme Shop" (`SEL-5`, `REV-9`, `O1`, `WORD-11`);
     - "devhost.toml: an unsaved draft for main, which the Configuration window opens again after you return to main" (`UNDO-2`);
     - "Hold Reloads: 2 held reloads on this page are discarded by the switch" (`REV-3`, `FB-4`);
     - "Page context: 2 marks · a mark whose element is gone after the reload is listed as lost; the tab share ends" (`UNDO-2`, `SEL-9`).
       Its first choice leads to the work and takes the pressed button's place with focus and Enter: **Answer First** while an agent waits for the person, which closes the panel and opens docked chat on that conversation's decision card; else **Review Drafts** while drafts are named, which opens the Configuration window on the first one; else **Cancel** (when only a working agent, terminal agent, held reload or page context exists). **Switch Anyway** sits beside it (`REV-3`, `REV-4`, `WORD-2`). A double press lands on the first choice. Escape, or a click in the panel on no control, cancels the question and returns focus to **Switch and Restart Stack** with the panel open; a click on another control cancels it and that control acts; Tab past the panel's last control, Shift+Tab before its first and a click outside close the panel and cancel the question with it (`REV-4`, `KEY-7`, `KEY-8`). With no such work the switch asks nothing. When chat is off, the reach line says that agents were not checked (`STATE-2`), and when running-agents reports an incomplete scan (such as "Codex agents could not be checked"), the reach line and question note which agents could not be checked (`REV-3`).
   - The services runtime runs every check before it stops anything: the target is registered and available, its manifest and includes load, its selected managed services' folders exist, and its hostnames and fixed ports are free, probed on their bind host with the holder named; a failed check refuses the switch with nothing stopped and names the check ("fix-nav's devhost.toml line 13 does not parse; nothing was stopped") (`REV-11`, `FAIL-2`). The page that loads finds the outcome in the record by the `operationId` it stored and shows it once, as an outcome notice whose sentence takes focus: "Switched acme from main ~/acme to fix-nav ~/acme/.worktrees/fix-nav: restarted 6 services · 6 of 6 running · 14 s" (`FB-2`, `FB-3`, `KEY-6`, `WORD-4`, `WORD-5`, `WORD-11`), announced once in the polite region (`FB-9`). The trigger names "fix-nav ~/acme/.worktrees/fix-nav" (`SURF-15`, `SEL-4`). The count is of the whole stack, the services the run left out included (`ACT-6`): in a run started with names the outcome reads "3 of 6 running · worker, admin and mail not started", and a selected name the target's manifest does not define is named, "not in fix-nav: search", while the rest of the selection starts (`SEL-5`). Its previous worktree, "main ~/acme", is a link that opens **Worktrees** with main highlighted, so the way back is one switch away (`UNDO-5`). Chat keeps its agent, model, edit mode, open state, side and draft across the switch, because they belong to the stack and page origin, not the worktree (`SEL-11`, `CC-9`).
   - When the page the switch reloaded is answered with a 5xx by a target service whose health check passed, the outcome says so instead of a plain success, "Switched acme to fix-nav ~/acme/.worktrees/fix-nav: 6 of 6 running · web answered 500 for this page", and the app's answer shows with devhost's notice (`SURF-16`, `FB-5`); when web's last output names a missing dependency, that notice leads with `MENU-5`'s needs-setup action: "web in fix-nav could not resolve "react"" with the command to run there, `bun install`, to copy, then **Restart** (`O32`, `FAIL-3`).
   - The terminal prints one line when the switch starts and one outcome line, naming both worktrees by label: "Switching acme from main ~/acme to fix-nav ~/acme/.worktrees/fix-nav · restarting 6 services", then "Switched acme from main ~/acme to fix-nav ~/acme/.worktrees/fix-nav: restarted 6 services · 6 of 6 running · 14 s", and no "exited … waiting for a restart" line for any service the switch stopped (`FB-10`, `FAIL-5`, `WORD-4`, `SEL-4`, `WORD-11`). Agent output (`AGENT=1`) carries the same facts with absolute paths, a failure on one `devhost: ERR:` line (`FB-11`, `WORD-9`), and `devhost stack info` (short alias `devhost status`, `O62`) reports the switch as the stack's last operation (`FB-11`, `ACT-1`, `O62`).

6. **Recover from a failed switch, in place (one write per retry).** When a target service cannot start, devhost stops the target's services and starts the previous worktree's again service by service, with its routes and hot reload; the saved selection never left main, because a switch saves its target only once it succeeds, and the pending-switch record is removed (Backend 13); while it restores, the busy control and the touched rows read "Returning to main ~/acme" (`UNDO-1`, `ACT-3`). The panel stays open and its outcome replaces the progress, taking focus on its sentence: "Switch to fix-nav failed: web exited with code 1 before its health check. Returned to main ~/acme: 6 of 6 running · 21 s", with web's evidence from the attempt, its exit code with the time, its last output lines frozen at the exit, the probe it failed and what devhost ran ("Ran bun run dev in web/ · fix-nav's devhost.toml line 9") (`FAIL-1`, `FAIL-2`, `FAIL-3`, `FB-2`, `FB-9`). The page does not reload. It leads with `MENU-5`'s action for the cause: for a fresh worktree whose service cannot find its dependencies, "web in fix-nav could not resolve "react"; run bun install in ~/acme/.worktrees/fix-nav" with the command to copy, then **Retry Switch** (`O32`); otherwise **Retry Switch**, which runs on one press, its accessible name and reach line naming the target, "Retry Switch to fix-nav ~/acme/.worktrees/fix-nav" (`REV-1`, `REV-2`, `WORD-2`). A restore that cannot bring a service back leaves it failed with its own recovery page while the rest run, "Returned to main ~/acme: 5 of 6 running · api still fails"; the set is never stopped as one unit because one member fails (`UNDO-1`, `FAIL-1`). The failure stays in the panel and as a notice until the person dismisses it or a later switch to that worktree succeeds; reconnects and page reloads never remove it (`FB-6`). The terminal prints "Switch to fix-nav ~/acme/.worktrees/fix-nav failed: web exited with code 1 before its health check. Returned to main ~/acme: 6 of 6 running · 21 s" (`FB-10`, `FAIL-1`).
7. **Recover a deleted worktree (`GET /__devhost__/worktrees` for Check Again, read only; Return to Configured Worktree, one write after a second step).** When the next read of the worktree list finds the running worktree's folder gone or unregistered, devhost stops nothing: it publishes the repository as blocked with one sentence, "The worktree ~/acme/.worktrees/fix-nav was deleted; its services still run from it", processes that still run keep running from the deleted folder until the recovery the person chooses restarts the repository or they exit, and devhost starts none of its services until then (`HOLD-4`, `O43`, `ACT-2`, `WORD-11`).
