Low-fidelity wireframe. Layout, names and numbers are illustrative; the redesign ticket's acceptance criteria are authoritative.

1. Open chat

Chat on the bar and pointing at an element or finishing a drawing (page-context's entry points) still open docked chat, which stays a non-modal region labelled "Chat" and stays open when focus leaves it; Alt+Ctrl+C is one more way to open it from the page. What changes is where it sits, what its header says and that opening it starts no agent CLI. Keys: Alt+Ctrl+C or Chat opens chat with focus in the composer, or focuses the composer while chat is docked; Escape there returns focus to the element that had it; Alt+Ctrl+B's cycle reaches the composer; Move Chat Panel moves with the arrow keys and Home returns it; hints read ⌃⌥C on macOS and Ctrl+Alt+C elsewhere, from the binding's one definition (KEY-2, KEY-3, KEY-6, KEY-8, KEY-12, KEY-13).

  1. 1 Chat opens compact at the toolbar's edge beside the notice stack, never over it: no devhost surface covers a notice, the dock and chat shift inward past the minimap strip and the pinned log panel (step 4), and an open toolbar panel, the running agents list included, paints above chat (SURF-1, SURF-5, CC-1).
  2. 2 The header names the conversation the composer writes to by its title, the first line of its first message, with its agent and state word, or "New conversation" before the first Send; then the conversation list control (step 8), New Conversation as a text button, never a second + icon, Expand Chat, Move Chat Panel and Close, which hides the panel and stops nothing (SEL-8, WORD-1, WORD-2, WORD-6).
  3. 3 A stack with no conversation yet says so and how to start one. Opening reads the agent catalog devhost discovered for this stack and starts no agent CLI by itself: discovery runs once, when chat first opens for the stack, and again only on Refresh Agents (step 2), and the catalog answers only the stack's own pages (STATE-2).
  4. 4 Compact chat shows the latest message and its reply; Expand Chat shows the whole conversation. In every state (compact, expanded, dragged, after a resize) and at 1600×1000, 1280×800 and 900×900 in the light and the dark theme, the header, the composer row with Send and the mode control, and a pending card stay inside the viewport: a moved or expanded panel sizes itself to the room between its top and the window's bottom edge, or moves up until the composer fits; only the transcript scrolls, and a dragged panel never covers the bar's row (SURF-6, SURF-9).
  5. 5 At 1280×800 under 200% zoom (640×400 CSS pixels), and in any window below 900 px wide, chat takes the window's width less 16 px on each side and keeps the order header, conversation, card, composer (O8). Whether chat was open, its side, the conversation, the agent, the model and the unsent text come back per stack and page origin, never per checkout; its dragged position is saved per manifest on the control server through toolbar-shell's layout route, never in browser storage (SEL-11, CC-9, SURF-7, CC-5).

2. Name the recipient, the mode and the context before Send

The proposal's steps 2 to 4, read together in the composer row before Send, all read only. Writing, pasting images and picking marks still work as today; what changes is that the row names who answers, how and where before anything leaves the page. Keys: the chip and the mode control are Tab stops in the composer row; Enter or Space opens either with focus in its first field; ArrowUp and ArrowDown move the highlighted option, Enter picks it and Escape closes the list, then the popover, with focus back on the control; keys typed into the composer never reach the page's listeners, and holding Alt alone starts Select Elements only from the first pointer move or after a 300 ms hold (KEY-10, KEY-8, KEY-6, KEY-5, KEY-2, O34, CC-28).

  1. 1 The agent and model chip, a button whose accessible name is its text, opens Chat Settings as a popover anchored to it, dismissed by a click outside or Escape. Agent and Model are comboboxes whose options carry the catalog's description of each model; the first model option names what it resolves to ("Configured default (Sonnet 4.5)", else "Configured default: set in your Claude Code configuration"); an agent that is not installed stays listed, disabled, with its reason as text and accessible description; Refresh Agents discovers again. Default: the agent and model last chosen on this stack; on a first visit Codex when installed, else the first installed agent (SEL-8, SURF-2, MENU-3, SEL-11).
  2. 2 The recipient line above the composer names where the message goes, or that Send starts a new conversation (SEL-8).
  3. 3 The mode control shows the edit mode and the checkout it edits, by its checkout label. It is a select-only combobox with three options in the owner's words, each with its effect as visible text and accessible description. Default: This checkout (live) when the message carries page context, else the conversation's last mode, and This checkout (live) for a conversation's first message (O1, O3, SEL-4, SEL-8, WORD-10).
  4. 4 Under the row: the approval line, read from the agent CLI's own configuration, since devhost passes no approval policy; "Added by devhost", collapsed, holding the mode's own instructions and then the team's [devtools.chat].prompt, so nothing is appended out of sight; and, when the chosen mode differs from the previous message's, one line naming the earlier mode and worktree (REV-6, O13, O35, O20, CC-10).
  5. 5 Attach Image and pasting add PNG and JPEG images as uncropped thumbnails with name and size, removable from the keyboard, and the message counts against its 8 MiB limit as it grows; an image that would pass the limit is refused when pasted, with one sentence naming it (WORD-5, WORD-8, FAIL-2).
  6. 6 Page context sits under the composer item by item: each mark's number, element and source file, and a mark whose element left the page flagged with Select Again and Remove; page-context owns the list. Page context tells the agent the page's URL, service and checkout; after a pick or a drawing, focus returns to the composer. The text stays in browser storage, and images and page context in the control server's draft record, so a reload devhost causes keeps them (SEL-9, SURF-12, SEL-3, KEY-12, UNDO-2, CC-19).
  7. 7 An open conversation's agent is fixed: choosing another agent never moves the next message silently, and the earlier conversation keeps running. A configuration that never asks shows in the warning style; one devhost cannot read says so (SEL-8, REV-6, O13).

3. Send

Enter or Send still sends, and the message still goes into the page's own checkout, as today. What changes is that it shows at once with its delivery state, records how it was sent, and asks only in two cases. Keys: Enter sends, Shift+Enter inserts a line break, and Enter during input-method composition never sends; in a question, focus and Enter start on the choice that changes nothing, and Escape cancels with focus back in the composer (KEY-9, REV-4, KEY-8).

  1. 1 The message appears in the conversation at once as the person's, with "Not sent yet" until the server acknowledges it. Focus stays in the composer; the draft stays until the acknowledgement, then clears, and its images and page context leave the draft record with it (STATE-1, UNDO-2).
  2. 2 Under the message, the mode line with the checkout it edited, "Added by devhost" collapsed and the page context it carried, collapsed. devhost writes these as records of its own into the session's journal, so every page and every reload shows them. A new conversation starts with the chosen agent and model in the page's checkout; the browser never names a directory, and the conversation's title is the first line of this message (UNDO-8, WORD-10, CC-40, SEL-8, CC-38).
  3. 3 A second agent: a message in This checkout (live) that would start this conversation's agent where an agent chat did not start works or waits asks in place above the composer, with Cancel in the pressed control's place, focused and taking Enter, and Start Second Agent beside it; nothing shows as working while it asks. It asks when the conversation's agent would start, never again for follow-ups while that agent works. In the other two modes the recipient line names that agent instead ("Claude Code, started outside chat, also works in this checkout") and Send sends (REV-3, REV-4, REV-6, CC-14).
  4. 4 Cancel and Escape keep the draft in the composer and leave the neutral line "Not sent", never an error; the next Send asks again while that agent works (UNDO-4, WORD-7).
  5. 5 A gone mark: a draft citing a mark whose element left the page asks with Select Again focused and Send Anyway (REV-6, SEL-9).
  6. 6 A send without an acknowledgement after 45 s reads Delivery unconfirmed and is never resent, by the owner's rule; a repeated command ID returns its first result (FB-5, REV-12).

4. Follow the turn

The reply still streams into the conversation, and a follow-up is still accepted while the agent works without interrupting or approving anything, as today. What changes is that the turn's progress, every follow-up and every line the agent or its CLI adds say what they are. Keys: Enter sends a follow-up into the running turn; Alt+Ctrl+. stops the turn from the composer and docked chat (step 7) (KEY-9, REV-6).

  1. 1 The reply streams into the transcript, which is aria-busy while it streams and never a live region; tool calls show as one line each in plain words (FB-9, WORD-4).
  2. 2 A status line above the composer names the turn's progress, adding "1 message not yet read" while follow-ups wait for the agent, with Stop Turn in a place of its own that Send never takes (FB-1, WORD-5, KEY-11, WORD-2).
  3. 3 Chat on the bar shows a working agent with its spinner, accessible name "Chat: Claude Code working" (SURF-8).
  4. 4 Beside Send, a follow-up says it joins the running turn. Sent, it appears at once as the person's message: "Not sent yet" with Take Back, which puts it back into the composer, while it waits on this page for an earlier send's acknowledgement; then "Sent into the running turn" once the agent's CLI has it, after which only Stop Turn cancels it, with the turn (REV-6, STATE-1, UNDO-4).
  5. 5 A turn the agent starts by itself reads "The agent continued on its own", and compact chat keeps the reply to the person's message in view with a line for the extra reply; text the CLI adds shows as one collapsed line, never as a message the person sent (WORD-10).
  6. 6 The stack's terminal and log print one line when a conversation starts or ends, one when its agent starts waiting, and one per turn outcome, never the delivery steps, model changes, usage or IDs; the pinned log panel, which log-minimap owns, shows them under devhost's own source, and sits outside docked chat in the edge order minimap strip, log panel, then the dock and chat (FB-10, FB-7, WORD-9, SURF-13, SURF-5, CC-40).
  7. 7 devhost starts every chat agent with AGENT=1 and DEVHOST_CHAT_SESSION, so a devhost command the agent runs gets agent output and its outcome is reported as the agent's; the agent restarts services with devhost service and reads outcomes with devhost status, which stack-run-stop builds (REV-8, FB-11, ACT-1, MENU-6, SEL-7).

5. Answer the agent

devhost still relays every approval and question and never answers or pre-approves one, and an answered or cancelled request still cannot be answered again, as today. What changes is that the request shows what will change with every answer in view, the wait shows wherever the person looks, and each answer leaves a line. Keys: the card is one Tab stop: Tab or Shift+Tab into it, from the composer included, focuses its question; ArrowUp and ArrowDown move between Details, the note, Deny, Allow Once and Stop Turn, and in the note ArrowLeft and ArrowRight move the caret; Tab leaves the card. Enter in the note denies with it, Shift+Enter inserts a line break, and Escape in the note returns to the question with nothing answered; no other key answers (REV-9, KEY-8, KEY-9, KEY-10).

  1. 1 A decision card is pinned between the conversation and the composer, outside any scroll area, so every answer is visible without scrolling in compact chat at every acceptance viewport. It leads with a plain question naming the tool and its target, then the checkout-relative path and a unified diff in a region of capped height that scrolls on its own. Several pending requests show their count and are answered in arrival order (SURF-6, REV-9).
  2. 2 The note, "Note for Claude Code (optional)": Deny sends it with the denial. Claude Code receives it as the denial's message; Codex receives the decline, then the note as a message into the running turn, shown as the person's message without devhost's instructions; an empty note denies with no message, and devhost no longer sends "Denied by the user." (REV-9, CC-16).
  3. 3 Deny, Allow Once and Stop Turn, with the native request under Details. No answer is a default: an arriving card never takes focus from a field being typed in, and is announced once, "Claude Code waits for you: Edit src/header.tsx?". There is no "don't ask again"; standing approvals stay in the agent CLI's own configuration (KEY-6, FB-9, O12).
  4. 4 While a card waits, the status line says that the card's Stop Turn ends the turn in place of its own, so there is one, and Alt+Ctrl+. stops nothing (KEY-9).
  5. 5 Waiting is a condition: Chat takes the waiting look ◆, a shape distinct from the working spinner ◐ in both themes and in forced colors, with the accessible name "Chat: Claude Code waiting for you"; the running agents trigger and Watch Live Activity show the same wait (ACT-7, ACT-13, SURF-8).
  6. 6 The notice stack shows the wait with Answer, which opens docked chat with focus on the card's question in one activation. The condition clears when the request is answered, cancelled or its turn ends, from any tab, and its clearing is announced once (FB-8, REV-9, ACT-7, FB-9).
  7. 7 A command request shows the exact command, its working directory relative to the checkout and the agent's stated reason; a question shows its options and Submit Answers the same way (REV-9).
  8. 8 Each answer leaves a line where it was given, recorded in the session's journal and shown after every reload; a denied call reads "Denied" in the neutral style, never with the success check. An answer from a second tab to a request already answered is refused with the current state, "Already answered in another tab: You allowed once: Run bun test · 13:24" (REV-9, UNDO-8, WORD-7, REV-13, CC-40).
  9. 9 Collapsed, the toolbar keeps the waiting notice in its one-line form beside the badge, whose look follows the attention order (SURF-8, ACT-7).
  10. 10 While the page shows a modal dialog, native or scripted, chat moves into it with the notice stack and keeps working, card included (SURF-11).
  11. 11 An exit while chat holds a draft, a card or a working agent opens the crash view minimized, as its notice, which startup-and-recovery owns; while the crash view is open, chat and the notice stack stay operable inside its Tab cycle. While the Configuration window is open, chat is inert, and an agent that starts waiting is announced from inside the window and named in its header (SURF-3, SURF-4, KEY-7).

6. Read the receipt

The agent still edits through its own tools, and devhost still runs no Git command for chat and never commits, stashes or reverts for the agent, as today. What changes is that the turn ends with a receipt that says what changed, where, and the way back; there is no Undo of devhost's own for an agent's edits, which is the way back the outcome names (UNDO-5). Keys: the receipt's actions are ordinary Tab stops after the reply (KEY-10).

  1. 1 Under the reply to the person's latest message, the receipt lists the files the agent changed, built from the edit events in the session's journal with no Git command; in This checkout (live) the edits stay uncommitted, and the page's own dev server shows them through its reloads (UNDO-5, O19, O22).

8. Manage conversations

A person still starts, switches between, closes and resumes conversations, and closing still ends the agent's process and drops its pending requests, as today. What changes is that conversations are named and listed across every checkout of the stack, a close keeps the transcript, and nothing that still runs or remembers disappears. Keys: the list puts its filter first, then each row's actions as Tab stops in row order, each named with its target ("Resume Footer links"); Escape, a click outside, Tab past its last control or picking a conversation closes the list and returns focus to its control in the header, or, when it was opened with the pointer, to the element that had focus before (KEY-10, KEY-5, KEY-6, KEY-7, KEY-8).

  1. 1 The conversation list opens from the header as a popover anchored to its control. It lists every conversation of the stack, this page's checkout first, then by last activity, each row naming its title, agent and model, checkout label, start time and state word with a cause where it has one; the conversation ID sits behind Copy ID (SURF-2, MENU-1, SEL-8, SEL-4, WORD-6).
  2. 2 New Conversation heads the list. Once the rows overflow, a filter appears, focused on open, matching title, agent and checkout as the person types (SEL-10, SURF-10, WORD-2).
  3. 3 Each row's actions follow its name: Close Conversation on an open one, Resume on a closed one, which continues the same conversation with its history and title in its own checkout. Conversations a stack stop ended stay listed as closed with their cause and Resume when the stack starts again, from the record devhost keeps after a stop (UNDO-4, O23, CC-38).
  4. 4 Close Conversation never asks: it ends the agent's process and turn, keeps the transcript, read-only, and leaves a line. A close that fails says so in words where it was pressed, with Copy Error holding the server's text and Close Conversation still available, never a raw response body (REV-1, REV-3, FAIL-2).
  5. 5 A conversation of another checkout, after a switch or picked from the list, shows its transcript, its cards and Stop Turn, and takes no message from this page: in place of Send the composer names both checkouts and offers New Conversation, which starts one in this page's checkout and keeps the draft; devhost never moves a conversation to another checkout. When the stack runs again, the page says "Connected again" once and lists the ended conversations with Resume (HOLD-1, HOLD-2, ACT-10, ACT-5).
  7. 7 When the chat socket drops, Send, every answer and Stop Turn are unavailable with one reason and Retry Now; sends in flight settle as Delivery unconfirmed; reconnecting replays the history and any pending request.
