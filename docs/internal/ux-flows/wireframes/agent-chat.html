1. Open chat

Chat on the bar and pointing at an element or finishing a drawing (page-context's entry points) still open docked chat, which stays a non-modal region labelled "Chat" and stays open when focus leaves it; Alt+Ctrl+C is one more way to open it from the page. What changes is where it sits, what its header says, its 320 px phone layout, and that opening it starts no agent CLI. Keys: Alt+Ctrl+C or Chat opens chat with focus in the composer, or focuses the composer while chat is docked; Escape there returns focus to the element that had it; Alt+Ctrl+B's cycle reaches the composer; Move Chat Panel moves with the arrow keys and Home returns it; bindings can be overridden per person in ~/.config/devhost/config.toml (O17, CC-39), and hints read ⌃⌥C on macOS and Ctrl+Alt+C elsewhere from the one binding definition (KEY-2, KEY-3, KEY-6, KEY-8, KEY-12, KEY-13).

  1. 1 Chat opens at the toolbar's edge beside the notice stack, never over it, compact on a first visit and afterwards compact or expanded as the person left it (O64): no devhost surface covers a notice, the dock and chat shift inward past the minimap strip and the pinned log panel (step 4), and an open toolbar panel, the running agents list included, paints above chat (SURF-1, SURF-5, CC-1).
  2. 2 The header names only the agent (O64): Move Chat Panel carries the agent's logo (✳) while it is idle, the working spinner (◐) while it works and the waiting shape (◆) while it waits for you, then the agent's display name, or "Agent Chat" before the first conversation; the state word stays in a visually hidden status, spelled out only after an error or while reconnecting ("Claude Code · reconnecting"); then the conversation list control (step 8), Expand Chat and Close, which hides the panel and stops nothing. The waiting shape and the display name are this design's additions to the shipped agent-only header. The conversation's title shows in the recipient line above the composer and in the list. The composer row keeps main's shipped icon buttons beside Send: Close Conversation (␡, once a conversation is open), New Conversation (✎, distinct from Attach Image) and page-context's Share Tab (⧉), each named by its tooltip (O64, SEL-8, WORD-1, WORD-2, WORD-6, ACT-13).
  3. 3 A stack with no conversation yet says so and how to start one. Opening reads the agent catalog devhost discovered for this stack and starts no agent CLI by itself: discovery runs once, when chat first opens for the stack, and again only on Refresh Agents (step 2), and the catalog answers only this machine or authenticated remote browsers on the stack's own pages (STATE-2, O36).
  4. 4 Compact chat shows the latest message and its reply; Expand Chat shows the whole conversation. In every state (compact, expanded, dragged, after a resize) and at 1600×1000, 1280×800 and 900×900 in the light and the dark theme, the header, the composer row with Send and the mode control, and a pending card stay inside the viewport: a moved or expanded panel sizes itself to the room between its top and the window's bottom edge, or moves up until the composer fits; only the transcript scrolls, and a dragged panel never covers the bar's row (SURF-6, SURF-9).
  5. 5 At 1280×800 under 200% zoom (640×400 CSS pixels), and in any window below 900 px wide, chat takes the window's width less 16 px on each side and keeps the order header, conversation, card, composer (O8). Below 900 px docked chat and the pinned log panel never sit side by side: when the log panel opens later, chat folds to Chat, which keeps showing the turn's state, and returns as it was, draft and scroll kept, when the panel closes; folding never closes chat (SURF-5, KEY-6). Whether chat was open, whether it was expanded (O64), its side, the conversation, the agent, the model and the unsent text come back per stack and page origin, never per worktree; its dragged position is saved per manifest on the control server through toolbar-shell's layout route, never in browser storage (SEL-11, CC-9, SURF-7, CC-5, WORD-11).
  6. 6 At the 320 CSS px phone layout (O8), docked chat, pinned decision cards (including standing approval) and notices stack cleanly with zero horizontal overflow and >=24×24 CSS px tap targets so an authenticated phone (O36) can ask for a change, answer approvals and see the change.

2. Name the recipient, the mode and the context before Send

The proposal's steps 2 to 4, read together in the composer row before Send, all read only. Writing, pasting images and picking marks still work as today; what changes is that the row names who answers, how and where before anything leaves the page. Keys: the chip and the mode control are Tab stops in the composer row; Enter or Space opens either with focus in its first field; ArrowUp and ArrowDown move the highlighted option, Enter picks it and Escape closes the list, then the popover, with focus back on the control; keys typed into the composer never reach the page's listeners, and holding Alt alone starts Select Elements only from the first pointer move or after a calibrated 400 ms hold (KEY-10, KEY-8, KEY-6, KEY-5, KEY-2, O34, CC-28).

  1. 1 The agent and model chip, a button whose accessible name is its text, opens Chat Settings as a popover anchored to it, dismissed by a click outside or Escape. Agent and Model are comboboxes whose options carry the catalog's description of each model; the first model option names what it resolves to ("Configured default (Sonnet 4.5)", else "Configured default: set in your Claude Code configuration"); an agent that is not installed stays listed, disabled, naming devbox's PATH (O61) as text and accessible description; Refresh Agents discovers again. Default: the agent and model last chosen on this stack; on a first visit Codex when installed, else the first installed agent (SEL-8, SURF-2, MENU-3, SEL-11, O61).
  2. 2 The recipient line above the composer names where the message goes, or that Send starts a new conversation (SEL-8).
  3. 3 The mode control shows the edit mode and the worktree it edits, by its worktree label. It is a select-only combobox with two options only — This worktree (live) and Make tickets — each with its effect as visible text and accessible description. Default: This worktree (live) when the message carries page context, else the conversation's last mode, and This worktree (live) for a conversation's first message (O1, O3, SEL-4, SEL-8, WORD-10, WORD-11).
  4. 4 Under the row: the approval line, read from the agent CLI's own configuration, since devhost passes no approval policy; "Added by devhost", collapsed by default and shown expanded here, holding the team's [devtools.chat].prompt first and then the chosen mode's instructions (live or tickets), which decide edit behavior whatever the guidance above says, so nothing is appended out of sight; and, when the chosen mode differs from the previous message's, one line naming the earlier mode (REV-6, O13, O35, O20, CC-10).
  5. 5 Attach Image and pasting add PNG and JPEG images as uncropped thumbnails with name and size, removable from the keyboard, and the message counts against its 8 MiB limit as it grows; an image that would pass the limit is refused when pasted, with one sentence naming it (WORD-5, WORD-8, FAIL-2).
  6. 6 Page context sits under the composer item by item: each mark's number, element and source file, and a mark whose element left the page flagged with Select Again and Remove; page-context owns the list. Page context tells the agent the page's URL, service and worktree; after a pick or a drawing, focus returns to the composer. The text stays in browser storage, and images and page context in the control server's draft record (migrated to the new origin on listeners-moving port changes), so a reload devhost causes keeps them (SEL-9, SURF-12, SEL-3, KEY-12, UNDO-2, CC-19, WORD-11).
  7. 7 An open conversation's agent is fixed: choosing another agent never moves the next message silently, and the earlier conversation keeps running. A configuration that never asks shows in the warning style; one devhost cannot read says so (SEL-8, REV-6, O13).

3. Send

Enter or Send still sends, and the message still goes into the page's own worktree, as today. What changes is that it shows at once with its delivery state, records how it was sent, and asks only in two cases. Keys: Enter sends, Shift+Enter inserts a line break, and Enter during input-method composition never sends; in a question, focus and Enter start on the choice that changes nothing, and Escape cancels with focus back in the composer (KEY-9, REV-4, KEY-8).

  1. 1 The message appears in the conversation at once as the person's, with "Not sent yet" until the server acknowledges it. Focus stays in the composer; the draft stays until the acknowledgement, then clears, and its images and page context leave the draft record with it (STATE-1, UNDO-2).
  2. 2 Under the message, the mode line with the worktree it edited, "Added by devhost" collapsed and the page context it carried, collapsed. devhost writes these as record frames of its own into the session's journal, so every page and every reload shows them. A new conversation starts with the chosen agent and model in the page's worktree; the browser never names a directory, and the conversation's title is the first line of this message (UNDO-8, WORD-10, WORD-11, CC-40, SEL-8, CC-38).
  3. 3 A second agent: a message in This worktree (live) that would start this conversation's agent where an agent chat did not start works or waits asks in place above the composer, with Cancel in the pressed control's place, focused and taking Enter, and Start Second Agent beside it; nothing shows as working while it asks. It asks when the conversation's agent would start, never again for follow-ups while that agent works. While devhost's agent scan is incomplete it asks too, naming the agents it could not check: "Start a second agent in fix-nav ~/acme/.worktrees/fix-nav? Codex agents could not be checked there, so one may be working, and both would edit the same files." In Make tickets the recipient line names that agent instead ("Claude Code, started outside chat, also works in this worktree") and Send sends (REV-3, REV-4, REV-6, CC-14, O1).
  4. 4 Cancel and Escape keep the draft in the composer and leave the neutral line "Not sent", never an error; the next Send asks again while that agent works (UNDO-4, WORD-7).
  5. 5 A cited mark that no longer exists: a draft citing a mark whose element left the page asks "Send with #2 missing? Its element is no longer on this page.", and one citing a mark the person removed asks page-context's "Send with #1 missing? It is not in page context."; each has Select Again focused, which picks the mark again under the same number, and Send Anyway (REV-6, SEL-9).
  6. 6 A send without an acknowledgement after 45 s reads Delivery unconfirmed and is never resent, by the owner's rule; a repeated command ID returns its first result (FB-5, REV-12).

4. Follow the turn

The reply still streams into the conversation, and a follow-up is still accepted while the agent works without interrupting or approving anything, as today. What changes is that the turn's progress, every follow-up and every line the agent or its CLI adds say what they are. Keys: Enter sends a follow-up into the running turn; Alt+Ctrl+. stops the turn from the composer and docked chat (step 7) (KEY-9, REV-6).

  1. 1 The reply streams into the transcript, which is aria-busy while it streams and never a live region; tool calls show as one line each in plain words (FB-9, WORD-4).
  2. 2 A status line above the composer names the turn's progress, adding "1 message not yet read" while follow-ups wait for the agent, with Stop Turn in a place of its own that Send never takes (FB-1, WORD-5, KEY-11, WORD-2).
  3. 3 Chat on the bar shows a working agent with its spinner, accessible name "Chat: Claude Code working" (SURF-8).
  4. 4 Beside Send, a follow-up says it joins the running turn. Sent, it appears at once as the person's message: "Not sent yet" with Take Back, which puts it back into the composer, while it waits on this page for an earlier send's acknowledgement; then "Sent into the running turn" once the agent's CLI has it, after which only Stop Turn cancels it, with the turn (REV-6, STATE-1, UNDO-4).
  5. 5 A turn the agent starts by itself reads "The agent continued on its own", and compact chat keeps the reply to the person's message in view with a line for the extra reply; text the CLI adds shows as one collapsed line, never as a message the person sent (WORD-10).
  6. 6 The stack's terminal and log print one line when a conversation starts or ends, one when its agent starts waiting, and one per turn outcome (naming agent, model and worktree label or CLI title, never message text), never the delivery steps, model changes, usage or IDs; the pinned log panel, which log-minimap owns, shows them under devhost's own source, and sits outside docked chat in the edge order minimap strip, log panel, then the dock and chat (FB-10, FB-7, WORD-9, SURF-13, SURF-5, CC-40).
  7. 7 devhost starts every chat agent with AGENT=1 and DEVHOST_CHAT_SESSION, so a devhost command the agent runs gets agent output and its outcome is reported as the agent's; when asked, an agent inspects the stack with devhost stack info / devhost status (O62) and restarts services with devhost service, which stack-run-stop builds, never through browser routes (REV-8, FB-11, ACT-1, MENU-6, SEL-7, O58).

5. Answer the agent

devhost still relays every approval and question and never answers or pre-approves one itself, and an answered or cancelled request still cannot be answered again, as today. What changes is that the request shows what will change with every answer (including the agent CLI's own standing approval when offered) in view, the wait shows wherever the person looks (the app tab title included, O16), and each answer leaves a line. Keys: the card is one Tab stop: Tab or Shift+Tab into it, from the composer included, focuses its question; ArrowUp and ArrowDown move between Details, the note, Deny, Allow Once, Allow for This Session (when offered) and Stop Turn, and in the note ArrowLeft and ArrowRight move the caret; Tab leaves the card. Enter in the note denies with it, Shift+Enter inserts a line break, and Escape in the note returns to the question with nothing answered; no other key answers or approves a standing approval (REV-9, O12, KEY-8, KEY-9, KEY-10).

  1. 1 A decision card is pinned between the conversation and the composer, outside any scroll area, so every answer is visible without scrolling in compact chat at every acceptance viewport and at the 320 px phone layout. Several pending requests show their count and are answered in arrival order (SURF-6, REV-9, O8).
  2. 2 The note, "Note for Claude Code (optional)": Deny sends it with the denial. Claude Code receives it as the denial's message; Codex receives the decline, then the note as a message into the running turn, shown as the person's message without devhost's instructions; an empty note denies with no message, and devhost no longer sends "Denied by the user." (REV-9, CC-16).
  3. 3 Deny, Allow Once, the agent CLI's own standing approval when the CLI offers one (Allow for This Session — session-only, granted by the person, never persisted across restart, O12), and Stop Turn, with the native request under Details. No answer is a default: an arriving card never takes focus from a field being typed in, and is announced once, "Claude Code is waiting for you: Edit src/header.tsx?" (KEY-6, FB-9, O12, CC-16).
  4. 4 While a card waits, the status line says that the card's Stop Turn ends the turn in place of its own, so there is one, and Alt+Ctrl+. stops nothing (KEY-9).
  5. 5 Waiting is a condition: Chat takes the waiting look ◆, a shape distinct from the working spinner ◐ in both themes and in forced colors, with the accessible name "Chat: Claude Code waiting for you"; the app page's tab title prefixes "(1) waiting · Acme Shop" (restored when cleared, O16); and the running agents trigger, stack directory deep link (GET /__devhost__/chat/open?session=<id>) and Watch Live Activity show the same wait (ACT-6, ACT-7, ACT-13, SURF-8, O16).

The condition clears when the request is answered, cancelled or its turn ends, from any tab, and its clearing is announced once (FB-8, REV-9, ACT-7, FB-9).
