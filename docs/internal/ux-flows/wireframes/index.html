Work with a coding agent

Chat with a coding agent

Before Send the composer names who answers, which of the two edit modes applies (This worktree (live) or Make tickets) and which worktree it edits; a card pinned above the composer keeps every answer (including the CLI's own standing approval) in view on desktop and 320 px phone screens while Chat, notices and the app tab title show the wait; each turn ends with a receipt of changed files, reload or restart hand-off, and way back; conversations are named, listed across worktrees and resumable; and remote browsers authenticate with one shared WebAuthn passkey (phone support included) or a one-time devhost pair fallback.

Keep services healthy

Switch the stack to another worktree

Worktrees becomes one shared worktree list, found by branch, path or commit, whose Switch and Restart Stack names everything it restarts and leaves behind, switches managed services freely beside external services with no warning (O7), asks only when other work is at stake, shows its steps in place and its outcome on the reloaded page, rolls back service by service, and turns a deleted worktree into an explicit choice instead of a restart that cannot work.

Startup pages, crash recovery and app error pages

Every state of a service gets one devhost page, or the crash view over the app, led by the action that can fix its cause and showing the evidence that explains it; an app's own 404 or 5xx passes through with a devhost notice instead of being replaced; and every restart shows its progress and its outcome where it started, never closing without a word.

Watch and restart services from the toolbar

Every service of the stack is counted and listed with its state, cause and route; each restart or start shows its steps and its outcome on the row that started it, with focus kept there; command-mode serve sessions model their command first-class with Restart Command; narrow popovers wrap cleanly clear of the minimap with >=3:1 button borders; and Restart Stack sits apart from Restart Changed and asks first, in place.

How devhost reports operations and problems

Every operation reports the same way, from one record: its progress where it started or as one activity line, then one outcome in that place that names what changed; successes close after calibrated reading time (pausing when arriving unfocused), failures stay until handled, conditions share one ordered notice stack beside the bar (with a 320 px phone layout and app tab-title prefixes), and a lost connection or closed command-mode port says why without painting healthy services as down.

Edit configuration in the browser

Set up and run stacks

Start, find, stop and restart stacks from the terminal

The terminal says when a stack is ready (keeping local URLs alongside remote previews), devhost stack info and devhost status report every service and rejection, parallel shutdown certifies that nothing remains within 30 s by default, devhost upgrade handles self-managed updates while restart and stack restart replace supervisors, and multi-stack commands print their set first and ask only when an agent's turn would end.

Change the shared proxy settings

The terminal says where the shared Caddy settings live and who can reach the stacks; a save states its reach before it is written, is checked and certified before it counts, and reports one outcome per stack, while open pages follow their stack to the new address with Open, relay previews keep answering on any port, and a refused change names its line and what keeps running.

Serve a folder, port or command

Covers all three devhost serve modes — folder (--dir), running port (--port), and command mode (devhost serve -- <command>, foreground or --detach) — plus manifest serve services. The terminal states what is served, where Caddy listens (honoring macOS bindHost from port 1024 upward), that chat is on by default for folder and command sessions with --no-chat to turn it off (and always off for --port), when it is ready, and how to stop it; command sessions appear first-class (1/1 with working Restart Command), handle multi-port changes without false 0/3 outages, exit with the command's exit code in the foreground, and keep valid HTTPS crash recovery when detached; served folders show the listing first with README below; and mistyped names stay in the file browser.
