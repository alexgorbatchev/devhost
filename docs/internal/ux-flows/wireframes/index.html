Proposed UX flow wireframes

One low-fidelity page per proposed flow. Each page walks the proposal step by step, with numbered callouts and the findings each step resolves. The redesign tickets and their acceptance criteria are authoritative; layout, names and numbers here are illustrative.

Shared patterns

Shared UX pattern reference (full text): the rules, keyboard map, decision log and contract changes every flow follows. A flow that behaves differently names its exception there.

Conflicts to settle before building

  • A conversation's name in log lines. agent-chat names a conversation in terminal and log lines by agent, model and checkout, never by its title, because the title is the first line of a message and log lines never hold message text; log-minimap shows each conversation's lines under "devhost" labelled with its title ("devhost · Fix the nav").
  • Focus after an element pick. agent-chat's proposal returns focus to the composer after every element pick or drawing made with chat's tools; page-context returns it to the composer after a pointer pick only and keeps a selection latched from the keyboard on its toggle until Escape.
  • Page context in the switch question. worktree-switch lists it as "Page context: 2 marks; a mark whose element is gone after the reload is listed as lost" and leaves the tab share out; page-context has the question read page context's own summary, "3 marks · they come back where their elements still exist; the tab share ends".
  • Sending a message that cites a missing mark. agent-chat asks "Send with #2 missing? Its element is no longer on this page.", which fits only a mark whose element left the page; page-context writes "Your message mentions #3, which is no longer on this page.", which also fits a mark the person removed while its element stays.
  • The hot reload notice's words. reload-control, which owns the notice, writes "Vite reloads this page when files change" with "Agent edits can reload it while you work." and the one-line form "Vite reloads this page"; toolbar-shell (also its steps reach the dock, beside the notices and collapsed) and notices-and-feedback draw "web's dev server, Vite, reloads this page when files change".
  • Held reloads in the switch question. worktree-switch writes "Hold Reloads is keeping this page as it is; the switch reloads it", without a count; reload-control has the question name the held count, "2 held reloads on this page are discarded by the reload", and the outcome say they were discarded.
  • Hold Reloads on the bar. toolbar-shell draws it as a toggle, pressed with an inset border and a check mark, or as a plain segment; reload-control makes it a popover trigger, "☑ Hold Reloads ▾" or "☐ Hold Reloads ▾", whose switch sits in the popover and whose state and held count are in its accessible name and marker, "☑ Hold Reloads · ◆ 2 held ▾".
  • Agents devhost could not check. running-agents publishes whether its agent scan is complete and has both questions name the agents it could not check ("Codex agents could not be checked"); agent-chat's second-agent question asks only when a listed agent works or waits, and worktree-switch's reach line says agents were not checked only while chat is off.
  • Which requests come from this machine. running-agents has the remote preview relay mark every request it forwards and counts a marked request as another machine's, because a relayed request reaches the control server from loopback; config-editor, component-source and worktree-switch limit their routes to this machine with the same check without the mark, so a relayed request passes as local.
  • The Worktrees trigger's label. worktree-switch and running-agents draw the branch alone, "main ▾"; the pattern page and most other pages that draw the bar show "main ~/acme ▾", for example services-panel, notices-and-feedback and toolbar-shell.
  • Copy actions on the rejected-manifest notice. With the config editor off, notices-and-feedback and config-editor offer Copy, then Open in Editor; manifest-hot-reload offers Open in Editor, then one Copy Error whose copied text starts with the file's location.
  • Where the "not applied" marker sits while the config editor is off. notices-and-feedback leaves a dismissed notice's marker, "1 not applied", on Config, which is absent while the editor is off, its default; manifest-hot-reload puts it on the stack name then, which toolbar-shell does not draw.
  • When Config shows "not applied". config-editor gives Config its not-applied look, "◆ Config · 1 not applied", while the rejection notice still shows; manifest-hot-reload and notices-and-feedback show the marker only after Dismiss, so the notice and the marker never repeat each other.
  • When an open page follows a port move. notices-and-feedback shows "devhost moved to port …" with Open as soon as the new address is sent, before Caddy moves, and stops retrying the old address; proxy-settings shows an activity line until the new listener answers, shows the notice only then, and goes back to the old address when the move is rolled back.
  • The devhost config file's name and rejection title. config-editor labels the file "Devhost config file", and notices-and-feedback and manifest-hot-reload's proposal title its rejection "Devhost config file not applied: …" without the values that keep running; proxy-settings keeps devhost lowercase, "devhost config file not applied: …", and names the shared Caddy settings that keep running.
  • The line beside Save for a devhost config file. config-editor writes "Saving moves the URLs of 3 stacks: Acme Shop, Docs and Blog"; proxy-settings, which owns what each setting does, writes "Saving moves the URLs of 3 stacks to port 4443: Acme Shop, Docs and Blog" and adds a line for each other setting.
  • A serve session's card in the stack directory. stack-directory, which owns the card, titles it "Serve session · ~/acme/docs" and leaves Configuration out; serve-folder titles it "~/acme/docs" with the kind label "Serve session · folder" beside it and keeps a Configuration line, "None: the serve session for ~/acme/docs reads no devhost.toml".
  • A serve session's name when stacks are replaced. stack-run-stop names it by its hostname in devhost stack replace --all's set and keep-running line ("serve session for docs.acme.test"); serve-folder names it by its folder or port ("Stopped the serve session for ~/acme/docs"), and its proposal prints "serve session ~/acme/docs (PID 48800) · keeps running" for the same set.
  • Chat on the bar while chat is off. serve-folder keeps Chat on the bar, unavailable with its reason and the way to turn chat on; agent-chat, with chat turned off in the manifest, keeps Chat on the bar only while a conversation still runs.
  • The stack directory's label in the terminal. stack-run-stop, stack-directory and proxy-settings print "All stacks on this machine:" before the directory's URL; first-run-setup prints "Stack directory:" before the same URL, followed by "· next: devhost start in your project's folder".
  • Third-party launcher labels. toolbar-shell draws today's labels, "Redux" and "TanStack", folding into "Devtools"; third-party-devtools names them "Redux DevTools" and "TanStack Devtools" (also when they fold).
  • Logs on the bar and in the layout record. log-minimap adds a Logs item to the bar whenever the toolbar renders and keeps the log panel's open state and width in the layout record; toolbar-shell's bar has no Logs item, and its layout record (move or collapse) keeps only the toolbar's placement, its collapsed state and chat's position.
  • Log lines in the crash view and the log panel. startup-and-recovery folds a line over 2,000 characters to its first and last 300 with Show All 50,138 Characters, shows a repeated block once with its count, and selects a service's lines by that service's source; log-minimap renders the panel, the peek and the crash view with one renderer that wraps every line in full, and files devhost's failure line about a service under the source "devhost" (from a failure), which that selection would leave out.
  • The log panel's header. services-panel, notices-and-feedback and agent-chat draw the pinned log panel with a "Logs" title, a source chip and Close (✕ on agent-chat's); log-minimap, which owns the panel, draws a source filter, a find field, a count line, a Copy button that names the line count, and Close, with no visible title.
  • The notice stack while a toolbar panel is open. services-panel draws a failure notice in the bar's row, left of the bar, with the Services panel directly above the bar; notices-and-feedback and toolbar-shell, like the pattern page, stack the notices above the bar and open the panel beyond them, its caret aimed at its trigger across the notices.
  • Notice icons and state glyphs. notices-and-feedback marks notice kinds with ✕ for a failure, ◐ for activity and ? for a lost connection, among six shapes; services-panel's shared state indicator uses ✕ for exited, ◐ for starting or restarting and ? for unknown, so three shapes carry two meanings.
  • The notice stack's fold control. notices-and-feedback writes it "2 More", and "Show Fewer" while expanded, title-style like every button label; toolbar-shell draws "2 more", as the reference's notice-stack example writes it.
  • Owners of the operation record and what is built on it. notices-and-feedback claims the operation record's model and readers, builds every operation's terminal outcome line, specifies the status stream's closing message, and lands the contract texts for a lost connection (CC-26) and the stack's log (CC-21); services-panel ships the record in its own backend work, builds the terminal outcome line with stack-run-stop, bundles the stream's close reason into its stream work and quotes the same CC-26 change; stack-run-stop quotes the same CC-21 change.

Work with a coding agent

Chat with a coding agent

Before Send the composer names who answers, how the agent handles the message and which checkout it edits; a card pinned above the composer keeps every answer in view while Chat and the notices show the wait; and each turn ends with a receipt of the files it changed and its way back, with conversations named, listed across checkouts and resumable after a close or a stop.

Keep services healthy

Switch the stack to another checkout

Worktrees becomes one shared checkout list, found by branch, path or commit, whose Switch and Restart Stack names everything it restarts and leaves behind, asks only when other work is at stake, shows its steps in place and its outcome on the reloaded page, rolls back service by service, and turns a deleted checkout into an explicit choice instead of a restart that cannot work.

DiagramProposal

Startup pages, crash recovery and app error pages

Every state of a service gets one devhost page, or the crash view over the app, led by the action that can fix its cause and showing the evidence that explains it; an app's own 404 or 5xx passes through with a devhost notice instead of being replaced; and every restart shows its progress and its outcome where it started, never closing without a word.

Watch and restart services from the toolbar

Every service of the stack is counted and listed with its state, cause and route; each restart or start shows its steps and its outcome on the row that started it, with focus kept there; and Restart Stack sits apart from Restart Changed and asks first, in place.

How devhost reports operations and problems

Every operation reports the same way, from one record: its progress where it started or as one activity line, then one outcome in that place that names what changed; failures stay until handled, conditions share one ordered notice stack beside the bar, and a lost connection says why with every service drawn unknown instead of down.

Read service logs in the page

The strip at the window's edge maps every line the page holds, telling errors and warnings apart, and its hover peek holds still, while a click, Logs or Alt+Ctrl+O pins a log panel where each line has its time and source and can be filtered by service, found, selected, copied and followed, opened straight at a failure's exit with the action that fixes it.

Configure a stack

Edit configuration in the browser

The Configuration window opens at the problem it was opened for, lists every problem on the line where the fix goes, states beside Save what saving will restart, reports each save's own outcome there, and keeps drafts and the way back to what the stack runs through reloads, disk changes and rejections.

Edit the manifest and watch it apply

Every save names what it restarts and why in one activity line and one outcome line, and an edit devhost cannot apply names its file, line and fix wherever it shows, while the stack keeps running the accepted manifest.

Set up and run stacks

Start, find, stop and restart stacks from the terminal

The terminal says when a stack is ready, what runs and why a stack ended, a stop reports success only once nothing of the stack remains, and every command that reaches several stacks prints its set first and asks only when an agent's turn would end.

Change the shared proxy settings

The terminal says where the shared Caddy settings live and who can reach the stacks; a save states its reach before it is written, is checked and certified before it counts, and reports one outcome per stack, while open pages follow their stack to the new address with Open instead of drawing every service down, and a refused change names its line and what keeps running.

Serve a folder or a running port
