1. Point at elements

Chat, holding Alt and Alt + right-click (component-source's source menu) still lead to the page's elements, a click still adds a mark the message carries, and picks still work over the page's own popovers and modal dialogs without closing them, with docked chat and its tools moved into the dialog's top layer (SURF-11). What changes: the tools sit in docked chat, the element is named before the click, the keyboard can pick, Alt chords never start a selection, a toggled selection lasts until the person ends it, and Escape never stops the agent. With [devtools.annotations].enabled = false chat shows no page-context tools, holding Alt starts nothing, and the setting's description says "Element selection, drawings and page context for chat; turning it off removes them, chat stays" (SEL-11). Keys: Enter on Select Elements latches it; in the mode the arrows walk, Enter picks, Shift+F10 or the context-menu key opens the source menu and Escape finishes; after a pointer pick or drawing focus is back in the composer where it was, a keyboard-latched selection keeps it on its toggle until Escape, and no pick ever focuses the page element (KEY-12, KEY-8, KEY-6).

  1. 1 Select Elements sits first in a row of page-context tools at the top of docked chat, beside Arrow, Line, Box, Undo and Redo, drawn pressed while it is on. The row follows the dock's corner and docked chat's placement, so no tool floats over the app's header at the top centre of the page. Default: Select Elements off (SURF-7, SURF-5, MENU-1).
  2. 2 One resolver serves Select Elements, holding Alt and Alt + right-click: it outlines the element under the pointer, drawn dashed here, with its role and name before the click. A click adds a mark with the draft's next number, drawn on the element with its number (solid outline, like #1 and #2), and a row in page context; clicking a marked element again does nothing. Each pick is announced once, politely: "Mark 3 added: button Add to cart". The first mark opens docked chat when it is closed, with focus in the composer, as agent-chat specifies (SEL-9, FB-9).
  3. 3 The hint names the mode by its tool label and its next step, then one Esc key cap followed only by its outcome, all from the bindings' one definition: "Select Elements · click an element to add it", Esc "Finish". It is sentence case, never says "Annotate" and never spells Esc out beside its cap (KEY-13, WORD-3, WORD-1).
  4. 4 From the keyboard: with Select Elements latched, the highlight starts on the element that had focus before devhost took it, else the page's main landmark, else the body's first visible element; ArrowUp moves it to the parent, ArrowDown to the first child, ArrowLeft and ArrowRight to the siblings; Enter picks, the same mark a click makes; Shift+F10 or the context-menu key opens the highlighted element's source menu, which component-source owns. Focus stays on the toggle, whose accessible description names the highlighted element; the hint sits under the toggle, and each move is announced politely (KEY-12, KEY-1, FB-9).
  5. 5 Picks reach the page wherever devhost draws nothing, and marks and highlights paint beneath the bar, the notice stack and docked chat, never over them. The empty strip above the bar that swallows clicks while a notice shows is toolbar-shell's to remove (page-context-03, related) (SURF-11, SURF-1).
  6. 6 Holding Alt alone starts a selection only on the first pointer move (a real change of position), on a pointer press, or once it has been held still for 400 ms (O34); any other keydown first, Shift, a dead key and input-method composition included, cancels it without drawing anything, so Alt+Ctrl+R, Alt+Shift+D, a page's own Alt shortcut and characters typed with Option never start it. A pointer press while Alt alone is held picks and never reaches the page, so Option+click never follows or downloads a link. Arrows pressed while Alt is held do nothing and never go Back or Forward, and Alt still belongs to the page's own fields while the person types there (KEY-2, KEY-12).
  7. 7 How a selection ends: one that holding Alt started selects only while Alt is held, so it ends when Alt is released, when the window loses focus or when a key that types is pressed, so a hesitant Option chord's outline never outlives its character (O34); one the toggle latched stays on until Escape, the toggle, another tool, closing chat or a send that takes a screenshot ends it, so the next click still adds a mark and never follows the page's link (KEY-2, KEY-12, KEY-8).
  8. 8 Escape leaves the mode and does nothing else, in the composer, on the toggle and on the page alike: the running turn goes on, and only Stop Turn or Alt+Ctrl+. stop it. With no mode active, Escape in the composer returns focus to the page element chat took it from. One devhost key handler checks the active mode first, so the result never depends on which listener registered last (KEY-8, KEY-9).

2. Draw Arrow, Line or Box

Arrow, Line and Box still draw with a drag over the page, a finished drawing still moves by its stroke, and drawings still go with the message beside the marks. What changes: a tool stays armed, two clicks or the keyboard draw too, drawings share the marks' numbers, and every mark and drawing stays on the element it marks. Keys: in a drawing tool the arrows walk the highlight, Enter sets each end, Escape cancels the drawing in progress and then leaves the tool (KEY-12, KEY-8).

  1. 1 A drawing tool stays armed until Escape or another tool, so three boxes take three drags, and its hint says how: "Box · drag, or click two corners", Esc "Finish"; with Arrow armed it reads "Arrow · drag, or click the start and then the end" (KEY-13, WORD-3).
  2. 2 Two clicks set the start and the end as a drag does, with a preview following the pointer between them; Escape between them cancels the drawing in progress, the hint reading Esc "Cancel" (KEY-12).
  3. 3 From the keyboard the arrows walk the highlight as in Select Elements: with Arrow or Line, Enter sets the start at the highlighted element and a second Enter the end; Box boxes the highlighted element on one Enter (KEY-12).
  4. 4 Each drawing takes the next number from the marks' counter and shows it on the page, "#3", and its row reads "#3 Box around button Add to cart"; numbers never shift or come back (SEL-9).
  5. 5 Every mark and drawing is anchored to the element it marks as an offset to it: a box to the smallest element that contains it, an arrow to the element under its head, a line to the elements under its ends. They are re-measured on scroll, resize, layout change and DOM mutation, a hot update's re-render included, within one frame, so the box stays on the button that moved and stays on it when the window narrows to 1280 (SURF-12).
  6. 6 When its element leaves the page, the mark leaves the page too, never floating over another element, and its row reads "#2 is no longer on this page" with Select Again, which picks again under the same number, and Remove (SURF-12, SEL-9).
  7. 7 Marks and drawings paint beneath devhost's surfaces: no mark covers the bar, the notice stack, a panel or docked chat, and native hit testing at a notice button returns that button while a mark lies under it (SURF-1).

3. Review what the message carries

Page context still sits with the composer, every mark and drawing still has a row with Remove, and Clear Page Context still empties it. What changes: each row says what it sends, the page's own details are a row of their own, a #n the message cites that matches no pick is flagged, and the rows come back after a reload. All of it is read only. Keys: each row's disclosure and its Remove are Tab stops in number order, and Enter or Space on the disclosure expands the row (KEY-10).

  1. 1 A #n in the message that no longer refers to a pick (removed, lost after a reload, or never made) is flagged under the composer before Send, "#1 is not in page context", with Select Again; Send stays available (SEL-9, REV-6).
  2. 2 A mark names its source file, "· ProductCard.tsx:42", or "· no source found" when devhost resolved none; on React 19 development builds component-source fills it (page-context-06, related) (SEL-9).
  3. 3 Each row expands to the exact fields that leave the machine for it: for a mark its element path, role and name, nearby text, bounds in page CSS pixels and source; for a drawing its kind, the element it is anchored to, its offsets and its page coordinates. Hovering or focusing a row outlines its element or drawing on the page, and hovering a mark highlights its row (SEL-9).
  4. 4 The page, once per message: its URL, its service and its worktree label (WORD-11). A URL whose query or fragment is long is shortened in the middle, with the full URL in its tooltip and accessible name (SEL-3, SEL-4, WORD-8).
  5. 5 One row per item, in number order, from the one page-context store the send reads, so the list and what is sent cannot differ (SEL-1). Each row's Remove is named "Remove #2"; removing #1 left #2 and #3 as they were, and the next pick takes #4, never a removed number; Clear Page Context removes every item and is undoable (step 4) (SEL-9, WORD-2).
  6. 6 With Select Elements or a drawing tool on and nothing picked, the list reads "No elements picked" with its next step; with no mode on and nothing picked the list is absent, as today, and the tools row stays (STATE-2).
  7. 7 The list is part of docked chat, inside the composer's area. At 1600×1000, 1280×800 and 900×900 in the light and the dark theme, and at 1280×800 under 200% zoom, its rows scroll inside a bounded area while the tools row, the composer, a pending decision card, Send and the mode control stay in view, every tool at least 24 by 24 CSS pixels; the 320 CSS pixel phone layout keeps the same order (callout 11) (SURF-6, SURF-9, O8).
  8. 8 After a reload devhost or the person causes (the browser's reload, Reload Now, a worktree switch, Restart Stack on a recovery page, an agent edit that reloads the page), the text comes back from browser storage, as today, and page context from the control server's draft record for this stack, page origin and conversation, never a screenshot. Marks whose elements still resolve return with their numbers; the rest stay listed with Select Again and Remove, announced once; a tab share always ends with the page and the list says so (UNDO-2, SEL-9, FB-4, WORD-4, FB-9).
  9. 9 Before a worktree switch runs, its question names page context, read from this list's summary: "Page context: 3 marks · a mark whose element is gone after the reload is listed as lost; the tab share ends"; whether and how the switch asks is worktree-switch's. After the switch the draft record follows the conversation the composer shows (SEL-5, REV-3, SEL-8).
  10. 10 When a turn that changed files ends while Hold Reloads holds the page's reload, devhost applies it once as its own reload, unless focus is in a text field, the composer included: then nothing reloads and agent-chat's turn receipt leads with Reload Now and "The page reload this change needs waits for you". A reload that runs brings the marks back as callout 8 shows (O57, UNDO-2, FB-12).
  11. 11 On a phone, signed in with the shared passkey or paired, docked chat takes the window's width less 16 px on each side; the tools row wraps above the composer and only the rows scroll. A tap with Select Elements latched adds a mark, the element outlined while the finger is down; Box, Arrow and Line draw with two taps. Where the browser cannot capture a tab, Share Tab stays in place, unavailable with its reason, and Attach Image takes a screenshot instead (O8, O36, MENU-3, HOLD-1).

4. Undo the last page-context change

A row's Remove and Clear Page Context still work as today. What changes: Undo Drawing, which removed the newest shape and never undid a move, gives way to one undo history per draft that reverses any page-context change, a cleared list included. This is a local undo, no write: there is no Undo of a sent message, and this flow's way back is this history and the page context kept through reloads (step 3) (UNDO-7, UNDO-2). Keys: Mod+Z undoes and Mod+Shift+Z redoes (KEY-12).

  1. 1 Undo reverses the last page-context action, whatever it was (add, move or remove a mark, draw, move or remove a drawing, Clear Page Context), back to the start of the draft, and Redo reapplies it. Each names what it will reverse in its tooltip and accessible description, "Undo Move #3 Box"; the tooltip shows ⌘Z on macOS and Ctrl+Z elsewhere, exposed as aria-keyshortcuts, from the binding's one definition (UNDO-7, KEY-13, BAR-4).
  2. 2 After drawing Line #4 and then moving Box #3, Undo returns the box and leaves the line, a second Undo removes the line, and Redo puts it back; the armed tool stays armed throughout (UNDO-7).
  3. 3 Undoing a removal restores the item with its number, so Clear Page Context followed by Undo brings every item back as it was (UNDO-7, SEL-9).
  4. 4 Mod+Z and Mod+Shift+Z act on page context while Select Elements or a drawing tool is active, or while focus is in devhost outside a text field; in the app's own fields and in the composer they stay that field's own undo. Send ends the draft's history (KEY-12, UNDO-7).

5. Write and Send

Enter or Send still sends, the message still goes into the page's own worktree, and a failed, cancelled or oversized send still keeps the draft, the marks and the drawings, as today. What changes: Send asks only when the message cites a mark that is gone, page context goes to the conversation the composer shows, and the mode starts at This worktree (live). A send whose acknowledgement never arrives reads Delivery unconfirmed and is never resent; its page context stays in the draft record until a send is acknowledged (owner rule; REV-12). Keys: in the question, focus and Enter start on Select Again, and Escape cancels it with the draft kept and focus back on Send (REV-4, KEY-8, KEY-9).

  1. 1 Send asks nothing, except when the message cites a mark that no longer exists: then the composer asks in place, verb first: "Send with #1 missing? It is not in page context." for a number the person removed or never picked, as drawn, or agent-chat's "Send with #1 missing? Its element is no longer on this page." for a mark whose element left the page. Select Again is focused and enters Select Elements to pick #1 again under the same number, the one way a cited number is bound again; Send Anyway sits beside it; Escape cancels the question and leaves the neutral line "Not sent"; with no gone mark cited, Send never asks (REV-6, REV-4, SEL-9, UNDO-4, WORD-7).
  2. 2 The composer names the recipient, the agent and model, and the edit mode with the worktree it edits; with page context the mode starts at This worktree (live), "This worktree (live) · fix-nav ~/acme/.worktrees/fix-nav", which edits the active worktree in place and commits nothing, and the person can choose Make tickets instead. agent-chat owns that control and the conversation choice (O1, SEL-8, REV-6, WORD-10, WORD-11).
  3. 3 A picked element's fix then asks through the agent's own decision card, pinned between the conversation and the composer with Deny, Allow Once, the agent CLI's own standing approval when it offers one (Allow for This Session) and Stop Turn, the tools row and the composer in view at 1280×800 and at 320 CSS pixels, no answer focused or preselected; agent-chat owns the card, and devhost never answers it (REV-9, O12, SURF-6, O8).
  4. 4 When chat cannot take a message (chat off, no agent CLI installed, the conversation disconnected), Send is unavailable with agent-chat's reason and its way out, and the picks, drawings and draft stay (HOLD-5, MENU-3).
  5. 5 With the lost connection, Send is unavailable with its reason, while picking, drawing, the list and Undo stay available, because none of them writes; the draft record is written once the connection returns (HOLD-2, HOLD-1).
  6. 6 Page context goes to the conversation the composer shows, also right after New Conversation, never to the previous one (SEL-8).
  7. 7 A browser in another environment that has not signed in sees the app working and the toolbar's one state, "Sign in with passkey or pair this browser to use devhost here": chat and its page-context tools are unavailable, holding Alt starts nothing, so the page's own clicks reach the page, and the draft record refuses it. Signed in with the shared passkey or paired, it uses every step here as this machine does (HOLD-7, HOLD-8, O36, WORD-7).

7. Read the sent record

The sent message still keeps the exact page data that went out, and the server still adds the mode's instructions, refuses a message over 8 MiB or an image that is not PNG or JPEG, and gives Codex the text and the image as one input, as today. What changes: that data reads in the same rows as before Send, with the raw data one press away, and it is kept as devhost's own record instead of JSON appended to the person's text. There is no Undo of a sent message; this flow's way back is the undo history (step 4) and the work kept through reloads (step 3) (UNDO-7, UNDO-2). Keys: the record's disclosure and Show Raw are Tab stops in reading order (KEY-10).

  1. 1 The message appears at once as the person's, with "Not sent yet" until the acknowledgement, then its mode line, "Mode: This worktree (live) · fix-nav", with the instructions devhost added under a collapsed "Added by devhost", as agent-chat specifies (WORD-10, UNDO-8, STATE-1).
  2. 2 Under it, "Page context: 1 mark, 1 drawing, 1 screenshot" starts collapsed and expands to the same rows as before Send, each with the fields it carried; the person's own text shows without any "Page context:" JSON (UNDO-8, FB-2, WORD-5).
  3. 3 Show Raw shows the exact data the agent received (UNDO-8).
  4. 4 What the agent receives, once per message: the page's title and URL, its service and worktree label, the viewport's size, the scroll offsets and the device pixel ratio; with a screenshot its size, crop and scale to CSS pixels, so a mark or a drawing can be placed on it; per mark its number, element path, role and name, nearby text, bounds in page CSS pixels with horizontal scroll included, computed styles once, and its source or that none was found; per drawing its number, kind, anchor element path, offsets and page coordinates, with no drawing IDs (SEL-3, SEL-9, SURF-12).
  5. 5 devhost writes that page context as a record of its own into the session's journal, apart from the person's text, so every page and every reload shows it; the server renders it into the agent's input as a labelled "Page context" section after the person's text. It travels as send's optional pageContext field beside agent-chat's mode; CC-40 covers the record frame, and the field itself still needs its CC-n from the reference (UNDO-8, CC-40).
  6. 6 Sending cleared only the items that went out, and their undo history ended with them, so the composer starts empty while the tab share goes on; no outcome notice reports a send: the message is the receipt, and agent-chat's delivery states apply (UNDO-7, FB-2, FB-5).
