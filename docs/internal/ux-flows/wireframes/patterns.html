Shared UX patterns

This is the one design reference every devhost flow proposal and wireframe follows. Each rule has an ID such as SEL-1 that proposals, tickets and tests cite, and a flow that needs to behave differently names its exception here.

  • O1 How a coding agent handles a chat message (the chat edit mode). Decided (product owner, 2026-11-16; updated 2026-11-18, q10a6): two edit modes only, beside the agent and model chip: This worktree (live) always edits whichever worktree the person has active (main's included), leaving changes uncommitted with no additional worktrees, commits or merges (the default with page context); Make tickets has the agent file tickets instead of editing (or say it cannot make tickets, O21). Every sent message records and shows its mode; New worktree (review before merge) is removed, superseding q4's worktree mode and q10a2 (CC-10). The prompt fix may change the documented default prompt before the mode control ships (q8a1), and no loopback-only stopgap ships first: the agent-chat redesign builds O36's check (a2a2, HOLD-8).
  • O2 What Disable Reloads does before an agent receives its request. Decided (product owner, 2026-11-16; clarification resolved 2026-11-18, O56): the label stays; pressing it opens a confirm popover anchored to the hot reload notice that names the agent and shows the exact, editable request for the detected framework, scoped to this worktree, with Send and Cancel, and offers Hold Reloads as the path without an agent. Cancel sends nothing. Once the request takes effect, devhost never reloads by itself after a later turn; each turn that changed files ends with "Reload to see the change" and Reload Page (O56).
  • O3 The edit mode of a message without page context. Decided (product owner, 2026-11-18): the conversation's last chosen mode (This worktree (live) or Make tickets, per O1), and This worktree (live) for a conversation's first message.
  • O4 Restart Changed's target when nothing changed. Decided (product owner, 2026-11-18): keep the documented fallback, retargeted to the page's service (else the stack's primary service) and named in the label, such as "Restart docs".
  • O5 Whether devhost keeps replacing the app's own 404 and 5xx documents. Decided (product owner, 2026-11-18): no; when the app answered, the page shows the app's own document with devhost's notice, and devhost's recovery page answers only for what devhost produced or a service that is not running.
  • O6 What devhost start <names> does when the stack runs without them. Decided (product owner, 2026-11-18): start them into the running stack and print what started.
  • O7 Whether an external service keeps blocking its repository's worktree switch. Decided (product owner, 2026-11-25, q17a6; reversed): external services (managed = false) never block worktree switches, and switching managed services needs no warning about external services staying put ("No need to warn about external services"); managed services restart from the target worktree's folder while external services stay untouched (still marked external in the Services panel). The 2026-11-18 comment on q17 established WORD-11.
  • O8 The narrowest window devhost's surfaces are designed for. Decided (product owner, 2026-11-18): acceptance viewports end at 900×900 and at 1280×800 under 200% zoom (640×400 CSS pixels), and full pages reflow at 320 CSS pixels; chat, its approval prompts and the toolbar's notices also get a phone layout down to 320 CSS pixels, so an authenticated phone (O36) can ask for a change and see it; below 640 CSS pixels the other surfaces never overflow the window horizontally but get no layout of their own.
  • O9 The default restart scope of a manifest edit. Decided (product owner, 2026-11-18): keep today's scope (the edited services, their dependents and every service of the same repository) and name each restarted service and why in the reload's outcome.
  • O10 Lifecycle actions the browser offers beyond today's. Decided (product owner, 2026-11-18): a not-started service's hostname gets a status page with Start; the browser still cannot stop the page's own stack; the stack directory stays read-only with links; from another environment Start answers authenticated browsers (passkey or paired, O36), and an unauthenticated one sees it unavailable with how to sign in or pair.
  • O11 Whether Make tickets shows the tickets before the agent files them. Decided (product owner, 2026-11-18): no review step of devhost's own; the agent ends its reply with every ticket it filed, and the agent's own approval of the filing command is the person's check.
  • O12 Standing approvals granted from the browser. Decided (product owner, 2026-11-18; reversed): offer the agent CLI's own standing approval on the decision card (such as Claude Code's "don't ask again" or Codex's approval for the session), alongside Deny, Allow Once and Stop Turn; later matching requests are answered without prompting (REV-9, CC-16).
  • O13 Whether turns started from the browser ask before acting by default. Decided (product owner, 2026-11-18): devhost passes no approval policy, as today; the composer names the resolved behavior before the first Send, in a warning style when the agent never asks.
  • O14 How long a success notice and an Undo stay. Decided (product owner, 2026-11-18; calibrated, refined by O53): a success notice stays for its reading time, 1.5 s plus 0.3 s per word, at least 4 s and at most 15 s; the Undo that replaces a dismissed notice stays 4 s; both count only while neither the pointer nor focus is in the notice and the page is visible, and a notice arriving while the browser window is not focused starts counting when the window is next focused (O53); a failure never closes by itself.
  • O15 How long a stopped stack is remembered. Decided (product owner, 2026-11-18; calibrated; HTTPS routes retained per O63): 24 hours, or until another stack claims its hostname or the shared Caddy stops; its configured Caddy routes and HTTPS certificates stay active for that window (O63), and the stack directory lists it as recently stopped only when its run lasted at least a minute.
  • O16 Whether a background tab shows that something needs the person. Decided (product owner, 2026-11-18; reversed): also prefix the app page's tab title while a waiting agent or failure persists (such as "(1) waiting · Acme Shop"), restoring the app's own title when it clears, as well as prefixing devhost's own pages (ACT-7).
  • O17 Whose key bindings: the team's or the person's. Decided (product owner, 2026-11-18): the manifest's [devtools.shortcuts] stays the team default, and the same table in the devhost config file overrides it binding by binding (CC-39).
  • O18 Process-replacement commands and self-upgrade. Decided (product owner, 2026-11-25, q79a2; supersedes q28a1): add built-in devhost upgrade (downloads the latest release excluding media, verifies checksums, swaps a user-writable binary or clearly reports read-only/externally managed installs without breaking them, and replaces running manifest stacks) and keep shipped devhost restart-all and project-scoped devhost stack restart on one verb for dotfiles, package managers and local rebuilds, withdrawing the devhost stack replace rename while stating clearly in help and output that they replace the running devhost supervisor process (CC-12, CC-31).
  • O19 What This worktree (live) lets the agent do with Git and uncommitted work. Decided (product owner, 2026-11-18): edit files in place and leave every change uncommitted; never commit, stash, restore, reset or check out files; build on the person's uncommitted change and say so (applies to every editing chat turn under O1).
  • O20 What a change of edit mode within a conversation tells the agent. Decided (product owner, 2026-11-18): each mode's instructions replace earlier workflow instructions for that message, and the composer says when the mode differs from the previous message's (between This worktree (live) and Make tickets; no earlier worktree or merge branch under O1).
  • O21 What Make tickets does when the agent cannot file tickets. Decided (product owner, 2026-11-18; reversed by comment): change no files and say it cannot make tickets; no ticket drafts (withdraws the ticket-drafts clause of CC-10).
  • O22 A record of what an agent's turn changed, and its way back. Decided (product owner, 2026-11-18): each finished turn lists the files the agent changed, from the session journal's events and with no Git command, and offers the reverse patch of the agent's own edits to copy and a follow-up asking the agent to undo the turn, never a whole-file git restore (worktree-mode merge/branch clause moot under O1).
  • O23 What an ended conversation keeps after its stack stops. Decided (product owner, 2026-11-18): the harness, native session ID, worktree, model, last mode, start and end times and the CLI's own title, never message text, for as long as O15 keeps the stopped stack.
  • O24 What the hot reload notice says after a Disable Reloads request. Decided (product owner, 2026-11-18; confirmed): once the turn ends, the notice names the request and its result in place of Disable Reloads, stating what devhost observed, never that reloads are on or off when the page cannot show it.
  • O25 The Disable Reloads request for a dev server with no verified switch. Decided (product owner, 2026-11-18): the popover says no verified switch is known, offers Hold Reloads first, and keeps a generic request editable.
  • O26 Whether the Disable Reloads request may change the manifest. Decided (product owner, 2026-11-18): it names the dev server's own setting, says watch must not be edited, and allows a change to a service's command only for a command-line switch, naming every service that reload restarts.
  • O27 Which conversation receives the Disable Reloads request. Decided (product owner, 2026-11-18): a new conversation, with each open conversation of this worktree offered by its title as the alternative; never one the popover does not name.
  • O28 How long a process-checked service must stay up before a reload counts it started. Decided (product owner, 2026-11-18; calibrated): 1 s after it is spawned; an exit within it, with any exit code, fails the start, restart or reload with its exit code and last lines, and a reload rolls back; an exit after it is reported after the outcome.
  • O29 What Revert returns to in the Configuration window. Decided (product owner, 2026-11-18): Revert shows the version on disk; returning to what the stack runs is Restore Running Version.
  • O30 How long devhost stop, stack restart, restart-all and upgrade wait for a stack to stop. Decided (product owner, 2026-11-18, q40a3; parallel-shutdown design settled 2026-11-25): parallel foreground and daemon shutdown from t = 0 with one shared process snapshot, a single termination signal, a 15 s foreground ceiling (10 s SIGTERM + 5 s SIGKILL verify + shared 2 s late-listener scan) concurrently with O41's 20 s daemon deadline (25.64 s combined worst case, 4.36 s margin inside 30 s default), configurable stopTimeout (5s..10m, --timeout > DEVHOST_STOP_TIMEOUT > devhost.toml > config.toml > 30s; daemon overrides > 20 s widen stack wait unless CLI --timeout caps the run), unified across all stop callers, keeping the progress line, never killing a stopping supervisor, and forcing remaining trees on Ctrl-C or a second stop (CC-35).
  • O31 Whether devhost restart-all and devhost upgrade replace foreground stacks and serve sessions. Decided (product owner, 2026-11-18; names updated by O18): they replace every manifest stack, each saying in its own terminal that it was replaced and where its replacement logs; serve sessions are listed and left running, with the command that restarts each.
  • O32 Whether devhost prepares a new worktree before switching to it. Decided (product owner, 2026-11-18): devhost runs nothing new on a switch; a service that fails for lack of setup is reported with the cause from its output and the command to run in that worktree.
  • O33 Whether multi-stack terminal commands ask. Decided (product owner, 2026-11-18; names updated by O18): stop --worktrees, restart-all and upgrade print their set and act; only when they would end a working or waiting agent's turn do they ask [y/N] in a terminal, and without one or under AGENT=1 they refuse unless --yes.
  • O34 How long Alt alone is held before Select Elements starts without a pointer move. Decided (product owner, 2026-11-18; calibrated, provisional): 400 ms, until human holds are measured; a pointer move while Alt alone is held starts it at once.
  • O35 What a manifest's [devtools.chat].prompt does with chat edit modes. Decided (product owner, 2026-11-18): each mode's instructions are built in and always sent, after the team's guidance: prompt becomes the team's guidance, sent first in every mode, and the mode's instructions follow it and decide whether the agent edits this worktree or makes tickets; [devtools.chat.modes.<mode>].prompt (live or tickets; no worktree key under O1) replaces one mode's instructions; a manifest that sets prompt today gets one warning.
  • O36 How devhost tells the person using it from another environment apart from other clients. Decided (product owner, 2026-11-25, q46a6; reversed): one shared WebAuthn passkey under a single owned parent HTTPS domain (ideally a dedicated subdomain; non-secret public key synced in config.toml; pure-Rust webauthn-rs 0.6.x backend), with phone support as a hard requirement via synced passkeys and hybrid/QR sign-in (pairing with O8's 320 px phone layout). This machine stays trusted (loopback connection and hops, not relayed, stack's own Host, no cross-site or same-site mark); passkey sign-in issues a 30-day idle host-only __Host- session cookie (O59) propagated via the reserved hostname; one-time devhost pair links stay as fallback for first-time enrollment bootstrapping, hostnames outside the shared domain (.localhost, .local, LAN IPs) and lockout recovery. Authenticated remote browsers use every control as this machine does; an unauthenticated client gets the app and "Sign in with passkey or pair this browser to use devhost here", with nothing started; the agent catalog answers from a cache and discovers again only on Refresh Agents.
  • O37 Who can switch worktrees, stop another stack and restart services from another environment. Decided (product owner, 2026-11-18): this machine and any authenticated remote browser (passkey or paired, O36) alike, on both worktree entry points and on Restart, Start, Restart Stack and a chat receipt's Restart Changed; other clients get the unauthenticated state and no worktree paths, PIDs or owner IDs; no separate setting.
  • O38 Who may read the configuration from another environment. Decided (product owner, 2026-11-18): this machine and authenticated remote browsers (passkey or paired, O36), with the editor on; other clients get the unauthenticated state; authenticated remote browsers also save (O54).
  • O39 What bindHost = "127.0.0.1" does on macOS. Decided (product owner, 2026-11-25, q49a5): honor loopback from port 1024 upward (default_bind 127.0.0.1 [::1]); below port 1024 (including default 443), keep listening on all interfaces so existing port-443 setups keep starting without error, while printing an explicit warning on every start explaining macOS's privileged-port restriction and naming the fix (httpsPort = 4443 or a privileged launcher); ships with the agent-chat redesign.
  • O40 Whether devhost serve sessions start with chat off. Decided (product owner, 2026-11-18; reversed): no: devhost serve keeps chat on by default, stated on the first line, with --no-chat to turn it off; a --port session still never hands an agent the shell's current folder; who can reach a session's chat is O36's check.
  • O41 The deadline on a daemon's lifecycle status and stop commands. Decided (settled by default, 2026-11-18; calibrated; O30 coordination settled 2026-11-25): one 20 s deadline shared by a daemon's status read and the stop it leads to, counted from the status read's start (20 s for a stop without a status command and for the status read at start), running concurrently with foreground stops under O30; then devhost kills the commands' whole process group, says the daemon may still be running, and releases the stack; a per-service override ([services.<name>.lifecycle].stopTimeout) ships in the same release and widens stack stop wait to max(stopTimeout, max_daemon_override + 10s) unless CLI --timeout caps the run.
  • O42 How long a save no reload has read waits before it says devhost did not see it. Decided (product owner, 2026-11-18; calibrated): 5 s from the write, counted only while no operation (startup, reload, restart, worktree switch) holds the stack, with the command that applies it; a version a later save replaced ends as replaced, never unseen.
  • O43 Whether a deleted running worktree's processes keep running until the person recovers. Decided (product owner, 2026-11-18): yes; a read stops nothing, devhost starts none of the repository's services, and the repository is blocked with one sentence until the person recovers.
  • O44 How a route's path matches. Decided (product owner, 2026-11-18): prefix routing: a path without /* matches itself and everything under it, and the docs and release notes say so. Recommended for the rest: a path without host starts with a warning. The starter manifest is O52.
  • O45 How a service learns its public URL. Decided (product owner, 2026-11-18; reversed): neither publicUrl nor DEVHOST_PUBLIC_URL; keep today's behavior (withdraws the proposed guides/service-references.md contract change).
  • O46 How close a mistyped hostname must be for the Caddy 404 and stack directory to offer it. Decided (product owner, 2026-11-18; calibrated; scope settled by O63): a stopped stack's own hostname names that stack first (and stays reachable over HTTPS for O15's 24 h window per O63); otherwise on plain HTTP (when httpEnabled = true) and in the stack directory, devhost offers routed hostnames within two edits of the name before the shared suffix (one edit for names of four characters or fewer), never the same name with a different number; at most three offers, closest first, ties alphabetical, each keeping the path.
  • O47 Who may read the stack directory and press Check Again from another environment. Decided (product owner, 2026-11-18): authenticated remote browsers (passkey or paired, O36) read it and press Check Again; readers admitted only by stackDirectoryAllowRemote see Check Again unavailable; the relay forwards the directory's hostname.
  • O48 How the CPU, RAM and Disk readouts set their levels. Decided (product owner, 2026-11-18; calibrated): CPU averaged over 20 s, high at 70% (back below 65%) and very high at 90% (back below 85%), with no extra hold; RAM per reading, high at 75% (back below 70%) and very high at 90% held for 10 s (back below 85%, uncalibrated); Disk by free space on a disk of any size, low below 20 GiB and very low below 10 GiB, each clearing 1 GiB above its floor.
  • O49 How many changes the page keeps per Zustand store before the Redux DevTools window opens. Decided (product owner, 2026-11-18; calibrated): the latest 50, kept from the store's registration and across reopening the window, within 16 MB per store (counting two bytes per character); a store too large to keep two changes keeps none while the window is closed; the window says how many it shows.
  • O50 Whether devhost starts the editor's command itself, and what Open does in another environment. Withdrawn (product owner, 2026-11-18, no editor support): devhost never starts an editor; editor support is removed completely (O51; withdraws proposed guides/react-highlight.md, guides/devtools.md and reference/control-api.md editor-launch contract changes).
  • O51 Editors beyond the four built-in ones. Withdrawn (product owner, 2026-11-18, no editor support): editor support is removed completely from devhost — no Open in Editor, no [devtools.editor] in manifests or the devhost config file, no DEVHOST_EDITOR, and no URL or command templates (withdraws editor parts of CC-39, roster SRC-03 and proposed template contract changes; retires O60).
  • O52 Whether devhost writes a starter manifest. Decided (product owner, 2026-11-18): yes: devhost init writes a commented devhost.toml with one service guessed from package.json, go.mod or a Procfile, never overwrites a file, and the message for a folder without a manifest offers it.
  • O53 Whether a success notice's time also stops while the browser window is not focused. Decided (product owner, 2026-11-18; reversed): pause only for a notice that arrives while the browser window is not focused — its countdown starts when the person next focuses the browser window (reading document.hasFocus(), not blur alone); notices that arrived while focused keep counting (FB-6).
  • O54 Whether an authenticated remote browser in another environment may save the configuration. Decided (product owner, 2026-11-18): yes: with the editor on, saves come from this machine and authenticated remote browsers (passkey or paired, O36); the editor stays off by default, and unauthenticated clients neither read nor save.
  • O55 Where Watch Live Activity opens for a browser in another environment. Decided (product owner, 2026-11-18): also on the stack directory's hostname, never an app's, for this machine and authenticated remote browsers (passkey or paired, O36); http://127.0.0.1:<port> keeps working on this machine.
  • O56 How a later chat turn's change reaches the page after a Disable Reloads request. Decided (product owner, 2026-11-18; reversed): Disable Reloads wins: once it takes effect, devhost never reloads by itself after a turn; each turn that changed files ends with "Reload to see the change" and Reload Page (FB-12, WORD-2).
  • O57 What a chat turn's end does with the reloads Hold Reloads keeps. Decided (product owner, 2026-11-18): devhost applies them once, on the page the message came from, when the turn ends; while the person types there, the receipt leads with Reload Now; nothing reloads while the turn runs.
  • O58 Who restarts a service whose running code a chat turn changed. Decided (product owner, 2026-11-18; reversed): the person restarts changed services: the turn's summary names each service the turn's edits marked changed ("api runs the old code until it restarts") with Restart Changed; services without watch paths go unnamed (withdraws the live-mode agent-restart clause of CC-10).
  • O59 How long an authenticated remote browser stays signed in. Decided (settled by default, 2026-11-18; calibrated; covers passkey and paired sessions under O36): until the person revokes it, ending after 30 days without use, with no fixed lifetime; devhost pair (and devhost passkey) lists and revokes sessions, and an authenticated remote page offers Sign Out This Browser (or Unpair This Browser).
  • O60 Where the machine name in a remote editor link comes from. Retired (product owner, 2026-11-18, by O51): no editor support, so no remote editor links or SSH machine-name prompt (withdraws proposed remote-editor contract change beside CC-39).
  • O61 How devhost's pages name the machine that runs the stacks. Decided (settled by default, 2026-11-18): one name for every reader, machineName in the devhost config file, else the host name up to its first dot: All Stacks on devbox, "No stacks are running on devbox"; terminal text keeps "this machine" for where a command runs (remote-editor sentences removed under O50/O51/O60).
  • O62 CLI stack inspection command. Decided (product owner, 2026-11-25, q80a1): extend the shipped devhost stack info command with manifest-reload rejection state, changed-file markers, --json, --wait and distinct non-ready exit status (3), and add devhost status as a short alias for the exact same command (one implementation and output contract, CC-23).
  • O63 Mistyped and recently stopped HTTPS hostnames under configured-hosts-only TLS. Decided (product owner, 2026-11-25, q81a1): keep strict configured-hosts-only TLS for arbitrary unknown HTTPS hostnames (zero on-demand certs for typos); keep configured routes and certificates active for recently stopped stacks (O15: 24 h window, ran ≥ 1 min for directory) so revisiting a stopped HTTPS tab renders the stopped-stack recovery page over HTTPS with its start command; keep close-hostname typo suggestions (O46) on plain HTTP (when httpEnabled = true) and in the stack directory (CC-27).

2.1 Selection

devhost has no multi-select list: selection is targeting, deciding which services, stacks, worktrees, conversations and page elements an action acts on, and showing that set before it runs. Use it for every action with a target, in the toolbar, on status pages, in chat and in the terminal; not for what an action shows while it runs or after (2.7, 2.8) or whether it asks first (2.5).

  1. SEL-1 1 Every action names its target set before it runs: by name for one or two members, else by count and unit, with every member in its tooltip and accessible description; a key or icon acts on the same set as its control and names it in its outcome. The set shown and the set acted on come from one selector.
  2. SEL-2 Restart Changed acts on every service marked changed. With nothing changed it targets the page's service, else the primary service, named in its label ("Restart docs", O4); while the stack restarts or a repository switches it is unavailable with its reason, and its key says why it did nothing.
  3. SEL-3 The page's service, the route that answered the page as the backend resolved it, is the implicit target of page-scoped surfaces: the crash view, Restart Changed's fallback, Reload blocked and page context. Stack-wide views show every service and say so; narrowing them is a filter.
  4. SEL-4 2 One worktree label and one worktree list everywhere: the branch, or "Detached" with the 7-character commit ID, then the path shortened with ~. The list puts the main worktree first, then linked worktrees by branch, each row with its short commit ID and its running, configured, unavailable and in use badges, reasons as text. A deleted selected worktree is never preselected.
  5. SEL-5 A worktree switch names everything it reaches: "Switch and Restart Stack", one line naming the stack, repository and target worktree, and each working or waiting agent, unsaved Configuration draft, page context and held reload before it runs. It keeps the run's service selection. External services (managed = false) never block worktree switches and need no warning: managed services restart from the target worktree while external services stay untouched (O7).
  6. SEL-6 5 Terminal commands resolve stacks by one rule (the nearest manifest upward, or --manifest) and a command acting on several stacks prints its set first: name, worktree, PID, foreground or detached, and for caddy stop the hostnames it takes offline. --dry-run prints the set and exits 0.
  7. SEL-7 3 The run's service selection is visible and changeable while it runs: left-out services are dimmed "not started" rows with their hostname and Start, which names the dependencies it also starts, plus a start-them-all action. Starts and restarts of different services queue (queued, starting, then the state), visible in every tab, the terminal and devhost stack info (alias devhost status, O62), and cancellable with Cancel Restart or Cancel Start; devhost service start|stop|restart reaches the running stack, and devhost start <names> adds services to it (O6).
  8. SEL-8 4 A message names its recipient before Send: the conversation (or that Send starts a new one), the harness and model as a chip that opens Chat Settings, and the edit mode with the worktree label (O1, O3). A conversation of another worktree shows its transcript, decisions and Stop Turn but takes no message from this page; the composer offers New Conversation in the page's worktree with the draft kept.
  9. SEL-9 One element resolver and stable mark numbers: Select Elements, holding Alt and Alt + right-click highlight the element before the click; numbers are never reused or shifted, except that Select Again on a number the message cites binds the new pick to it (revision 7); before Send a gone number asks "Send with #2 missing? Its element is no longer on this page." or, for a mark the person removed, "Send with #1 missing? It is not in page context."; page context shows per pick what it will send.
  10. SEL-10 Lists filter as the person types, keep group headers with counts, highlight matches, state their match keys, and in an empty result say what was searched with a way to clear it; close-hostname typo suggestions (O46) show on plain HTTP (when httpEnabled = true) and in the stack directory, while unknown HTTPS hostnames keep strict configured-hosts-only TLS (O63). Refresh is a control of its own.
  11. SEL-11 A switch or setting names everything it turns off and turns off nothing else; [devtools].enabled = false is the one master switch. 2.6 What can block an action

Nothing outside devhost locks a stack; what blocks an action is devhost's own state: a lost status stream, another operation on the stack, an unavailable worktree, chat that cannot take a message, and a control a browser cannot use where it is: under HOLD-8, every gated control for an unauthenticated browser in another environment (O36).   2. HOLD-2 2 A lost connection blocks every write and is not an outage: services keep their last known state drawn as unknown, never down; the reason names the cause the backend sent (a stop with its start command, a proxy stop, a port move with Open), else "retrying" with Retry Now; drafts, page context and queued operations stay.
  3. HOLD-3 One stack-wide operation at a time, named while it runs ("Restart Stack is running · 3 of 6 started"); per-service writes queue behind it; the control API refuses with 409 naming the operation; chat, page context and reads stay available.
  4. HOLD-4 3 An unavailable worktree blocks its repository, said once as a sentence, never falling back to another worktree: its services show blocked, its restarts are unavailable, and the lead actions are returning to the configured worktree or choosing another. A read of the worktree list stops nothing (fixed on Rust main); processes keep running from the deleted folder until the person chooses a recovery (O43). External services never block worktree switches (O7).
  5. HOLD-5 Chat that cannot take a message (off, no agent CLI, disconnected) says why and how out, keeps the draft and page context, and keeps running conversations reachable: their approvals can be answered and their turns stopped until they end; which clients may reach those routes is O36's check.
  6. HOLD-6 4 A rejected configuration blocks nothing: the stack keeps running the accepted manifest, every action stays available, and a control that starts services says in its reach line that it uses the accepted manifest and names the change not applied.
  7. HOLD-7 A control a browser cannot use here says so before the person tries it: an unauthenticated browser in another environment sees every gated control unavailable with "Sign in with passkey or pair this browser to use devhost here", the one sign-in sentence (revision 7), from the moment its surface opens, and nothing starts; a signed-out page shows only the stack name and that notice, no service state, logs or other notices; an authenticated remote browser (shared-domain passkey on phone or desktop, or devhost pair fallback, O36) uses every control as this machine does, reading and saving the configuration with the editor on (O38, O54).

HOLD-8 Using devhost from another environment is a primary use case, so no feature is held to this machine (the product owner, 2026-11-18): every feature works from the person's browser in another environment (phones included), made safe for it instead of refused; this machine stays trusted; bindHost is honored on macOS from port 1024 upward, and below 1024 keeps listening on all interfaces with an explicit warning (O39). 2.7 Progress and outcome feedback

2.8 Partial results and failures

An operation often reaches several services or stacks, and its targets can end differently. Use it for every operation that ends with some targets failed, every failure report in the browser and terminal, and every stop or cancel someone meant; not for the action a failure leads with (MENU-5), where reports show (2.7) or service states (2.10).

  1. FAIL-1 1 A partial result reports every target with its own result (restarted, started, failed with its cause, left as it was) and how many of the stack's services run, never as a plain success or failure. The healthy services keep running and the failure stays on the failing service; a detached start that stops before readiness is the intended exception and says so. The terminal prints one line per failed target and exits non-zero.
  2. FAIL-2 3 A failure says what failed, why, and the next step, in words: a manifest or devhost config file problem names the file, line, column and key, shows the offending line, offers a close key, and says the stack still runs the accepted manifest. Never a response body, markup, a raw Rust error chain or the same path twice; the original text stays behind Copy Error. Every action that fails says so where it started, chat and page actions included.
  3. FAIL-3 2 A process failure carries its evidence: the exit code, or the signal by name with its status, with its time and whether devhost sent it; the service's own last output lines, frozen at its exit; a failed health check's probe; a port held by another program; and what devhost ran (command, folder, manifest file and line). An agent process that dies ends its reply with a plain cause, never as a finished reply.
  4. FAIL-4 One cause, one report: a repeated failure updates its own report with a count and the latest time, and a failure ends visibly when its cause does ("Configuration restored · nothing restarted").
  5. FAIL-5 4 A deliberate stop, cancel or replacement is never a failure: services devhost stops are steps of the operation; a person's stop reads stopped; one devhost had to force reads force-stopped; a replaced foreground stack prints who replaced it, the new PID and its log, and exits 0; a stopped chat turn ends with a neutral line (O31).
  6. FAIL-6 A retired setting warns and is ignored; an unknown one is rejected (revision 7): [devtools.editor] and DEVHOST_EDITOR warn with file, line, column and key, so an upgrade never stops a stack; [devtools.editor].enabled = false still turns the source menu off. A declined terminal question exits 1, Ctrl-C at a question 130.

Backend: each target's result in the operation record; one structured error with the offending line and a close key; output retained per service and frozen at exit; each exit published with its code or signal, time and sender; health-check probe results; the holder of a fixed port; repeated rejections counted; a replaced stack told who replaced it · Accessibility: the cause sentence is the accessible description of its notice, row or view; failures go to the assertive region; per-target results are a list, not only colored rows · Contracts: CC-22, CC-24, CC-36

2.9 Undo and history

Most writes start or stop processes, which can be done again but not taken back, so undo is a rollback when an operation fails, work kept through the reloads devhost causes, local undo of what the page holds, and a named way back for writes devhost does not own. Use it for every way back and every record a decision leaves; not for the question before a write (2.5) or failure reports (2.8).

  1. UNDO-1 A rollback restores what the operation found, service by service, never stopping the set because one member fails; a failed switch restores the previous worktree. It says what it is restoring while it runs and reports its own outcome, naming what it put back, then what runs now: "Restored the accepted manifest: 5 of 6 running · api still fails" after a reload, "Restored the services as they ran before Restart Stack: …" after Restart Stack, "Returned to main ~/acme: …" after a switch.
  2. UNDO-2 Work in progress survives every reload devhost causes: chat's unsent text (in browser storage, as today), its pasted images and page context (in a draft record on the control server, up to 8 MiB), sent and unsent messages, queued starts, and Configuration window drafts kept per stack and file; marks that no longer resolve are listed with Select Again and Remove; a draft changed in another tab offers Compare, Keep Mine and Use Other Version. A held reload is the one thing a reload cannot keep.
  3. UNDO-3 4 Nothing pending is cleared silently: turning Hold Reloads off never reloads by itself, the held reload stays pending with Reload Now; a file changed on disk under a draft offers Compare, Keep Mine and Use Disk Version; dismissing the hot reload notice offers Undo and later Show Reload Notice.
  4. UNDO-4 Chat actions on their own target are recoverable instead of asking: Stop Turn offers Continue; a closed conversation stays read-only in the list with Resume; Cancel on a question restores the draft; a conversation a stop ended stays resumable after the stack starts again (O23).
  5. UNDO-5 3 A write devhost cannot take back names its way back: each finished turn lists the files the agent changed; in This worktree (live) (the only editing mode, O1) the way back is the reverse patch of the agent's own edits to copy and a follow-up asking the agent to undo the turn, never a whole-file git restore; Make tickets reports each ticket filed or says it cannot make tickets with no files changed and no drafts (O21); a stop prints its start command; a certificate install prints its removal (O11, O19, O22).
  6. UNDO-6 1 The way back in the configuration is to what runs: a rejected file says it differs from what the stack runs, marks the lines, and offers Show Differences and Restore Running Version, which applies like any save; Revert shows the version on disk (O29); the editor's undo history survives a save.
  7. UNDO-7 Page context's Undo reverses its last action, whatever it was, back to the start of the draft, Clear Page Context included; Send ends its history.
  8. UNDO-8 2 Every decision leaves a record where it was made: each sent message keeps its mode with its worktree, its page context and the instructions devhost added; each answer its line; each stopped turn that the person stopped it; written into the session's journal and replayed to every page. The Configuration window keeps each file's last save outcome.

Backend: per-service rollback with a published restoring state; configuration and chat draft records on the control server with revisions; devhost's own record frames in the session's journal; the running manifest text kept for Show Differences; per-turn changed files with the reverse patch; devhost caddy untrust · Accessibility: restored and lost marks are announced once with their counts; Undo stays while it has focus; decision lines and modes are text in reading order · Contracts: CC-13, CC-14, CC-16, CC-19, CC-20, CC-38, CC-40

2.10 Background work and activity

devhost's background work is the services runtime: operations run on the server whatever started them, services change state on their own, and conditions arise from saves, agents and the proxy. Use it for every display of a service's, stack's or agent's state, every condition and the collapsed badge; not for progress text (2.7), failure reports (2.8), what blocks an action (2.6) or the words (2.12).

  1. ACT-1 One operation record per operation, whatever started it: a caller-generated ID, kind, target set, origin as far as the backend can see it (this tab or another, the terminal, an agent devhost started, a file changed on disk), times and each target's step and outcome; write routes answer 202 Accepted with it, and every page, the terminal, the log and devhost stack info (alias devhost status, O62) read it.
  2. ACT-2 1 One service state, published with its cause and since when, the same on every surface and in both outputs: not started, starting, running, restarting, stopping, failed, exited, blocked, and for external services reachable or not reachable; changed is independent, and a lost stream makes every state unknown. No surface shows a state it did not receive.
  3. ACT-3 A transition belongs to the services it touches: touched services show restarting, starting or stopping with their step, every other service keeps its own state, a stopping stack counts what has stopped, and a switching repository says it is switching to the target worktree.
  4. ACT-4 2 Starting is not failing: a service is starting until its first passing health check or the timeout, says which dependency it waits for, and shows the check's target, the elapsed time and the timeout.
  5. ACT-5 A lost connection is unknown, never down: last known states drawn hollow and neutral with when they were last seen, a condition notice with Retry Now, and "Connected again · 6 of 6 running" once when it returns.
  6. ACT-6 5 A stack summary counts the whole stack, left-out services included, and leads with what needs the person; a stack is in one stack state (stopped, stopping, proxy offline, failed, starting, changing, running). The stack directory lists failed stacks and waiting agents first, each waiting agent a link to its decision card.
  7. ACT-7 Conditions make up the attention state, start and end with the published state, are announced once each way, and clear with their cause; dismissing one leaves its marker. The collapsed badge shows the highest, in this order: a lost connection or offline proxy, a failed, exited or blocked service, a rejected configuration, an agent waiting, a held or blocked reload, changed, else healthy; a routine restart never shows as failed. A waiting agent or failure also prefixes the tab title of devhost's own pages and app pages alike ("(1) waiting · Acme Shop"), restoring the app's own title when it clears (O16, reversed 2026-11-18).
  8. ACT-8 3 Changed means the running process does not reflect its watched files, computed on the server against the process's launch, so every tab reads the same mark; reverting an edit clears it; it names its files and stays beside a failure; an external service is never changed.
  9. ACT-9 4 An external service shows reachability from devhost's own check, with the check, its last result and time, and says it runs outside devhost; no Restart, Start or logs; never blocks worktree switches and needs no warning when managed services switch (O7).
  10. ACT-10 6 A stack's end is a state with its reason (stopped from a terminal or another stack's page, the idle timeout, replaced by stack restart, restart-all or upgrade, killed, every service gone) and time; its hostnames keep configured HTTPS routes and certificates active for O15's 24 h window (O63) and answer with a page naming when and why it stopped and the command that starts it in its folder, while unknown HTTPS hostnames keep strict configured-hosts-only TLS. devhost never starts a stack from these pages.
  11. ACT-11 A reported state matches the processes that run: a stack reads stopped only when no process, route or port claim remains (parallel foreground and daemon shutdown within O30's configurable 30 s default); leftovers of a killed stack are found and named, and devhost start refuses while one holds a service's port or hostname.
  12. ACT-12 State is live wherever it shows, and a snapshot says its age; devhost's own status pages re-check on state changes, else back off to 1, 2, 5, 10 s and then every 30 s, and never in a hidden tab.
  13. ACT-13 A state is told by shape and text, never by color alone, at any scale and in forced colors; when dots do not fit, the summary gives counts by state at a fixed width and names up to three services that need the person, then "+N".
  14. ACT-14 devhost signals only the processes it started for a service, by their identity, on macOS and Linux alike (the product owner, 2026-11-18; landed on Rust main 190a8bb5): each process is recorded with its PID and start time and checked again before every signal, so a later process that reuses a PID is never signalled; a re-parented daemon still stops with its service; external services are never signalled.

2.13 Empty, loading and error states

What a surface shows before its content arrives, when there is none, and when it cannot get it. Use it for every view's loading, waiting, empty and cannot-load state in the browser and the terminal; not for a service's or stack's own state (2.10) or an operation's failure (2.8).
