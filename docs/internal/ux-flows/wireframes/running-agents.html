1. Read the trigger

The trigger still sits among the bar's items, still reads the agents record every 10 s while chat is on and the page is visible, still counts the agents in this checkout and still spins while one works. What changes: it never leaves the bar, shows an agent waiting for the person apart from a working one, and says when devhost could not look. Keys: Alt+Ctrl+B reaches the bar; the trigger is one arrow stop (ArrowLeft, ArrowRight, Home, End); Enter, Space or the arrow that points toward the panel opens the list (KEY-3, KEY-4).

  1. 1 The trigger shows the count of agents in this checkout, spins ◐ while any works, and while any listed agent waits for the person takes the waiting look ◆ with "1 waiting", distinct from working in its shape, its text and its accessible name, also in forced colors. Its name counts in words and its description names its scope, "this checkout" (SURF-8, ACT-7, ACT-13, WORD-5, WORD-6). The waiting notice with Answer above the bar is agent-chat's, for the agent chat started.
  2. 2 With no agent it stays in its place showing "0", so no bar item moves when the first agent starts or the last one stops; toolbar-shell keeps the segment's place (STATE-2, CC-33).
  3. 3 Agents of the stack's other checkouts are counted only in the list; one that waits still gives the trigger its waiting look, and the accessible name names its checkout.
  4. 4 The incomplete mark ◌: some agent CLI could not be listed, so the count is "at least"; when the scan failed for every CLI the mark shows without a count. Its accessible description is the list's sentence naming those agents and the way forward (step 2) (MENU-3, HOLD-1).
  5. 5 With chat off the trigger stays, dimmed but operable, without a count, and opens the list that says why; the page makes no agents request while chat is off (STATE-2, CC-33, MENU-3).
  6. 6 When the page loses its status stream, the trigger keeps its last count drawn as unknown ? with its age, never "0" or a hidden trigger (ACT-5, STATE-3).
  7. 7 An agent started in a terminal that waits for the person raises a condition notice in the notice stack's first group, announced once, with no answer of devhost's own; it clears by itself, announced once, when the agent's state leaves waiting, and Dismiss leaves the waiting look on the trigger until then. An agent chat started raises agent-chat's notice with Answer instead, never both (ACT-7, FB-8, FB-9, SURF-8).
  8. 8 Collapsed, the badge reads the same waiting state in ACT-7's order and the notice stays beside it in its one-line form, so collapsing never hides a waiting agent (SURF-8).

2. Open the list

The list still opens from the trigger, still lists agents devhost did not start, from chat or a terminal, still counts agents working in a subdirectory, folds subagents into the session that started them and sorts waiting agents first, and it still only reports: it sends nothing to an agent. What changes: it opens above docked chat, names every agent in words people use with its checkout, hands a chat agent to its conversation from its row, and says when it is empty, off or could not look. Keys: focus lands in the filter when there is one, else on the first row action, else on Watch Live Activity; Tab and Shift+Tab move through the filter, each row's actions and Watch Live Activity in visual order; Tab past the last control or Shift+Tab before the first closes the list and returns focus to the trigger; Escape or a click outside closes it and returns focus to the trigger, or, when it was opened with the pointer, to the page element that had focus before; keys typed into the filter never reach the page (KEY-5, KEY-6, KEY-7, KEY-8, KEY-10).

  1. 1 An anchored toolbar panel titled "Agents in this checkout". It opens toward the page from the dock's corner and paints above docked chat, compact or expanded, never over the notice stack, so every row action and Watch Live Activity answer hit testing with chat docked; toolbar-shell lands that layering. At every acceptance viewport (1600×1000, 1280×800 and 900×900 in both themes, 1280×800 at 200% zoom) it fits with its status line, every row action and Watch Live Activity reachable, only the rows scrolling, no text clipped and every action at least 24 by 24 CSS pixels; a long folder or checkout path is shortened in the middle, with the full path in its accessible name (SURF-1, SURF-2, SURF-9, CC-1, WORD-8).
  2. 2 One status line: the checkout by its one label, the count and when devhost last looked. Until the first answer the frame reads "Loading agents…" (SEL-4, ACT-12, WORD-8, STATE-1).
  3. 3 An agent chat started: the product name, its conversation's title and edit mode, then its state and folder, and Answer while it waits for the person, Open Conversation otherwise (step 3). Row actions are Tab stops in row order whose accessible names name their target, "Answer Claude Code · Fix the nav header" (SEL-8, WORD-10, REV-9, KEY-10).
  4. 4 An agent started in a terminal: the product name, "in a terminal" and its PID, then its state, folder and last activity, and no action, because devhost never answers for an agent it did not start; while it waits it reads "waiting for you since 14:10 · answer it in its terminal". Codex in a terminal records no pending approval, so it reads "working", as documented (REV-9, MENU-3, WORD-1, WORD-4).
  5. 5 States use one word each, working, waiting for you, idle, and "state not reported" for a CLI that records none (Pi, OpenCode); the folder is the path inside the checkout, "checkout root" for its top folder, never "."; times are local and 24-hour with a relative age, outside every live region. Order: waiting, working, state not reported, idle, newest activity first within each (SEL-4, WORD-3, WORD-6, WORD-7, WORD-8, FB-9).
  6. 6 Agents of the stack's other checkouts follow this checkout's rows after a separator, each naming its checkout, under "Other checkouts of Acme Shop" when there are two or more. A name the CLI gave its session shows as a detail, "named project-37" (SEL-5, MENU-2, CC-38).
  7. 7 Watch Live Activity sits under the rows, outside the scrolling area (SURF-10); step 4 shows where it leads.
  8. 8 The notice stack stays beside the bar, uncovered by the list and by chat (SURF-1, FB-8).
  9. 9 With the dock moved to the top edge, the list opens downward from it, in the same form (SURF-2, SURF-7).
  10. 10 With no agent, "No agents in this checkout" takes the status line's place, and agents of the stack's other checkouts still follow; it never shows while the scan is incomplete or the last request failed (STATE-2, STATE-3, CC-33).
  11. 11 With chat off, the list says why and how to turn it on: Edit opens the Configuration window at that line, and with the config editor off the file and line show with Copy and Open in Editor (STATE-2, MENU-3, MENU-4, CC-33).
  12. 12 When a save turns chat off, the open list and the trigger's accessible description say what happens to running agents; agent-chat's notice names each conversation chat keeps with its state, and the [devtools.chat] setting's description names the running agents list and Watch Live Activity among what it turns off (SEL-11, HOLD-5, CC-18).
  13. 13 When one CLI cannot be listed, the list keeps what the others found and its status line names the agents and the kind of failure without a path, because page scripts can read this record; the path stays in the log line. Check Again leads; Logs opens the pinned log panel on devhost's own lines. The same sentence is the trigger's accessible description. devhost logs one line when a CLI starts failing and one when it recovers, never one per request (MENU-3, MENU-5, HOLD-1, FAIL-2, FAIL-4, FB-7, WORD-7, SURF-13).
  14. 14 Check Again asks for one fresh scan at once, past the 5 s shared scan; while it runs the button keeps focus, busy, reading "Checking…", and the line clears by itself, announced once, when every CLI can be listed again (HOLD-1, KEY-11, FB-9).
  15. 15 When the scan fails for every CLI, the list keeps the rows it last had, drawn as unknown with "last seen 14:02", under one sentence with Check Again and Logs (STATE-3, STATE-4, HOLD-1).
  16. 16 When the page's status stream closes, the rows stay drawn as unknown with their age, and the status line carries the one reason the backend sent: after a stop, the stack, when and the command that starts it, otherwise "Lost connection to devhost; retrying". Notices-and-feedback owns that notice and Retry Now; Answer and Open Conversation still open chat, which names its own block (ACT-5, HOLD-2, STATE-3).
  17. 17 After a switch, the agents still working or waiting in the checkout the stack left stay listed with that checkout; a waiting one keeps Answer and the trigger's waiting look (SEL-5, CC-38).
  18. 18 When the rows overflow the panel's height (a fit test, never an agent count), the list gains a filter, focused on open, that matches product name, conversation title, checkout label and folder as the person types and highlights the match (drawn bold here); a filter that matches nothing names the query with Clear Filter; the status line and Watch Live Activity stay outside the scroll (SEL-10, SURF-10, STATE-2).
  19. 19 While the page's own modal dialog is open, the bar shows its paused state and an open list stays anchored and paused, inert, its rows kept; the notice stack moves into the dialog with the line "Paused while this page's dialog is open", and a terminal agent's waiting notice shows there, announced once; the list is live again when the dialog closes (SURF-11, KEY-7, FB-9).

3. Go to a chat agent's conversation

The list still sends nothing and answers nothing: the person's own answer on agent-chat's decision card stays the one way to act on a chat agent, as the owner settled, and an agent started in a terminal is still answered in its terminal. What changes: the row's action replaces "this chat" and lands on the card or the conversation in one activation. Nothing in this flow writes, so there is no Undo: its outcome is the wait clearing in place after the person's own answer. Keys: Enter or Space on Answer or Open Conversation; from the card, agent-chat's keys apply (KEY-9, KEY-10).

  1. 1 Answer opens docked chat on that conversation in one activation, also for a conversation of another checkout of the stack, which agent-chat makes answerable from this page; the list closes and focus lands in chat, where the person asked to go.   4. 4 After the person's own answer, agent-chat's one write, the trigger turns to working and the wait's end is announced once; the list only reported, so there is no Undo here (ACT-7, FB-9).
  5. 5 Open Conversation on a working chat agent opens docked chat on that conversation with focus in its composer (SEL-8, KEY-6).
  6. 6 For a conversation of another checkout, focus lands on its transcript, which takes no message from this page; agent-chat's composer names both checkouts and offers New Conversation (SEL-8, CC-38).

4. Watch Live Activity

Watch Live Activity still opens in its own tab on the stack machine's loopback address, answers only a direct loopback request, refuses routed hostnames, sends no-store and no-referrer, shows no history, cuts long text at 4,096 characters, keeps at most 500 entries, stops watching when the tab closes and cannot answer an agent, as the owner settled; Restart Stack, a switch and a hot reload keep its connection. What changes: it names what it watches, groups entries under each agent with its state, labels each entry with what a tool call touches, shows an agent waiting for the person, says why it ended instead of reconnecting forever, and the list says when it can open only on the stack's machine. Keys: the page uses the document's standard keys and has no shortcuts of its own; Retry Now and Retry are ordinary buttons (KEY-1).

  1. 1 It opens in its own tab, the one devhost link that does (SURF-15). Its document title reads "Agent activity · Acme Shop", so tabs of two stacks differ, and starts with "Waiting for you · " while an agent waits for the person and with "Could not start · " while its stream cannot start (O16, WORD-1).
  2. 2 The heading names the stack and the checkout it watches, with one state beside it: Live, Lost connection, Stopped or Could not start (SEL-4, HOLD-2).
  3. 3 Entries group under each agent's heading, named as in the list, with its state and since when from the agents record: "answer in the page's chat" for an agent chat started, "answer it in its terminal" for another. The page shows the wait and cannot answer it. An agent starting to wait, and the wait ending, are each announced once in the polite region; entries, elapsed times and streaming text sit outside every live region (SURF-8, ACT-6, ACT-7, REV-9, WORD-6, FB-9).
  4. 4 Each entry is labelled: Tool call with the command a shell tool runs, the path a file tool reads or writes and the lines an edit adds and removes; Result with the tool's output; Denied for a refused call, never "user"; Reply rendered as Markdown with raw HTML shown as text; Prompt for the person's message. Tool inputs travel only on this loopback stream, never to the app's origin (WORD-1, WORD-4, WORD-10).
  5. 5 Newest first and at most 500 entries, as today; a text longer than 4,096 characters says where it was cut (FAIL-2).
  6. 6 On the stack's machine the list's link opens this page in its own tab, as today. The list renders the link only when the agents record says this browser runs on the stack's machine (SURF-15).
  7. 7 On a page opened from another machine, over the network or through a remote preview relay, Watch Live Activity stays in its place as an unavailable control, never a link: no loopback address is rendered, it keeps its Tab stop and announces the sentence beside it, which is its accessible description, and activating it opens nothing. The rows and their hand-offs to chat are unchanged (MENU-3, HOLD-1, HOLD-7, SURF-15).
  8. 8 Until an entry arrives, the page says why it is empty and that it shows no history (STATE-2).
  9. 9 Before closing the stream after a stop, the server sends why: the page stops reconnecting, reads "Stopped" with the reason and the command that starts the stack again, and keeps the entries already shown under "From the run that ended at 14:32" (ACT-10, HOLD-2, STATE-3, SURF-15).
  10. 10 The idle timeout, Ctrl-C in the stack's terminal and devhost stack restart read in the same form, never Reconnecting; a replaced stack's new run listens on a new port this page cannot learn, so the page shows the run ended and how to come back (ACT-10, WORD-7, FAIL-5).
  11. 11 When a save turns chat off, the page says so, stops reconnecting and keeps its entries (SEL-11, HOLD-5).
  12. 12 When the watcher cannot start, the server sends the cause before closing the stream, and the page offers Retry, never Reconnecting (FAIL-2, STATE-4, WORD-7).
  13. 13 When the control server dies without closing the stream, the page keeps its entries and retries after 1, 2, 4 and 8 s and then every 10 s, as today; Retry Now tries at once (HOLD-2, ACT-5, STATE-3).
  14. 14 A turn the person stopped reads "Stopped by you after 29 s" in the neutral style, never as a failure (FAIL-5, WORD-7).
  15. 15 Two agents of one CLI keep separate headings by PID, so their entries never interleave unnamed (WORD-4).
