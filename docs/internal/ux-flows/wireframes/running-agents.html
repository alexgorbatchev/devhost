1. Read the trigger

The trigger still sits among the bar's items, still reads the agents record every 10 s while chat is on and the page is visible, still counts the agents in this worktree and still spins while one works. What changes: it never leaves the bar, shows an agent waiting for the person apart from a working one, also in the app's tab title, and says when devhost could not look. Keys: Alt+Ctrl+B reaches the bar; the trigger is one arrow stop (ArrowLeft, ArrowRight, Home, End); Enter, Space or the arrow that points toward the panel opens the list (KEY-3, KEY-4).

  1. 1 The trigger shows the bot icon, drawn here as "Agents", with the count of agents in this worktree, spins ◐ while any works, and while any listed agent waits for the person takes the waiting look ◆ with "1 waiting", distinct from working in its shape, its text and its accessible name, also in forced colors. 2. Open the list

The list still opens from the trigger, still lists agents devhost did not start, from chat or a terminal, still counts agents working in a subdirectory, folds subagents into the session that started them and sorts waiting agents first, and it still only reports: it sends nothing to an agent. What changes: it opens above docked chat, names every agent in words people use with its worktree, hands a chat agent to its conversation from its row, and says when it is empty, off or could not look. Keys: focus lands in the filter when there is one, else on the first row action, else on Watch Live Activity; Tab and Shift+Tab move through the filter, each row's actions and Watch Live Activity in visual order; Tab past the last control or Shift+Tab before the first closes the list and returns focus to the trigger; Escape or a click outside closes it and returns focus to the trigger, or, when it was opened with the pointer, to the page element that had focus before; keys typed into the filter never reach the page (KEY-5, KEY-6, KEY-7, KEY-8, KEY-10).

  1. 1 An anchored toolbar panel titled "Agents in this worktree". It opens toward the page from the dock's corner and paints above docked chat, compact or expanded, never over the notice stack, so every row action and Watch Live Activity answer hit testing with chat docked; toolbar-shell lands that layering. At every acceptance viewport (1600×1000, 1280×800 and 900×900 in both themes, 1280×800 at 200% zoom) it fits with its status line, every row action and Watch Live Activity reachable, only the rows scrolling, no text clipped and every action at least 24 by 24 CSS pixels; a long folder or worktree path is shortened in the middle, with the full path in its accessible name (SURF-1, SURF-2, SURF-9, CC-1, WORD-8).
  2. 2 One status line: the worktree by its one label, the count and when devhost last looked. Until the first answer the frame reads "Loading agents…" (SEL-4, ACT-12, WORD-8, STATE-1).
  3. 3 An agent chat started: the product name, its conversation's title and mode (This worktree (live) or Make tickets, O1), then its state and folder, and Answer while it waits for the person, Open Conversation otherwise (step 3). Row actions are Tab stops in row order whose accessible names name their target, "Answer Claude Code · Fix the nav header" (SEL-8, WORD-10, REV-9, KEY-10).
  4. 4 An agent started in a terminal: the product name, "in a terminal" and its PID, then its state, folder and last activity, and no action, because devhost never answers for an agent it did not start; while it waits it reads "waiting for you since 14:10 · answer it in its terminal". Codex in a terminal records no pending approval, so it reads "working", as documented (REV-9, MENU-3, WORD-1, WORD-4).
  5. 5 States use one word each, working, waiting for you, idle, and "state not reported" for a CLI that records none (Pi, OpenCode); the folder is the path inside the worktree, "worktree root" for its top folder, never "." (WORD-11); times are local and 24-hour with a relative age, outside every live region. Order: waiting, working, state not reported, idle, newest activity first within each (SEL-4, WORD-3, WORD-6, WORD-7, WORD-8, FB-9).
  6. 6 Agents of the stack's other worktrees follow this worktree's rows after a separator, each naming its worktree, under "Other worktrees of Acme Shop" when two or more agents of other worktrees are listed; a chat agent's mode there carries that worktree's branch, "This worktree (live) · fix-nav" (WORD-10). A name the CLI gave its session shows as a detail, "named project-37" (SEL-5, MENU-2, CC-38).
  7. 7 Watch Live Activity sits under the rows, outside the scrolling area, and opens the address the agents record gives this browser (SURF-10); step 4 shows where it leads.
  8. 8 The notice stack stays beside the bar, uncovered by the list and by chat (SURF-1, FB-8).
  9. 9 With the dock moved to the top edge, the list opens downward from it, in the same form (SURF-2, SURF-7).
  10. 10 With no agent, "No agents in this worktree" takes the status line's place, and agents of the stack's other worktrees still follow; it never shows while the scan is incomplete or the last request failed (STATE-2, STATE-3, CC-33).
  11. 11 With chat off, the list says why and how to turn it on: Edit opens the Configuration window at that line, and with the config editor off the file and line show with Copy; editor integration is removed (STATE-2, MENU-3, MENU-4, SURF-15, CC-33, O51).
  12. 12 When a save turns chat off, the open list and the trigger's accessible description say what happens to running agents; agent-chat's notice names each conversation chat keeps with its state, and the [devtools.chat] setting's description names the running agents list and Watch Live Activity among what it turns off (SEL-11, HOLD-5, CC-18).
  13. 13 When one CLI cannot be listed, the list keeps what the others found and its status line names the agents and the kind of failure without a path, because page scripts can read this record; the path stays in the log line. Check Again leads; Logs opens the pinned log panel on devhost's own lines. 3. Go to a chat agent's conversation

The list still sends nothing and answers nothing: the person's own answer on agent-chat's decision card stays the one way to act on a chat agent, as the owner settled, and an agent started in a terminal is still answered in its terminal. What changes: the row's action replaces "this chat" and lands on the card or the conversation in one activation. Nothing in this flow writes, so there is no Undo: its outcome is the wait clearing in place after the person's own answer. Keys: Enter or Space on Answer or Open Conversation; from the card, agent-chat's keys apply (KEY-9, KEY-10).

  1. 1 Answer opens docked chat on that conversation in one activation, also for a conversation of another worktree of the stack, which agent-chat makes answerable from this page; the list closes and focus lands in chat, where the person asked to go.   4. 4 After the person's own answer, agent-chat's one write, the trigger turns to working and the wait's end is announced once; the list only reported, so there is no Undo here (ACT-7, FB-9).
  5. 5 Open Conversation on a working chat agent opens docked chat on that conversation with focus in its composer (SEL-8, KEY-6).
  6. 6 For a conversation of another worktree, focus lands on its transcript, which takes no message from this page; agent-chat's composer names that conversation's worktree and offers New Conversation (SEL-8, CC-38).

4. Watch Live Activity

Watch Live Activity still opens in its own tab, never on an app's hostname, sends no-store and no-referrer, shows no history, cuts long text at 4 KiB, keeps at most 500 entries, stops watching when the tab closes and cannot answer an agent, as the owner settled; Restart Stack, a switch and a hot reload keep its connection. What changes: it names what it watches, groups entries under each agent with its state, labels each entry with what a tool call touches, shows an agent waiting for the person, says why it ended instead of reconnecting forever, and opens on the stack directory's hostname, on this machine and in a browser elsewhere that signed in with the devhost passkey or paired; the loopback address still answers a direct request from this machine, but nothing links it. Keys: the page uses the document's standard keys and has no shortcuts of its own; Retry Now is an ordinary button (KEY-1).

  1. 1 It opens in its own tab, the one devhost link that does (SURF-15). Its document title reads "Watch Live Activity · Acme Shop", so tabs of two stacks differ, prefixed "(1) waiting · " while an agent waits for the person and "(1) failed · " while its stream cannot start (ACT-7, O16, WORD-1).
  2. 2 The heading names the stack and the worktree it watches, with one state beside it: Live, Lost connection, Stopped or Could not start. The lead line under it says "this worktree" where the page says "this checkout" today (SEL-4, HOLD-2, WORD-11).
  3. 3 Entries group under each agent's heading, named as in the list with the PID added and the mode left out, with its state and since when from the agents record: "answer in the page's chat" for an agent chat started, "answer it in its terminal" for another. The page shows the wait and cannot answer it. An agent starting to wait, and the wait ending, are each announced once in the polite region; entries, elapsed times and streaming text sit outside every live region (SURF-8, ACT-6, ACT-7, REV-9, WORD-6, FB-9).
  4. 4 Each entry is labelled: Tool call with the command a shell tool runs, the path a file tool reads or writes and the lines an edit adds and removes; Result with the tool's output; Denied for a refused call, never "user"; Reply rendered as Markdown with raw HTML shown as text; Prompt for the person's message. Tool inputs travel only on this stream, which no app hostname serves (WORD-1, WORD-4, WORD-10).
  5. 5 Newest first and at most 500 entries, as today; a text longer than 4 KiB says where it was cut (FAIL-2).
  6. 6 On the stack's machine the list's link opens this page on the stack directory's hostname in its own tab, because this machine's browser there counts as this machine; the loopback address keeps answering a direct loopback request, but nothing links it.
