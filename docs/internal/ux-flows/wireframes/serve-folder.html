Serve a folder, port or command

TLDR: Covers all three devhost serve modes — folder (--dir), running port (--port), and command mode (devhost serve -- <command>, foreground or --detach) — plus manifest serve services. The terminal states what is served, where Caddy listens (honoring macOS bindHost from port 1024 upward), that chat is on by default for folder and command sessions with --no-chat to turn it off (and always off for --port), when it is ready, and how to stop it; command sessions appear first-class (1/1 with working Restart Command), handle multi-port changes without false 0/3 outages, exit with the command's exit code in the foreground, and keep valid HTTPS crash recovery when detached; served folders show the listing first with README below; and mistyped names stay in the file browser.

Low-fidelity wireframe. Layout, names and numbers are illustrative; the redesign ticket's acceptance criteria are authoritative.

1. Start a serve session

devhost serve gives a folder, a running port, or a manifest-free command an HTTPS hostname with no devhost.toml, writing nothing in the served folder and starting Caddy on demand. Keys: Ctrl-C at any point during start cancels it, removes what it claimed, stops any spawned command, and reports a cancellation rather than an error (KEY-14, FAIL-5). Agent output (AGENT=1) carries the same facts as devhost: lines with absolute paths and PIDs, and errors as devhost: ERR: / devhost: INFO: lines (WORD-9, FB-11, CC-30).

  1. 1 Every devhost line carries the short label devhost, never an invented serve-<domain> prefix, never over-padded devhost | columns, and never calls a serve session a stack or a primary service (WORD-1, WORD-3, WORD-9).
  2. 2 Under O40, folder and command sessions keep chat ON by default, stated explicitly on line 1 with (pass --no-chat to turn it off) (FB-10, O40).
  3. 3 --no-chat turns chat off for the session: /__devhost__/config.json answers chatEnabled: false and chat routes return 404 (SEL-11, O40).
  4. 4 A --port session routes an external server devhost never starts or stops (ACT-9) and always keeps chat off with empty projectRootPath — it never hands an agent the shell's current folder (O40, serve-folder-04).
  5. 5 Command mode (devhost serve "<cmd>" or devhost serve -- <cmd>, with optional --name, --detach, and -s/--startup-timeout) names the command and working directory directly on line 1.
  6. 6 Every start prints proxy-settings' proxy line after its first line, "Proxy: HTTPS on port 443, every interface, reachable from your network · ~/.config/devhost/config.toml", or on a loopback listener "Proxy: HTTPS on 127.0.0.1:4443 and [::1]:4443, direct connections from this machine only; relay previews and SSH forwards still reach it · …" (WORD-12). Under O39, macOS honors bindHost = "127.0.0.1" from port 1024 upward; below 1024 (including default 443), Caddy keeps listening on every interface without failing startup and prints proxy-settings' macOS warning after the proxy line, naming httpsPort = 4443 or a privileged launcher.
  7. 7 Before the trust password prompt, one line explains what trust does; under AGENT=1 or non-TTY stdin the prompt never runs and one warning points to devhost caddy trust (REV-8, CC-13, UNDO-5).
  8. 8 A taken hostname exits 1 before routing, naming the holding serve session's folder/port/command, PID, start time, and stop command (never "from .") (FAIL-2, WORD-7, WORD-8).
  9. 9 A stack holder names the stack, its worktree label, and its root manifest with devhost stop --manifest (SEL-4, WORD-11).
  10. 10 Spawn failures surface the OS launch error directly on [ERROR]/ERR:, never "command process is unavailable" (serve-command-07).
  11. 11 HTTP probe timeouts state that HEAD / did not receive an HTTP response and suggest --startup-timeout (serve-command-07).
  12. 12 Detached startup failures preserve Failure.hint ([INFO] Read the full log in …) and say the serve session rather than the stack (serve-command-07).
  13. 13 --startup-timeout uses .allow_hyphen_values(true) so negative values give a clear duration error; devhost serve --help Quickstart includes command-mode examples and aligns -s short flags with start/serve.md and reference/cli.md (serve-command-08).

2. Read that it is ready and inspect running sessions

Routes stay active from the start, --port pages reload automatically once their server answers, and the Stack Directory lists every serve session beside manifest stacks. What changes is honest readiness, clean foreground and detached command summaries, first-class command modeling across toolbar and CLI, discoverability in stack commands, and accurate Stack Directory cards.

  1. 1 A folder session prints its ready line once its route answers, with elapsed time, URL, and Ctrl-C cue; a Caddy outage prints one line when Caddy stops and one when the route answers again (FB-5, FB-10, ACT-10, CC-22).
  2. 2 A --port session stays waiting in the terminal until its port first accepts a connection (updating once per second on TTY, no timeout), prints the ready line only once the server answers, logs reachability changes once per transition, and shows startup-and-recovery's not-reachable page with Check Again in the browser (ACT-4, ACT-9, STATE-1, manifest-hot-reload-2-04, serve-folder-01).
  3. 3 Foreground command mode removes pre-startup Stop: headers and over-padded devhost | prefixes, printing its ready summary with session name and Ctrl-C cue once ready (serve-command-03).
  4. 4 Detached command mode prints Started, URL(s), Log:, and Stop: devhost stop --session <name> in both human and AGENT=1 output (serve-command-03).
  5. 5 devhost stack info --session <name> (alias devhost status --session, O62) shows the command string and discovered URLs/ports directly under the command with no synthetic external port-<port> rows (serve-command-02).
  6. 6 devhost stop, stack info/status, stack find, and interactive stack list surface running serve sessions or point to devhost stack list --sessions and --session <name>, while scripted stack list keeps its manifest-only format (serve-command-04).
  7. 7 In the browser toolbar (matching services-panel's seam), a command session counts 1/1, lists the command string with discovered HTTP URLs and ports directly beneath it, omits external badges on its own ports, and omits repeated Services headings (serve-command-02).
  8. 8 The footer omits Restart Changed and offers working Restart Command (operationId, 202 Accepted, manifest-free restart) instead of failing with "stack restart requires an accepted manifest" (serve-command-02, CC-37).
  9. 9 Folder and command toolbars carry the stack-name ▾ chevron (toolbar-shell), leave Chat off the bar when started with --no-chat, because a segment that is off is absent (BAR-5), while the chat entry points that remain, such as Disable Reloads' Send, are unavailable with the O40 chat-off sentence (HOLD-5), and show O36's passkey/pairing prompt to unauthenticated remote browsers (O40, O36, CC-5).
  10. 10 All Stacks on devbox (O61) counts serve sessions separately from manifest stacks, uses singular 1 file for single-file manifests, and filters by folder, port, session name, command, or hostname (WORD-5, SEL-10, serve-folder-11, serve-command-06).
  11. 11 Folder and port cards title by folder or target address (never serve-<domain>), omit Directory lines, never mark a folder's file server External, and drop "Manifest-free file or port session" (serve-folder-11).
  12. 12 Command cards read sessionKind: "command" and command from statuspage::Stack, show the command string, discovered URLs/ports without External, and the exact stop command (serve-command-06).

3. Follow multi-port changes and command exits

Command-mode sessions can open and close multiple HTTP ports during a run and exit after readiness in either foreground or detached mode. Under O63, Caddy uses strict configured-hosts-only TLS, so deleting a route blindly while a user still holds a tab turns every reload into browser ERR_SSL_PROTOCOL_ERROR. This step handles secondary port closure and post-readiness exits cleanly.

  1. 1 Newly discovered ports log with an explicit Added route: label, and the first port explains that the primary hostname aliases that port (FB-10, serve-command-05).
  2. 2 When a secondary port stops listening while the command stays healthy, the terminal logs a labeled Removed route: line rather than dumping unlabeled URLs (serve-command-05).
  3. 3 Before refresh_command_routes removes port 4002's active proxy route, the server sends {"type": "port-closed", "port": 4002, "session": "demoapp", "activeUrls": […]} over /__devhost__/ws/health and closes that stream normally; openReconnectingWebSocket.ts stops retrying and the open tab shows a targeted notice with Open links to remaining active URLs, never painting sibling ports as a false 0/3 outage (ACT-5, HOLD-2, CC-26, serve-command-05).
  4. 4 While the session keeps running, port 4002's hostname keeps a session-scoped 410 status page over valid local HTTPS listing active URLs so reloading never hits ERR_SSL_PROTOCOL_ERROR; stopping the session removes it (O63, serve-command-05).
  5. 5 In foreground mode, post-readiness exit (exit 0 or non-zero) immediately tears down routes, claims, and session record, prints the exit outcome, and exits with the command's own exit code — matching start/serve.md:23 and ending the infinite waiting for a restart hang (serve-command-01).
  6. 6 In detached mode, a post-readiness crash never prints waiting for a restart while deleting routes into ERR_SSL_PROTOCOL_ERROR: devhost keeps the hostname routed over valid local HTTPS to this recovery page with the exit code and frozen recent output lines; a detached clean exit 0 tears down routes and exits cleanly (O63, serve-command-01).
  7. 7 Restart Command on the detached recovery page uses the same manifest-free restart operation (operationId, 202 Accepted) to relaunch the command and restore routes; devhost stop --session demoapp tears down the crashed session (serve-command-01, serve-command-02).

4. Open the folder

Files are still read on every request, reads stay confined to the served folder (hidden files and ../ escapes answer 404), and a folder holding index.html still serves it unchanged as a site. What changes is that the page shows the folder itself, named, ordered, and described, with its README below the listing instead of replacing it. Keys: standard document keys only, no extra shortcuts (KEY-1); Tab moves through the heading path, filter, and rows; Escape clears the filter.

  1. 1 The page's one heading is the path from the served folder's name (never absolute path, never "Directory listing", never rooted at devhost), with each ancestor a same-tab link and the shown folder aria-current="page" (WORD-1).
  2. 2 When the machine does not yet trust devhost's local certificate authority, full file-browser pages render first-run-setup's shared trust line under the heading as a condition, in its one sentence naming the machine (FB-9, WORD-12, SURF-14, O61).
  3. 3 One line counts what the folder holds (WORD-5).
  4. 4 A filter labelled with the folder's name sits above every non-empty listing (SEL-10).
  5. 5 Name, Size, and Modified columns: folders first, then files, each group in natural, case-insensitive order (file2 before file10, alpha before UPPER.TXT); folders end in "/" beside a folder icon, files sit beside a kind icon; binary sizes with one decimal under 10, local 24-hour dates, compact rows at least 24 CSS px tall (ACT-13, WORD-8, SURF-9).
  6. 6 Every name is a same-tab link prefixed with ./ so colon names like notes:2026/, Re: meeting.md, and TODO:list.md open cleanly; rows carry no external-link arrow (SURF-15).
  7. 7 A folder holding index.md, README.md, or readme.md (in that order) shows its listing first and renders the file below under a heading linking to the file's own page, with step 5's view control (serve-folder-05).
  8. 8 The filter narrows rows as you type, highlights matched text, keeps folders first, and announces the count politely (SEL-10, WORD-5).
  9. 9 Zero matches name the folder and query with Clear Filter (SEL-10, STATE-2, WORD-2).
  10. 10 An empty folder renders the shared empty-state block with no filter (STATE-2, SURF-14).

6. Recover from a missing file

Missing paths, hidden files, ../ escapes, and symlinks leaving the folder still answer 404 and reveal nothing. What changes is that devhost's file server keeps the person in the file browser rather than letting document injection swap in a service recovery page with disabled Restart serve, empty logs, internal ports, and a worktree picker. Keys: standard document keys only (KEY-1).

  1. 1 devhost's file server answers document 404s inside the file browser, headed by the path down to the nearest existing folder, for both CLI serve sessions and manifest serve services; startup-and-recovery's document injection leaves it untouched (SURF-16, CC-4, O5).
  2. 2 States the missing name and folder searched in plain words (FAIL-2, WORD-7).
  3. 3 Offers up to three visible close names (case-insensitive, at most two edits away) as same-tab links (MENU-5).
  4. 4 Shows that folder's listing directly below so a typo is one click away from recovery (MENU-5).
  5. 5 Offers no Restart, no worktree list, no internal address, and no logs; tab title starts with the failure (MENU-3, MENU-5, WORD-11, O16).
  6. 6 A missing folder on the path names that folder and lists the deepest existing parent.
  7. 7 Hidden names and out-of-root escapes answer identically to missing files and are never suggested.
  8. 8 Non-document requests receive a single plain-text 404 line.
  9. 9 Manifest serve configuration errors report file, line, column, and key; when the config editor is off, browser rows show the location with Copy only (Open in Editor removed under O51) (MENU-4, FAIL-2, O51).

7. Stop the session

Stopping removes routes, closed-port status routes, hostname claims, and the session record, stops the file server or verified command process tree (ACT-14), leaves Caddy and any --port server running, and keeps exit status 130 for Ctrl-C and 143 for SIGTERM. There is no Undo: the session wrote nothing in the served folder, and the outcome prints the command that starts it again (UNDO-5).

  1. 1 One outcome line names what the stop removed, what keeps running, and elapsed time (KEY-14, FB-10, WORD-4).
  2. 2 Prints the start-again command on its own line with the full path so it works from any folder (UNDO-5).
  3. 3 --port outcomes state that the user's server keeps running (ACT-9); SIGTERM reads as a stop with signal and status 143, never a failure (FAIL-5, WORD-7, WORD-8).
  4. 4 Shutdown shares O30's configurable stopTimeout (5s..10m, default 30s), shows a progress line if slow, and lets a second Ctrl-C or second devhost stop --session force remaining verified process trees within a second while still releasing routes, claims, and records (KEY-14, O30, ACT-14, CC-35).
  5. 5 devhost stop --session <name> prints a clear stop confirmation naming the session, PID, removed URL(s), and what keeps running in both human and AGENT=1 output instead of exiting silently (serve-command-03).
  6. 6 devhost restart-all and devhost upgrade list serve sessions by their WORD-1 names and keep them running (O18, O31, CC-36).
  7. 7 A page left open shows the lost-connection notice with the stop reason (and the collapsed badge shows ? dh · lost connection ▴, or ■ dh · ~/acme/docs stopped at 14:05 ▴ on a known stop), disabling every write with that reason (HOLD-2, ACT-5).
