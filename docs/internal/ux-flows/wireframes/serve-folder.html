Serve a folder or a running port

TLDR: The terminal says what a serve session serves, where Caddy listens, whether chat is on, when it is ready and how to stop it, and a --port session waits for its server instead of claiming it is ready; the folder's page shows the folder itself, folders first in natural order with sizes, dates, a filter and its README below; a mistyped name stays in the file browser; and chat stays off unless --chat names the folder an agent may edit.

Low-fidelity wireframe. Layout, names and numbers are illustrative; the redesign ticket's acceptance criteria are authoritative.

1. Start a serve session

devhost serve still gives a folder or a server already listening on a port an HTTPS hostname with no manifest: --domain stays required and bare, --dir stays relative to the current folder, the session reads no devhost.toml and writes nothing in the folder, and it starts the shared Caddy when Caddy is not running, as today. What changes is what the terminal says: what is served, where Caddy listens, whether chat is on, and, for a taken hostname, who holds it. Keys: Ctrl-C at any point of the start cancels it, removes what it claimed and says so as a cancellation, not an error (KEY-14, FAIL-5). Agent output (AGENT=1) carries the same facts as devhost: lines with absolute paths and PIDs, and the refusal as one devhost: ERR: line holding the holder's kind, folder or port, PID, start time and next steps (WORD-9, FB-11, CC-30).

  1. 1 Every line devhost writes carries the short label devhost, as the output reference already gives lines written before a manifest is read, never an invented stack name such as serve-notes.acme.test or serve (primary), so at 120 columns no line wraps because of its label; today a 37-column invented prefix splits the certificate warning mid-word. No line, page, card or help text calls a serve session a stack or a project (WORD-1, WORD-3, WORD-9).
  2. 2 The first line names what is served, the listener and chat. The listener is what the shared Caddy settings resolve to, so a person serving notes reads that other machines can reach them; with bindHost = "127.0.0.1" where it applies it reads "Caddy listens on 127.0.0.1, port 443", and proxy-settings owns that resolution (FB-10, WORD-8).
  3. 3 A --port session names the server it routes to, which devhost never starts, restarts or stops (owner rule; ACT-9). Without --chat its chat is off: it never gives an agent the shell's current folder (serve-folder-04).
  4. 4 --chat <folder>, relative to the current folder like --dir, turns chat on and names the folder an agent may edit; the header line then says so. Without it chat is off. Who can reach chat from the network stays network-exposure-01's, decided outside this redesign (SEL-11).
  5. 5 Before the trust step's password prompt, one line says what the step does and that it asks for the password, in first-run-setup's words; the prompt runs only when a person at a terminal can answer it, as today, and never under AGENT=1, where one warning tells the agent to have the person run devhost caddy trust in a terminal. An install prints the root's name, its SHA-256 fingerprint and the command that removes it (REV-8, WORD-9, UNDO-5, CC-13).
  6. 6 A taken hostname is refused before anything is routed, with exit status 1 and nothing left running, as today; the refusal now names the holder in the person's terms, its folder or port, PID and start time, and how to stop it, and never prints "from ." or an empty path (FAIL-2, WORD-7, WORD-8).
  7. 7 A stack holder is named by its name, its checkout label and its root manifest, with devhost stop --manifest as the command, in stack-run-stop's words for a stack (SEL-4, FAIL-2).

2. Read that it is ready

The hostname is still routed from the start, a --port page still reloads into the app once the port answers, and the stack directory still lists serve sessions beside manifest stacks, read-only with links, as today. What changes is that the session says when it is ready, a --port session waits for its server instead of printing its URL as if it answered, and every surface names the session by its folder or its port.

  1. 1 A folder session prints its ready line once its route answers: the elapsed time, the URL and how to stop it (FB-5, FB-10, KEY-14, WORD-4, CC-22).
  2. 2 A --port session is starting until its port first accepts a connection: on a terminal it keeps one status line updated at least once a second, and without a terminal it prints that line once. It waits as long as the person lets it, with no timeout, because starting the server after the route is the ordinary order of work (FB-5, ACT-4, STATE-1).
  3. 3 The ready line follows only once the port answers, never before; today the URL prints at once, while nothing listens (FB-5).
  4. 4 After the ready line, a target that stops answering prints one line, and one when it answers again, never one line per check (ACT-9, FAIL-4, FB-10).
  5. 5 A page opened while the session waits shows startup-and-recovery's not-reachable page with Check Again, never a disabled Restart or an empty log, and reloads into the app once the port answers. In the browser the target reads reachable or not reachable, never starting, failed or exited (ACT-9, MENU-5, MENU-3).
  6. 6 While the shared Caddy is stopped, the session prints one line, and one when its route answers again, as ACT-10 gives a stack. A rejected change to the devhost config file leaves the session on the running shared Caddy settings and prints nothing of its own (ACT-10, FB-10, HOLD-6).
  7. 7 The toolbar names the session by its folder or port, shortened in the middle when long with the full label in its tooltip and accessible name, and its one service by the same label: a folder session's file server reads running, and a --port target reachable or not reachable with its check and time, from services-panel's shared state indicator. toolbar-shell draws the name and keeps the toolbar's placement per served folder (WORD-1, WORD-8, ACT-2, ACT-9, SURF-14, SURF-7, CC-5).
  8. 8 With chat off, the toolbar's chat entry points are unavailable with one reason, its way out included, which agent-chat draws; with --chat ~/acme/docs, chat behaves as in a stack, its agent editing that folder (HOLD-5, MENU-3).
  9. 9 The directory's counts name serve sessions apart from stacks, so no count calls a serve session a stack (WORD-1, WORD-5).
  10. 10 A serve session's card is titled by its folder, or its target for a --port session, shortened in the middle when long, with the absolute folder or the address in its tooltip and accessible name, and never serve-notes.acme.test; a kind label beside it says "Serve session · folder" or "· port". The hostname URL stays the card's main link. There is no Directory line, so a --port card never shows the folder its command ran in. Two sessions of one folder on two hostnames are two cards told apart by their links (WORD-1, WORD-8).
  11. 11 The card's one row comes from the shared state indicator: running for a folder session's file server, which devhost runs; reachable or not reachable with its check, its time and "runs outside devhost" for a --port target, whose hostname link opens the not-reachable page with Check Again. Neither reads External (ACT-2, ACT-9, ACT-13, MENU-5, SURF-14).
  12. 12 Configuration's root manifest line says the session reads no devhost.toml, never "Manifest-free file or port session"; the details line says how to stop it, in the refusal's words (MENU-6, SEL-6, WORD-8).
  13. 13 The filter finds a session by its name, so "3000" or "acme/docs" keeps its card, and by its hostname (SEL-10).

3. Open the folder

Files are still read on every request, so a reload shows edits and new files; reads stay confined to the served folder, with hidden files and ../ escapes answering 404; and a folder holding index.html still serves it unchanged, as a site, as today. What changes is that the page shows the folder itself, named, ordered and described, with its README below the listing instead of in its place. Keys: the page keeps the document's standard keys and adds no shortcuts (KEY-1); Tab moves through the heading path's links, the filter, then each row's link in order; Escape in the filter clears it, as the browser does.

  1. 1 The page's one heading is the path: the served folder's name, then each folder down to the one shown, each ancestor a same-tab link and the shown folder plain text with aria-current="page". The served folder's absolute path never appears, and the tab title starts with the same path. Today every listing is headed "Directory listing" under a breadcrumb rooted at devhost (WORD-1).
  2. 2 One line counts what the folder holds (WORD-5).
  3. 3 A filter labelled with the folder's name sits above every non-empty listing (SEL-10).
  4. 4 Name, Size and Modified columns: folders first, then files, each group in natural, case-insensitive order (file2 before file10, alpha before UPPER.TXT); a folder's name ends in "/" beside a folder icon and a file's sits beside an icon of its kind, so neither is told by the icon alone. Sizes use binary units with one decimal under 10, folders show none, and times are local and 24-hour: today "14:02", this year "Nov 15 14:02", older "Nov 15, 2025". Rows are compact, at least 24 CSS pixels tall (ACT-13, WORD-8, SURF-9).
  5. 5 Every name is a same-tab link built as a path relative to the folder with ./ in front, so "Re: meeting.md", "TODO:list.md" and "notes:2026/" open like any other name; today a name that starts with a word and a colon reads as a URL scheme and goes nowhere. Rows carry no external-link arrow, because nothing on these pages opens a new tab (SURF-15).
  6. 6 A folder holding index.md, README.md or readme.md, in that order, shows its listing first and that file rendered below it, under a heading that names the file and links to its own page, with step 4's view control. Every entry of the folder, the files the README never links to included, is one click from the folder's URL.
  7. 7 The filter narrows the rows as the person types, by name, highlights the matched text (drawn in bold here), keeps folders before files, and says the count, announced politely (SEL-10, WORD-5).
  8. 8 With no match it names the folder and the query, with Clear Filter, which restores every row (SEL-10, STATE-2, WORD-2).
  9. 9 An empty folder says so in the shared empty-state block, with no filter (STATE-2, SURF-14).

4. Read a Markdown file

Keys: Tab reaches Rendered and Source, and Enter or Space presses one; the page adds no shortcuts (KEY-1).

  1. 1 The heading path ends with the file's name, and the tab title starts with it (WORD-1).
  2. 2 Two buttons, Rendered and Source, the active one pressed (aria-pressed="true", drawn selected here), so the control shows the view and its labels are not actions. 5. Recover from a missing file

A name that does not exist under the served folder still answers status 404, and hidden files, ../ escapes and symbolic links that leave the folder still answer as missing names and reveal nothing, as today. What changes is who answers the page: devhost's file server keeps the person in the file browser, where today a mistyped name shows a service recovery page with a disabled Restart serve, empty logs, the file server's internal address and, in a manifest serve service, a worktree picker. Keys: the page keeps the document's standard keys (KEY-1).

  1. 1 devhost's file server answers the page load with status 404 and a page inside the file browser, headed by the path down to the nearest folder that exists. The same page answers for a CLI serve session and a manifest serve service, and startup-and-recovery's document injection never replaces it (SURF-16, CC-4, O5).
  2. 2 The failure in words, naming the missing name and the folder searched (FAIL-2, WORD-7).
  3. 3 Up to three names of that folder closest to the missing one, ignoring case and at most two edits away, as same-tab links (MENU-5).
  4. 4 Then that folder's listing, as step 3 draws it: the nearest listing leads, because it is what can fix a typo (MENU-5).
  5. 5 The page offers no Restart, no checkout list, no internal address and no logs, because a typo is no service's failure. Its tab title starts with the failure (MENU-3, MENU-5, O16).
  6. 6 A missing folder on the way names that folder and lists the deepest folder that exists.
  7. 7 A hidden name, or a link that leaves the served folder, gets the same page as any missing name and is never offered as a close name, as today.
  8. 8 A request that is not a page load gets one line of text with status 404.
  9. 9 A manifest serve service shows these same pages with its stack's toolbar. A serve folder the manifest declares wrongly is rejected with the file, line, column and key, in manifest-hot-reload's and stack-run-stop's structured error, and so is each key serve rejects (cwd, env, injectPort, lifecycle, proxyLocalOrigin, watch, managed = false, a process-only health check) (MENU-4, FAIL-2).
  10. 10 A file or folder that exists but cannot be read answers status 500 inside the file browser with one sentence, Retry, which reloads the page, and the heading path to its folder; never "Could not read document" as plain text and never a recovery page (STATE-4, FAIL-2).

6. Stop the session

Ctrl-C still ends the session: it removes the route and the hostname claim and stops the file server, Caddy keeps running, a --port server keeps running, and the exit status stays 130 after Ctrl-C and 143 after SIGTERM, as today. There is no Undo: the session wrote nothing in the folder, and the printed command is its way back (UNDO-5). Keys: a second Ctrl-C while it stops forces the rest within a second, as for a foreground stack (KEY-14).

  1. 1 One outcome line names what the stop removed and what keeps running, with the time it took (KEY-14, FB-10, WORD-4).

  5. 5 A page left open shows the lost connection with the reason the session sent before its stream closed, and every write on the page is unavailable for that reason; notices-and-feedback words the notice (HOLD-2, ACT-5).
