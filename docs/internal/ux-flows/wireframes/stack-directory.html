2. Read every stack at a glance

The page still lists every stack on the machine in a single column, works without the toolbar and answers this machine only unless stackDirectoryAllowRemote is set. What changes is that it leads with what needs the person, and that each card reads apart from its neighbours. Keys: the document's standard keys only; the page binds none (KEY-1). Tab goes from the filter to Refresh Stacks, then through each card's links and actions in row order; cards and rows are not Tab stops, and each action's accessible name names its target (KEY-10).

  1. 1 The heading reads "Stacks on this machine", and one totals line counts what needs the person first; the count of URLs goes (ACT-6, WORD-5, O16).
  2. 2 The document title starts with the same attention, so a background tab shows a failure or a waiting agent; with nothing that needs the person it reads "Stacks on this machine" (O16).
  3. 3 One line says once what the page cannot do and where that happens instead; it ends "· readable from your network" while stackDirectoryAllowRemote is on (MENU-3, MENU-6, O10).
  4. 4 The filter (step 5) and Refresh Stacks (step 4) come first, each a control of its own; "Updated 17:15:02" is the age of what the page shows (SEL-10, ACT-12).
  5. 5 Three groups, each headed with its count and shown only when it holds a card: "Needs you" (a failed stack or one with an agent waiting for the person), "Running" (every other live stack, starting, changing and stopping ones included) and "Stopped recently" (step 3). Within a group, stacks sort by name, then the main checkout before its worktrees, then by branch, then by start time (ACT-6, SEL-4, SEL-10).
  6. 6 Each card names its stack, then its checkout label: the branch, or "Detached" with the 7-character commit, then the path shortened with ~, so two checkouts of one project read apart. Then the stack state word and its summary; a blocked repository is said once, with its way back on the status page and Check Again, which reads that stack's checkout list again and stops nothing (SEL-4, WORD-1, ACT-6, HOLD-4, HOLD-1).
  7. 7 An agent waiting for the person is a link on its stack's card, with the agent, the conversation, its checkout and since when; step 6 shows where it leads (ACT-6, REV-9).
  8. 8 With nothing running and nothing stopped within O15's 24 hours, the page reads one sentence and nothing else; with stacks stopped recently and none running, that sentence heads the page above "Stopped recently" (STATE-2, ACT-10, O15).

3. Read a stack's card

A card still lists every service with its hostnames, aliases and path routes as links, and services a partial start left out as not started. What changes is where its words come from: every state, word and shape on a card comes from the state the stack's services runtime publishes, the one the toolbar, the status pages and devhost status read; the directory never works out a state of its own, and no state is a default (ACT-2, FB-11).

  1. 1 The stack's name is the card's heading, then its checkout label. The folder appears once, in the label, shortened in the middle when long, with the full path in its tooltip and accessible name; the raw "Registered" timestamp and the absolute folder under every row go. A stack whose repositories run from more than one checkout names each checkout over its repository's rows (SEL-4, SEL-6, WORD-8).
  2. 2 The stack state word, then the summary, which counts every service of the manifest with the states that need the person first; a changed service counts as running. One shared summary builder writes it for this card and for the toolbar's Services trigger, so the two never differ (ACT-6, WORD-5, WORD-6).
  3. 3 The PID and how the stack runs are details; times are local and 24-hour, and the ISO time is only in copyable details (WORD-8).
  4. 4 One line per condition that needs the person, in ACT-7's order: a blocked repository, a manifest file not applied (step 7), each agent waiting (step 6). A failed or exited service shows in its row and counts in the summary, never as a second line (ACT-7).
  5. 5 The last operation's outcome, the sentence devhost status prints for the same record, in a quiet line, or in the failure style while it failed: "Last: Restart Stack: 5 of 6 running · api exited with code 1 before its health check · 17:22" (FB-2, FB-3, FB-11, ACT-1, WORD-4).
  6. 6 Each row draws services-panel's shared service state indicator, shape, word and accessible name, from the status pages' stylesheet, so ✕ exited never looks like ○ not started, also in forced colors. Changed is a detail of the row, and a service's folder shows only where it differs from the stack's ("backend/"). A route link answers; a path route with no page of its own shows as copyable text, as in the Services panel (SURF-14, ACT-13, ACT-8, SURF-15).
  7. 7 An exited service shows its code and time with its last output line; its route opens devhost's status page for it, so the link says so, and its way forward is the restart that page offers with the same action's terminal command and Copy (step 6) (FAIL-3, MENU-5, MENU-6, CC-11).
  8. 8 A service the run left out is counted and listed in its place as not started, with why ("left out of this run" or "stopped by you") and the start it can have; until startup-and-recovery's not-started status page answers its hostname, the hostname shows as text (SEL-7, ACT-2, O10).
  9. 9 Starting shows its health check with the elapsed time of the timeout, or the dependency it waits for; restarting, stopping and switching show their step and offer no action. A daemon service reads what its status check last found, never running by default (ACT-3, ACT-4, MENU-5).
  10. 10 A live process that stops answering its health check reads failed, never running in green; a service killed from outside reads terminated by its signal, with its status; one whose dependency failed stays running and names it (ACT-2, FAIL-3, WORD-7).
  11. 11 An external service reads reachable or not reachable from devhost's own check, with the check and its time, and says once that it runs outside devhost; Check Again runs its check now (ACT-9, MENU-3, HOLD-1).
  12. 12 A deleted saved checkout blocks its repository: the condition says once why, and each of its services that does not run reads blocked, never starting or running; a service still running from the deleted checkout reads running under that condition (HOLD-4, HOLD-1, ACT-2).
  13. 13 A stack that stopped within O15's 24 hours keeps its card with when and why it stopped and the command that starts it again, with Copy; its hostnames are text, because for that time they answer stack-run-stop's stopped-stack page (ACT-10, STATE-2, STATE-3, UNDO-5, CC-27).
  14. 14 A killed stack names each service process stack-run-stop found still running, with devhost stop in its folder, because a stack reads stopped only when nothing of it remains (ACT-11).

4. Keep the view current

Each stack is still asked over loopback with a 2 s deadline, in parallel, so one busy stack never holds the others up. What changes is that the page keeps asking while it is visible, through GET /stacks.json on the directory hostname, and updates every card, row, summary, total and the title in place, without a reload. A stack that starts appears in its group, one that stops moves to "Stopped recently" with its reason, one that devhost stack replace replaced keeps its card with the new PID and "replaced at 14:12", each announced once (ACT-12, ACT-3, ACT-10).

  1. 1 Within 4 s of the kill the row reads its signal and status, the summary, totals and title follow, and Acme Shop moves to "Needs you" once focus is outside its card: a focused card keeps its place until focus leaves it. The page reads every 2 s after the previous read ended, never overlapping, nothing while the tab is hidden and at once when it shows. The page's one announcer says "Acme Shop: reports terminated by SIGTERM" once, in its assertive region; changes that start or end a need of the person are announced once per stack, reports within one second merge, and ticking times are never announced (ACT-12, FB-9, KEY-6, ACT-7).
  2. 2 Refresh Stacks reads every stack at once: it keeps focus while busy, "Refreshing Stacks…" with aria-busy, then the status line reads "Updated 21:53:38"; it is never a side effect of filtering (SEL-10, FB-1, FB-2, KEY-11, WORD-4).
  3. 3 A stack that does not answer within 2 s keeps its last known rows drawn as unknown, never stopped or failed, with Copy Error holding the original error, never Go's error text on the card, and the totals count it, "1 unknown". The directory lists a stack only while its devhost process runs, so the card says how to resume a paused one: fg in its terminal, or the debugger. Such a stack never holds the page: Caddy's health checks skip it within about 3 s and another running stack serves the page. After fg it is live again at the next read; the announcer says once that it stopped answering and once that it answers again (ACT-5, STATE-3, STATE-4, ACT-11, WORD-6, FB-9; the MENU-5 exception of step 6).
  4. 4 When no read succeeds, one status sentence gives the age of what the page shows and its cause, or that the directory moved, with its new address, which proxy-settings words. The page keeps asking every 2 s while visible, Refresh Stacks asks at once and keeps focus, and the first read that succeeds draws the live directory in place; the announcer says once that the condition started and once that it ended, "Stacks answer again · 2 stacks" (STATE-4, ACT-5, HOLD-2, FB-9).
  5. 5 A page load while no stack answers, after a crash, a kill or with every stack's devhost process paused, gets devhost's directory with status 503, never one line of plain text: Caddy's error handler serves the page devhost last wrote, with the stacks registered then, each unknown with when it was last seen, its PID, how to resume a paused devhost process and its two commands, and the stacks that stopped recently. It retries as above and draws the live directory within 4 s after a stack answers. The next devhost command that finds a stack's devhost process gone, devhost stack list included, writes its stopped-stack record and rewrites the directory without its control port, so later loads answer at once with it under "Stopped recently" (STATE-4, FAIL-2, ACT-10, ACT-11, O15).
  6. 6 That page's title starts "No stack answered", and its heading comes before the status code in reading order (O16, FB-9).
  7. 7 A fetch, a script or an agent's curl gets 503 with Retry-After: 2 and one line under 2 KB, never the page; the page's own /stacks.json gets the static data with 503 (FB-11, SURF-16).
  8. 8 A stack record devhost cannot read is named in plain words above the groups, and the directory still lists every stack it can read; Copy Error holds Go's error and the file's full path, neither shown on the page, and an unreadable file reads "devhost is not allowed to read it. Make it readable, or remove it if no stack uses it." The condition is announced once when it appears (STATE-4, FAIL-2, WORD-7, WORD-8).

5. Filter as you type

The filter keeps its place above the cards, and a saved link with ?q= keeps working. What changes is that it filters the cards on the page as the person types, with no form, no reload and no request; today it waits for Enter, reloads the whole page through every stack and returns whole stacks unmarked. Keys: the field keeps its own keys; Escape clears it as a search field does, Enter does nothing more, and no key typed in it reaches anything but the field (KEY-9, KEY-1, KEY-5).

  1. 1 The field "Filter stacks and services" narrows the cards at once; the query is kept in the page's address as ?q= without a reload, so a reload or a shared link keeps it, and once typing pauses the announcer says the number of matches politely, "1 stack matches "search"" (SEL-10, FB-9).
  2. 2 It matches stack name, checkout label (branch, commit ID prefix and path), service names and hostnames, ignoring case, never a manifest file's or the devhost config file's path. A stack whose name or checkout matches keeps every row; any other stack keeps only its matching rows, with one line for the rest. The matched text is highlighted, underlined in this drawing (SEL-10, BAR-3, WORD-5).
  3. 3 Each group header counts what it shows, "Running · 1 of 2", while the totals line keeps counting the whole machine (SEL-10, WORD-5).
  4. 4 No match names the query, with Clear Filter, which empties the field and returns focus to it; it replaces today's "Clear filter" and "Show all stacks" (STATE-2, WORD-2, KEY-6).

6. Open a service, or the page that fixes it

What changes is that every state it draws has its way forward one step away. Being read-only, it never acts on what it shows: a link reaches the hostname, which answers with its current state, and Copy copies the command from the latest read (REV-13).

  1. 1 A route of a service that is not running opens devhost's status page for it, which leads with that cause's action, here Restart reports; a route of a running service opens the app (SURF-15, MENU-5).
  2. 2 Each state's lead action as text with its terminal command and Copy: exited or failed, "Restart it on its status page, or run …"; not started, "Start it on its status page, or run …"; stopped recently, the start command (step 3); a blocked repository, the way back on its status page with Check Again, and no command, because a switch has none (MENU-5, MENU-6, CC-11, HOLD-4).   3. 3 Check Again keeps focus while busy, "Checking search…", and its result replaces the row's state and time; on a blocked repository it reads that stack's checkout list again and stops nothing (ACT-9, HOLD-1, HOLD-4, KEY-11).
  4. 4 Starting, restarting, stopping and switching offer no action: the row shows its progress (MENU-5).
  5. 5 When the browser refuses the clipboard, the failure stays beside Copy and the command stays as selectable text (FAIL-2, WORD-7).
  6. 6 Read from another machine, Check Again is unavailable, with its reason beside it and as its accessible description (MENU-3, HOLD-1).
  7. 7 The waiting agent's link opens a page of its stack in the same tab, with docked chat on that conversation's decision card, in one activation; the app's URL keeps no parameter or fragment of devhost's, and the conversations of every checkout of the stack are listed, the configured checkout first. devhost never answers for the person, and the directory cannot (ACT-6, REV-9, SURF-8, CC-38).
