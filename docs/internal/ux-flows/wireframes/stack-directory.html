Low-fidelity wireframe. Layout, names and numbers are illustrative; the redesign ticket's acceptance criteria are authoritative.

1. Reach the directory from where you are

The directory keeps its address, devhost.acme.test here, and a link saved with ?q=search still opens it with that query in the filter. What changes is that every surface that knows about stacks leads there, because devhost never opens a browser; today nothing does, and the address comes from the docs (SURF-15, MENU-1).

  1. 1 All Stacks on devbox sits in the stack name menu's one group of toolbar items, after Reset to Manifest Default with no separator, and opens the directory in the same tab, with no target; "devbox" is the machine name, machineName in the devhost config file, else the host name up to its first dot. toolbar-shell draws the menu and its keys; this flow defines where the item leads: the directory's current address from the applied shared Caddy settings, read when the menu opens, so after proxy-settings moves the directory to port 4443 the item links https://devhost.acme.test:4443/, never the old address; on a page opened through the remote or relay suffix it links the directory under that suffix (MENU-1, MENU-2, WORD-2, SURF-15, O61).
  2. 2 devhost start prints the directory's URL after its ready line with the page's own words, and devhost stack list on a terminal and devhost stack info (devhost status) print it too (stack-run-stop's slice). The plain-HTTP 404 (step 8), stack-run-stop's stopped-stack page and startup-and-recovery's status pages carry the same link (SURF-15, O61, O62).

2. Read every stack at a glance

The page still lists every stack and serve session on the machine in a single column and works without the toolbar. What changes is that it leads with what needs the person, and that each card reads apart from its neighbours. Keys: the document's standard keys only; the page binds none (KEY-1). Tab goes from the filter to Refresh Stacks, then through each card's links and actions in row order; cards and rows are not Tab stops, and each action's accessible name names its target (KEY-10).

  1. 1 The document title starts with ACT-7's attention prefix, the number of stacks that need the person and what they need, so a background tab shows a failure or a waiting agent; with nothing that needs the person it reads "Stacks on devbox" (ACT-7, O16).
  2. 2 The heading names the machine, "Stacks on devbox", and one totals line counts what needs the person first, serve sessions apart from stacks; the count of URLs goes (ACT-6, WORD-1, WORD-5, O61).
  3. 3 One line says once what the page cannot do and where that happens instead; it ends "· readable from your network without signing in" while stackDirectoryAllowRemote is on (step 9) (MENU-3, MENU-6, O10, O47).
  4. 4 The filter (step 5) and Refresh Stacks (step 4) come first, each a control of its own; "Updated 17:20:02" is the age of what the page shows (SEL-10, ACT-12).
  5. 5 Three groups, each headed with its count and shown only when it holds a card: "Needs you" (a failed stack or one with an agent waiting for the person), "Running" (every other live stack and serve session, starting, changing and stopping ones included) and "Stopped recently" (step 3). Within a group, stacks sort by name, then the main worktree before its linked worktrees, then by branch, then by start time (ACT-6, SEL-4, SEL-10, WORD-11).
  6. 6 Each card names its stack, then its worktree label: the branch, or "Detached" with the 7-character commit, then the path shortened with ~, so two worktrees of one project read apart. Then the stack state word and its summary; a blocked repository's label names the saved worktree it cannot load, and the block is said once, with its way back on the status page and Check Again, which reads that stack's worktree list again and stops nothing (SEL-4, WORD-1, WORD-11, ACT-6, HOLD-4, HOLD-1).
  7. 7 An agent waiting for the person is a link on its stack's card, with the agent, the conversation, its worktree and since when; step 6 shows where it leads (ACT-6, REV-9).
  8. 8 A serve session uses serve-folder's card: titled by its folder, target address or session name, with its kind beside the title and, for a command session, its command; never a stack name devhost invented (WORD-1).
  9. 9 With nothing running and nothing stopped within O15's 24 hours, the page reads one sentence and nothing else; with stacks stopped recently and none running, it lists them under its heading and totals with no empty sentence, as STATE-2 gives that sentence only when nothing stopped recently. A stack whose run lasted under a minute is not listed; Copy copies cd ~/blog && devhost start, which works from any folder (STATE-2, ACT-10, O15, O61).

3. Read a stack's card

A card still lists every service with its hostnames, aliases and path routes as links, and services a partial start left out as not started. What changes is where its words come from: every state, word and shape on a card comes from the state the stack's services runtime publishes, the one the toolbar, the status pages and devhost stack info read; the directory never works out a state of its own, and no state is a default (ACT-2, FB-11, O62).

  1. 1 The stack's name is the card's heading, then its worktree label. The folder appears once, in the label, shortened in the middle when long, with the full path in its tooltip and accessible name; the raw "Registered" timestamp and the absolute folder under every row go. A stack whose repositories run from more than one worktree names each worktree over its repository's rows (SEL-4, SEL-6, WORD-8, WORD-11).
  2. 2 The stack state word, then the summary, which counts every service of the manifest with the states that need the person first; a changed service counts as running. One shared summary builder writes it for this card and for the toolbar's Services trigger, so the two never differ (ACT-6, WORD-5, WORD-6).
  3. 3 The PID and how the stack runs are details; times are local and 24-hour, and the ISO time is only in copyable details (WORD-8).
  4. 4 One line per condition that needs the person, in ACT-7's order: a blocked repository, a manifest file not applied (step 7), each agent waiting (step 6). A failed or exited service shows in its row and counts in the summary, never as a second line (ACT-7).
  5. 5 The last operation's outcome, the sentence devhost stack info prints for the same record, with its origin, in a quiet line, or in the failure style while it failed: "Last: Restart Stack: 5 of 6 running · api exited with code 1 before its health check · 17:22" (FB-2, FB-3, FB-11, ACT-1, WORD-4).
  6. 6 Each row draws services-panel's shared service state indicator, shape, word and accessible name, from the status pages' stylesheet, so ✕ exited never looks like ○ not started, also in forced colors. Changed is a detail of the row, and a service's folder shows only where it differs from the stack's ("backend/"). A route link answers, its arrow kept beside the address; a path route with no page of its own shows as copyable text, as in the Services panel (SURF-14, ACT-13, ACT-8, SURF-15).
  7. 7 An exited service shows its code and time with its last output line; its route opens devhost's status page for it, so the link says so, and its way forward is the restart that page offers with the same action's terminal command and Copy (step 6) (FAIL-3, MENU-5, MENU-6, CC-11).
  8. 8 A service the run left out is counted and listed in its place as not started, with why ("left out of this run" or "stopped by you"); its hostname links startup-and-recovery's not-started status page, which offers Start (SEL-7, ACT-2, O10).
  9. 9 Starting shows its health check with the elapsed time of the timeout, or the dependency it waits for; restarting, stopping and switching show their step and offer no action. A daemon service reads what its status check last found, never running by default (ACT-3, ACT-4, MENU-5).
  10. 10 A live process that stops answering its health check reads failed, never running in green; a service killed from outside reads terminated by its signal, with its status; one whose dependency failed stays running and names it (ACT-2, FAIL-3, WORD-7).
  11. 11 An external service reads reachable or not reachable from devhost's own check, with the check and its time, and says once that it runs outside devhost; Check Again runs its check now (ACT-9, MENU-3, HOLD-1).
  12. 12 A deleted saved worktree blocks its repository: the card's label names that worktree as deleted, the condition says once why, as a failure, and each of its services that does not run reads blocked, never starting or running; a service still running from the deleted worktree reads running under that condition (HOLD-4, HOLD-1, ACT-2).
  13. 13 A stack that stopped within O15's 24 hours after a run of at least a minute keeps its card with when and why it stopped and the command that starts it again from any folder, with Copy, as the pattern reference draws it; its hostnames stay links, because for that time they keep their HTTPS routes and answer stack-run-stop's stopped-stack page (ACT-10, STATE-2, STATE-3, UNDO-5, O15, O63, CC-27).
  14. 14 A killed stack names each service process stack-run-stop found still running, with devhost stop in its folder, because a stack reads stopped only when nothing of it remains (ACT-11).
  15. 15 At 320 CSS pixels each row keeps its state's shape and word beside the service's name and the same content as the wide card, a route's arrow stays beside its address, the lead action, its command and Copy stack one per line instead of truncating, the rows align with the card's header and every control stays at least 24 CSS pixels (ACT-13, SURF-9, O8).

4. Keep the view current

Each stack is still asked over loopback with a 2 s deadline, in parallel, so one busy stack never holds the others up. What changes is that the page keeps asking while it is visible, through GET /stacks.json on the directory hostname, and updates every card, row, summary, total and the title in place, without a reload. A stack that starts appears in its group, one that stops moves to "Stopped recently" with its reason, one that devhost stack restart, devhost restart-all or devhost upgrade replaced keeps its card with the new PID and "replaced by devhost stack restart at 14:12", each announced once (ACT-12, ACT-3, ACT-10, O18).

  1. 1 Refresh Stacks reads every stack at once: it keeps focus while busy, "Refreshing Stacks…" with aria-busy, then the status line reads "Updated 21:53:38"; it is never a side effect of filtering (SEL-10, FB-1, FB-2, KEY-11, WORD-4).
  2. 2 Within 4 s of the kill the row reads its signal and status, the summary, totals and title follow, and Acme Shop moves to "Needs you" once focus is outside its card: a focused card keeps its place until focus leaves it. The page reads every 2 s after the previous read ended, never overlapping, nothing while the tab is hidden and at once when it shows. The page's one announcer says "Acme Shop: reports terminated by SIGTERM" once, in its assertive region; changes that start or end a need of the person are announced once per stack, reports within one second merge, and ticking times are never announced (ACT-12, FB-9, KEY-6, ACT-7).
  3. 3 A stack that does not answer within 2 s keeps its last known rows drawn as unknown, never stopped or failed, with Copy Error holding the original error, never the raw error text on the card, and the totals count it, "1 unknown". The directory lists a stack only while its devhost process runs, so the card says how to resume a paused one: fg in its terminal, or the debugger. Such a stack never holds the page: Caddy's health checks skip it within about 3 s and another running stack serves the page. After fg it is live again at the next read; the announcer says once that it stopped answering and once that it answers again (ACT-5, STATE-3, STATE-4, ACT-11, WORD-6, FB-9; the MENU-5 exception of step 6).
  4. 4 When no read succeeds, one status sentence gives the age of what the page shows and its cause, or that the directory moved, with its new address, which proxy-settings words. The page keeps asking every 2 s while visible, Refresh Stacks asks at once and keeps focus, and the first read that succeeds draws the live directory in place; the announcer says once that the condition started and once that it ended, "Stacks answer again · 2 stacks" (STATE-4, ACT-5, HOLD-2, FB-9).
  5. 5 That page's title starts "No stack answered", and its heading comes before the status code in reading order (O16, FB-9).
  6. 6 A page load while no stack answers, after a crash, a kill or with every stack's devhost process paused, gets devhost's directory with status 503, never one line of plain text: Caddy's error handler serves the page devhost last wrote, with the stacks registered then, each unknown with when it was last seen, its PID, how to resume a paused devhost process and its two commands, and the stacks that stopped recently. It retries as above and draws the live directory within 4 s after a stack answers. The next devhost command that finds a stack's devhost process gone, devhost stack list included, writes its stopped-stack record and rewrites the directory without its control port, so later loads answer at once with it under "Stopped recently" (STATE-4, FAIL-2, ACT-10, ACT-11, O15).
  7. 7 A fetch, a script or an agent's curl gets 503 with Retry-After: 2 and one line under 2 KB, never the page; the page's own /stacks.json gets the static data with 503 (FB-11, SURF-16).
  8. 8 A stack record devhost cannot read is named in plain words above the groups, and the directory still lists every stack it can read; Copy Error holds the original error and the file's full path, neither shown on the page, and an unreadable file reads "devhost is not allowed to read it. Make it readable, or remove it if no stack uses it." The condition is announced once when it appears (STATE-4, FAIL-2, WORD-7, WORD-8).

5. Filter as you type

The filter keeps its place above the cards, and a saved link with ?q= keeps working. What changes is that it filters the cards on the page as the person types, with no form, no reload and no request; today it waits for Enter, reloads the whole page through every stack and returns whole stacks unmarked.   1. 1 The field "Filter stacks and services" narrows the cards at once; the query is kept in the page's address as ?q= without a reload, so a reload or a shared link keeps it, and once typing pauses the announcer says the number of matches politely, "1 stack matches "search"" (SEL-10, FB-9).

The matched text is highlighted, underlined in this drawing (SEL-10, BAR-3, WORD-5).
  4. 4 No match names the query, with Clear Filter, which empties the field and returns focus to it; it replaces today's "Clear filter" and "Show all stacks" (STATE-2, WORD-2, KEY-6).
  5. 5 A query with a dot that matches nothing offers up to three close running hostnames by O46's rule, each a link that keeps the path and query typed after it. Over HTTPS a mistyped hostname gets no certificate and the browser shows its own error, so this is where that typo recovers; a hostname of a stack that stopped recently matches its card under "Stopped recently" instead of a neighbour (SEL-10, O46, O63, CC-27).

6. Open a service, or the page that fixes it

Route links still open in the same tab, and the directory still starts, restarts, stops and switches nothing, so no control on it asks or waits for another operation (O10, REV-1).
