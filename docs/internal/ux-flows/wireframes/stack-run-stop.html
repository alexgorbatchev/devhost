Start, find, stop and restart stacks from the terminal

TLDR: The terminal says when a stack is ready (keeping local URLs alongside remote previews), devhost stack info and devhost status report every service and rejection, parallel shutdown certifies that nothing remains within 30 s by default, devhost upgrade handles self-managed updates while restart-all and stack restart replace supervisors, and multi-stack commands print their set first and ask only when an agent's turn would end.

Low-fidelity wireframe. Layout, names and numbers are illustrative; the redesign ticket's acceptance criteria are authoritative.

1. Start a stack, or learn exactly why it cannot start

devhost start finds the root manifest from the current folder upward up to the first folder containing .git (or --manifest, DEVHOST_MANIFEST), starts the manifest's selection, and checks the manifest, its includes, every hostname (including reserved hostnames) and fixed-port claim, and every service's cwd before any service runs; a refused start starts nothing (REV-11). Route path values use prefix matching (O44: path = "/api" routes /api and everything under it, while "/api/*" keeps working). Keys: Ctrl-C stops the stack gracefully, a second Ctrl-C forces it (step 5, KEY-14).

  1. 1 The first line names the stack, its worktree by the shared label (branch, or "Detached" with its commit ID, then the path shortened with ~) and its size; after an interrupted switch it names the worktree a repository runs from when it is not the configured one (SEL-4, FB-10, WORD-1, WORD-11).
  2. 2 Each URL prints, labelled by its service, as soon as its route is published, the primary service's first among those published together; no URL prints before its route answers. With [remote] configured, local hostnames stay active alongside public preview hostnames, both clearly labelled, public hostnames without a DNS record are marked, an unreachable relay keeps the stack running locally with the preview offline, and --local publishes nothing to the relay (FB-10, SURF-15, relay-previews-02).
  3. 3 One ready line, certified: it prints only once every started service passed its health check, or for a process check or none still runs after O28's 1 s time, with no leftover of a killed run answering in its place. It gives the elapsed time and the primary URL first, then the count; services the run left out are counted ("4 of 6 running · 2 not started: admin, mail"), and a long list collapses to "34 services not started · devhost status" (FB-5, WORD-4, WORD-5, ACT-11).
  4. 4 The stack directory's URL follows using the machine name ("All stacks on devbox: https://devhost.acme.test/", O61), with its port when it is not 443, then the active proxy listener line (naming macOS bindHost = "127.0.0.1" port < 1024 warnings per O39), and a foreground terminal names its key. The full URL list prints at the first start and on request (devhost stack info / devhost status), never again after a later action (SURF-15, KEY-14, FB-10, O39, O61).
  5. 5 Agent output (AGENT=1) carries the same facts in its own layout: each line labelled Acme Shop:, absolute paths, no padding or wrapping (WORD-9, FB-11, CC-30).
  6. 6 A service that exits during the start leaves the other five running (the recovery contract); the ready line says so and the command that restarts it prints on its own line, without trailing punctuation (FAIL-1, FAIL-3, MENU-6, WORD-8).
  7. 7 Every problem of every file prints at once as file:line:column key message, with the offending line and a close key when one exists, files relative to the root manifest; under AGENT=1 they join one devhost: ERR: line with absolute paths. Hostname and port clashes name the owning stack, its worktree and the command that stops it (FAIL-2, MENU-4, WORD-7, WORD-11, FB-11).
  8. 8 While it waits, a slow health check shows what the probe last saw; a failed one says what answered, what it got and what to change, never only that it timed out (FAIL-3, STATE-1, ACT-4).
  9. 9 Under O44, path = "/api" routes as a prefix with no warning; a path without host and watch on an external service each print a warning with file, line, column and key and keep starting; the ready line counts warnings and devhost stack info (devhost status) lists them. Nothing is refused (O44, FAIL-2, MENU-4, ACT-8).
  10. 10 Relay connection runs in parallel with service startup; non-retryable auth, fingerprint, or reverse-port refusals fail fast in under 5 s naming the cause and connector.log instead of waiting 45 s silently, retrying only transient network errors with progress lines, and joining onto one devhost: ERR: line under AGENT=1 (relay-previews-04, FAIL-2, FAIL-3).
  11. 11 A cwd that does not exist is checked before the worktree lookup, so it reads as the manifest problem it is, never as a Git error (FAIL-2, REV-11).
  12. 12 With no manifest, the message names the .git repository-root boundary where upward search stopped (stack-run-stop-17), prints devhost init on its own line (O52: writes a commented devhost.toml from package.json, Cargo.toml, go.mod, or Procfile and refuses to overwrite), and prints the Quickstart URL (STATE-2, SURF-15, O52).

2. Start in the background, or add services to a running stack

A detached start still waits for readiness, reuses a stack that already runs, serializes concurrent starts of one manifest, and on a failure before readiness stops what it started (using step 5's unified parallel stop routine) and prints the log tail, now with the cause once, by service (owner rule; FAIL-1, O30). What changes is that the terminal is never blank while it waits, naming services of a running stack starts them instead of saying "Already running", and an offline relay preview is marked offline rather than presented as ready. Keys: Ctrl-C while it waits cancels the start (KEY-14).

  1. 1 Within a second the terminal names the stack, its worktree and its size (FB-10, SEL-4, WORD-11).
  2. 2 On a terminal, one status line is rewritten at least once a second: the services running, the one it waits on, its health check and the elapsed time (FB-10, STATE-1, ACT-4, WORD-4).
  3. 3 It ends with the same labelled URLs and certified ready line as a foreground start, "All stacks on devbox: …" (O61), then where the stack's output goes: one log per manifest, read with devhost logs (step 4) (FB-7, SURF-13).
  4. 4 A stack with an idle timeout says when it will stop by itself, so an idle shutdown is expected rather than a mystery (ACT-10).
  5. 5 When output is not a terminal, as for an agent or a script, the status line becomes one line per change; agent output keeps the PID and absolute paths (FB-10, WORD-9).
  6. 6 Ctrl-C during the wait is a cancellation, never an error: it stops what had started, says so without an error tag and exits 130 (FAIL-5, KEY-14, WORD-7).
  7. 7 Naming services the running stack left out starts them into it, with what they depend on, exactly as the Services panel's Start does, without touching running services, and prints what it started (SEL-7, O6, FB-3, CC-7).
  8. 8 When everything named already runs, it says so and prints only those services' URLs, marking any disconnected remote preview as offline (FB-10, relay-previews-05).
  9. 9 The start queues behind another service's start or restart, and is refused while the stack starts, stops or runs a stack-wide operation, naming that operation and its progress, with exit 1 (HOLD-3, HOLD-1, CC-8).
  10. 10 devhost never breaks a URL, path or command across lines: a token longer than the line moves to its own line whole, for the terminal to wrap, and URLs are links (OSC 8) where the terminal supports them (WORD-8).

3. Ask what runs, and find stacks

O62 extends shipped devhost stack info (GET /__devhost__/stack-info) and adds devhost status as its short alias sharing one implementation and output contract: both read the published state and operation record every surface reads, never a guess of the CLI's own (FB-11, ACT-1, ACT-2, CC-23). devhost stack list and devhost stack find stay read only, keep their TSV picker format for programs, resolve folders as devhost stop does, and guide users to active manifest-free serve sessions instead of returning empty or manifest-only errors (serve-command-04).

  1. 1 The header names the stack, its worktree, its PID, how it runs, its stack state and its summary, leading with what needs the person, and the time of the snapshot, because this answer does not update (ACT-6, ACT-12, WORD-5, WORD-11).
  2. 2 One line per service: its state word, cause and since when, its URL, changed-file markers, and for a service that needs the person the command that is its lead action (ACT-2, MENU-5, WORD-6, ACT-8). A starting service shows its health check ("starting · health check 4 s of 60 s"), a restarting one its operation ("restarting · Restart Stack"), and a blocked repository its one sentence instead of its URLs (ACT-4, ACT-3, HOLD-4).
  3. 3 An external service shows its reachability with its check and its time and says it runs outside devhost; it is never offered a restart (ACT-9, MENU-3).
  4. 4 A rejected manifest file prints "devhost.toml line 12 is not applied: …" while the stack keeps running the accepted manifest, and an offline remote preview names when the relay disconnected while local URLs keep running (HOLD-6, O62, relay-previews-05).
  5. 5 The last operation's outcome with its origin, where the log is read, and "All stacks on devbox: …" (FB-3, FB-7, SURF-15, O61).
  6. 6 Exit 0 when every started service runs, 3 naming each one that does not; 1 stays a failure of the command itself (FB-11, O62).
  7. 7 --json prints the same facts with the state identifiers (not-started, not-reachable), rejected manifest state, changed files, remote preview status, absolute paths and ISO times; --wait first waits for a running operation to end, printing its progress line, then its outcome (FB-11, WORD-6, WORD-8, WORD-9, FB-1, O62).
  8. 8 A stack whose devhost process runs but does not answer prints its last known state marked with its age and exits 1, never an empty list or "not running"; a stopped stack names when and why it stopped and the command that starts it, for O15's 24 hours (STATE-4, STATE-3, ACT-5, ACT-10, STATE-2).
  9. 9 When no manifest stack runs in the current directory and serve sessions are active, stack info / status names them and prints devhost stack info --session <name> instead of a bare no-manifest error (serve-command-04, STATE-2).
  10. 10 A query that names an existing folder, . and .. included, finds the stack of the nearest devhost.toml from it upward, as devhost stop does; other words keep matching part of a hostname, name or manifest path, and when only a serve session matches, stack find names it with --session (SEL-6, CC-34, serve-command-04).
  11. 11 On a terminal each stack shows its name, worktree label, PID, how it runs, its summary and offline preview flag, followed by any active serve-session hint (--sessions) and "All stacks on devbox: …"; a stack with leftovers of a killed run is listed with them (step 7) (SEL-4, WORD-1, WORD-11, SURF-15, O61, serve-command-04, relay-previews-05).
  12. 12 Piped, or under AGENT=1, both commands print <PID><TAB><manifest path> byte for byte as today, because scripts and shell completion read it; a search with no match says what was searched (WORD-9, SEL-10, STATE-2).

4. Act on one service, reload, and read the stack's log

New: the terminal becomes one of each service's entry points, beside its row in the Services panel, the crash view and the control API, and every stack writes one log that follows it through replacements (MENU-1, MENU-6, FB-7). devhost service start|stop|restart <service|group>… targets named services or groups, and devhost service restart --all is the terminal form of in-process Restart Stack, which the toolbar, crash view, recovery pages and control API offer; its help says "Restart Stack in the browser" (CC-11, MENU-6, applied default of owner item q86), while devhost stack restart, devhost restart-all, and devhost upgrade replace the running devhost supervisor process (O18). These commands reach the running stack through its control server on the loopback port recorded in the state directory.

  1. 1 Each command sends an operationId, waits for health checks with one progress line, then prints one outcome per target, as the toolbar's Restart would; a lost response is read back from the operation record and never sent again (SEL-7, REV-12, ACT-1, FB-3, WORD-4, CC-11, CC-37). A failure prints the target, the exit with its time, its last output lines and what devhost ran, and exits 1 (FAIL-3); with devhost.toml rejected, "Restarted api from the accepted manifest · devhost.toml line 12 is not applied · 2.6 s" (HOLD-6).
  2. 2 An external service is refused with why, exit 1 (MENU-3, ACT-9).
  3. 3 A restart of another service queues and runs after the current one; one clashing with a stack-wide operation is refused with one sentence naming it, its progress and the way out (HOLD-3, HOLD-1, CC-8).
  4. 4 The crash line a running stack prints names the command that restarts the service, never "devhost is waiting for a restart" (MENU-6, MENU-5, FAIL-5).
  5. 5 devhost reload [--dry-run] [--stdin <file>] checks or applies the manifest on disk against the running stack and prints manifest-hot-reload's reload report (FB-11, REV-10, CC-23).
  6. 6 Foreground or detached, every stack appends to one log per manifest whose name no replacement changes; each run starts with a header naming the command, the PID, the worktree and the time; lines carry their time and one format, failures marked ERR: as warnings are WARN:; -f follows across replacements and service names filter it. Every operation from any origin is one outcome line here, so an outcome the toolbar closed stays readable (FB-7, FB-11, WORD-11, CC-21, CC-23).
  7. 7 --path prints where the log lives, for tools (FB-7).

5. Stop a stack in parallel and see it stopped

devhost stop finds the stack through any path to its manifest, acts on that one stack without asking, releases its hostnames, ports and routes before unregistering it, signals only processes verified as the stack's own, and leaves the shared Caddy running (REV-7, ACT-11, ACT-14). One unified parallel stop routine serves every stop caller: devhost stop, stop --worktrees, stop --session, stack restart, restart-all, upgrade, start --detach cleanup, Worktrees Stop Stack, and serve sessions (O30, O41, CC-35). Keys: Ctrl-C while devhost stop waits, or a second devhost stop, forces remaining verified service trees and daemon stop groups; in a foreground stack the first Ctrl-C stops gracefully and the second forces (KEY-14).

  1. 1 The first line names the stack, its worktree, its PID as a detail, its size and the conversations the stop will close, with each one's state; before it signals, the stop records why beside the stack's record so the stack's terminal, its open pages and its hostnames can say so (step 7) (SEL-6, SEL-4, FB-4, ACT-10, WORD-1, WORD-11).
  2. 2 Foreground services and daemon lifecycle stops launch in parallel from t = 0 with one shared process snapshot and exactly one termination signal per managed foreground service (interrupted-operations-06): 15 s foreground bound (10 s shared grace + verified SIGKILL + 5 s check + shared 2 s port scan) and 20 s shared daemon deadline (O41) give a 25.64 s combined worst case inside O30's 30 s default stopTimeout (configurable 5s..10m via --timeout > DEVHOST_STOP_TIMEOUT > devhost.toml stopTimeout > config.toml stopTimeout > 30s; widens to max(stopTimeout, max_daemon_override + 10s) when a daemon sets lifecycle.stopTimeout > 20 s unless CLI --timeout caps the run). Callers never kill a stopping supervisor (FB-10, KEY-14, ACT-3, ACT-11, O30, O41, CC-35).
  3. 3 A service devhost had to force reads force-stopped with why, never stopped or failed (FAIL-5, WORD-7).
  4. 4 Success is certified: it prints only once no process, route or port claim of the stack remains, names the conversations it closed, which stay listed and resumable after the next start, and prints the command that starts the stack again on its own line. There is no Undo: the start command is the way back (FB-5, FB-4, UNDO-5, WORD-4, O23).
  5. 5 Anything that survives stopTimeout is named with its service, PID and port, and the command exits 1 (FAIL-1, ACT-11). During a start it cancels that start and says so in both terminals (REV-12).
  6. 6 In a foreground stack the first Ctrl-C sends one signal per running service and prints the status line with "Ctrl-C again forces them"; a service that had already exited is not signalled again; the second Ctrl-C forces the rest within a second, still releases the stack's routes, port claims and record, and ends with the stack's end line (KEY-14, FAIL-5, ACT-10, interrupted-operations-06).
  7. 7 With no manifest stack running (or no devhost.toml found), devhost stop names other stacks of the repository with --worktrees and any active serve sessions with devhost stop --session <name> (and devhost stack list --sessions) instead of a bare manifest-not-found error (STATE-2, serve-command-04).

8. Upgrade devhost, replace supervisors, and follow what a running stack reports

Process replacement stops nothing when the executable is unavailable or a stack is the command's own ancestor, re-checks each stack's identity just before its signal, keeps each stack's flags and worktrees, and leaves the shared Caddy running (REV-11, REV-13). Under O18, built-in devhost upgrade downloads, verifies and swaps user-writable installs and replaces running stacks, while shipped devhost restart-all (global) and project-scoped devhost stack restart (one stack, never asks, REV-7) stay on one verb for dotfiles, package managers and local rebuilds and state clearly in help and output that they replace the running devhost supervisor process (O18, WORD-2, CC-31, CC-36). Every replacement uses step 5's unified parallel stop routine instead of giving up at 15 s (O30), and a running stack's terminal reports each change once instead of reprinting the stack.

  1. 1 devhost upgrade looks up the latest GitHub Release (skipping media), verifies SHA256SUMS, atomically swaps a user-writable binary, and clearly reports read-only paths, externally managed installs (dotfiles, package managers), or protected 999.0.0-dev--… dev builds without modifying them (O18, FAIL-2).
  2. 2 devhost restart-all and devhost upgrade print their set first, as in step 6, with each stack's worktree, PID and how it runs, listing the serve sessions of the state directory (which keep running).   3. 3 Each stack waits for its old devhost process's parallel shutdown up to O30's stopTimeout (30 s default, widening for daemon overrides > 20 s) with step 5's progress line, then starts from the new executable with the services it runs at that moment, those started later included, and reports one line.   5. 5 A replaced foreground stack prints which command replaced it (devhost upgrade, devhost restart-all, or devhost stack restart), when, the new PID and the commands that follow and stop the replacement, and exits 0, never 143; open pages reconnect to the replacement and say so once (FAIL-5, ACT-10, O18, CC-24).
  6. 6 Every operation on a running stack, from any origin, prints one outcome line with its time and origin in the stack's terminal and log, never the whole URL list again, and services devhost stops for an operation (Restart Stack, a switch, a hot reload, a shutdown, a failed health check) never print as exits waiting for a restart; a switch's line, in worktree-switch's words, names both worktrees by label (FB-3, FB-10, FAIL-5, ACT-3, WORD-5, WORD-11, CC-22).
