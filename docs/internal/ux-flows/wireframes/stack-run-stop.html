Start, find, stop and restart stacks from the terminal

TLDR: The terminal says when a stack is ready, what runs and why a stack ended, a stop reports success only once nothing of the stack remains, and every command that reaches several stacks prints its set first and asks only when an agent's turn would end.

Low-fidelity wireframe. Layout, names and numbers are illustrative; the redesign ticket's acceptance criteria are authoritative.

1. Start a stack, or learn exactly why it cannot start

devhost start still finds the root manifest from the current folder upward (or --manifest, DEVHOST_MANIFEST), starts the manifest's selection, and checks the manifest, its includes, every hostname and fixed-port claim and every service's cwd before any service runs; a refused start still starts nothing (REV-11). What changes is that the terminal says what it is doing and when the stack is ready, and every problem names its file, line and next step. Keys: Ctrl-C stops the stack gracefully, a second Ctrl-C forces it (step 5, KEY-14).

  1. 1 The first line names the stack, its checkout by the shared label (branch, or "Detached" with its commit ID, then the path shortened with ~) and its size; after an interrupted switch it names the checkout a repository runs from when it is not the configured one (SEL-4, FB-10, WORD-1).
  2. 2 Each URL prints, labelled by its service, as soon as its route is published, the primary service's first among those published together; no URL prints before its route answers (FB-10, SURF-15).
  3. 3 One ready line, certified: it prints only once every started service passed its health check, or for a process check or none still runs after O28's time, with no leftover of a killed run answering in its place. It gives the elapsed time and the primary URL first, then the count; services the run left out are counted ("4 of 6 running · 2 not started: admin, mail"), and a long list collapses to "34 services not started · devhost status" (FB-5, WORD-4, WORD-5, ACT-11).
  4. 4 The stack directory's URL follows, with its port when it is not 443, and a foreground terminal names its key. The full URL list prints at the first start and on request (devhost status), never again after a later action (SURF-15, KEY-14, FB-10).
  5. 5 Agent output (AGENT=1) carries the same facts in its own layout: each line labelled Acme Shop:, absolute paths, no padding or wrapping (WORD-9, FB-11, CC-30).
  6. 6 A service that exits during the start leaves the other five running (the recovery contract); the ready line says so and the command that restarts it prints on its own line, without trailing punctuation (FAIL-1, FAIL-3, MENU-6, WORD-8).
  7. 7 Every problem of every file prints at once as file:line:column key message, with the offending line and a close key when one exists, files relative to the root manifest; under AGENT=1 they join one devhost: ERR: line with absolute paths. Hostname and port clashes name the owning stack, its checkout and the command that stops it (FAIL-2, MENU-4, WORD-7, FB-11).
  8. 8 While it waits, a slow health check shows what the probe last saw; a failed one says what answered, what it got and what to change, never only that it timed out (FAIL-3, STATE-1, ACT-4).
  9. 9 A route that matches only an exact path, a path without host and watch on an external service each print a warning with file, line, column and key and keep starting; the ready line counts the warnings and devhost status lists them. Nothing is refused (FAIL-2, MENU-4, ACT-8).
  10. 10 A cwd that does not exist is checked before the checkout lookup, so it reads as the manifest problem it is, never as a Git error (FAIL-2, REV-11).
  11. 11 With no manifest, the command that creates one prints on its own line, then the Quickstart's URL (a pending decision: devhost init writes a commented devhost.toml and refuses to overwrite one) (STATE-2, SURF-15).

2. Start in the background, or add services to a running stack

A detached start still waits for readiness, reuses a stack that already runs, serializes concurrent starts of one manifest, and on a failure before readiness stops what it started and prints the log tail, now with the cause once, by service (owner rule; FAIL-1). What changes is that the terminal is never blank while it waits, and naming services of a running stack starts them instead of saying "Already running". Keys: Ctrl-C while it waits cancels the start (KEY-14).

  1. 1 Within a second the terminal names the stack, its checkout and its size (FB-10, SEL-4).
  2. 2 On a terminal, one status line is rewritten at least once a second: the services running, the one it waits on, its health check and the elapsed time (FB-10, STATE-1, ACT-4, WORD-4).
  3. 3 It ends with the same labelled URLs and certified ready line as a foreground start, then where the stack's output goes: one log per manifest, read with devhost logs (step 4) (FB-7, SURF-13).
  4. 4 A stack with an idle timeout says when it will stop by itself, so an idle shutdown is expected rather than a mystery (ACT-10).
  5. 5 When output is not a terminal, as for an agent or a script, the status line becomes one line per change; agent output keeps the PID and absolute paths (FB-10, WORD-9).
  6. 6 Ctrl-C during the wait is a cancellation, never an error: it stops what had started, says so without an error tag and exits 130 (FAIL-5, KEY-14, WORD-7).
  7. 7 Naming services the running stack left out starts them into it, with what they depend on, exactly as the Services panel's Start does, without touching running services, and prints what it started (SEL-7, O6, FB-3, CC-7).
  8. 8 When everything named already runs, it says so and prints only those services' URLs (FB-10).
  9. 9 The start queues behind another service's start or restart, and is refused while the stack starts, stops or runs a stack-wide operation, naming that operation and its progress, with exit 1 (HOLD-3, HOLD-1, CC-8).
  10. 10 devhost never breaks a URL, path or command across lines: a token longer than the line moves to its own line whole, for the terminal to wrap, and URLs are links (OSC 8) where the terminal supports them (WORD-8).

3. Ask what runs, and find stacks

New: one command answers whether the stack's services are up, from the same published state and operation record every surface reads, never a guess of the CLI's own (FB-11, ACT-1, ACT-2, CC-23). devhost stack list and devhost stack find stay read only and keep their picker format for programs; stack find now resolves folders as devhost stop does.

  1. 1 The header names the stack, its checkout, its PID, how it runs, its stack state and its summary, leading with what needs the person, and the time of the snapshot, because this answer does not update (ACT-6, ACT-12, WORD-5).
  2. 2 One line per service: its state word, cause and since when, its URL, and for a service that needs the person the command that is its lead action (ACT-2, MENU-5, WORD-6, ACT-8). A starting service shows its health check ("starting · health check 4 s of 60 s"), a restarting one its operation ("restarting · Restart Stack"), a rejected manifest file "devhost.toml line 12 is not applied: …" while the stack runs the accepted manifest, and a blocked repository its one sentence instead of its URLs (ACT-4, ACT-3, HOLD-6, HOLD-4).
  3. 3 An external service shows its reachability with its check and its time and says it runs outside devhost; it is never offered a restart (ACT-9, MENU-3).
  4. 4 The last operation's outcome with its origin, where the log is read, and the stack directory's URL (FB-3, FB-7, SURF-15).
  5. 5 Exit 0 when every started service runs, 3 naming each one that does not; 1 stays a failure of the command itself (FB-11).
  6. 6 --json prints the same facts with the state identifiers (not-started, not-reachable), absolute paths and ISO times; --wait first waits for a running operation to end, printing its progress line, then its outcome (FB-11, WORD-6, WORD-8, FB-1).
  7. 7 A stack whose devhost process runs but does not answer prints its last known state marked with its age and exits 1, never an empty list or "not running"; a stopped stack names when and why it stopped and the command that starts it, for O15's 24 hours (STATE-4, STATE-3, ACT-5, ACT-10, STATE-2).
  8. 8 A query that names an existing folder, . and .. included, finds the stack of the nearest devhost.toml from it upward, as devhost stop does; other words keep matching part of a hostname, name or manifest path (SEL-6, CC-34).
  9. 9 On a terminal each stack shows its name, checkout label, PID, how it runs and its summary, so two stacks named Acme Shop read apart, then the stack directory's URL; a stack with leftovers of a killed run is listed with them (step 7) (SEL-4, WORD-1, SURF-15).
  10. 10 Piped, or under AGENT=1, both commands print <PID><TAB><manifest path> byte for byte as today, because scripts and shell completion read it; a search with no match says what was searched (WORD-9, SEL-10, STATE-2).

4. Act on one service, and read the stack's log

New: the terminal becomes one of each service's entry points, beside its row in the Services panel, the crash view and the control API, and every stack writes one log that follows it through replacements (MENU-1, MENU-6, FB-7). Restarting one service keeps doing exactly what the toolbar's Restart does today. These commands reach the running stack through its control server on the loopback port the state directory records, so they run only on this machine (HOLD-7).

  1. 1 Each command sends an operationId, waits for health checks with one progress line, then prints one outcome per target, as the toolbar's Restart would; a lost response is read back from the operation record and never sent again (SEL-7, REV-12, ACT-1, FB-3, WORD-4, CC-11, CC-37). A failure prints the target, the exit with its time, its last output lines and what devhost ran, and exits 1 (FAIL-3); with devhost.toml rejected, "Restarted api from the accepted manifest · devhost.toml line 12 is not applied · 2.6 s" (HOLD-6).
  2. 2 An external service is refused with why, exit 1 (MENU-3, ACT-9).
  3. 3 A restart of another service queues and runs after the current one; one clashing with a stack-wide operation is refused with one sentence naming it, its progress and the way out (HOLD-3, HOLD-1, CC-8).
  4. 4 The crash line a running stack prints names the command that restarts the service, never "devhost is waiting for a restart" (MENU-6, MENU-5, FAIL-5).
  5. 5 devhost service restart --all prints the statement Restart Stack shows in the Services panel before it stops anything, then runs, reports per-service progress and one outcome, and on a failure rolls back service by service, naming what it put back, with exit 1 (REV-2, UNDO-1, FAIL-1, BAR-2). devhost reload [--dry-run] [--stdin <file>] applies or checks the manifest on disk the same way and prints manifest-hot-reload's reload report (FB-11, REV-10, CC-23).
  6. 6 Foreground or detached, every stack appends to one log per manifest whose name no replacement changes; each run starts with a header naming the command, the PID, the checkout and the time; lines carry their time and one format, failures marked ERR: as warnings are WARN:; -f follows across replacements and service names filter it. Every operation from any origin is one outcome line here, so an outcome the toolbar closed stays readable (FB-7, FB-11, CC-21, CC-23).
  7. 7 --path prints where the log lives, for tools (FB-7).

5. Stop a stack and see it stopped

devhost stop still finds the stack through any path to its manifest, acts on that one stack without asking, releases its hostnames, ports and routes before it unregisters it, signals only processes verified as the stack's own, and leaves the shared Caddy running (REV-7, ACT-11). What changes is that it names the stack instead of PIDs, waits for the stack's own shutdown instead of killing devhost after 15 s, and reports success only once nothing of the stack remains. Keys: Ctrl-C while devhost stop waits, or a second devhost stop, forces the services still stopping; in a foreground stack the first Ctrl-C stops gracefully and the second forces (KEY-14).

  1. 1 The first line names the stack, its checkout, its PID as a detail, its size and the conversations the stop will close, with each one's state; before it signals, the stop records why beside the stack's record so the stack's terminal, its open pages and its hostnames can say so (step 7) (SEL-6, SEL-4, FB-4, ACT-10, WORD-1).
  2. 2 One status line, rewritten while it waits: services stopped of the total, the ones still stopping, the time before devhost forces them and the key that forces them now. It waits as long as the stack's own shutdown needs, up to O30's allowance (a minute plus 20 s per service: 3 min for 6), and never kills the stack's devhost process while it still stops services (FB-10, KEY-14, ACT-3, ACT-11, CC-35).
  3. 3 A service devhost had to force reads force-stopped with why, never stopped or failed (FAIL-5, WORD-7).
  4. 4 Success is certified: it prints only once no process, route or port claim of the stack remains, names the conversations it closed, which stay listed and resumable after the next start, and prints the command that starts the stack again on its own line. There is no Undo: the start command is the way back (FB-5, FB-4, UNDO-5, WORD-4, O23).
  5. 5 Anything that survives the allowance is named with its service, PID and port, and the command exits 1 (FAIL-1, ACT-11). With nothing running it says "Acme Shop is not running", then names the repository's other stacks with the --worktrees command; during a start it cancels that start and says so in both terminals (STATE-2, REV-12).
  6. 6 In a foreground stack the first Ctrl-C prints the same status line with "Ctrl-C again forces them"; a service that had already exited is not signalled again; the second Ctrl-C forces the rest within a second, still releases the stack's routes, port claims and record, and ends with the stack's end line (KEY-14, FAIL-5, ACT-10).
  7. 7 Agent output gets the same facts with absolute paths, one line per change, on the stream reference/output.md names for progress and outcomes (WORD-9, FB-11).

6. Stop every stack of the repository

devhost stop --worktrees still acts only on stacks whose root manifest is in the named manifest's repository, never on another repository's stacks, and each stack stops with step 5's routine and progress line. What changes is that it shows its set before it acts, asks only when that set would end an agent's turn, and attempts every stack instead of giving up at the first one it cannot stop. Keys: the question takes y or yes; Enter, any other answer or end of input is No (REV-4, KEY-14).

  1. 1 The set prints first: every stack of the repository with its checkout label, PID, foreground or detached, and the conversation each would close with its state; a stack whose folder was deleted is classified from the repository's worktree list, never by running Git in the missing folder (SEL-6, SEL-4, FB-4, FAIL-2, REV-11).
  2. 2 Only when the set would end an agent's turn that works or waits, a turn in a stack whose chat was turned off included, does it ask, naming those turns, and only when standard input and output are both a terminal and CI is unset; with no turn at stake it prints the set and stops at once (REV-7, REV-3, REV-4, HOLD-5, O33).
  3. 3 A stack that cannot be stopped never ends the run: every stack is attempted, each ends with its own line, and the command exits 1 naming each stack that still runs (FAIL-1).
  4. 4 Without a terminal, or under AGENT=1, it refuses with one line telling the agent to ask the person, as the certificate trust commands do, and exits 1; --yes acts without the question and is the one flag that skips a devhost question; no command takes --force for it (REV-7, REV-8, WORD-9, CC-12).
  5. 5 --dry-run prints the set and exits 0 without acting (SEL-6, CC-12).

7. See why a stack ended, and clear what a killed run left

Idle shutdown stays as configured (idleTimeout, --idle-timeout, DEVHOST_IDLE_TIMEOUT), devhost never opens a browser, and only a terminal starts a stack. What changes is that every end says why, the stack's hostnames say so for a day instead of the generic 404, and the processes of a stack whose devhost process died are found and named instead of answering unseen. Open pages of the stack learn the reason before their status stream closes, so their lost-connection notice reads "Acme Shop stopped. Start it with devhost start in ~/acme"; notices-and-feedback draws that notice (HOLD-2, ACT-5).

  1. 1 However a stack ends, its terminal and its log print one line naming the stack, the reason and the time: the idle timeout with its duration, devhost stop from another terminal, another stack's Worktrees panel, a replacement or every service exited (ACT-10, CC-27).
  2. 2 While the shared Caddy is stopped, every running stack prints one line that it lost its proxy and one when its routes answer again, never one per check (ACT-10).
  3. 3 For O15's time, 24 hours or until another stack claims the hostname or the shared Caddy stops, each hostname of the stack answers this full page: the heading, when and why it stopped, and the command that starts it with Copy. It starts nothing. It is drawn with the shared status-page components in the status pages' stylesheet, carries no toolbar and no devhost key listener, fits every acceptance viewport in both themes, reflows at 320 CSS pixels, and tells its state by its heading and words, never by color alone (ACT-10, STATE-2, STATE-3, UNDO-5, SURF-14, SURF-9, ACT-13, O15, CC-27). Keys: the document's own; Tab reaches Copy, then All Stacks on This Machine, after the heading and the sentence; Enter or Space activates; Escape has nothing to close. Copy keeps focus after copying, and the page's one polite region says "Copied devhost start" once (KEY-1, KEY-6, KEY-11, FB-9).
  4. 4 All Stacks on This Machine opens the stack directory, which lists Acme Shop as recently stopped; stack-directory draws it (SURF-15, CC-27).
  5. 5 devhost stack list and devhost status name the services of a killed run that still run, from the PIDs, ports and hostnames its record kept (ACT-11).
  6. 6 Before launching a service, devhost start refuses while such a leftover holds its port or hostname, naming the leftover and, on its own line, the command that stops it, so a leftover answering a hostname is never reported ready (ACT-11, REV-11, FAIL-3).
  7. 7 devhost stop in that folder stops only processes whose start identity matches the record, and an unrelated process that later reuses one of their PIDs is never signalled (ACT-11, FB-5).

8. Replace stacks after an upgrade, and follow what a running stack reports

A replacement still stops nothing when the executable is unavailable or a stack is the command's own ancestor, re-checks each stack's identity just before its signal, keeps each stack's flags and checkouts, and leaves the shared Caddy running (REV-11, REV-13). What changes is that it is named replace, with devhost stack restart kept as its alias (O18, WORD-2, CC-31), it waits for each stack's own shutdown instead of giving up at 15 s, and a running stack's terminal reports each change once instead of reprinting the stack. A single stack's replacement, devhost stack replace in its folder, never asks (REV-7).

  1. 1 The set prints first, as in step 6, with each stack's checkout, PID and how it runs; --all lists the serve sessions of the state directory, which keep running. It asks or refuses only when the set would end an agent's turn, with --yes and --dry-run as in step 6, and the documented post-upgrade step passes --yes (SEL-6, REV-7, O31, O33, CC-12, CC-36).
  2. 2 Each stack waits for its old devhost process's own shutdown up to O30's allowance with step 5's progress line, then starts from this executable with the services it runs at that moment, those started later included, and reports one line. A stack that stopped after the command captured it reads "Acme Shop had already stopped; not replaced", never a failure; one whose manifest was saved meanwhile is still replaced, because the check compares its PID, start identity and root manifest; one whose shutdown outlasts the allowance is named with what still stops and the command that starts it, and the command exits 1 (O30, ACT-11, SEL-7, REV-13, FAIL-1, FAIL-5, UNDO-5, CC-35).
  3. 3 A serve session left running says which devhost it still runs and how to move it to the new one (O31, CC-36).
  4. 4 A replaced foreground stack prints who replaced it, when, the new PID and the commands that follow and stop the replacement, and exits 0, never 143; open pages reconnect to the replacement and say so once (FAIL-5, ACT-10, CC-24).
  5. 5 Every operation on a running stack, from any origin, prints one outcome line with its time and origin in the stack's terminal and log, never the whole URL list again, and services devhost stops for an operation (Restart Stack, a switch, a hot reload, a shutdown, a failed health check) never print as exits waiting for a restart; a switch's line, in worktree-switch's words, names both checkouts by label (FB-3, FB-10, FAIL-5, ACT-3, WORD-5, CC-22).
  6. 6 An exit from outside names the signal, its status, the time and whether devhost sent it (FAIL-3, FAIL-5, WORD-8).
  7. 7 A daemon that stops on its own prints one line naming its check and what its status command reported, and one line when it recovers, never one per poll (FAIL-3).
  8. 8 A devhost config file save prints its outcome, whose change summary proxy-settings words, and the stack directory's URL when it moves; a rejected manifest edit prints manifest-hot-reload's "not applied" line with its file and line, and a blocked repository is named once with its sentence (FB-3, SURF-15, MENU-4, HOLD-4).
  9. 9 devhost skill prints the agent guidance embedded in this binary, for this version and offline, naming devhost status, devhost service, devhost logs and devhost reload; devhost skill --install keeps today's install text, and the Quickstart in devhost --help starts with creating the manifest (a pending decision) (MENU-6, SURF-15, CC-11, CC-23).
