Use your framework's devtools from the toolbar

TLDR: Launchers name their library, panels on one window edge take turns while devhost's dock steps off them, the Redux window opens on a named store and survives reloads, a launcher that cannot act or fails says why, and each integration turns off on its own.

Low-fidelity wireframe. Layout, names and numbers are illustrative; the redesign ticket's acceptance criteria are authoritative.

1. Find the launcher

The launchers keep their place in the bar's order, which toolbar-shell keeps, in the order devhost finds the libraries, and each still opens the library's own panel through the library's own control. What changes is what they say: each names the library whose panel it opens, so nothing needs a hover to tell them apart. Today the same bar reads Router, Query, TanStack, Form 1, Jotai 1 and Redux, and the library is named only in hover text. A page with no integration shows no launcher and no Devtools control. Keys: Alt+Ctrl+B focuses the bar; each launcher is an arrow stop (ArrowLeft, ArrowRight, Home, End); Enter or Space toggles it; Tab leaves the bar (KEY-3, KEY-4).

  1. 1 One toggle per library panel the page mounts, named by the product name of the library whose panel it opens; the two that open a tool for several libraries take the tool's name: TanStack Devtools for the unified shell with its Form, Table and Pacer plugins, and Redux DevTools, which inspects the Redux Toolkit and Zustand stores the page registers. No label reads "Form" (WORD-3).
  2. 2 Each launcher's tooltip and accessible description say what it opens and that it acts on this page, as toolbar-shell words the reach of the other bar items (SEL-3).
  3. 3 While pressed, the description reads "Close the TanStack Query devtools of this page", and the launcher reads open in the bar's active look, by shape as well as color (drawn here as an inset border and ☑, toolbar-shell's pressed look), so it holds in forced colors (ACT-13).
  4. 4 On a page that mounts every integration the launchers read TanStack Router, TanStack Query, TanStack Devtools, React Hook Form, Jotai and Redux DevTools. A lone panel has no number. When they would wrap the bar's one row, they fold into Devtools (step 6).
  5. 5 An instance name appears only when the page mounts two or more panels of one library, after " · ": a React Hook Form panel takes its form's name from its DevTool's id prop where its panel exposes it, else its number in discovery order, renumbered on remount and from 1 after a reload, as documented. Jotai keeps numbers ("Jotai 1", "Jotai 2"), because devhost collects no atom data and has nothing else to name a store by.
  6. 6 devhost binds none of the libraries' keys: they stay the libraries' own, and guides/devtools.md's Keyboard section lists them as keys devhost leaves alone (KEY-2, CC-29).

Fixes third-party-devtools-06 · Backend: each adapter reports its library's product name and an instance name or none (Backend 2); React Hook Form names from the id prop, still to be confirmed on the fixture (Backend 4, [discuss])

2. Open a library panel

Pressing a launcher still clicks the library's own open control, and the panel is still the library's, where the library docks it, with its own look; devhost never moves, resizes or restyles a panel to make room. What changes: panels docked to the same window edge take turns, the launcher says so before the press, and devhost's dock steps off a panel at the bottom edge. Opening a panel is a read: no notice, no log line and no announcement; the pressed states are the result. Focus stays on the pressed launcher, devhost moves no focus into a library's panel, which the person reaches with the pointer or the page's own Tab order, and Alt+Ctrl+B brings focus back to the bar. After a pointer press the page's keys keep working, the libraries' hotkeys included (KEY-5, KEY-6, CC-28).

  1. 1 Before the press, the launcher's tooltip and accessible description name its reach: the open panel on the same edge it will close (SEL-1).
  2. 2 While a panel docks to the bottom edge, toolbar-shell moves the dock onto the panel's top edge, or to the top of the window when the panel is taller than half of it, and follows the panel's own resize handle, so the last row of a panel's list is fully visible when scrolled to its end. This flow supplies the seam: each adapter reports its open panel's element and edge, which the dock measures (SURF-1, SURF-7, SURF-5).
  3. 3 Enter closes TanStack Router through its own close control, then opens TanStack Query, so at most one launcher per edge reads pressed and it is the panel on screen; Router's launcher unpresses in the same frame as Query's presses (SEL-11, SEL-1). Today Query opens over Router, both read pressed, and the next press on Router acts on a panel nobody can see.
  4. 4 A panel's edge is read from its own rectangle while it is open: it docks to an edge when it touches that edge of the window and spans more than half of it. TanStack Router and Query, the unified shell and Jotai dock to the bottom by default; panels on different edges stay open together, both launchers pressed, each closing on its own. An app that docks TanStack Query to the top with the library's own setting gets the same turn-taking on that edge.
  5. 5 A React Hook Form panel opens a full-height column on the right. It meets the dock and docked chat, which SURF-1 does not place yet; that is recorded for the reference.

3. Use the panel and close it

The panel keeps its own keys, Escape and close controls, and devhost adds no Escape to a library's panel (KEY-1, KEY-8). Closing a panel by its own control, its pressed launcher, Escape or a library hotkey still unpresses its launcher within one frame, as today. What changes: every panel shows its own close or minimize control, and the dock returns to the person's placement when the panel closes.

  1. 1 devhost's stylesheet hides only the floating launchers, so TanStack Query's minimize button ("Close tanstack query devtools") and the unified shell's "Close TanStack Devtools" button stay visible, as Router's chevron, React Hook Form's ✕ and Jotai's minimize button already do. Today devhost hides both.
  2. 2 The panel closes, TanStack Query unpresses within one frame, and the dock returns to the corner the person chose; its temporary move above the panel was never saved (SURF-7).
  3. 3 With the toolbar collapsed the launchers are hidden, and an open panel still closes from its own control. An open panel is not a condition, so the collapsed badge does not show it (SURF-8).
  4. 4 Picks reach the panel: an open library panel is part of the page, where devhost draws nothing, so Select Elements and Alt + right-click resolve its elements like any other page element, and a pick's element path shows the library's root, so the person can point an agent at a query's state (SEL-9, SURF-11).

Fixes third-party-devtools-02 · Backend: the hide selectors keep only floating launchers; Query's minimize button and the shell's close button leave them (Backend 2)

4. Open the Redux inspector

Pressing Redux DevTools still opens devhost's own inspector in a popup window, served from /__devhost__/redux, with no browser extension; the window still accepts a connection only from its opener, at the same origin, with the matching session ID, and the inspector's own styles stay in its window. What changes: it opens on a named store, says which store it follows, and its title names the store, the stack and the page's host.

  1. 1 The unpressed launcher's tooltip names the stores it will show (SEL-1).
  2. 2 The window opens on the first registered store, named in the store picker, never on "Select..."; the person's later choice is kept while the window lives (STATE-2).
  3. 3 The window's title names the store, the stack and the page's host; choosing Zustand counter retitles it (WORD-3).
  4. 4 While the inspector's own "Autoselect instances" is chosen, a line devhost draws above the inspector, outside the upstream panel, names the store it shows. While the window connects, the line reads "Connecting to shop.acme.test…" and the launcher's description says the same (STATE-1).
  5. 5 Zustand history starts when the store registers, not when the window connects: the page keeps each Zustand store's latest changes, at most 50, so a window opened after three clicks lists those three zustand/setState changes after @@INIT, and closing and reopening the window keeps them; once a store has dropped older changes, the line says so. Redux Toolkit stores keep their own full history, as today.
  6. 6 Each tab keeps its own window session, and each title names its store, stack and host, so two stacks' windows, or windows of pages on different hosts, never read alike in the window switcher (WORD-3).

5. Bring the window back, keep it through reloads, close it

Closing the window still unpresses the launcher within 100 ms, Redux Toolkit history still survives a reopen, and turning redux or the whole integration off, or unmounting the toolbar, still closes the window and leaves the stores untouched. What changes: the pressed launcher brings the window to the front instead of closing it, closing is a control of its own, and a reload of the page keeps the window. Keys: Close Redux DevTools is the next arrow stop after the launcher.

  1. 1 While the window is open, Redux DevTools reads pressed, and pressing it brings the window to the front and never closes it (SEL-11). Today the obvious press closes the window, and the reopened one has lost its store choice and every Zustand change made before.
  2. 2 Close Redux DevTools is a ✕ of at least 24 by 24 CSS pixels beside the pressed launcher, its own arrow stop, with that label as its accessible name; the window's own close does the same, and either unpresses the launcher within 100 ms (SEL-11, SURF-9, KEY-4, WORD-2).
  3. 3 Reloading the page, devhost's own reloads after a restart or a switch included, or opening another page of the same origin in the same tab, keeps the window: it waits with the elapsed time, then reattaches to the next page's toolbar with the chosen store and the inspector's tab kept (STATE-1).
  4. 4 A loaded page that registers no store leaves the window waiting for one (STATE-2). When the tab closes or leaves the origin, the window says its page is gone and offers Close Window; the stores are untouched.

Fixes third-party-devtools-03 · Backend: on pagehide the page tells the window it is leaving instead of closing it; the tab keeps the session ID in sessionStorage; the window says hello to its opener every 500 ms, under today's origin and session checks (Backend 5)

6. Fold the launchers when they would wrap the bar

Inline launchers stay bar toggles while they fit on the bar's one row, and what each opens does not change. What is new is the folded form: by the bar's fit test, second in toolbar-shell's sequence after the Services summary, the launchers fold into one Devtools control when they would wrap the bar, never by a count (SURF-10, SEL-10). Keys: Enter, Space, the arrow that points toward the panel, or a click opens it; on open, focus goes to the filter when there is one, else the first row's toggle; Tab moves through each row's controls in row order; Tab past the last control or Shift+Tab before the first closes the panel and returns focus to Devtools; Escape or a click outside closes it and returns focus to Devtools, or, when it was opened with the pointer, to the page element that had focus before (KEY-6, KEY-7, KEY-8, KEY-10).

  1. 1 The control counts what is open, "Devtools · 1 open"; its accessible name spells the summary out, "Devtools: 6 on this page, TanStack Query open", and its tooltip lists each open panel.
  2. 2 It opens an anchored panel listing every launcher as a row in the bar's order: the toggle named by its library and its state in words; an unavailable row carries its reason sentence (step 7). The panel stays open while rows toggle, so panels on different edges open in one visit. It never overlaps the notice stack and paints above docked chat (SURF-2, SURF-1).
  3. 3 While the Redux window is open, Redux DevTools' row offers Show and Close, whose accessible names add their target ("Show Redux DevTools", "Close Redux DevTools"). While a store needs setup, the control shows the problem look with its count, "Devtools · 1 needs setup" (ACT-13).
  4. 4 When its rows overflow its height, it gains a filter field, focused on open, that matches library and instance names as the person types; an empty result names the query with Clear Filter (SEL-10, STATE-2).
  5. 5 At every acceptance viewport (1600x1000, 1280x800 and 900x900 in the light and the dark theme, and 1280x800 at 200% zoom) the bar keeps one row, the Devtools panel fits the viewport with every row reachable, and every launcher, Close Redux DevTools and Devtools is at least 24 by 24 CSS pixels or spaced as WCAG 2.5.8 accepts. Below them, the panel takes the window's width less 16 px on each side (SURF-9, O8).
  6. 6 While the page shows a modal dialog, the launchers pause with the bar, inert, and the reason is one line in the moved notice stack. Library panels and an open Redux window stay as they are, and a Devtools panel open when the dialog opens stays anchored and paused until it closes (SURF-11, KEY-7, CC-3).

Fixes nothing on its own; the Devtools control is new · Backend: none of its own; the inline and folded forms read one launcher model with state, name, reach and reason (Backend 2)

7. A launcher that cannot act now says why

Launchers still appear and disappear as libraries mount and unmount, without a page reload, and Vue is still offered only from a trusted, visible dock with one Vue entry: devhost never bypasses the dock's authorization. What changes: an installed library whose panel the toolbar cannot open or close right now keeps its launcher in place, aria-disabled, with a short state after its name and one reason sentence as its tooltip, its accessible description and its row in the Devtools panel, never removed and never live-looking (MENU-3, HOLD-1). These states come from the library, its version or the person's choice and last until the person acts, so they raise no notice; a press that fails is an event, which step 8 reports. The launcher becomes available again by itself when its condition ends, without a page reload; a focused launcher that becomes unavailable keeps focus, and pressing it does nothing (KEY-11). A library that unmounts, or a Vite dock with no Vue app, has no launcher, because there is nothing to open.

  1. 1 The unified shell detached into its own window reads "TanStack Devtools · detached", with its way back in the sentence. Today the entry disappears.
  2. 2 Vue reads "dock hidden", "not authorized" or "ambiguous", each sentence naming what to do in the dock. Today the entry disappears in all three.
  3. 3 A library version whose controls devhost cannot find: detection requires the control the launcher's next press needs, the open control while the panel is closed and the close control while it is open, so the entry reads "not recognized" instead of staying live and doing nothing, as it does today (MENU-3, MENU-5).
  4. 4 While any of a library's launchers is not recognized, devhost stops hiding that library's own launchers, so its panel still opens from the page; they hide again once devhost recognizes the controls. React Hook Form's open state reads its panel's own visibility, never its launcher's absence. A Jotai release that changes the controls devhost reads removes the Jotai entry and leaves Jotai's own launcher in place, as today.
  5. 5 While the page's status stream is lost, every library launcher keeps working, because it acts in the page; Redux DevTools is unavailable while its window is closed, because devhost serves that window's page, with "Lost connection to devhost; retrying" as its accessible description and the condition notice as its visible reason. An open window keeps working, because it talks to the page directly (HOLD-2, HOLD-1).

Fixes third-party-devtools-07 · Backend: the adapters report detached, dock hidden, not authorized, ambiguous and not recognized instead of removing the entry; detection checks the control the next press needs; a library's hide selectors stop applying while it is not recognized (Backend 8)

8. Report failures in words where they started

devhost still never weakens popup blockers, a page's Content Security Policy or its opener policy, it creates, instruments or changes no store, and a press that succeeds still raises nothing. What changes: a launcher press that fails says so as a failure notice in the notice stack, the dock's status line, announced once in the assertive region and kept until the person dismisses it or the same launcher succeeds (FAIL-2, FB-6, FB-9, WORD-7). Today the press ends in silence: no notice, no new tooltip and no console line, and the blocked popup and a store's setup error live only in hover text.

  1. 1 A popup the browser blocks leaves the launcher unpressed, and the notice says so with the way out; a store's setup problem never masks it.
  2. 2 When the press clicked a control but the panel's state still differs after 60 frames (about a second), the library ignored it. Each notice links its integration page of devhost's docs, which lists the versions devhost is tested with and the key that turns that integration off (step 9) (MENU-5).
  3. 3 Pressing it again with the same result updates that notice with a count instead of adding another (FAIL-4). Focus stays on the launcher, whose accessible description becomes the failure sentence (KEY-11).
  4. 4 Until a press of that launcher succeeds, devhost stops hiding the library's own launchers, so the way out the notice names is on screen; the press that succeeds hides them again and clears the notice.
  5. 5 A press that finds no control, because the control went away since detection, knows it at once, because each adapter's open and close report what they did, and the launcher turns "not recognized" (step 7). A close that fails reads "did not close" and ends "Close it from the panel itself."; a dock that refuses the switch keeps its message behind Copy Error (FAIL-2, WORD-7).
  6. 6 A store that cannot connect is a state, not an event: the launcher keeps working for the other stores and shows the problem by shape and text, "Redux DevTools · 1 needs setup", with the count of connected stores in its tooltip and accessible description, never "unavailable" (ACT-13, WORD-7).
  7. 7 Opening the window shows the store's name and its fix above the inspector, with Copy Error, which holds the original message. When every store fails, the window still opens on that line (FAIL-2).

Fixes third-party-devtools-04, third-party-devtools-07 · Backend: open() and close() return pressed or no control, the Vue adapter's a promise that rejects with the dock's message; toggleLauncher raises the failure at once or after 60 frames and counts repeats; a library's hide selectors stop applying until a press succeeds (Backend 2)

9. Turn one integration off

[devtools.externalToolbars] keeps enabled as the master switch, and a save still applies through hot reload without a page reload and asks nothing; open panels stay open, and an unknown key in the table is still reported with its file, line and key, as today (REV-1, REV-10). What changes: the table gains one key per integration, each true by default, so a team that prefers one library's own launcher turns off only that one (SEL-11). Nothing in this journey writes except this manifest save, so there is no Undo: an integration turned off comes back by saving its key as true again, which hot reload applies, and a panel opened by mistake closes from the same launcher.

  1. 1 The keys tanstack, redux, vue, reactHookForm and jotai sit under the kept master switch. The description of each key in the example manifest, guides/devtools.md and each integration page says what it removes; redux = false, like enabled = false, removes Redux DevTools, which has no native launcher (SEL-11).
  2. 2 The stack's terminal and log print the reload's one outcome line, the line toolbar-shell words for every toolbar change (FB-3, FB-10).
  3. 3 Only the Jotai launcher leaves: Jotai's own launcher comes back, an open Jotai panel stays open, and every other launcher, Redux DevTools included, stays. Restored native launchers sit where their libraries put them; keeping devhost's dock off them is toolbar-shell's per-person placement (toolbar-shell-02, related, owned by toolbar-shell).
