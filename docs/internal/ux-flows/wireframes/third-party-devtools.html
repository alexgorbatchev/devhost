Use your framework's devtools from the toolbar

TLDR: Launchers name their library, panels on one window edge take turns, the Redux window opens on a named store and survives reloads, a launcher that cannot act or fails says why, and each integration turns off on its own.

Low-fidelity wireframe. Layout, names and numbers are illustrative; the redesign ticket's acceptance criteria are authoritative.

1. Find the launcher

The launchers keep their place in the bar's order, in the order devhost finds the libraries, and each still opens the library's own panel through the library's own control. What changes is what they say: each names the library whose panel it opens, so nothing needs a hover to tell them apart. Today the same bar reads Router, Query, TanStack, Form 1, Jotai 1 and Redux. A page with no integration shows no launcher. Keys: Alt+Ctrl+B focuses the bar; each launcher is an arrow stop; Enter or Space toggles it; Tab leaves the bar (KEY-3, KEY-4).

  1. 1 Each launcher's tooltip and accessible description say what it opens and that it acts on this page, as toolbar-shell words the reach of the other bar items; the Vue launcher's tooltip keeps Vue DevTools' connection status after it (SEL-3).
  2. 2 One toggle per library panel the page mounts, named by the library whose panel it opens; the two that open a tool for several libraries take the tool's name: TanStack Devtools for the unified shell, and Redux DevTools for the Redux Toolkit and Zustand stores the page registers. No label reads "Form" (WORD-3).
  3. 3 While pressed, the launcher reads open by shape as well as color (an inset border and ☑, toolbar-shell's pressed look), so it holds in forced colors (ACT-13).
  4. 4 A lone panel has no number. When the launchers would wrap the bar's one row, they fold into Devtools (step 5).
  5. 5 A number appears only with two or more panels of one library, counted from the panels on the page each time: React Hook Form's panel does not expose its DevTool's id prop, and devhost collects no atom data, so neither library gives a name to show.
  6. 6 devhost binds none of the libraries' keys, and guides/devtools.md's Keyboard section lists them. It has no row for TanStack Devtools' held source-inspector key, which opens an editor: devhost offers no editor path (KEY-2, CC-29, O51). The reference's keyboard table no longer lists that key.

Fixes third-party-devtools-06 · Backend: each adapter reports its library's product name and its number among several panels, or none (Backend 2, 4)

2. Open a library panel

Pressing a launcher still clicks the library's own open control, and the panel is still the library's, where the library docks it; devhost never moves, resizes or restyles a panel. What changes: panels docked to the same window edge take turns, the launcher says so before the press, and devhost's dock steps off a panel at the bottom edge, inward of one at the right and below one at the top. Opening a panel is a read: no notice, no log line and no announcement. Focus stays on the pressed launcher, and devhost moves no focus into a library's panel; after a pointer press the page's keys keep working (KEY-5, KEY-6, CC-28).

  1. 1 Before the press, the launcher's tooltip and accessible description name its reach: the open panel on the same edge it will close (SEL-1).
  2. 2 While a panel docks to the bottom edge, toolbar-shell moves the dock onto the panel's top edge, or to the top of the window when the panel is taller than half of it, and follows the panel's resize handle. This flow supplies the seam: each adapter reports its open panel's element and edge (SURF-1, SURF-7, SURF-5).
  3. 3 Enter closes TanStack Router through its own close control, then opens TanStack Query, so at most one launcher per edge reads pressed and it is the panel on screen. When that close fails, nothing opens on top and the failure is reported (step 7). Today Query opens over Router and both read pressed (SEL-11, SEL-1).
  4. 4 A panel's edge is read from its own rectangle: it docks to an edge it touches and spans more than half of. A React Hook Form panel opens a full-height column on the right, where the dock and docked chat shift inward by its width, as they do for the minimap strip, and return when it closes (SURF-1, SURF-5).
  5. 5 Panels on different edges stay open together, both launchers pressed, each closing on its own; with Query at the bottom and the column at the right, the dock sits on Query's top edge, inward of the column.
  6. 6 An app that docks TanStack Query to the top edge gets the same turn-taking on that edge, and a dock the person placed in a top corner sits below the panel; the person's placement returns when it closes, and the move is never saved (SURF-1, SURF-7).

3. Use the panel and close it

The panel keeps its own keys, Escape and close controls, and devhost adds no Escape to it (KEY-1, KEY-8). Closing a panel by its own control, its pressed launcher, Escape or a library hotkey still unpresses its launcher within one frame. What changes: every panel shows its own close or minimize control, and the dock returns to the person's placement when the panel closes.

  1. 1 devhost's stylesheet hides only the floating launchers, so TanStack Query's minimize button and the unified shell's close button stay visible, as Router's, React Hook Form's and Jotai's already do. Today devhost hides both.
  2. 2 The panel closes, TanStack Query unpresses within one frame, and the dock returns to the corner the person chose; its temporary move was never saved (SURF-7).
  3. 3 With the toolbar collapsed the launchers are hidden, and an open panel still closes from its own control. An open panel is not a condition, so the collapsed badge does not show it (SURF-8).
  4. 4 Picks reach the panel: an open library panel is part of the page, so Select Elements and Alt + right-click resolve its elements like any other, and the element path starts at the library's root. Alt + right-click copies a path and never opens an editor (SEL-9, SURF-11, O51).

Fixes third-party-devtools-02 · Backend: the hide selectors keep only floating launchers; Query's minimize button and the shell's close button leave them (Backend 2)

4. Open the Redux inspector, bring it back, keep it through reloads

Pressing Redux DevTools still opens devhost's own inspector in a popup window with no browser extension, which accepts a connection only from its opener, at the same origin, with the matching session ID. What changes: it opens on a named store, says which store it follows, keeps Zustand changes made before it opened, comes to the front instead of closing, and survives reloads. Keys: Close Redux DevTools is the next arrow stop after the launcher.

  1. 1 The unpressed launcher's tooltip names the stores it will show (SEL-1).
  2. 2 The window's title names the store, the stack and the page's host, and changes with the chosen store (WORD-3).
  3. 3 The window opens on the first registered store in the inspector's instance picker, never on "Select..."; the person's later choice is kept (STATE-2).
  4. 4 While "Autoselect instances" is chosen, a line devhost draws above the inspector names the store it shows.
  5. 5 Zustand history starts when the store registers: the page keeps each store's latest 50 changes within 16 MB, so changes made before the window opened follow @@INIT and survive a reopen (O49).
  6. 6 While the window connects, its line and the launcher's description say so with the elapsed time (STATE-1).
  7. 7 Whenever the count or the limit dropped older changes, the line names how many it shows; a store too large to keep two changes keeps none while the window is closed, and the line says so (O49).
  8. 8 Each tab keeps its own window session, so two stacks' windows never read alike in the window switcher (WORD-3).
  9. 9 While the window is open, pressing Redux DevTools brings it to the front and never closes it. Today that press closes the window and loses the store choice and the Zustand changes (SEL-11).
  10. 10 Close Redux DevTools, a ✕ of at least 24 by 24 CSS pixels and its own arrow stop, closes the window; so does the window's own close, and either unpresses the launcher within 100 ms (SURF-9, KEY-4, WORD-2).
  11. 11 A reload of the page, devhost's own reloads included, keeps the window: it waits with the elapsed time, then reattaches to the next page with the chosen store, and the launcher, Show and Close Redux DevTools act on the same window (STATE-1).
  12. 12 A page that registers no store leaves the window waiting for one (STATE-2); a closed tab or another origin leaves Close Window, with the stores untouched.

5. Fold the launchers when they would wrap the bar

Inline launchers stay bar toggles while they fit on the bar's one row. What is new is the folded form: by the bar's fit test, second in toolbar-shell's sequence after the Services summary, the launchers fold into one Devtools control, never by a count (SURF-10, SEL-10). It is the third-party launchers' panel that SURF-2 lists among the anchored popovers. Keys: on open, focus goes to the filter when there is one, else the first row; Tab past the last control or Escape closes it and returns focus to Devtools (KEY-6, KEY-7, KEY-8).

  1. 1 The anchored panel lists every launcher as a row in the bar's order, the toggle named by its library with its state in words, an unavailable row with its reason sentence (step 6). It stays open while rows toggle, never overlaps the notice stack and paints above docked chat (SURF-2, SURF-1).
  2. 2 The control counts what is open; its accessible name spells it out, "Devtools: 6 on this page, TanStack Query open".
  3. 3 While the Redux window is open, its row offers Show and Close, named with their target ("Show Redux DevTools").
  4. 4 With a panel open and a store that needs setup, the control reads both, the problem by shape and text (ACT-13).
  5. 5 When its rows overflow, the panel groups them under each library with a count, pins the rows that need the person above the rest, and gains a filter focused on open that highlights the match and announces the count; an empty result names the query with Clear Filter. It has no panel-level actions, so no footer (SURF-10, SEL-10, STATE-2).
  6. 6 At every acceptance viewport the bar keeps one row, the panel fits with every row reachable, and every target is at least 24 by 24 CSS pixels. Below 640 CSS pixels the panel takes the window's width less 16 px on each side (SURF-9, O8).
  7. 7 While the page shows a modal dialog, the notices move into it and the launchers pause with the bar; library panels and an open Redux window stay as they are (SURF-11, KEY-7, CC-3).

6. A launcher that cannot act now says why

Launchers still appear and disappear as libraries mount and unmount, without a page reload, and Vue is still offered only from a trusted, visible dock with one Vue entry. What changes: an installed library whose panel the toolbar cannot open or close right now keeps its launcher in place, aria-disabled, with a short state after its name and one reason sentence as its tooltip (also on focus), its accessible description and its Devtools row, never removed and never live-looking (MENU-3). It raises no notice: the condition comes from the library, its version or the person's choice and lasts until the person acts there. It becomes available again by itself, and a focused launcher keeps focus (KEY-11).

  1. 1 The unified shell detached into its own window reads "TanStack Devtools · detached". Today the entry disappears.
  2. 2 Vue reads "dock hidden", "not authorized" or "ambiguous", each sentence naming what to do in the dock. Today the entry disappears.
  3. 3 Detection requires the control the launcher's next press needs, so a version whose controls devhost cannot find reads "not recognized" instead of staying live and doing nothing, as it does today (MENU-3, MENU-5).
  4. 4 While a library's launcher is not recognized, devhost stops hiding that library's own launchers, so its panel still opens from the page.
  5. 5 While the page's status stream is lost, every library launcher keeps working, because it acts in the page; Redux DevTools is unavailable while its window is closed, with the lost connection's notice as its visible reason (MENU-3, HOLD-1).
  6. 6 From another environment, the launchers and Redux DevTools work as on this machine beside toolbar-shell's sign-in prompt: they act in the page, so the passkey or pairing check gates none of them (HOLD-8, O36).

Fixes third-party-devtools-07 · Backend: the adapters report detached, dock hidden, not authorized, ambiguous and not recognized instead of removing the entry; detection checks the control the next press needs; a library's suppression stops while it is not recognized (Backend 8)

7. Report failures in words where they started

devhost still never weakens popup blockers, a page's Content Security Policy or its opener policy, and a press that succeeds still raises nothing. What changes: a launcher press that fails says so as a failure notice in the notice stack, announced once in the assertive region and kept until the person dismisses it or the same launcher succeeds (FAIL-2, FB-6, FB-9, WORD-7). These are page actions, not operations of the stack, so they have no operation record: each failure writes one line to the stack's log (FB-7), which keeps it after a page reload clears the notice with the page, FB-6's one exception. Today the press ends in silence.

  1. 1 A popup the browser blocks leaves the launcher unpressed, and the notice gives the way out; a store's setup problem never masks it.
  2. 2 When the panel's state still differs 60 frames (about a second) after the press, the library ignored it. Each notice links its integration page of devhost's docs, with the tested versions and the key that turns the integration off (MENU-5).
  3. 3 Pressing again with the same result updates that notice with a count (FAIL-4). Focus stays on the launcher, whose description becomes the failure sentence (KEY-11).
  4. 4 Until a press succeeds, devhost stops hiding the library's own launcher, so the way out is on screen.
  5. 5 A press that finds no control knows it at once, and the launcher turns "not recognized" (step 6). A close that fails reads "did not close"; a dock that refuses the switch keeps its message behind Copy Error (FAIL-2, WORD-7).
  6. 6 A store that cannot connect is a state, not an event: the launcher keeps working for the other stores and shows the problem by shape and text, never "unavailable" (ACT-13, WORD-7).
  7. 7 The window names the store and its fix above the inspector, with Copy Error holding the original message, and opens on that line even when every store fails (FAIL-2).

8. Turn one integration off

[devtools.externalToolbars] keeps enabled as the master switch, and a save still applies through hot reload without a page reload and asks nothing; open panels stay open, and an unknown key is still reported with its file, line and key (REV-1, REV-10). What changes: the table gains one key per integration, each true by default, so a team that prefers one library's own launcher turns off only that one (SEL-11). This save is the journey's only write, so there is no Undo: saving the key as true again brings the integration back.

  1. 1 The keys tanstack, redux, vue, reactHookForm and jotai sit under the master switch, each described in the example manifest, guides/devtools.md and its integration page; redux = false, like enabled = false, removes Redux DevTools, which has no native launcher (SEL-11).
  2. 2 The stack's terminal and log print the reload's one outcome line, as toolbar-shell words every toolbar change (FB-3, FB-10).
  3. 3 Only the Jotai launcher leaves: Jotai's own launcher comes back, an open Jotai panel stays open, and every other launcher stays. Keeping devhost's dock off a restored launcher is toolbar-shell's per-person placement (toolbar-shell-02, related).

Fixes third-party-devtools-05 · Backend: the manifest's externalToolbars becomes six booleans, each true when omitted, carried by the injected configuration and the health stream; the reload's outcome line names the integrations a save turned on or off (Backend 1)
