Switch the stack to another checkout

TLDR: Worktrees becomes one shared checkout list, found by branch, path or commit, whose Switch and Restart Stack names everything it restarts and leaves behind, asks only when other work is at stake, shows its steps in place and its outcome on the reloaded page, rolls back service by service, and turns a deleted checkout into an explicit choice instead of a restart that cannot work.

Low-fidelity wireframe. Layout, names and numbers are illustrative; the redesign ticket's acceptance criteria are authoritative.

1. Open Worktrees

The Worktrees panel still opens from the bar, still reads the checkout list again when it opens, as today (git worktree list, each checkout's manifest and service folders), and still lists the main checkout and every worktree. What changes: that read stops nothing (HOLD-4), the panel names the repository and when it read the list, and focus starts in a find field at the top instead of at the bottom. Keys: Alt+Ctrl+B focuses the bar; ArrowLeft and ArrowRight reach the trigger; Enter, Space or the arrow toward the panel opens it (KEY-3, KEY-4).

  1. 1 An anchored popover (SURF-2), placed and sized so it never overlaps the notice stack in either corner placement, painted above docked chat, and fitted to every acceptance viewport with its find field, details line, reach line and footer outside the scrolling list (SURF-1, SURF-9, SURF-10). Escape or a click outside closes it, focus returning to the trigger, or to the page element that had focus when it was opened with the pointer (KEY-5, KEY-6, KEY-8).
  2. 2 The header names the repository whose checkouts it lists, "acme" (SEL-4).
  3. 3 "Read 14:02" says when the list was read, beside Refresh Worktrees, which reads it again; while the panel is open the list updates in place from the published state (ACT-12). Opening the panel, Refresh Worktrees and a status page's first check only publish what the read found and stop no service, whatever they find (HOLD-4).
  4. 4 Focus starts in Find checkout at the top of the panel; Tab moves to the highlighted row's remedies in the details line, then the footer; Shift+Tab from the find field reaches Refresh Worktrees and the Repository choice; Tab past the last control or Shift+Tab before the first closes the panel and returns focus to the trigger (KEY-6, KEY-7, KEY-10). Keys typed into the find field never reach the page (KEY-5). The hint line under it reads "↑↓ Move · Enter Pick · Esc Close", drawn from the same key definitions as its handlers, in the platform's notation (KEY-13, BAR-4).
  5. 5 The pick starts on the selected checkout, so Switch and Restart Stack is unavailable until another one is picked, its reason as visible text in the panel's status line and as its accessible description (SEL-4, MENU-3, HOLD-1).
  6. 6 The trigger shows the selected checkout's branch, or "Detached" with its 7-character commit ID, and its accessible name says the same, "Worktrees: main" (SEL-4, WORD-1). It is one arrow stop on the bar (KEY-4).
  7. 7 When a repository of the stack is blocked or its selected checkout is unavailable, the trigger adds the state as a shape and a word, never by color alone, and the collapsed badge carries the same condition with its one-line notice beside it (ACT-13, SURF-8, ACT-7).
  8. 8 When the stack runs services from several repositories, the header offers a Repository choice (SEL-4).
  9. 9 While the list loads, its place reads "Loading checkouts of acme…", here for acme-web (STATE-1).

2. Find and pick a checkout

The list still shows the main checkout and every worktree with its badges, and picking still happens in the list. What changes: rows read the same everywhere, find matches commits too, Enter picks without switching, and every reason is text with its way forward in one details line under the list.

  1. 1 One shared checkout list, shipped in the devtools stylesheet and the status pages' stylesheet, so the toolbar, recovery pages, the crash view and the collapsed list on an app's own 404 render the same rows (SURF-14). The main checkout comes first, then worktrees by branch; each row reads its label from one checkout-label builder, "fix-nav · 08c92af · ~/acme/.worktrees/fix-nav", a long path shortened in the middle with the full path in its tooltip and accessible name (SEL-4, WORD-8). It is a combobox: ArrowUp and ArrowDown move the highlight (aria-activedescendant), Enter picks the highlighted row and never starts a switch, and rows are never Tab stops and hold no controls (KEY-10, REV-2, KEY-9).
  2. 2 Branch and path match fuzzily with the matched text highlighted, and every checkout's HEAD commit matches by exact prefix: "08c92a" finds fix-nav, and "c521449" would list both main and the detached checkout, which share that commit (SEL-4, SEL-10).
  3. 3 Each badge is a shape and a word: running, configured, unavailable, in use, blocked, deleted and edit not applied, from services-panel's shared state indicator and words module; each reason is text in the row's accessible description, never only on hover (ACT-13, WORD-6, KEY-10). The highlight and the pick start on the selected checkout when it is available (SEL-4).
  4. 4 The details line sits below the list, outside it, headed by the highlighted row's label and its reason, never covering another row's badges; its remedies are the Tab stops after the find field and follow the highlight. For a checkout whose manifest fails, the reason is one structured line with the file relative to that checkout, its line and key, the path written once; Open in Editor opens that line in that checkout, Copy Error copies the original text, and Check Again reads the list again once the file is fixed, because devhost does not watch the manifests of checkouts it does not run. Validation issues list one per line (MENU-4, FAIL-2, WORD-7, HOLD-1, KEY-10).
  5. 5 A deleted worktree reads as deleted, never as a raw Git exit status, with git worktree prune to copy: devhost runs only read-only Git commands. A deleted checkout the stack does not run restarts nothing and blocks nothing (WORD-7, SURF-15).
  6. 6 A hexadecimal query that matches nothing says that no checkout has HEAD at it, any other query names what was searched, each with Clear Filter (SEL-10, STATE-2).
  7. 7 A repository with only its main checkout says so and gives the command that adds a worktree on its own line (STATE-2).

3. Read the reach and press Switch and Restart Stack

A switch still changes one repository's checkout and restarts every managed service of the stack, and the press is still the one write. What changes: the button says what it reaches before it runs, the switch keeps the run's service selection, and it asks first only when other work would be left behind. Keys: Tab from the find field reaches the details line's remedies, then Switch and Restart Stack; Enter switches, or opens the question with its first choice focused (KEY-9, KEY-11).

  1. 1 The reach line names the stack, the repository and the target checkout and what the press does; the button's tooltip and accessible description list the six, "web, api, docs, worker, admin and mail" (SEL-5, SEL-1, BAR-2, REV-2).
  2. 2 Switch and Restart Stack reads the same on every surface, title-style and without a count (WORD-2, WORD-3, MENU-6). Picking is the first step and the press the second; with nothing else at stake it runs on one press (REV-1, REV-2).
  3. 3 Before it runs, the control names each item of other work the switch moves the page away from: every conversation of this checkout that works or waits, by agent, title and edit mode, every agent the running agents list sees working here ("Codex in a terminal · working"), unsaved Configuration window drafts, a held reload and page context. While any exists, the press expands in place into one question, a group labelled by its sentence and described by its items and the six services (REV-3, REV-4, SEL-5, WORD-10, O1, UNDO-2, SEL-9, REV-9).
  4. 4 The first choice takes the pressed button's place with focus and Enter: Answer First while an agent waits for the person, which closes the panel and opens docked chat on that conversation's decision card; else Review Drafts while drafts are named, which opens the Configuration window on the first one; else Cancel. Switch Anyway sits beside it; a double press lands on the first choice. Escape, or a click in the panel on no control, cancels the question and returns focus to Switch and Restart Stack with the panel open; a click on another control cancels it and that control acts; Tab past the panel's last control, Shift+Tab before its first and a click outside close the panel and cancel the question (REV-3, REV-4, KEY-7, KEY-8).
  5. 5 In a run started with names, the switch keeps that selection and the line says what stays off (SEL-5, SEL-7).
  6. 6 The button is unavailable, focusable, with its reason in the panel's status line and as its accessible description: while nothing other than the running checkout is picked, while another operation runs, here Restart Stack with its progress, while the page has lost its stack's status stream, and while the repository is blocked (step 7) (MENU-3, HOLD-1, HOLD-2, HOLD-3).
  7. 7 With chat off, the reach line says that agents were not checked (STATE-2).
  8. 8 The services runtime runs every check before it stops anything: the target is registered and available, its manifest and includes load, its service folders exist, and its hostnames and fixed ports are free, probed with the holder named. A failed check refuses the switch with nothing stopped and names the check; a target that changed since the list was read is refused with the current state, the list redraws and the pick is kept when it still exists (REV-11, REV-13, FAIL-2). The switch then writes a pending-switch record and leaves the stack's saved selection on main until it succeeds; a state directory that cannot be written refuses it the same way.

4. Watch the switch in place

The switch still runs on the server with the stack's lifecycle, so closing the tab never cancels it, and it still stops every managed service before starting them in the target. What changes: the pressed control and the panel say which step runs and which service it waits on, and every surface draws the switch as a switch, never as failures or a lost connection.

  1. 1 The panel lists the steps, updated at least once a second: "Checked fix-nav", "Stopping 6 services · 3 of 6 stopped", "Starting in fix-nav · web · health check 2 s of 30 s", "Moving routes and hot reload to fix-nav" (FB-1, STATE-1, ACT-4). Services devhost stops for the switch are steps of it, never exits (FAIL-5).
  2. 2 The old row keeps running until the target's services run (ACT-3).
  3. 3 The confirm control stays where it was as the busy control and keeps focus, aria-busy and aria-disabled, never disabled, reading what runs: "Switching to fix-nav · 3 of 6 stopped · 5 s", then "Switching to fix-nav · 2 of 6 started · 9 s" (KEY-11, FB-9, WORD-4).
  4. 4 The trigger reads "main · switching to fix-nav", never claiming the target before it runs (ACT-3).
  5. 5 Closing the panel moves the progress to one activity line in the notice stack (FB-1, FB-8). The page's status stream stays open throughout, so no lost-connection state appears (ACT-5, HOLD-2).
  6. 6 Every surface draws the switching repository's services as "switching to fix-nav ~/acme/.worktrees/fix-nav" and the target's services as starting with their health check, never failed and never running from the old checkout; changed marks clear against the new launch (ACT-3, ACT-4, ACT-8).
  7. 7 While the switch runs, Restart Changed, its badge icon, every Restart, Start and Restart Stack are unavailable with "Switch to fix-nav is running · 2 of 6 started", and Alt+Ctrl+R shows that reason in a notice instead of doing nothing (HOLD-3, SEL-2, MENU-3).

5. Read the outcome on the reloaded page

The page still reloads at the same URL after a switch, and the stack still restores its saved checkout at the next devhost start. What changes: the switch succeeds only once the target's services run, the reloaded page says what happened and what was left behind, focus starts on that sentence, and the terminal names checkouts by branch and path. A switch restarts processes and cannot be taken back, so there is no Undo: its rollback restores the previous checkout when the target fails (step 6), and its outcome links the previous checkout as the way back (UNDO-1, UNDO-5).

  1. 1 The switch succeeds only once every target service passed its health check, with no leftover of a killed run answering in its place, and the routes and hot reload follow the target; only then does devhost save fix-nav as the stack's selection, remove the pending-switch record and reload the page (FB-5, ACT-11, UNDO-1). The page that loads finds the outcome by the operationId it stored and shows it once, as an outcome notice whose sentence takes focus, announced once in the polite region (FB-2, FB-3, KEY-6, FB-9, WORD-4, WORD-5). It closes 4 s after the pointer and focus leave it and stays readable in the stack's log, links included (FB-6, FB-7, O14).
  2. 2 The outcome names what the switch left behind: the conversation's title opens its decision card in docked chat in one activation, and marks of page context that did not survive the reload are named too (FB-4, SEL-5, REV-9, UNDO-2). The previous checkout, "main ~/acme", opens Worktrees with main highlighted, so the way back is one switch away (UNDO-5).
  3. 3 The trigger names fix-nav (SURF-15). Chat keeps its agent, model, edit mode, open state, side and draft, because they belong to the stack and page origin, not the checkout (SEL-11, CC-9).
  4. 4 The count is of the whole stack, the services the run left out included; a selected name the target's manifest does not define is named and never fails the switch (ACT-6, SEL-5).
  5. 5 When the reloaded page is answered with a 5xx by a target service whose health check passed, the outcome says so instead of a plain success, and the app's answer shows with startup-and-recovery's notice; when web's last output names a missing dependency, that notice leads with the needs-setup action: the command to run in fix-nav, to copy, then Restart (SURF-16, FB-5, O32, FAIL-3, MENU-5).
  6. 6 The terminal prints one line when the switch starts and one outcome line, naming both checkouts by label, and no "exited … waiting for a restart" line for any service the switch stopped (FB-10, FAIL-5, WORD-4, SEL-4). Agent output carries the same facts with absolute paths and a failure on one devhost: ERR: line, and devhost status reports the switch as the stack's last operation (FB-11, WORD-9, ACT-1). A switch has no terminal command of its own; another checkout runs from a terminal as its own stack, in its folder.
  7. 7 A start that restores a linked worktree keeps the names it was given and names the restored checkout in its ready line, in the foreground or with --detach (SEL-5, FB-10, WORD-9).
  8. 8 When devhost was killed before a switch ended, the next start runs the checkout the stack ran before, never a target no switch verified, and says so once, in human output, agent output and the stack's log; later starts say nothing about it. A page that started that switch and reconnects shows the same sentence as its failed outcome, with fix-nav linked to Worktrees with fix-nav picked (UNDO-1, FB-10, FB-11, FB-7, ACT-10, FB-2).

6. Recover from a failed switch, in place

A failed switch still returns to the checkout it left, never to a third one, with that checkout's routes and hot reload, and the stack's saved selection still names it. What changes: the return is service by service and reported as a return, the panel keeps the failure with its evidence and the way forward, and a retry is one press.

  1. 1 The outcome replaces the progress in the open panel and takes focus on its sentence, with web's evidence from the attempt: its exit code with the time, its last output lines frozen at the exit, the probe it failed and what devhost ran (FAIL-1, FAIL-2, FAIL-3, FB-2, FB-9). It stays in the panel and as a notice until the person dismisses it or a later switch to that checkout succeeds; reconnects and page reloads never remove it (FB-6).
  2. 2 It leads with the action for its cause: for a fresh checkout whose service cannot find its dependencies, the command to run in that checkout, to copy (O32, MENU-5).
  3. 3 Retry Switch runs on one press; its accessible name and reach line name the target, "Retry Switch to fix-nav ~/acme/.worktrees/fix-nav" (REV-1, REV-2, WORD-2).
  4. 4 While it restores, the busy control and the touched rows read "Returning to main ~/acme". The saved selection never left main, because a switch saves its target only once it succeeds, and the pending-switch record is removed (UNDO-1, ACT-3).
  5. 5 A restore that cannot bring a service back leaves it failed with its own recovery page while the rest run; the set is never stopped as one unit because one member fails (UNDO-1, FAIL-1).
  6. 6 The terminal prints the same outcome in one line (FB-10, FAIL-1).

7. Recover a deleted or blocked checkout

A deleted or unregistered selected checkout still never falls back to another checkout by itself (owner rule), devhost still notices it when it next reads the list, and other repositories keep running. What changes: that read stops nothing, the deleted state reads as deleted, and the way out leads with returning to the configured checkout on every surface, never with a restart that cannot work.

  1. 1 devhost publishes the repository as blocked with one sentence; processes that still run keep running from the deleted folder until the recovery the person chooses restarts the repository or they exit, and devhost starts none of its services until then. The sentence shows once in the panel's status line and is the accessible description of every control it blocks: each Restart of the repository's services, Restart Changed's members in it, and Switch and Restart Stack while nothing is picked (HOLD-4, HOLD-1, MENU-3, ACT-2).
  2. 2 The panel leads with Return to Configured Checkout, then the list to choose another checkout; Check Again reads the list again and clears the block when the folder is back, restarting nothing (MENU-5, HOLD-1, HOLD-4).
  3. 3 The deleted row stays listed, disabled with "deleted · ~/acme/.worktrees/fix-nav is gone", and is never preselected: the highlight starts on the configured checkout (SEL-4, MENU-5).
  4. 4 Return to Configured Checkout asks every time, in place: Cancel takes the pressed button's place, focused and taking Enter, with Return to Configured Checkout beside it; other work joins the question when it exists. Once confirmed it runs and reports like a switch (steps 4 to 6) (REV-1, REV-2, REV-3, REV-4).
  5. 5 Once none of its services runs, the sentence says the services are blocked, and each one reads "blocked" (ACT-2). A rejection notice that the deleted checkout's manifest caused clears when the stack accepts a configuration from another checkout; manifest-hot-reload owns that notice (FAIL-4).
  6. 6 A rejected manifest edit never makes its checkout unavailable: the read keeps the running checkout running, adds edit not applied, and the details line gives the rejection once with Edit, the Configuration window at that line, or with the config editor off Open in Editor and Copy Error; nothing is stopped, blocked or disabled, and switching away stays possible (HOLD-6, HOLD-4, MENU-4).
  7. 7 An external service whose folder lies in the repository blocks the repository's switch, as O7 recommends: the status line says so once, every row stays listed and readable, each disabled with that sentence as its reason, Switch and Restart Stack is unavailable with it as its accessible description, and the details line opens [services.preview] in devhost.toml. The block clears when hot reload accepts a manifest without it; that reload's own line is manifest-hot-reload's (SEL-5, HOLD-4, MENU-4, HOLD-1).

9. Switch from a status page or the crash view

Startup and recovery pages still offer switching and Refresh Worktrees, even with the toolbar off, as today. What changes: they render the same checkout list and the same operation as the toolbar instead of a native select, and a deleted checkout's recovery page leads with the way back, not with a restart.

  1. 1 Startup, recovery and app error pages render the shared checkout list, its details line, the reach line, Switch and Restart Stack, Return to Configured Checkout and Refresh Worktrees, replacing today's native select with its full paths, 40-character commit IDs and errors inside options (SURF-14, SEL-4, MENU-1).
  2. 2 A deleted checkout's recovery page leads with Return to Configured Checkout, then the list; Restart web is unavailable with the cause above it as its reason until a checkout is chosen, and the deleted checkout is never preselected (MENU-5, SEL-4, HOLD-1).
  3. 3 The list keeps the toolbar's keys and words: focus in the find field, arrows to move, Enter to pick without switching, the remedies after it (KEY-10, WORD-1, WORD-2).
  4. 4 The question, progress and outcome follow steps 3 to 8, and the page that loads after a switch shows its outcome (FB-2).
  5. 5 The crash view, when its cause is a deleted or blocked checkout, shows the same list inside its recovery view, and a switch started there reports its progress and failure in the view (SURF-3).
  6. 6 On an app's own 404 or 5xx, startup-and-recovery's notice holds the same list collapsed under "Is this route in another checkout?"; switching from it takes the same two steps (SURF-16, O5).
