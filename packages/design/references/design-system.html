devhost design system

The written specification for devhost's two surfaces: the devtools UI injected into routed apps, and the public docs site. devtools.html and docs.html are the authoritative visual references. This page restates what they do as rules and shows the shared primitives side by side. When this page and a reference disagree, the reference is right and this page gets fixed.

Concern Source of truth
Colors, radii, host markers packages/design/src/constants.ts → generated tokens.css (--dh-*)

Principles

These six ideas explain every rule further down.

Monospace everywhere

Chrome, prose, tables, and code all use one monospace stack with ligatures off. Inline code stands out through its surface, because the font can't set it apart.

One palette, two densities

Both surfaces share every color and radius. Only size differs: the devtools use 11–13px on a 20px control height, and the docs use 11–26px on a 28px control height.

Visible on anything

Devtools draw over pages devhost does not own. Floating surfaces use the frame (edge + halo + shadow), and host overlays use a two-tone ring, so some layer always contrasts with the pixels underneath.

Structure first, color as signal

Size, weight, rules, and surfaces carry the hierarchy. Color marks state and emphasis, and it always comes from a token, never from a new hue.

Native primitives

Use <dialog> for modals, <details> for disclosure, <select> and checkboxes with accent-color, and ARIA state attributes (aria-pressed, aria-expanded, aria-current) as styling hooks.

Sharp geometry

Corners are 2px or 4px. The only round shapes are circles and counters that encode status or a marker number.

                Type

                Use one monospace family at weights 400, 600, and 700, plus italic 400 for code comments. Don't use 500. Set font-variant-ligatures: none and -webkit-font-smoothing: antialiased on every surface. Don't uppercase text and don't widen letter-spacing for labels. The only tracking adjustments are −0.02em on the page title and −0.04em on the logo mark.

                Surface --dh-font stack
                Docs "JetBrainsMono Nerd Font", "JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, Consolas, monospace
                Devtools "devhost JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace

                "devhost JetBrains Mono" is a namespaced family, so it can't collide with fonts the host page declares. Browsers ignore @font-face inside a shadow root, so the devtools register the @fontsource-variable/jetbrains-mono subsets with document.fonts (FontFace API) and inject no CSS into the host page. The references register the same subsets from jsDelivr, pinned to the locked version.

                Frame

                Everything that floats over content uses the frame: the toolbar, panels, hint, composer, menus, component source menu, terminal, minimap preview, and the docs search dialog. It has an opaque --dh-surface fill, a 1px --dh-edge border of opposite lightness, a 1px --dh-halo outer ring, and --dh-shadow. On a dark page the light edge separates the frame. On a light page the dark halo (dark theme) or dark edge (light theme) separates it. In-flow docs content (code, tables, asides) doesn't use the frame. It gets a 1px --dh-line border only.

                Motion

                Motion shows state changes and nothing else. Nothing bounces, scales, lifts on hover, or glows. Every animation turns off under prefers-reduced-motion: reduce.

                Motion Spec Used for
                Fade --dh-duration-fade 120ms ease-out on opacity, display, with transition-behavior: allow-discrete and a @starting-style enter Persistent surfaces toggled with hidden. Hidden surfaces are also inert.
                Spin 0.8s linear infinite Restarting dot, restart icon
                Pulse 1.2s ease-in-out infinite, opacity → 0.35 Running session LED only
                Width 0.12s ease-out Minimap strip widening on hover
                Rotate 90°, --dh-duration-fade Disclosure chevrons (sidebar groups, mobile TOC)

                Default tags are outlined in fg-muted. Filled tags are 600 on the matching --dh-on-*. On the docs site they map to Starlight <Badge> variants default, note, success, caution, and danger. Keys draw a currentColor outline at 0.8 opacity with no fill, so they adapt to whatever surface they sit on, including primary buttons.

                Inputs

                Devtools · textarea 13px

                Docs · input 36px, select 28px

                Inputs sit on surface-2 with a line border and fg-faint placeholder text. On focus the border becomes accent and a 1px accent ring is added, which replaces the global outline. Checkboxes are native, tinted with accent-color. Selects are native with appearance: none and icon overlays.

                Icons

                Icons use Lucide geometry at 14px (12px for disclosure chevrons and select carets), with stroke 2, round caps and joins, and currentColor. Use .ic.fill for solid glyphs (play, GitHub). Mark decorative icons aria-hidden="true".

                State

                Status indicators

                up up, files changed down restarting
                running connecting error finished

                8px dots show service health. 6px LEDs show session activity. A finished session shows an ok check instead of an LED. Only the running LED animates. Don't add glows or other animation. Every dot and LED needs its state as text next to it: visible, title, or .sr-only.

                Current and selected

                Selection never uses weight or color alone. It uses a raised surface plus an accent bar or ring. Each case has a fixed treatment:

                State Treatment Seen on
                Current item in a list surface-2 + inset 2px 0 0 accent, text fg, weight unchanged Docs sidebar current page, search result hover, component source item hover
                Current heading in the TOC fg, 600, 2px accent left border Docs "On this page"
                Open toolbar segment surface-3 + 2px accent bar on the panel side Devtools toolbar (bottom bar; top bar when docked top-right)
                Pressed chip accent border + inset 0 0 0 1px accent Devtools session chip whose terminal is open
                Toggled on Primary fill via aria-pressed="true" Devtools external tool toggles
                Checked menu item Accent check icon visible Devtools action menu (menuitemradio)
                Section heading 1px line rule + short 2px accent tick Docs h2 (32px tick), sidebar group header (16px tick)

                Errors

                Health check failed: devhost control server unreachable (ECONNREFUSED)
                Session exited before the annotation finished. Resume to retry.
                Delete this annotation?

                Errors get louder with scope. A panel-wide failure is a .notice (filled danger). A per-item cause is a .reason (danger text on danger-soft). An inline destructive confirmation is a .confirm strip. An error on a toolbar segment turns the whole segment danger (.seg.alert).

                Devtools UI

                This UI renders inside Shadow DOM. :host { all: initial !important } blocks host styles from inheriting in, and buttons and inputs reset letter-spacing and text-transform. The specimens below are rendered in-flow. In the product they are position: fixed. See devtools.html for live behavior.

                Toolbar

                The toolbar is a single framed bar, 8px from the bottom-right corner (or top-right), with segments separated by 1px line rules. From left to right: the logo and stack name (click to collapse to one stack-health dot), services, annotation queues, external devtools toggles, and session chips. Session chips that don't fit fold into +N. The toolbar never clips.

                Panels

                Panels open from the segment that triggered them, using CSS anchor positioning: above the toolbar (below when docked top-right), start-aligned, and flipped inline near the viewport edge. Max height is min(60vh, 520px). The header is a 24px row at 700. Rows are 24px minimum, separated by line, and hover to surface-2.

                Rules

                Apply these when extending either surface. Each one comes from something the references do.

                • Change colors, radii, and markers only in packages/design/src/constants.ts, then run just design write-tokens. Never add a color literal to a consumer when a token exists. Host scene colors in the references are simulated host content, not design.
                • Tints come only from the derived tint recipes.
                • Use weights 400, 600, and 700 only. Don't uppercase text or widen tracking. Build hierarchy from size, weight, rules, and surfaces.
                • Use --dh-radius-sm for controls and --dh-radius-md for containers. Round shapes are reserved for status dots and marker counters.
                • Anything that floats over content uses .frame. In-flow content uses a 1px --dh-line border.
                • Mark state with the fixed current and selected treatments. Don't invent new ones, and never mark state with color alone.
                • Disabled controls are dashed and hollow, not faded. Destructive buttons are outlined until hovered.
                • Style from ARIA state (aria-pressed, aria-expanded, aria-current, aria-checked) instead of parallel classes, so the visual state and the accessible state can't drift apart.
                • Use native primitives before custom widgets: <dialog>, <details>, <select>, checkboxes with accent-color, and hidden + inert for dismissed surfaces.
                • Devtools styles must survive hostile host CSS: :host { all: initial !important }, marker tokens for anything drawn over host pixels, and z-indices of six significant digits or fewer.
                • Motion is limited to the motion table, and all of it turns off under prefers-reduced-motion.
                • Every runtime design decision must work with several devhost instances open at once. Scope state and theme per Shadow DOM host and never to the host document.
