# devhost UI package

Local React workspace for the injected `devhost` browser UI and standalone status pages, exercised through Storybook.

`src/statusPages/` owns every built-in page: 404, recovery, unavailable backend, running-stack directory, file listing, Markdown, and preview gallery. Build these as React views composed from `@alexgorbatchev/shadcn`; do not create hand-written HTML page templates or inline page behavior. Its document stylesheet is separate from the injected Shadow DOM stylesheet. The `status-pages` export is bundled by `apps/devhost/scripts/buildStatusPages.ts` and embedded by Go; preserve self-contained assets, abortable recovery requests, and the escaped server-rendered fallback. Keep behavior coverage in component stories, hook tests, and Go browser tests, including Caddy route independence, file navigation, remembered Markdown source view, and narrow-screen contrast. Markdown uses `react-markdown` and `remark-gfm` with raw HTML disabled and default safe URL handling; its upstream stylesheet and license live beside `statusPages.css`.

## Commands

- Check package-local validations: `just ui check`
- Unit, browser, and Storybook tests, each writing a coverage report: `just ui test`
- Hook and `*.browser.test.ts` tests in Chromium, optionally limited to matching paths: `just ui test-browser [path]`
- Merged line coverage of the last `just ui test`, with its floor: `just ui coverage`
- Storybook: `just ui storybook`
- Record the real scenes and render the promo: `DEVHOST_DEMO_INTERACTIVE=1 just demo record`; render it again from an earlier recording: `just demo promo`; regenerate its ElevenLabs narration: `just demo audio`; recording tests: `just demo test`. Annotation recording requires a graphical browser and an operator for native tab sharing and permissions. See `../../docs/internal/references/demo-recording.md` for prerequisites, scene refreshes, promo editing, and artifact locations.
- Refresh every public guide video: `DEVHOST_DEMO_INTERACTIVE=1 just demo guides` (or `just demo guides <guide-slug>` for guides without annotation capture); render one guide's film again from its latest recording: `just demo guide-film <guide-slug>`; generate the guide films' ElevenLabs narration, keeping the take of each unchanged line: `just demo audio-guides`. Publication tests require FFmpeg/ffprobe; full rendering also needs VHS/ttyd and Node.js. The Docker guide needs Docker; source-highlight recording uses the running stack's native source-locator API.
- Open the design reference in the default browser (from the repo root): `just design devtools`
- Linux recording regression tests require `Xvfb` on PATH. They create an owned display with `-displayfd`, disable TCP listening, launch Chromium on it with the GPU disabled because Xvfb has none, and stop it after checking real headed-window geometry. CI installs Xvfb alongside FFmpeg and unzip.

## Local conventions

- Keep the injected UI source under `src/devtools/` so the Go app and the public website can both consume the same entrypoint.
- `just ui check` runs `ts-unused` over `src/` and `scripts/`. Its `[INFO]` findings, such as an export or property "Used only in tests", pass the check but must all be resolved; the root `AGENTS.md` says how. The shared lint policy forbids type declarations in fixture files (`no-local-type-declarations-in-fixture-files`), so a type that only tests and their fixtures use belongs in the sibling `__tests__/helpers.ts`, which fixtures import, as `IStartingStackState` in `scripts/demo/__tests__/helpers.ts` does. `test-support/` is type-checked too, `.tsx` included.
- Render button keyboard hints through `Button`'s `shortcut` prop. It owns the shared `Kbd` treatment and keeps the hint outside the accessible button name. Reserve enhancers for icons or other content; use `Kbd` directly only for standalone hints.
- Re-export public entrypoints through `package.json` exports. Consumers should use `@alexgorbatchev/devhost-ui` or `@alexgorbatchev/devhost-ui/main` instead of reaching into source paths.
- Keep package-owned Storybook and browser tests inside this workspace. Storybook discovers owning stories in both `src/**` and `scripts/**`; the native fixture components' stories exercise their UI callbacks and host state, while genuine extension inspection remains in the separately provisioned native command.
- Keep repeatable recording scenes under `scripts/demo/`. Capture real playground interactions through the compiled devhost, with accessible locators and observable readiness checks. Fixed pauses are allowed only for viewer pacing in recordings. The package TypeScript and Bun checks include these scripts and their unit tests.
- `scripts/architecture/` serves the root stack's contributor diagram site using Bun. Keep its handler tests in the package's ordinary Bun suite; the served content and regeneration recipe live in `../../docs/internal/architecture/` and the root `archify` just module. Render index frontmatter as an escaped, compact metadata bullet list and preserve Markdown separators in the body. Serve the Markdown index and HTML diagrams without exposing source specifications or local verification receipts.
- Record portless HTTPS URLs through the existing managed Caddy on port 443. Inherit the devhost state directory, remove only the recording manifest's routes, and leave Caddy running. Use distinct hostnames for concurrent recordings.
- Annotation recordings use real native Codex chat and HMR against a copied playground. Preserve configured CLI authentication, settings, and model defaults. Require an operator to share the current tab and review native requests; never simulate capture or automate permission decisions. Keep the prompt scoped to the copied layout, retain actual edits in `agent-changes.json`, and restore the copy after cleanup; never edit or reset checkout source. Request reduced motion and use click rings without action text labels.
- The full `just demo record` sequence renders the promo from `scripts/demo/promo/`, a HyperFrames project, and writes its docs copy (`publishPromoDemo.ts`) for the docs landing page; single scenes keep the caption-band export. Each guide renders a narrated film from the one template in `scripts/demo/guide/`: a title card, the recorded clips in a window under one spoken line each, and an end card. Neither the promo nor a guide film has music: the narration is the only sound. `guide/narration.json` holds the voice and every guide's lines and `planGuideFilm.ts` times the film from the measured audio, so a guide film needs no hand timing; the recorded clips must be the ones the narration has lines for. `film.css` holds the styles both projects share. A frame requests real footage with `data-footage` on a `<video>`; never rebuild devhost's interface in the composition. Take every devhost color from the staged `--dh-*` tokens. The promo's narration comes from `promo/narration.json` through `just demo audio` and is committed; after regenerating it, re-time `index.html` and the frames to the new `timings.json`.
- Promo scenes and guides capture at device scale 2 through Chromium's `--force-device-scale-factor`. Playwright's emulated `deviceScaleFactor` does not reach the screencast: the page then fills a quarter of the frame. Single scenes stay at scale 1.
- A terminal guide is one VHS recording whose tape clears the screen out of sight before each step. `findGuideStepWindows.ts` cuts it into steps at the frames where the picture falls back to an empty screen; do not time steps from the tape's pauses, because at twice the size VHS's video runs faster than the session it recorded. Keep that clear before every step, and keep step output brighter than an empty screen.
- devhost answers a browser navigation with its startup page until the service passes its health check, while other requests already reach the app. Wait for a stack with `isDemoStackReady.ts`, which requests the page with `Sec-Fetch-Dest: document`; a plain request reports a stack ready too early.
- `scripts/demo/guide/assets/audio/timings.json` records with each guide line's take the SHA-256 of the ElevenLabs request it was generated from, and `generateGuideAudio.ts` speaks only the lines whose request changed or whose MP3 is missing. Change a line in `guide/narration.json` and run `just demo audio-guides`; never edit `timings.json` or replace a line's MP3 by hand. The promo's `just demo audio` speaks every line on every run.
- Read an ElevenLabs SDK stream to bytes before `Bun.write`. Under Bun 1.4, `Bun.write(path, new Response(stream))` never completes for that stream.
- Keep the browser sequence minimap → toolbar/worktrees → selected page context/native chat/live fix → TanStack Query → minimize Query and end. Worktrees belong to the copied Git fixture. Change captions on actual native running state and heading-update events, using native video segments and measured durations. Published films and narration still show the retired interfaces; refresh their narration/audio before rendering replacement footage, and retain **No demo** coverage until a replacement is reviewed.
- Load the playground and wait for UI/fonts before starting capture. Reuse that page across browser scenes, preserve its live state, and reject full-page navigations during capture. Keep real HMR and client-side Query navigation visible.
- Guide recordings exercise real CLI routing, dependency injection, manifest includes/reload, Docker, daemon lifecycle, and the source-highlight API with native DOM-match diagnostics. Keep the shared-listener guide on its own Caddy state/admin/ports and stop that instance after recording; leave the user's shared Caddy running. Publish only reviewed MP4/poster/captions and player blocks with complete HTTPS docs asset URLs.
- `../design/references/devtools.html` (`just design devtools`) is the visual design reference for the injected UI: a standalone page that mounts every devtools surface in a Shadow DOM over switchable host backgrounds. Match its tokens, layout, and state treatments when changing devtools components, and update it in the same change when the design intentionally diverges.

## Local gotchas

- Keep React and React DOM type-package versions aligned with the shared shadcn library. Bun can otherwise resolve separate assistant-ui context instances through different type peers; the production bundle then fails to connect native components to their provider. Preserve native bundled chat acceptance in addition to Vite-based tests.
- `@alexgorbatchev/shadcn` provides native Thread `UserText` and `ComposerActions` slots, `viewportProps`, a `composerInputRef` forwarded to the native composer input, and Capital Case action labels. Keep the native Thread renderer and its lazy boundary for the expanded conversation; the default compact view uses native assistant-ui composer, attachment, and message primitives, shows working state during a turn, and shows only the latest reply afterward. Keep draft and attachment state in the shared runtime when switching views; `ChatUserText` and `ChatComposerActions` use these slots without replacing native message, attachment, or send behavior. `ChatComposerActions` places New Conversation beside Share Tab, and `useChatComposerFocus` focuses the composer through the ref. The owning stories exercise the slots and composer focus; preserve them when updating the dependency. Make changes to this owned package in its source repository and consume a published release; do not patch its compiled output here.
- The native Thread viewport anchors turns at the bottom and follows new replies only while the reader is at the bottom: `useChatScrollPosition` passes the persisted `isAtBottom` as `autoScroll`, so a reader who scrolled back, or whose saved position is above the bottom, keeps their place. `RepliesFollowUntilReaderScrollsBack` fills an empty conversation with live replies and covers following, scrolling back, and returning; `src/devtools/AGENTS.md` explains the footer spacer it depends on.
- `patches/@assistant-ui%2Freact@0.15.30.patch` makes the native composer's Escape handler read the key's original target from `composedPath()`. Its document listener otherwise sees the devtools shadow host and never cancels a running turn from the injected composer. `EscapeInInjectedComposerInterruptsTurn` covers it inside a shadow root; drop the patch once upstream reads the composed path.
- Chat visibility and the chat target (`project` or `devhost`) live in the page's project settings store; the conversation's settings live in a store scoped by the target's directory, which `App` passes to `PageChat`. When that directory is the project root, pass the page's own store: two persisted stores with the same scope write the same storage key and overwrite each other. The **Chat Directory** switch appears only when `/__devhost__/config.json` names a `devhostSourceRootPath`; `DirectoryToggleSwitchesToDevhostCheckout` covers switching and reload.
- Chat uses assistant-ui’s queue for active-turn follow-ups and its image attachment adapter for clipboard PNG/JPEG images. Delivery acknowledgements release the composer without waiting for turn completion. Forward attachment content together with annotated snapshots; keep failed input recoverable and clear queue state when changing conversations.
- Tab sharing belongs to the mounted page chat. An explicitly opened share stays active across snapshots and panel collapse; stopping sharing or unmounting releases its tracks. Chat sends capture only when an explicit share is active and Include Tab Snapshot is enabled; selected metadata and drawings can be sent without an image. Every included screenshot waits for Share Selected Area or Share Whole Tab in the lazy-loaded preview dialog before the native send. Crop source image pixels with canvas, carry the original bounds in page context, and forward only the cropped PNG. Keep keyboard coordinate editing available. Cancel pending previews on share replacement or chat unmount; a late crop for an old request must never resolve a newer send. The capture helper owns and releases its own stream when called without a shared stream. Each snapshot owns a cloned video track with a minimum frame rate, preserving the shared track's constraints and lifetime. Start its native video playback before preparing visibility, then reattach the reader's sink and wait for a frame captured after preparation. The minimum rate supplies fresh frames for static tabs. Capture/presentation timestamps alone can still describe pixels from before visibility changed: save the initial image and require a significant pixel change in every visible excluded surface rectangle before accepting a prepared frame. Map viewport rectangles to video pixels, clip them, ignore empty/offscreen regions, and omit retained annotated surfaces. Compare only those regions so animation elsewhere cannot release stale chrome. Portaled `[role=tooltip]` and `[data-slot=tooltip-content]` surfaces are excluded and checked independently of their trigger panels, even when annotated chat stays visible; never retain tooltips because an annotation overlaps them. A viewport or video-size change restores visible surfaces, rebuilds the baseline, and prepares capture again using the same stream; retries share the ten-second reader deadline and caller cancellation. Those remain active while waiting; a surface whose pixels never visibly change can time out rather than send an unconfirmed image. Stop the reader clone on every outcome, and abort an in-progress capture when the active share changes or chat unmounts. With the `devhost` chat target, keep annotated devhost surfaces visible in capture, with annotation tools excluded, across both the ordinary and annotation roots; with the `project` target, capture hides every devhost surface (`shouldKeepAnnotatedSurfaces`). The native tab-capture tests exercise fresh and reused shares with open popovers and modal dialogs. Clear accumulated page context only after a successful native send acknowledgement.
- The native TanStack Table harness declares `@tanstack/table-core` at the version used by `@tanstack/react-table`, so the table devtools peer resolves the same table types and runtime. Update that pair together.
- This package is the source of truth for the injected browser UI, but the Go app embeds a generated bundle from `apps/devhost/internal/devtools/dist/`. That directory is ignored; run `just devhost build-devtools-bundle`, `just devhost check`, or `just devhost compile` instead of committing generated bundle files.
- Shared `oxfmt` / `oxlint` enforcement runs from the repo root, not from this workspace `check` recipe.
- `just ui check` runs its browser suite with `NODE_ENV=development bun vitest run -c vitest.storybook.config.ts`. Native TanStack event clients and panels intentionally become no-ops under Vitest's default `NODE_ENV=test`; Vite's mode is separate. Preserve the command-scoped environment for targeted browser runs from this package, while Bun unit tests keep their usual runtime.
- TanStack Form reports a form's state to its devtools through a 300 ms throttle that the form's unmount does not cancel, and the Form devtools list any form they receive state for. A story that changes a form and then unmounts it first waits until the Form pane shows the form's final state, as `TanStackNativeCleanup` does; otherwise a late report lists the form again after its removal, which showed up as an intermittent failure whenever the story reached the unmount within 300 ms of the last keystroke.
- Root `patches/jotai-devtools@0.14.0.patch` removes only the dependency's unconditional tree-shaking deprecation notice from both published module builds; native rendering and production guards remain intact. The [upstream discussion](https://github.com/jotaijs/jotai-devtools/discussions/188) confirms that the notice also fires with the recommended integration. Jotai is a Storybook-only host fixture. `.storybook/vitest.setup.ts` forwards warnings and fails on this notice; the real Jotai stories cover store updates, history, multiple stores, and inspector lifecycle. Recheck the patch when changing this dependency and remove it when upstream stops emitting the notice.
- Vitest's browser server uses its own Vite 8/Rolldown dependency, while the workspace declares Vite 7.3.1. `vitest.storybook.config.ts` groups the complete native `@tanstack/query-devtools`, `@tanstack/router-devtools-core`, `@tanstack/table-devtools`, and `@tanstack/devtools-utils` packages separately in its optimizer output so rendering and mounting code arrive with their public entries before interaction or mount. The shared utility matcher includes the reachable 0.4.0 and 0.7.0 versions used by Form, Table and Pacer; preserve their native lazy mounting, abort and disposal behavior. Preserve `strictExecutionOrder` for native module initialization and the original browser assertions and lookup budgets; do not replace this with warmed stories, private imports or longer waits. This optimizer setting applies to automated browser checks, not the standalone Storybook server or shipped Go bundle.
- For styling, theme, and feature-layout rules under `src/devtools/`, follow `src/devtools/AGENTS.md` and `src/devtools/features/AGENTS.md`.
- The browser-test optimizer prebundles `@alexgorbatchev/shadcn` with React before tests start. Keep that entry in `vitest.browser.config.ts`: discovering it during a test reloads the browser and can split the React runtime.
- Storybook's `preview.beforeAll` configures a shared five-second failure budget for Testing Library async queries and assertions. Native panels lazy-load while stories run in parallel; wait for observable readiness and popover visibility without sleeps, retries, or per-story timeout overrides.
- Two kinds of test run in Chromium through `vitest.browser.config.ts`. Every hook test (`src/**/hooks/__tests__/*.test.ts`) does, because the hooks listen to the page, hit-test it, measure it, and follow its media queries. So does a test named `*.browser.test.ts`: name a test that way when its module queries or changes the DOM, and build real elements for it. Do not fake `document`, elements, or browser globals in a `bun test` file. They import from `vitest` and `@testing-library/react`. A hook test fails when anything reaches `console.error`, which is how React reports a state update outside `act`; fix the test's timing instead of silencing it. `bunfig.toml` keeps the whole `hooks/__tests__/` tree and every `*.browser.test.ts` out of `bun test`, whose runner has no DOM, so a new browser test needs no registration.
- Coverage is one figure for the package. `bun test`, the browser tests, and the stories each cover different code and each write an LCOV report under `.cache/coverage/`; `just ui coverage` (the last step of `just ui check`) merges them with `scripts/lineCoverage/reportCoverage.ts`, prints one table, and fails below the floor in the `justfile`. A line counts as covered when any run executed it. Only lines are merged: Bun and V8 count functions and branches differently. The table covers `src/` and `scripts/` without tests, stories, and fixtures. Raise the floor when coverage has risen; lower it only together with the reason. `just ui coverage` reads the reports of the last full run, so run `just ui test` or `just ui check` first.
- The browser-test viewport is 1024 by 768. `test-support/hostPageUtils.ts` fixes elements at stated rectangles so layout and hit testing are exact. Drive a hook with the browser's own input through `userEvent` from `vitest/browser`, inside `await act(async () => …)`: keys, clicks with a button and modifiers, hover, and wheel. Vitest releases held keys after each test. Produce window events by what causes them: a wheel on a page made scrollable for `scroll`, `page.viewport()` for `resize` (restore 1024 by 768 afterwards), and a press inside `addHostFrame()` for `blur`. A hook that cancels an event shows it in the outcome: a canceled press does not move the focus, and a listener added after the hook's reads `defaultPrevented`. Dispatch an event by hand only for one that no input produces, such as a press a page script dispatches on the document, and say so in the test. Change the system color scheme through `cdp()` and wait for the media query's own `change` event inside `act`, record navigations through the Navigation API because `location.assign` cannot be replaced, and spy on `navigator.clipboard.writeText` because headless Chromium refuses clipboard writes from an unfocused page.
- Devtools control requests use no authentication token. Preserve session IDs and instance routing when changing HTTP/WebSocket clients. Requests with a body send `content-type: application/json`; the control server refuses other bodies with 415.
- The config editor's TOML editor is CodeMirror 6, loaded only when its window first shows a file, through the dynamic import of `features/configEditor/createConfigEditorView.ts`, which Bun emits as its own chunk. Every `@codemirror/*` package and `@lezer/highlight` is pinned exactly, and each must exist once in the install: a second copy of `@codemirror/view` or `@codemirror/language` silently drops the extensions and facets built against it. After changing one, check `node_modules/.bun` for a single version of each, and clear stale nested resolutions in `bun.lock` when Bun keeps an older one for a dependent. `vitest.browser.config.ts` pre-bundles them, so a browser test is not reloaded when Vite first meets them.
- Stories that type into the TOML editor render in the document, not a shadow root: user-event types into `document.activeElement`, which is the shadow host for a field inside a shadow root. Browser tests with `userEvent` from `vitest/browser` send real input, which reaches the editor in the shadow root, as the save-shortcut test does. A synthetic click puts the editor's cursor at the start of the text. The completion list ignores keys for 75 ms after it opens, so stories accept a completion by clicking its option, and Escape right after typing cancels a pending completion instead of reaching the window.
- The browser entry awaits uncached `/__devhost__/config.json` before rendering. Every health message also carries that configuration as `config`, current when it was sent; `useServiceHealth` replaces the injected configuration global through `updateInjectedConfig` only when it changed, so a manifest edit reaches open pages without a reload and readers keep telling a change by object identity. Keep instance data out of the static bundle. Load the heavy native chat Thread renderer through its genuine React lazy boundary while keeping page-selection listeners synchronous. Production JavaScript and hashed chunks/fonts use one-year immutable caching; source-mode entry scripts use `no-store`.
- Native Vue regressions start genuine Vue DevTools 9.0.0-beta.1/Vite 8.3.3 hosts and owned Chromium profiles. Their exact dependencies, lockfile, ports, and runtime artifacts stay under `<os.tmpdir()>/devhost-e2e/vue-native-host/`; repository Vite remains 7.3.1. The fixture pins every devframe package, including the optional `@devframes/agentic` peer, to the `devframe` version devhost-ui depends on, so native MCP loads a compatible implementation. Each run owns its Vite dependency cache under `runs/<uuid>/.vite`: the default cache beside the shared dependency installation lets independent hosts replace each other's optimized modules and stall authorization. Run them through normal `just ui check` and stop all owned resources. Preserve the real authorization flow and host APIs; a simulated context cannot verify this integration.
- Keep the explicit native host `cacheDir`: the copied host has no package manifest. The overlapping cold-load regression retains genuine module requests and authorization while exercising different public dependency optimizer inputs and checking both actual Vue launchers and iframe entries.

- Native Redux browser regressions use the actual app-core inspector, Toolkit, Zustand middleware, and a checksum-pinned released extension in fresh owned Chromium profiles under `<os.tmpdir()>/devhost-e2e/redux-native-host/`. The fixture bundler runs in its own Bun process; the fixture extension is unpacked with `unzip`, which must be on `PATH`. Preserve real native controls, extension ownership, CSP denial, cleanup, and positive recovery assertions. Public registration is exported as `@alexgorbatchev/devhost-ui/redux` inside this private workspace and delivered to external hosts as `/__devhost__/redux.js`; this is not a published SDK.
- The Go-served Redux popup loads the emitted upstream `redux-monitor.css` in its own document. Preserve native CSS/font output, production content-versioned caching/gzip, and source rebuild failure responses without adding inspector styles to the injected host page.
- `ReduxDevtoolsMonitor` gives the upstream inspector an Emotion cache under Emotion's default key, marked `compat`. The monitor is rendered in the browser only; without the mark, Emotion's development build logs upstream's `:first-child` and `:nth-child` selectors as unsafe for server-side rendering. The key keeps upstream's class names. `.storybook/vitest.setup.ts` fails a story that logs that notice.

- Playwright `waitForFunction` fails as soon as its predicate throws; it does not poll again. A predicate that waits for the Vue entry must not call the fixture's `readVueEntry()`, which throws until the entry is registered. Wait with `waitForNativeVueEntry(page)`, or read `readContext().docks.entries` in the predicate.
- A test that launches Chromium passes `createOwnedBrowserEnvironment(runDirectoryPath)` from the repository's `test-support/` as the browser's `env`, never as the environment of the process that launches it: Playwright finds its browsers through the real home. The browser gets a home inside the run directory with a `Downloads` directory, because Chromium cancels a download when its default download directory is missing, and an OS-selected `TMPDIR` from `node:os.tmpdir()`, because long checkout-relative paths can crash Chromium. The native Vue host process gets a home inside its run directory as well; it keeps an instance registry and devtools state there. The demo recorder is not a test: `launchDemoBrowser` takes the environment `createDemoRuntime` builds.

## Boundaries

- Always: update the Go-side bundle build in `apps/devhost/` when the devtools entrypoint, generated asset contract, or package export shape changes.
- Ask first: publishing this package outside the monorepo or changing its package name.
- Never: make consumers import `src/devtools/*` directly when a package export can express the boundary.
