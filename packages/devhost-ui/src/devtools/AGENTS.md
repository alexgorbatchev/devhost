# `packages/devhost-ui/src/devtools/`

This `AGENTS.md` file must be kept up to date.

## Styling isolation

Its vital that when devtools are injected into the user's web application, CSS that devtools uses/defines must never ever conflict or affect the host application.

- The injected devtools UI must mount inside its own Shadow DOM root.
- Devtools component styling must use the Tailwind v4 entry stylesheet at `shared/devtools.css`; runtime and Storybook must install that compiled CSS through `shared/devtoolsStyles.ts` into the active Shadow DOM root. The CSS text comes from `shared/devtoolsCssText.ts`, an empty placeholder that each build replaces: `apps/devhost/scripts/buildDevtoolsBundle.ts` for the shipped runtime and the `inlineDevtoolsStylesheet` plugin in `vite.config.ts` for Storybook (dev server and static build) and browser tests. Do not read the stylesheet out of the page.
- shadcn/ui primitives live under `packages/devhost-ui/src/components/ui/` and may be composed by devtools features. Put app-specific behavior or stable test IDs in devtools-owned wrappers under `shared/` instead of forking generated primitives.
- Tailwind Preflight is allowed only inside the devtools Shadow DOM root. Do not load the devtools stylesheet into host-page globals.
- Do not add CSS modules, document-global CSS, or host-page global CSS for devtools UI styling.

- Do not rely on inherited app CSS for layout, typography, spacing, colors, borders, or shadows.
- `:host` is reset with `all: initial !important`, `display: contents`, and `pointer-events: none`. Host-page rules that match the host element still beat plain `:host` rules and inherit into the shadow tree; only an inner-context `!important` wins. Base typography therefore lives on `:host > *`, not `:host`, and every interactive surface must opt back in with `pointer-events-auto`.
- Chat's `PortalProvider` targets its own interactive modal-layer container inside `AnnotationTopLayer`. Portaling dialogs directly into the passive root inherits `pointer-events: none` and sends clicks through to the host page. Keep the empty container without a viewport-sized box so the host remains interactive after a dialog closes.
- Keep every theme size in px (`--spacing`, `--text-*`, radii). `rem` resolves against the host document's root font size, so rem-based utilities rescale with whatever page devhost is injected into.
- Browsers also ignore `@property` inside a shadow root, which leaves Tailwind v4's `--tw-*` variables undefined there, so border, ring, shadow, and transform utilities silently compute to nothing in production. `shared/devtoolsStyles.ts` restates every registered property's initial value in `@layer properties` when installing into a shadow root. Storybook's preview also loads `devtools.css` into the main document, which registers the properties globally and masks this; the `ShadowRootWithoutDocumentStyles` App story covers it inside a clean iframe.
- Browsers ignore `@font-face` inside a shadow root. The devtools font is registered with `document.fonts` by `shared/registerDevtoolsFonts.ts` under the namespaced `devhost JetBrains Mono` family; this is the documented document-level escape hatch for fonts. Bun emits the `.woff2` subsets as content-hashed files under `/__devhost__/assets/`; the Go server embeds them and serves them with immutable caching so browsers fetch only the subsets in use.
- Ordinary devtools surfaces share `DevtoolsTopLayer`, a passive manual popover above host stacking contexts and clipping ancestors. Order them with `--devhost-z-*` inside that root. Chat, selection highlights, the drawing canvas, and annotation controls share `AnnotationTopLayer`, a separate manual popover above native host and devhost popups. Do not add independent top-layer entries to individual surfaces: entry order overrides their z-index relationships.
- Host popovers and modal dialogs opened later enter the top layer above the root, so it re-enters (`shared/promoteDevtoolsTopLayer.ts` hides and shows it within one task, which keeps focus, scroll offsets, and transitions) after every host `toggle` event the document can observe. Popovers inside host shadow roots emit none, so `HighlightOverlay` and React Highlight also re-enter when they show host markers. Re-entry waits while a devtools popover or dialog is open, and while a closing popover still has computed `overlay: auto`: those must stay above the root, and a toolbar panel loses its anchor when its trigger re-enters above it. Retry on overlay transition completion or cancellation; `:popover-open` alone stops matching before the exit fade finishes. A host modal makes ordinary controls outside it inert; promotion changes paint order only. `observeAnnotationTopLayer` moves only the owned annotation mount into the active modal/popover, preserving the target node, anchor, and open state. Auto/hint popover ancestry prevents annotation clicks from light-dismissing the target. When the target lives in a different tree, the mount uses an owned shadow host with the compiled stylesheet and the source root's color scheme. Observe document and accessible shadow-root toggles directly, discover added shadow trees, and return the mount when targets close or disappear. Never patch host platform methods or reparent host panels.
- Toolbar panels use the Popover API (`ToolbarPopover`) plus CSS anchor positioning, so they light-dismiss natively and only one is open at a time. Other floating surfaces stay mounted and toggle `hidden`/`inert`; they and toolbar panels use the shared `devhost-fade` utility for enter/exit transitions, and `useRetainedValue` keeps their last content while fading out.
- Layering uses the `--devhost-z-*` tokens in `shared/devtools.css`, bottom to top: `overlay` (cursor highlights), `popover` (component-source menu), `dock` (toolbar), `edge` (the minimap and chat panel), `modal`, `annotation` (element selection and drawings), `annotation-controls` (floating tools and hint). The App layering stories check paint order. The separate annotation entry keeps its canvas and tools above native popovers/dialogs, while chat stays usable inside the active modal. Ending annotation with Escape must prevent the target's default close request; a later Escape resumes native dismissal. `position: fixed` always creates a stacking context, so put the token on the outermost fixed element of a surface; on a child of a fixed wrapper it only orders that child inside the wrapper. The Go bundle's CSS minifier (Bun) rounds every number to six significant digits, so keep z-index and other large numeric token values within six significant digits or neighbouring layers collapse into one and stacking falls back to DOM order. Storybook compiles CSS through Vite and does not show this; `TestBundledDevtoolsLayersStackInOrder` in `apps/devhost/internal/devtools/assets_test.go` checks the shipped bundle.
- Native browser control uses a direct native Connect/Disconnect command and complete visible status/setup/error/Copy in the dock's ordinary readout. This operation has no floating panel. Keep the toolbar compact at 26px when its controls fit one row; allow segments and grouped controls to wrap on narrow viewports. Preserve unrelated popovers, full native browser labels, the same command button and native focus during connection transitions. Dock composition stays generic; App/feature components own browser state. Prove real viewport clipping/hit bounds and keyboard operation without manual focus/scroll repairs.
- Direct JSX `style={...}` props are allowed only for dynamic geometry that cannot be represented statically, such as measured top/left/width/height values. Static visual values belong in Tailwind classes or semantic CSS variables.
- The shared lint policy bans `className` and `style` on components, a styled element that wraps a single component, and `[&…]` selectors that reach into children. Give the owning component a typed prop instead:
  - Icons render through `components/ui/Icon` (`glyph`, `size`, `tone`, `isSpinning`). Lucide components take no class, so `Icon` marks the glyph with data attributes and the `[data-slot="icon"]` rules in `shared/devtools.css` style it.
  - A raw button that shows only an icon names itself with a visually hidden `sr-only` text child instead of `aria-label`.
  - A child that reacts to its parent's state uses `group` variants on the child, not a selector on the parent.
  - `shared/components/FloatingSurface` places a popup at viewport coordinates, `shared/components/PanelActions` aligns panel-level actions, and `Button` joins a neighbor through `joinedEdge`.
- Exception: minimap ANSI fragments receive dynamic foreground/background colors from service logs. `LogAnsiFragment` measures the rendered background before paint and uses `use-color` to adjust only the foreground to 4.5:1; ANSI backgrounds stay opaque, and dimming affects only text. Recompute for theme and focused-row changes.
- Any intentional document-level styling escape hatch must be narrowly justified at the use site because it breaks isolation guarantees.
- Keyboard events leave the shadow root retargeted to its host, so host shortcuts cannot recognize that a devtools field or control has focus. `DevtoolsTopLayer` ends the propagation of every `keydown`, `keypress`, and `keyup` from inside devtools at the shadow root. Devtools listeners on the document or window that must see those keys, such as Escape ending selection or cancelling a drawing move, listen in the capture phase. A third-party document listener that reads `event.target` sees the shadow host: read `composedPath()[0]` instead, as the assistant-ui patch does for the composer's Escape.
- Exception: the genuine Redux DevTools App owns its Emotion styles in its separate monitor window document. Keep the injected Redux launcher inside devhost's Shadow DOM; never load those native inspector styles into the host document or restyle the upstream panel.
- The injected devtools UI must remain visually isolated from the host page.

## Theme tokens & Visual Design

- **Design reference:** `packages/design/references/devtools.html` (`just design`) is the visual source of truth for tokens, layout, and state treatments.

- **Compact Layout & Sizing:** The UI styling must be compact. This means no large spaces and no large rounded corners. Keep spacing values tight and border-radius options small.
- **Fixed Monospace Typography:** Fixed monospace fonts must be used throughout the devtools interface (e.g., Maple Mono Normal NF, JetBrainsMono, or other system monospaces). Font sizes must not be too small even though the layout is compact, ensuring high readability.
- **Distinct Status States:** Disabled, error, active, and neutral states must all be visually distinct from one another. Avoid subtle styling differences that could be missed.
- **High Contrast:** The overall styling and color palette must provide enough contrast to be easily visible and readable on top of any layout or background color. This rule applies equally to both light and dark themes.
- **Contrast contracts:** Readable text, placeholders, and shortcuts meet 4.5:1 in both themes; form-control boundaries use `--input` / `--dh-input-line` for 3:1 contrast. Keep shortcut text opaque.
- **No Redundancy:** There must not be repeated labels, content, or indicators in the layout. Keep the layout lean and informative.
- **Visual Isolation & Variables:** Shared visual values come from semantic CSS variables in `shared/devtools.css`, mapped to shared design tokens. Runtime JavaScript theme access stays in narrow adapters for values CSS cannot consume directly, such as canvas colors and matched font settings. Interaction geometry and layout constants belong near their owning logic.
- **Component Access:** Presentational devtools components must read theme values via semantic Tailwind tokens and shadcn primitives first, not a `theme` prop.
- **Semantic Mapping:** Shared visual values must come from semantic tokens instead of being duplicated inline across components.
- **Minimum Token Checklist:** Reusable tokens must include, at minimum:
  - font sizes: `sm`, `md`, `lg` (must be readable, not overly small)
  - colors: background, foreground, muted, border, accent, danger when needed
  - spacing values (compact and tight)
  - border radii (small, no large round corners)
  - shadows when used
  - z-index values when they are actual reusable visual tokens
- **Anti-Patterns:** Repeated hardcoded visual values are not allowed when they belong in the shared theme. Component styles must compose from the shared theme first and add only the minimum component-local overrides.

## Feature organization

- Organize devtools code by feature first.
- Put feature-owned React components under `features/<featureName>/components/`, with their Storybook files under the sibling `features/<featureName>/components/stories/` directory.
- Put exported feature hooks under `features/<featureName>/hooks/use*.ts[x]`, with hook tests under the sibling `features/<featureName>/hooks/__tests__/` directory.
- Keep feature-owned pure helpers and their tests under `features/<featureName>/` and `features/<featureName>/__tests__/` unless they are component or hook ownership files.
- Keep cross-feature theme, config, websocket helpers, and shared types under `shared/`; shared React components belong in `shared/components/`, shared hooks in `shared/hooks/`, and shared Storybook harness components in `shared/components/stories/helpers.tsx`.
- Do not leave feature-specific logic in the `src/devtools/` root when it belongs to a concrete feature folder.
- See `features/AGENTS.md` for specific rules on feature encapsulation, stories, and tests.

## Annotation metadata

- Resolve page context by the current routed hostname and path. Native chat sessions retain their selected project's working directory; keep browser and Go routing resolution aligned.

- Annotation capture may collect optional React development source metadata from host-page elements when the host app exposes it via React fiber debug/source fields.
- When the raw React metadata points at generated JavaScript and the host serves fetchable source maps, devhost should attempt source-map symbolication before storing the annotation source location.
- Treat source metadata capture as best-effort host introspection, not a guaranteed contract across all frameworks, bundlers, or production builds.
- Do not leave annotation-selection console logging enabled once source-location debugging is complete because it exposes host source paths and pollutes the host-app console.

## React Highlight matching

- Cursor hook lifecycle coverage lives in `features/reactHighlight/hooks/__tests__/useReactHighlightOverlay.test.ts`, which renders the real hook against the shared mock socket and an injected async renderer. Cleanup must detach the socket listener, close the connection, and remove current or late-resolving rectangles; newer cursor messages invalidate older results.
- Source-highlight rectangles are fixed, pointer-transparent `overlay`-layer elements appended to `DevtoolsTopLayer`, above host content and below devtools controls. Showing them re-enters the top layer; the `ReactHighlightsAbove*` App stories cover host stacking contexts, host popovers, and popovers inside host shadow roots.
- React Highlight browser matching must prefer React fiber source metadata and then fall back to fetchable script source maps when host fibers do not expose source locations.
- Keep the browser diagnostic event `devhost:react-highlight` in sync with matching behavior; it should remain useful for distinguishing transport success from DOM match failure.
- Treat source-map matching as best-effort for lowercase host JSX tags. Do not claim reliable component-callsite highlighting for uppercase component tags unless runtime instrumentation or fiber metadata proves the rendered DOM subtree.
- When changing React Highlight matching, update `packages/docs/src/content/docs/guides/react-highlight.md` and feature-local tests under `features/reactHighlight/__tests__/`.

## Implementation intent

- Keep **Restart Stack** available in both Services and the crash recovery dialog. Use the dedicated stack endpoint, disable duplicate/conflicting restart actions while pending, report failures, and reload a recovery page after successful recovery. Individual service restart preserves its assigned port.

- `health.stoppedServices` lists the services a run left out. Keep them out of the service counts, dots, and rows: the Services panel reaches them through its **Stopped services** button and view, which closes by itself when the last one has started. The view's **Start** posts to `/__devhost__/start-service`; the started service arrives through the health stream, not the response. Disable **Start** while a service restarts, a repository switches, or the stack restarts, because devhost runs those operations one at a time.

- Every health-stream message carries the injected configuration as `config`. Apply it through `updateInjectedConfig`, which replaces the injected configuration global only when it changed, so open panels follow service, route, and devtools-setting reloads; a worktree refresh response carries none and leaves the configuration as it is. Retain instance connections and native chat settings, which live outside it.
- Read the injected configuration with `readInjectedDevtoolsConfig()`. It parses each injected object once, so components get the same object and arrays on every render until the configuration changes. Change the configuration by replacing the injected object, as `updateInjectedRouting` does; an edit in place is invisible to readers.
- Consume native chat session state, catalog metadata, pending request IDs, and replay events from the control server without inventing models or permissions. Keep native approval and question responses explicit. Collapse preserves the conversation; close terminates its owned process.

- The config editor (`features/configEditor`) is a modal-layer window. It stays mounted while closed, so unsaved changes survive closing it, and keeps one draft per file. A file with unsaved changes keeps the version it was opened at, and a save sends that version, so a file changed on disk since is refused. After a save the window waits for the health stream's `configuration` entry of the saved file's source to count a reload past the count read before the save, and then reports that reload as applied or rejected. Rejected reloads show in the dock readout through `ConfigRejectionNotice` whether or not the editor is on. Typing reaches the CodeMirror view a task before the page renders it, so put text into the view only from the hook's `readContent()`, never from a rendered `content`: an older render otherwise replaces the newer text and moves the cursor to the start (`KeepsTextTypedWhileThePageCatchesUp`).
- Persist browser view settings through `shared/createDevtoolsSettingsStore.ts`, using Zustand's versioned persistence and Zod validation. Scope storage to the project directory and page origin so navigation followed by reload keeps the conversation; inject the store into consumers, and keep transcripts, images, permissions and host DOM references out of it. Reattach only an existing live saved session on reload; never restart a closed one or resend prompts/approvals. Restore scroll through the native Thread viewport props after replay and visibility. The published shadcn package exposes those props; preserve its existing composer and user-text slots. Storybook clears only the devhost settings namespace between stories.

- Keep flexible empty-thread spacing outside the native `ThreadPrimitive.ViewportFooter`. It measures its own height plus top margin, but its size observer does not track auto-margin changes when history fills the viewport. The shadcn Thread uses a sibling flex spacer so a stale footer inset cannot pull a restored reading position to the bottom. Wait for the native runtime to apply the replayed message IDs before restoring scroll; its external-store adapter updates in a React effect.

- Open health, logs, resource usage, React Highlight, and native chat streams through `shared/openReconnectingWebSocket.ts`. It retries lost connections with bounded backoff and leaves normally closed streams closed. During disconnection, health shows unavailable services, logs retain entries until the next snapshot, resource readouts disappear, and React Highlight clears its overlay. Chat restores its authoritative snapshot and pending request IDs after reconnecting; never replay sent prompts or permission responses automatically.
- `features/resourceUsage` renders the host CPU, memory, and disk readouts. The server omits a readout that is off or failing, and the segment renders only what it receives. Each readout is a native `<meter>`; its track and fill live in pseudo-elements, so `[data-slot="usage-meter"]` rules in `shared/devtools.css` style them. Browsers do not expose a meter's fill color to scripts, so stories check the meter's `low`/`high` regions instead. The level thresholds live in `features/resourceUsage/constants.ts`; keep them equal to the ones in `packages/design/references/devtools.html`.

- With status devtools enabled, foreground service exit codes trigger a full-screen recovery dialog with retained service logs and restart controls. Keep the dialog open during recovery and failed attempts; remove it after healthy recovery. Health-probe failures and control-stream disconnects alone are not process exit events.
- Keep the theme small and explicit.
- Prefer stable semantic names over raw color names.
- Treat the injected UI like a self-contained widget system, not like page-local markup.

## Testing guidance

- Do not write unit tests or Storybook `play` assertions that only snapshot exact HSL values, Tailwind class strings or raw stylesheet text when those values are static implementation details.
- Prefer tests that prove observable behavior, accessibility state, integration wiring, or layout/geometry behavior that users can actually notice.
- Assert paint order with native hit testing (`expectDevtoolsSurfaceOnTop` in `shared/components/stories/helpers.tsx`), not z-index values. Ordinary controls outside a modal are inert and invisible to hit testing; their root stories check after closing it or observe re-entry. Annotation stories must instead click real controls while the dialog remains open, including nested and shadow-root dialogs, and prove target state and cleanup.
- Direct `userEvent` calls share no key state: `userEvent.keyboard("{Alt>}")` followed by a separate `userEvent.keyboard("{/Alt}")` never dispatches the keyup, which leaves Alt-selection active and swallows later clicks. Hold and release modifiers through one `userEvent.setup()` session.
- `shared/components/stories/helpers.tsx` builds the story shadow tree the way `renderDevtools` builds the production one: a host marked `data-devhost-devtools` and an unmarked mount node. Events leaving a shadow root are retargeted to the host, so page-level listeners recognize a devtools interaction only by that marker. `renderDevtoolsInStoryShadowRoot` renders a tree that brings its own `DevtoolsTopLayer`, such as the app; `renderInDevtoolsStoryShadowRoot` renders a single component inside a stand-in for that root, which keeps the story in normal flow.
- `resolveDevtoolsPortalContainer` uses the enclosing annotation layer when present; otherwise it finds the devtools root by id and throws when the tree has none. A story that renders `HighlightOverlay`, directly or through page selection, therefore renders a `DevtoolsTopLayer` in the same tree, including stories that render in the document instead of a shadow root.
- `test-support/createMockWebSocket.ts` is the only `WebSocket` replacement, shared by stories and hook tests: a connect handler plays the server, and can send raw frames, close the connection, and read how the client closed it. The Storybook preview and both App mocks in `.storybook/` supply that handler; hook tests install the mock with `test-support/installMockWebSocket.ts` and answer control-plane requests through `test-support/installMockFetch.ts`. Like a real socket, the mock still delivers messages between the client's `close()` and the close event. `.storybook/withDevhostMock.tsx` installs the mock selected by story `parameters` (`designOverview`, `serviceRecovery`, `worktreeRecovery`, `configEditor`) and renders the story once it is in place. Add a stack factory to `components/stories/fixtures.ts` and a parameter instead of another mock: a mock installed by a story-level decorator runs inside the meta decorator and is overwritten.
- A hook test renders the real hook in Chromium and drives it the way the page does: keyboard and pointer input through `userEvent` from `vitest/browser`, control-plane traffic through the mock socket and fetch, and the collaborators the hook takes as arguments. A test that only checks that the hook is a function, or only calls helpers the hook uses, satisfies the hook-test lint rule without covering the hook; tests of those helpers belong beside the helper.
- `renderDevtools()` returns an unmount function. Stories that mount the production app give the independent root to `.storybook/setupInjectedDevtoolsStory.ts`; Storybook's `beforeEach` cleanup disposes it outside React's commit. Mount from `InjectedMountScene` after the control-plane decorator is ready, and toggle through the owner's methods in event handlers. Never unmount this root in a React effect cleanup. Removing only its host leaves page-level listeners alive, which swallow selection clicks in later stories. The browser test setup forwards console errors and fails on React's synchronous root-unmount warning.
- user-event installs its value tracking from a document-level `focus` listener, which sees the shadow host instead of the field. Text typed into a React-controlled input inside a shadow root therefore changes the DOM value without firing `onChange`. Assert the typed value there, and cover controlled-input behavior in stories that render the component in the document.

## Done policy

- Done: devtools work is complete only when the root/workspace done policy is satisfied and any required devtools docs, stories, tests, or design notes stay in sync.
- Done: if styling-isolation changes, source-location behavior, or feature rules still need follow-up docs/tests, report the work as incomplete instead of done.
