# devhost docs site

Public Astro + Starlight docs workspace for `devhost`, published to GitHub Pages under `/devhost`.

## Commands

- Record marketing demos: `bun run record:marketing [scenario-id ...]`
- Sync the generated landing page and manifest reference: `bun run sync`
- Start the local docs server: `bun run dev`
- Check package-local validations: `bun run check`
- Build the static site: `bun run build`
- Preview the production build: `bun run preview`

## Local conventions

- `apps/devhost/README.md` is the source of truth for the landing page.
- `apps/devhost/devhost.example.toml` is the source of truth for the manifest reference page.
- `src/content/docs/guides/**/*.md` is the source of truth for the Guides section.
- `src/content/docs/architecture/**/*.md` is the source of truth for the Architecture section.
- `sync.ts` only regenerates `src/content/docs/index.mdx` and `src/content/docs/reference/devhost-example.md` from the app README and manifest reference.
- The browser-hosted demo recording surface for the injected devtools lives in `src/pages/[captureRoute].astro`, `src/components/CaptureSourceCardSurface.tsx`, and `src/scripts/devhostCaptureDemo.ts`, and is served at `/__capture__/`.
- `src/recordings/` owns the recorder scenario metadata and rrweb helpers.

## Local gotchas

- This workspace uses the repo-root `bun.lock`. Do not add a package-local lockfile.
- Shared `oxfmt` / `oxlint` enforcement runs from the repo root, not from this workspace `check` script.
- `bun run check` runs `bun test`, content sync, `astro check`, and `astro build`.
- `bun run dev`, `bun run start`, and `bun run preview` bind the Astro server to `0.0.0.0` so the site is reachable from outside the current environment.
- `astro.config.mjs` allows all dev/preview hosts for this workspace; treat the docs server as broadly reachable while it is running.
- The site ships from GitHub Pages at `/devhost`, so content should rely on relative links or Starlight routing instead of hard-coded root-relative `/...` paths.
- `src/content/docs/index.mdx` and `src/content/docs/reference/devhost-example.md` are generated outputs; edit `apps/devhost/README.md` and `apps/devhost/devhost.example.toml` instead.
- Keep the `__capture__` route stable unless the recorder workflow is intentionally changing; the recorder command and any external capture automation depend on that path.
- `bun run record:marketing` builds the docs site, starts a temporary local Astro preview server, and writes rrweb JSON artifacts under `public/recordings/marketing/`.
- Keep the capture-page target test IDs stable unless the recorder choreography and affected fixtures are updated in the same change.
- `src/recordings/marketingRecordingScenarios.ts` is shared metadata for both the overview-page playback tabs and the recorder flow. Keep scenario ids, labels, viewports, and recording filenames aligned across both surfaces.
- Generated replay files under `public/recordings/marketing/` are outputs, not editable source files.
- Recorder changes are only trustworthy after re-recording the affected scenario and visually checking the replay, especially when cursor timing, modifier keys, or highlight state changes.
- For the annotation handoff replay, move to the first target before pressing `Alt`, wiggle slightly to reveal the highlight, pause briefly, click the first target, move to the second target with `Alt` still held, pause again, click, then release `Alt` before typing.

## Boundaries

- Always: update this file, the repo-root `AGENTS.md`, and `.github/workflows/docs.yml` when the docs build or publish workflow changes.
- Always: edit `apps/devhost/README.md` for the landing page, `apps/devhost/devhost.example.toml` for the manifest reference, and `src/content/docs/guides/` or `src/content/docs/architecture/` for published docs pages.
- Never: hand-edit `src/content/docs/index.mdx` or `src/content/docs/reference/devhost-example.md`; they are generated by `sync.ts`.
- Done: only claim docs work complete after required docs/AGENTS updates are done and `bun run --cwd packages/docs check` passes.
- Always: rerun `bun run record:marketing <scenario-id>` after changing replay scenarios, capture-page targets, recorder choreography, or playback metadata for the affected scenario.
- Always: visually inspect the affected replay after regeneration when timing, keyboard modifiers, or perceived highlight state changes.
- Ask first: changing the GitHub Pages base path, replacing Astro/Starlight, or introducing another published docs workspace.
